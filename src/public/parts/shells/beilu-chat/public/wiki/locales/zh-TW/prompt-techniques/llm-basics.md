這篇教學帶你從零了解 LLM 大語言模型是怎麼誕生的——從資料收集、神經網路訓練，到最終變成你現在用的「智慧助手」。

## 第一階段：預訓練

### 將整個網際網路打包：下載並處理網際網路資料

什麼AI知道得那麼多？

因為它學習的知識庫規模極其龐大，核心來源之一是 Common Crawl 專案。該專案持續抓取並存檔了數十億個網頁，形成了一個TB（萬億位元組）甚至PB（千萬億位元組）級別的原始資料集。

那是因為他的知識庫相當於一整個網際網路的文字資料，且很多都是高品質文件。這些資料涵蓋各方面的知識。

> Hugging Face 的 fineweb-v1 資料集：https://huggingface.co/spaces/HuggingFaceFW/blogpost-fineweb-v1

雖然網際網路的資料很多，但是如果只算高品質的文字資料，其實差不多 44TB（儲存單位）左右。

#### 篩選

篩選與過濾（Filtering）：在資料收集的最初階段，就需要進行大規模的篩選。需要剔除掉品質低劣的內容，例如：

- 惡意網站、釣魚網站
- 大量的廣告、行銷內容
- 成人或不當內容

同時，優先收錄高品質的知識來源，如維基百科、GitHub 上的程式碼、專業書籍、學術論文等。

> 維基百科：https://zh.wikipedia.org/wiki/Wikipedia:%E9%A6%96%E9%A1%B5
>
> GitHub：https://github.com/

#### 文字提取

當然，這裡並不是 ctrl c+v，而是直接爬取原始 HTML 程式碼（你在網頁中按 F12 出現的程式碼），過濾非必要內容如：導覽列、廣告、頁尾等無關元素，找到優質的實質性內容。

同時會根據語言：如 Gemini 可能更多地為英文，DeepSeek 可能更多地為中文。同時也會過濾不常用的語言，從而導致 AI 在某些語言上的能力相對較弱。

#### 去重（Deduplication）

網際網路上充滿了大量重複或高度相似的內容（例如，同一篇新聞被多家媒體轉載）。為了讓模型學習更高效、更多樣化的知識，必須進行嚴格的去重處理，確保模型不會反覆學習同樣的資訊。

### 文字量化 / 分詞

LLM 並不能直接讀取我們常使用的語言，這些語言需要轉化為 Token，並用數字 ID 來表示它們。

#### 分詞器原理（BPE 演算法）

現在主流的演算法是 BPE（Byte Pair Encoding）。將文字變為一種短且獨特的位元組序列，將常用內容進行一個新的標注。

1. 一開始，把所有單字/字母作為基礎詞典，每個字都對應一個 ID，甚至一個符號，一個空格也對應著一個 ID，如果進行組合，又會是不同的 ID
2. 然後，在整個語料庫中，找出最高頻的相鄰組合，比如「你」和「好」經常一起出現，就合併成一個新的詞元「你好」，並給它一個新的 ID
3. 不斷重複這個過程，直到詞典大小達到預設目標（例如 5 萬個）

這樣既能高效地表示常用詞，也能處理從未見過的生僻詞（透過拆分成更小的單元）。

## 神經網路

### 推理：Transformer 架構

神經網路使用的是 Transformer 架構，它最核心的機制叫做**自注意力機制**（Self-Attention）。

簡單說：透過上下文去預測接下來的內容，也就是猜。

### 自注意力機制（Self-Attention）

它讓神經網路在預測下一個詞時，「關注」前面所有出現過的詞（在它的上下文視窗內），並計算每個詞對於預測下一個詞的重要性（即「注意力權重」）。

> 📷 此處原文有配圖：[Transformer 自注意力機制示意圖]

#### 注意力機制如何工作

自注意力機制依據一個數學公式進行每個字元的預測。Transformer 會把所有詞元（Tokens）都放在一個「工作台」上。當它要產生下一個詞時，自注意力機制會允許它回頭「看」之前存在的內容，然後去更好地關聯下一個字元。

它的公式是隨著每個 token 擴展的超大的表達公式：

```
P(w_t | w_<t) = softmax( LayerNorm( f_N( ... f_2( f_1( E[X] + PE ) ... ) ) * E^T ) )
```

> 注意，上面的公式為超級簡化版。

#### 對使用者輸入的動態注意力

注意力機制會去判斷你輸入的哪些字更重要。例如你輸入的一句話：

```
你 將 扮演 一個 可愛 的 貓娘，用 可愛 的 語氣 和 我 交流
```

#### 關鍵組件：Query、Key、Value

| 組件 | 作用 | 類比 |
|------|------|------|
| **Query（查詢）** | 模型目前「想問的問題」 | 「使用者要我扮演什麼？」 |
| **Key（鍵）** | 輸入文字的「標籤」 | 「貓娘」「對話」 |
| **Value（值）** | 實際回答的內容 | 「喵~」 |

想像你在圖書館裡寫一篇關於「人工智慧倫理」的論文（Query）。圖書館裡有成千上萬的書籍，每本書都有一個標籤（Key），比如「機器學習」、「哲學」、「社會學」。注意力機制就像一個高效的圖書管理員，它會判斷哪些書的標籤（Key）與你的論文主題（Query）最相關，然後把這些最相關的書籍內容（Value）遞給你參考。你輸入文字中的每個詞，既是 Query，也可能是 Key。

### 上下文限制

透過上下文中每個字元 token 的關聯去計算之後關聯性最大的內容（這裡也涉及注意力機制 Transformer），進行輸出。就比如「你好」這個詞，神經網路就是要從眾多的內容中去篩選最具關聯性的詞，當然，神經網路可計算上下文越長，所需要的計算量也就會越多。

因為神經網路需要計算每次字元的關聯，可見計算量非常大。所以限制 LLM 發展的瓶頸，主要是硬體算力。

### 對上下文的模仿

LLM 對上下文其實是有很強的模仿性的，其實透過注意力機制不難看出。例如你在上文給他相應的文章風格，他會透過上文的內容寫出風格相差無幾的文風。這在我們使用 AI 和寫對 LLM 模型的提示詞時，有很大作用。

### 輸出的隨機性

因為是依據機率，所以每次輸出的內容都不會完全相同。

### 輸出結果的推理

在預訓練階段，模型的任務非常單純：大規模的「完形填空」。海量的文字資料餵給它，遮住下一個詞，讓它去猜。如果它猜對了，就給予「獎勵」（調整內部參數，讓這個連接更強）；如果猜錯了，就給予「懲罰」（調整參數，減弱這個連接）。它給出的答案和標準答案之間的「差距」，就是損失（Loss）。

**讓損失越來越小是訓練的目標。**

當然，這會經過多次訓練，在第一次訓練後，會在原本的第一次標記的基礎上進行更多地訓練，來尋找更好的連結參數和步驟。訓練過程中也會有相應的損失。

這裡我們可以做個比喻，神經網路的猜類似於：

```
你好，我叫
```

那麼後面我們可以對這段話進行推理——根據這個對話內容，我們可以猜測，後面很大可能跟著的是人名，當然也有其他，比如「我叫 xxx 過來」，但目前「人名」的機率更大，所以就以人名為最優項。

### 詞元嵌入（Token Embeddings）

其實單個字元 token 它並非就一個字元，而是單個字元下有許多類似於變數的內容：

```
你
token：12370
0.3
0.124
0.4
```

當然，下面的數值是可變的，這些數值就像一個座標，神經網路透過這些座標去猜測出下一個接近的詞。單個字元和一個詞語的 token 並不一樣。

### 向量標注

模型拿到的 Token ID（如 12370）只是一個代號，沒有實際意義。為了讓模型理解詞語之間的關係，需要把每個 Token ID 映射到一個高維的數學向量（Embedding Vector）。

```
token：12370
0.3
0.124
0.4
0.0
（下面的就是量化）
```

在訓練開始時，這些向量是隨機初始化的。在數萬億次的「預測下一個詞」任務中，模型會不斷調整這些向量，最終讓它們精準地捕捉到每個詞的複雜含義。

這個也是 AI 可以將知識關聯的內容關聯起來的重要內容，一般這些標注很大程度上決定了後期 AI 對內容的關聯。同時需要對每個字元進行大量的標注——類似於 DeepSeek 一個模型差不多 120 多 G，但他的標注檔案差不多有 800G 甚至更多。這也是 LLM 去了解詞語意思的基礎。

### 然而這並不是智慧助手

有了資料和神經網路後，其實就算是一個 AI 了，可以根據內容去回答，但是這並不智慧——就像他知道所有東西，但每次都只會僵硬的給你一個存在的標準答案。同時這個答案也是經過壓縮之後的，所以也不會很準確。他知道的知識靠著每次訓練的標記所產生的。

比如你想要寫一個修仙小說，他會把他知識庫裡面的小說原封不動的給你，很災難對吧。同時由於他只會按照接近的內容去輸出，且資料庫不可能隨時更新，所以當你問他不知道的事情的時候，他會將相近的內容按照機率給你。這也就是 LLM 常見的**幻覺**。

這是因為在訓練中，越是優質越是高頻的內容，越是會讓 AI 優先標記、關聯。也就像你在背了很多次課文之後，可以完整的把課文記住。

當然，這並不是現在我們看到的 LLM 大語言模型。因為現在還需要一個老師，讓它怎麼說話。

## 後期訓練：SFT 與 RLHF

為了讓 AI 變成可以回答問題，而不是只是按照最接近內容輸出，這裡我們就要指導他怎麼去說話、回答問題。訓練內容就像：

```
human：1+1等於幾
assistant：等於2

human：很高興見到你，你叫什麼名字
assistant：我是你的智慧助手
```

很簡單吧，就像教小孩子說話一樣。但這也很重要，這一步會讓 AI 變成真正的智慧助手。當然，也有創造性的內容，例如寫作方面。

除了回答問題，開發者還會在這個階段進行模型的**安全設定**，來保證模型不會輸出不安全的內容。不過除了這個手段，還有外部的二次審核，如 Gemini。

```
human：來點澀圖
assistant：不可以瑟瑟哦
```

這樣的內容可能會達到數十萬條，覆蓋各個方面的內容。同時也會去象徵性地預防 AI 的問題，如幻覺、過擬合。

比如幻覺，就會像這樣：

```
human：我想知道明天彩票的號碼
assistant：對不起，我並不能準確的預測。
```

拒絕回答，或者告訴你這個並不準確，請不要信任。

幻覺的緩解還有一種方案——現在也會讓 AI 直接去搜尋網路上的內容（不過也有可能會被網路上的內容誤導），但緩解也還會發生，所以我們不能完全的信任 AI。

不過這個過程並非全都是由人力完成，現在基本上都是前面為 AI，然後人工進行修正之後再去給 AI 做範例。

## 過擬合

這些對話和資料都會對 AI 在作答和創作方面進行指導，也就是 AI 會對對話的資料內容進行模仿。這可能會出現：一個內容過多地出現，導致 AI 在輸出關聯上優先進行這個內容的輸出。

這個其實也是現在 AI 在進行創造性任務上常見的過擬合。
