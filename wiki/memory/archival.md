# 记忆归档与检索

记忆归档是记忆系统的"新陈代谢"——将不再活跃的记忆从热层搬迁到温层和冷层；检索则在需要时尝试找回相关记忆。归档动作本身是搬迁而不是主动删除，但历史是否仍可恢复和召回，还取决于文件保留、写入与索引是否成功、召回路线以及备份情况。

## 三层搬迁路径

```
hot（热层）
  ↓ 阈值触发 / 日终归档
warm（温层）
  ↓ 满约一个月，整月搬迁
cold（冷层/归档）
```

### hot → warm 搬迁

自动搬迁由**机械的阈值规则**驱动（不需要调用 AI）：

- 当日临时记忆表攒满（默认 50 条）时，超出部分按批次归档到温层。物理归档自动执行；P2 的后台自动回调已停止，当前手动按钮会显式以 `manual:true` 进入总结链，但本轮尚未用真实模型服务验收最终总结产物
- "关于用户"等表的过期条目按天数规则归入对应热层文件
- 点"结束当天"按钮执行日终归档流程：合并当天总结、写入日总结文件、清理临时表

搬迁后，条目从每轮自动注入变为**按需检索**。

### warm → cold 搬迁

温层按日期存档，覆盖最近约一个月。超过约 30 天的内容以**整月目录**为单位搬入冷层（每天最多执行一次）。搬迁后，条目进入长期归档，在**检索/搜索命中**时依然可达。

### 关于 P3/P4/P5

你可能注意到 P 系列预设里有"每日总结 AI（P3）""热→温转移 AI（P4）""月度总结 AI（P5）"。它们**默认全部关闭**，上面描述的自动搬迁是不调 AI 的机械操作。想让 AI 参与生成日总结/月总结，需要去 P 系列引擎面板开启对应预设并手动运行。详见[记忆系统概览](overview.md)的预设一览表。

## 搬迁的例外

以下内容**不参与搬迁**，始终留在热层：

- `forever.json` 中的永久记忆
- 当前活跃的表格条目（正在使用的表格行）
- 系统级配置信息

## 记忆怎么被"想起来"：P1 召回（两条线互斥）

P1 有三个可用状态，两个召回器互斥：`10` 本地自驱动召回（当前默认方向）、`01` 原 AI P1、`00` 两者都关，不开放 `11` 双开。

**`10` 自驱动 P1（本地 Node0–4 白盒链）**：每条合格用户消息自动触发，以"当前输入 + 最近 5 条用户消息 + Data"为锚点（AI 历史输出不作锚点），本地完成分词/词性/时间/专名提取 → 关联扩展 → 多证据审查 → 从 Data 与 hot/warm/cold 真实记录融合排序，产出召回记录与联想方向。召回阶段 0 次生成式 LLM 调用。详见[当前生产合同](../p1-recall/ch7-current-runtime.md)。

**`01` AI P1（保留的原召回线）**：每条消息触发一次真实 AI 子调用，由 P1 预设的提示词指导它像人一样主观判断：这句话需不需要翻旧记忆、翻哪些（它能看到表格、热层和最近对话，可以发 `<memorySearch>` 指令主动去温/冷层翻记忆文件，支持多轮搜索）、找到之后怎么整理交给主 AI。它的判断是联想式的，深浅自适应——闲聊时轻取，被问"还记得几月那件事吗"时深入冷层去翻。

P1 还身兼两个判断职责：判断本轮要不要联网（需要时唤起 P8）、要不要建议切换预设。

### 召回溯源卡

AI 每次用到记忆后，回复下方会出现可折叠的「🧠 本轮运用记忆 (N)」溯源卡。展开可以看到：本轮用了哪些记忆文件、相关度、内容摘要。想知道"AI 为什么突然提起这件事"，点开它就有答案。

### 向量语义兜底（默认关闭）

系统内置了一个可选的向量数据库语义召回增强：开启后，当关键词检索一无所获时，会用语义相似度做兜底捞取；P1 检索前也会用它做一轮初筛。该功能默认关闭，属于进阶选项。

## 两套归档，别搞混

系统里有两套彼此独立的"归档"：

1. **记忆文件归档**：本页上文讲的三层搬迁——热层 JSON 文件/临时记忆按阈值和日终流程移动到温层、冷层。归档工具栏的按钮操作的就是这一套。
2. **表格行归档**：AI（或你在表格编辑器里）把某张表的行**归档而非删除**——行被移入热层的归档文件，之后可以恢复。AI 用 `archiveRows` 指令执行这类归档；与之相对，`deleteRow` 是不留档的直接删除。

两套归档落盘位置不同、恢复入口不同。找"消失的表格行"去表格归档；找"以前聊过的事"去温/冷层。

## 快照管理

在[记忆管理](beilu:mode/memory)中点击工具栏的 **snapshot** 按钮，或在记忆运维区切换到"快照"子 Tab，可管理记忆快照。

快照分为两类：

### 记忆快照

- **创建**：点击创建按钮，可附带说明文字描述本次快照的目的
- **恢复**：从快照列表中选择一条，确认（confirm）后恢复到该快照时的记忆状态
- **列表**：按时间倒序展示所有已创建的记忆快照

### Git 快照

- **创建**：点击创建按钮，输入 label 作为标签标识
- **恢复**：选择一条 Git 快照恢复；系统会在恢复前自动创建一个 pre-restore 保险快照，防止误操作导致数据丢失
- **列表**：按时间倒序展示所有已创建的 Git 快照

## 归档工具栏

在[记忆管理](beilu:mode/memory)的文件浏览器中，顶部归档工具栏提供以下批量操作：

| 操作 | 说明 |
|------|------|
| 归档临时记忆 | 将临时记忆条目从热层搬迁到温层 |
| 结束当天 | 执行当天的收尾归档流程 |
| Hot 转 Warm | 手动将选中的热层条目搬迁到温层 |
| Warm 转 Cold | 手动将选中的温层条目搬迁到冷层 |
| 归档已完成任务 | 将标记为已完成的任务记忆归档 |

这些操作是自动搬迁机制的手动补充，适用于需要立即整理记忆层级的场景。

## 检索配置

在[记忆管理](beilu:mode/memory)中点击工具栏的 **retrieval** 按钮，或在检索/诊断区切换到"检索"子 Tab，可调整 P1 检索的运行参数：

- **P1 自动触发 toggle**：开关 P1 每条消息的自动检索
- **引用聊天条数**：控制 P1 检索时参考的近期聊天轮数（分模式独立配置）
- **最大搜索轮数**：P1 多轮搜索的上限
- **超时**：搜索超时时间设置

## 格式检查

在[记忆管理](beilu:mode/memory)中点击工具栏的 **format** 按钮，或在记忆运维区切换到"格式"子 Tab，可对记忆文件进行格式合规检查。

- **扫描**：点击扫描按钮启动检查
- **统计**：显示符合 / 警告 / 错误 / 总计四项计数
- **按文件统计**：每个文件的检查结果分别列出
- **问题清单**：展示前 20 条格式问题的详细信息
- **一键升级**：对可自动修复的格式问题执行批量升级

## 对使用者的影响

- 归档和检索都是自动进行的，使用者无需手动操作
- AI "忘了"某件事，可能是该记忆已搬到冷层且 P1 本轮没判断需要去翻——直接问"还记得……吗"通常能唤起它去深翻
- 特别重要的信息建议让 AI 标记为"永远记住"，进入 forever.json 免于搬迁
- 想知道 AI 本轮用了哪些记忆，看回复下方的溯源卡

## 对开发者的说明

- 搬迁的时间阈值和容量阈值在配置中可调
- P1 检索的引用条数影响上下文占用，需要平衡召回质量与上下文空间
- 冷层存储没有容量限制，但检索性能需要关注
- 代码锚点见开发者 Wiki《03 记忆系统》
