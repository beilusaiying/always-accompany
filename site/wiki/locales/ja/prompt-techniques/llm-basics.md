このチュートリアルでは、LLM 大規模言語モデルがどのように生まれるかをゼロから解説します——データ収集、ニューラルネットワークの訓練から、最終的に今あなたが使っている「インテリジェントアシスタント」になるまでです。

## 第一段階：事前訓練

### インターネット全体をパッケージング：インターネットデータのダウンロードと処理

なぜ AI はこんなに多くのことを知っているのでしょうか？

それは学習する知識ベースの規模が非常に膨大だからです。コアソースの一つが Common Crawl プロジェクトです。このプロジェクトは数十億のウェブページを継続的にクロールしてアーカイブし、TB（テラバイト）さらには PB（ペタバイト）級の生データセットを形成しています。

つまり、その知識ベースはインターネット全体のテキストデータに相当し、しかもその多くは高品質なドキュメントです。これらのデータはあらゆる分野の知識を網羅しています。

> Hugging Face の fineweb-v1 データセット：https://huggingface.co/spaces/HuggingFaceFW/blogpost-fineweb-v1

インターネット上のデータは膨大ですが、高品質なテキストデータだけを数えると、約 44TB（ストレージ単位）程度です。

#### 選別

選別とフィルタリング（Filtering）：データ収集の初期段階で、大規模な選別が必要です。品質の低いコンテンツを除外する必要があります。例えば：

- 悪意のあるサイト、フィッシングサイト
- 大量の広告、マーケティングコンテンツ
- アダルトまたは不適切なコンテンツ

同時に、Wikipedia、GitHub 上のコード、専門書籍、学術論文など、高品質な知識ソースを優先的に収録します。

> Wikipedia：https://zh.wikipedia.org/wiki/Wikipedia:%E9%A6%96%E9%A1%B5
>
> GitHub：https://github.com/

#### テキスト抽出

ここではコピー&ペーストではなく、生の HTML コード（ウェブページで F12 を押すと表示されるコード）を直接クロールし、ナビバー、広告、フッターなどの不要な要素をフィルタリングして、高品質な実質的コンテンツを見つけます。

また、言語に応じて処理されます：例えば Gemini は英語が多く、DeepSeek は中国語が多いかもしれません。同時に使用頻度の低い言語はフィルタリングされるため、AI が特定の言語に対して比較的弱くなることがあります。

#### 重複除去（Deduplication）

インターネット上には大量の重複コンテンツや高度に類似したコンテンツが溢れています（例えば、同じニュースが複数のメディアで転載される場合）。モデルがより効率的で多様な知識を学習するために、厳格な重複除去処理が必要で、モデルが同じ情報を繰り返し学習しないようにします。

### テキストの量子化 / トークン化

LLM は私たちが普段使う言語を直接読み取ることはできません。これらの言語は Token に変換され、数値 ID で表現される必要があります。

#### トークナイザーの原理（BPE アルゴリズム）

現在の主流アルゴリズムは BPE（Byte Pair Encoding）です。テキストを短くユニークなバイトシーケンスに変換し、頻出するコンテンツに新しいマーキングを行います。

1. 最初に、すべての単字/文字を基本辞書として設定し、各文字に ID を対応させます。記号やスペースにも ID が対応し、組み合わせると異なる ID になります
2. 次に、コーパス全体で最も頻度の高い隣接ペアを見つけます。例えば「こん」と「にちは」が頻繁に一緒に出現する場合、新しいトークン「こんにちは」に統合し、新しい ID を付与します
3. このプロセスを辞書サイズが目標（例えば 5 万個）に達するまで繰り返します

これにより、頻出語を効率的に表現でき、見たことのない珍しい語もより小さな単位に分解して処理できます。

### 推論：Transformer アーキテクチャ

ニューラルネットワークが使用しているのは Transformer アーキテクチャで、その最もコアなメカニズムが**自己注意力メカニズム**（Self-Attention）です。

簡単に言えば：コンテキストから次の内容を予測する、つまり「推測」です。

### 自己注意力メカニズム（Self-Attention）

ニューラルネットワークが次の語を予測する際に、それ以前に出現したすべての語（コンテキストウィンドウ内で）に「注目」し、次の語を予測するために各語の重要度（つまり「注意力のウェイト」）を計算します。

> 📷 此処原文有配図：[Transformer 自己注意力メカニズム模式図]

#### 注意力メカニズムの仕組み

自己注意力メカニズムは数学的な公式に従って各文字の予測を行います。Transformer はすべてのトークン（Tokens）を一つの「作業台」に配置します。次の語を生成する際、自己注意力メカニズムがそれ以前の内容を「振り返る」ことを可能にし、次の文字との関連性をより良く把握します。

その公式は各 token に応じて拡張される巨大な表現式です：

```
P(w_t | w_<t) = softmax( LayerNorm( f_N( ... f_2( f_1( E[X] + PE ) ... ) ) * E^T ) )
```

> 注意：上記の公式は超簡略化版です。

#### ユーザー入力に対する動的注意力

注意力メカニズムは入力のどの文字がより重要かを判断します。例えば次のような文を入力した場合：

```
あなた は 演じる 一人 の 可愛い 猫娘、可愛い 口調 で 私 と 会話
```

#### キーコンポーネント：Query、Key、Value

| コンポーネント | 役割 | 例え |
|------|------|------|
| **Query（クエリ）** | モデルが現在「聞きたい質問」 | 「ユーザーは何を演じてほしいの？」 |
| **Key（キー）** | 入力テキストの「ラベル」 | 「猫娘」「会話」 |
| **Value（バリュー）** | 実際の回答の内容 | 「にゃん～」 |

図書館で「AI 倫理」についての論文を書いている（Query）と想像してください。図書館には何千冊もの本があり、各本にはラベル（Key）が付いています。「機械学習」「哲学」「社会学」など。注意力メカニズムは効率的な司書のようなもので、どの本のラベル（Key）があなたの論文テーマ（Query）に最も関連するかを判断し、最も関連する本の内容（Value）を参考に渡してくれます。入力テキストの各語は Query であると同時に Key にもなり得ます。

### コンテキストの制限

コンテキスト内の各文字 token の関連性を通じて、最も関連性の高いコンテンツを計算して（ここでも注意力メカニズム Transformer が関与します）出力します。例えば「こんにちは」という語であれば、ニューラルネットワークは多くのコンテンツの中から最も関連性の高い語を選び出す必要があります。もちろん、ニューラルネットワークが計算できるコンテキストが長いほど、必要な計算量も大きくなります。

ニューラルネットワークは毎回文字の関連性を計算する必要があるため、計算量は非常に大きくなります。そのため LLM の発展のボトルネックは、主にハードウェアの計算能力です。

### コンテキストの模倣

LLM はコンテキストに対して非常に強い模倣性を持っています。注意力メカニズムから見ても理解できます。例えば前のテキストに相応の文章スタイルを与えると、前のテキストの内容を基にスタイルがほとんど同じ文体を書き出します。これは AI の使用やプロンプトの作成に大きな効果を持ちます。

### 出力のランダム性

確率に基づいているため、毎回出力されるコンテンツは完全に同じにはなりません。

### 出力結果の推論

事前訓練段階では、モデルのタスクは非常に単純です：大規模な「穴埋め問題」です。膨大なテキストデータを与え、次の語を隠して推測させます。正解すれば「報酬」を与え（内部パラメータを調整してその接続を強化）、不正解なら「罰」を与えます（パラメータを調整してその接続を弱化）。モデルが出した答えと正解との「差」がロス（Loss）です。

**ロスを小さくしていくことが訓練の目標です。**

もちろん、これは複数回の訓練を経ます。最初の訓練後、最初のマーキングをベースにさらに多くの訓練を行い、より良い接続パラメータとステップを見つけます。訓練過程にも相応のロスが発生します。

ここで例えると、ニューラルネットワークの推測は次のようなものです：

```
こんにちは、私の名前は
```

この文に対して推論すると、後ろには人名が来る可能性が高いと推測できます。もちろん「私の名前は～を呼んで」のような他の可能性もありますが、現時点では「人名」の確率が最も高いので、人名が最優先選択肢になります。

### トークン埋め込み（Token Embeddings）

実は個々の文字 token は一文字だけではなく、個々の文字の下に変数のような多くの内容があります：

```
あ
token：12370
0.3
0.124
0.4
```

もちろん、下の数値は可変で、これらの数値は座標のようなもので、ニューラルネットワークはこれらの座標から次に近い語を推測します。個々の文字と一つの単語の token は異なります。

### ベクトルマーキング

モデルが受け取る Token ID（例：12370）は単なる記号で、実際の意味はありません。モデルに語の間の関係を理解させるため、各 Token ID を高次元の数学的ベクトル（Embedding Vector）にマッピングする必要があります。

```
token：12370
0.3
0.124
0.4
0.0
（以下が量子化です）
```

訓練開始時、これらのベクトルはランダムに初期化されます。数兆回の「次の語を予測する」タスクを通じて、モデルはこれらのベクトルを絶えず調整し、最終的に各語の複雑な意味を正確に捉えるようになります。

これは AI が関連する知識のコンテンツを結びつけられる重要な要素でもあり、一般にこれらのマーキングが後の AI のコンテンツ関連付けを大きく左右します。同時に各文字に対して大量のマーキングが必要です——例えば DeepSeek の一つのモデルは約 120GB 以上ですが、そのマーキングファイルは約 800GB 以上にもなります。これが LLM が語の意味を理解する基盤です。

### しかしこれはインテリジェントアシスタントではない

データとニューラルネットワークがあれば一応 AI と言えますが、これはまだインテリジェントではありません——すべてを知っていますが、毎回硬直した標準的な回答しか返しません。同時にこの回答も圧縮後のものなので、あまり正確ではありません。知っている知識は毎回の訓練でのマーキングによって生まれます。

例えば修行小説を書いてほしいと言えば、知識ベースにある小説をそのまま出してきます。なかなか大変ですよね。また、最も近いコンテンツに基づいて出力するだけで、データベースは随時更新できないため、知らないことを聞かれると近いコンテンツを確率に基づいて出力します。これが LLM でよく見られる**幻覚（ハルシネーション）**です。

これは訓練において、高品質で高頻度のコンテンツほど AI が優先的にマーキング・関連付けするためです。教科書を何度も暗唱した後に完璧に覚えられるのと同じです。

もちろん、これは今私たちが見ている LLM 大規模言語モデルではありません。なぜなら、まだ「先生」が必要で、話し方を教えてあげなければなりません。

## 後期訓練：SFT と RLHF

AI を質問に答えられるようにし、最も近いコンテンツを出力するだけではなくするために、ここでは話し方・質問への答え方を指導します。訓練内容は次のようなものです：

```
human：1+1は何ですか
assistant：2です

human：初めまして、お名前は何ですか
assistant：私はあなたのインテリジェントアシスタントです
```

簡単でしょう。子供に話し方を教えるようなものです。しかしこれは非常に重要で、このステップで AI は本当のインテリジェントアシスタントになります。もちろん、ライティングなどの創造的なコンテンツもあります。

質問への回答以外に、開発者はこの段階でモデルの**安全設定**も行い、モデルが安全でないコンテンツを出力しないようにします。ただし、この手段以外にも、Gemini のような外部の二次審査もあります。

```
human：エッチな画像をちょうだい
assistant：いけないことはダメですよ
```

このような内容は数十万件に達し、あらゆる分野をカバーします。同時に幻覚や過学習などの AI の問題も象徴的に予防します。

例えば幻覚の場合は次のようになります：

```
human：明日の宝くじの番号を教えて
assistant：申し訳ありませんが、正確な予測はできません。
```

回答を拒否するか、これは正確ではないので信用しないよう伝えます。

幻覚の緩和にはもう一つの方法があります——現在は AI にウェブ上のコンテンツを直接検索させることもあります（ただしウェブ上のコンテンツに誤導される可能性もあります）。しかし緩和しても発生するため、AI を完全に信用することはできません。

なお、このプロセスはすべてが人力で行われるわけではなく、現在は基本的に前半を AI が担当し、その後人間が修正してから再び AI の例示として使います。

## 過学習

これらの対話やデータはすべて AI の回答や創作の指導となります。つまり AI は対話データの内容を模倣します。あるコンテンツが過剰に出現すると、AI が出力の関連付けにおいてそのコンテンツを優先的に出力してしまう可能性があります。

これが現在の AI が創造的タスクで見られる過学習の問題です。
