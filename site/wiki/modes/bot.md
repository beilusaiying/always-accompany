# Bot 模式

管理 AI 角色在多个外部平台（Discord、Telegram、LINE 等）上的自动运行和消息回复。

## 进入方式

通过辅助菜单进入 Bot 管理视图。

## 界面布局

### 活动栏按钮（3 个）

| 按钮 | 名称 | 打开的面板 |
|------|------|-----------|
| list | Bot 列表 | 所有 Bot 实例的配置与管理 |
| log | 日志 | Bot 运行日志 |
| monitor | 监控 | Bot 运行状态实时监控 |

## 核心功能

### 多平台配置

Bot 列表面板顶部有 10 个平台 Tab，点击切换到对应平台的配置区：

| 平台 | 需要填写的凭据字段 |
|------|-------------------|
| Discord | Bot Token、Application ID |
| Telegram | Bot Token |
| Slack | Bot Token、App Token、Signing Secret |
| LINE | Channel Access Token、Channel Secret |
| X (Twitter) | API Key、API Secret、Access Token、Access Secret、Bearer Token |
| 飞书 | App ID、App Secret |
| 钉钉 | App Key、App Secret |
| 企微 | Corp ID、Agent ID、Secret |
| 微信 | App ID、App Secret |

每个平台填写对应凭据后即可上线运行。

**操作按钮**：
- 保存 —— 保存当前平台的凭据配置
- 启动 —— 启动 Bot 开始监听消息
- 停止 —— 停止 Bot 运行
- 查看监控 —— 跳转到 monitor 面板查看运行状态

### 关于 webhook：为什么平台回调不用登录

各平台把消息推送到 beilu 的 webhook 回调端点。这个端点**不走 beilu 的登录鉴权，是正确设计而不是漏洞**——因为发消息过来的是 Discord/微信这些平台的服务器，它们不可能登录你的 beilu 账号。安全性由各平台自己的机制保证：签名验证、token 校验、消息 AES 解密，每个平台的回调都逐条验证过才会被处理。

### C6 触发规则

配置 Bot 对谁的消息做出回复：

| 选项 | 说明 |
|------|------|
| 所有人 | 任何人发送的消息都触发回复 |
| 仅主用户 | 只响应主用户的消息 |
| 主用户 + 白名单 | 响应主用户和白名单中指定用户的消息 |

### 权限分档（L0 - L3）

权限档位决定"通过 Bot 说话的这个人，能让 AI 做多大的事"：

| 等级 | 说明 |
|------|------|
| L0 | 只读——只能对话，AI 不会为其执行任何操作 |
| L1 | 读——可触发读取类操作 |
| L2 | 读写需确认——写入类操作要经过确认 |
| L3 | 完整权限 + 白名单命令 |

主用户和其他用户可以分别设置档位。**默认两者都是 L3（不限制，保持开箱即用）**——如果 Bot 开在公开频道，建议手动把"非主用户档位"调低。

**档位的真实生效范围**：它不是一个摆设开关，而是在这些关键动作上逐一把关——

- **文件操作**：低档位用户无法让 AI 读写文件；
- **IDE 工具调用**：编程类工具操作被档位拦截；
- **委派与分身**：让 AI 派任务、开分身，需要足够档位；
- **模式切换**：低档位用户不能让 AI 切换工作模式；
- **跨窗口唤醒/传话**：档位低于 L2 时，AI 的跨窗口操作（唤醒其他对话线、定时唤醒）会被直接拦截。

档位判定以**触发这条消息的发送者本人**为准——群里张三触发的回复按张三的档位算，不会沾主用户的光。

### 聊天内命令：!chat 和 !skill

主用户可以直接在平台聊天框里打命令管理 Bot，不用回到 beilu 界面：

| 命令 | 作用 |
|------|------|
| `!chat new` | 新建一条对话线并切换过去（旧线保留，可随时切回） |
| `!chat list` | 列出本平台全部对话线，标记当前在用哪条 |
| `!chat use <序号>` | 切换到第 n 条对话线 |
| `!skill list` | 列出可用预设，标记本线当前预设 |
| `!skill use <序号或名>` | 本线切换到该预设（下条消息生效）——预设=技能集，切换即改 AI 行为 |
| `!skill clear` | 回退到全平台默认预设 |

这两组命令都是**主用户专用**（ownerOnly），其他用户打了不生效。

### 委派回程：Bot 里派出去的任务会自己回来

在 Bot 对话里让 AI 委派任务（AI 输出委派标签）时，和网页端行为不同：

- **网页端**：委派任务要等你下一次发消息触发生成时才被执行；
- **Bot 端**：你在微信/Discord 里不会一直发消息等 AI，所以委派任务会**立即在服务端后台执行**，完成后结果自动"回程"——Bot 主动在原频道发消息告诉你结果，不需要你再问一句"做完了吗"。

### 角色卡两层管理

Bot 模式对角色卡采用两层结构：

**外层 —— 窗口模式分类**：角色卡按 always-accompany 的窗口模式分组展示：
- chat —— 聊天模式的角色卡
- code —— 编程模式的角色卡
- work —— 工作模式的角色卡

**内层 —— 角色卡实例**：每个角色卡实例包含：
- 永久链路 —— Bot 与角色卡的绑定关系持久化，重启后自动恢复
- 对话列表 —— 该角色卡下的所有对话
- 任务清单 —— 该角色卡关联的任务

为不同平台绑定不同角色卡，每个角色保持独立的人格设定和对话上下文。

**隔离粒度是"角色卡级"，不是"频道级"**：一个平台 × 一个角色卡 = 一条对话线。同一平台上不同频道、不同私聊说的话，默认进的是**同一条线、同一份上下文**——这是设计而非限制（Bot 的记忆隔离与整个系统的角色卡级隔离基准对齐）。如果想把话题分开，用 `!chat new` 给它开一条新线即可。

## 后端模式值

Bot 管理视图的前端 Tab 为 `bot`，对应后端模式值 `chat`（复用聊天模式的后端逻辑）。

## 使用建议

- **单平台起步**：先配置一个平台验证效果，再扩展到多平台
- **权限控制**：生产环境中建议设置触发白名单和权限分档，避免滥用
- **角色差异化**：为不同平台/场景配置不同角色卡，让 AI 表现符合该平台的风格
