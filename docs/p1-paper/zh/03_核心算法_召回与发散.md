# 第四章 核心算法：召回与发散

> 本章导读：4.1 节展开召回侧四条路径（多路池构建、上下文锚点召回、数据层召回、IDF/IPW 加权）如何把候选词汇聚成一个池；4.2 节展开发散侧从 SWOW 联想、六轴定位、47 子轴坐标到空间投票、二次发散五路径的完整链路；4.3 节说明系统如何通过实时统计、P9 校准、热加载三层机制持续自我更新。每个子算法都配有学术依据、数学公式、核心代码、设计决策与实际效果，是理解 P1 算法内核的核心章节。

P1 管线的核心任务是将用户的一句自然语言输入，经过"收拢-定位-发散-投票-选词"的完整链路，产出**分层的方向词（direction words）集合**：核心层 4-5 个高质量方向词（对应 Cowan 4±1 工作记忆容量论证，实现取值为 v5.K top6 与金字塔 apex 层），外加擦边层至多 15 个（p1_act top15，对应"容忍低价值候选、以低门槛换取大面积语义触达"的擦边层设计原则），用于引导下游大语言模型的响应方向。方向词并非单一的学科术语——按设计对收拢二的职能定义（提取词汇性质并转换为专业术语、作品引用或片段词），方向词分为三类：**专业术语**（chat/work/ide 模式的主力输出）、**作品/桥段引用**（airp 模式的主力输出，如"给出一些小说类似的桥段"）与**片段词**。

本章按管线执行顺序，完整展开召回侧（阶段 1）与发散侧（阶段 2-7）的每一个算法子系统：给出学术依据、数学公式、核心代码、设计决策和实际效果。

## 4.1 召回算法

召回是 P1 管线的第一步。系统设计确立的职能定义是：P1 的核心职能为"召回 + 发散"两段，召回是整条管线的起点；且召回阶段执行的是低门槛、大容量的擦边式记忆触达——宁滥勿缺，为下游发散提供尽可能广的锚点覆盖，而非本体侧为注入服务的精确召回。这一 recall 导向（而非 precision 导向）的检索目标与 RAG 的精确匹配范式构成系统性对照（见第二章 2.2 节）；从融合理论看，低门槛多路召回配合下游加性融合，正是 CombSUM 类方法"证据宁多勿缺、由融合层区分质量"的经典分工（Fox & Shaw, 1994）。

召回侧的编排器 `recallV2`（Recall 编排模块）本身不含算法，仅串联五个子系统：

```
inputText → 节点1(分词) → 节点2(SWOW发散+NB质心) → 多路池(4路合并)
         → 节点0(上下文锚点) → 节点0-data(数据层召回) → 返回 recallResult
```

以下逐一展开。

### 4.1.1 多路召回池构建

#### 学术依据

多路召回池的核心思想来自信息检索领域的 **CombSUM 融合**（Fox & Shaw, 1994）：多条独立检索路径的结果通过加性累计合并，而非相乘或取交集。系统设计对此确立的融合铁律是：多路结果汇总到同一空间池内做加性累计，禁止乘性融合——加性保留每条路径的独立贡献（OR 门语义），乘性则使任一路径的零分否决整体（AND 门语义），与多源互补的设计目标相悖。

四条路径各有独立的学术出处：
- **路径 1（名称组合）**：基于角色别名展开，属于实体消解（Entity Resolution）范式。
- **路径 2（SWOW）**：Small World of Words 人脑联想网络（De Deyne et al., 2019），见 4.1.3 节详述。
- **路径 3（NB300 近邻）**：ConceptNet Numberbatch 多语言词向量（Speer et al., 2017），结合 Goldilocks 远程联想理论（Mednick, 1962; Kenett et al., 2014）。
- **路径 4（模式资源）**：ConceptNet 因果关系（Speer & Havasi, 2012）、感觉运动规范（Lynott et al., 2020）、CFN 中文语义框架（Liu & Li, 2016）。

#### 公式

**CombSUM 合并**：

$$\text{strength}(w) = \sum_{r \in \text{routes}} s_r(w)$$

其中 $s_r(w)$ 为词 $w$ 在路径 $r$ 的强度分。各路径强度定义：

- 路径 1（names）：$s_1(w) = 1.0$（命中即满权）
- 路径 2（swow）：$s_2(w) = 1.0$（divergeNode2 产出直接登记）
- 路径 3（nb300）：$s_3(w) = \cos(\mathbf{c}, \mathbf{v}_w) \cdot \text{ibFactor}(\cos)$
- 路径 4（modeRes）：$s_4(w)$ 取决于具体子通道（CN 按 REL_WEIGHTS，SM/CFN 为 1.0）

**Goldilocks ibFactor**（路径 3 的非线性分段缩放）：

$$\text{ibFactor}(\cos) = \begin{cases} \text{截断} & \cos < 0.15 \\ 0.7 & 0.15 \leq \cos < 0.25 \quad \text{(太近区)} \\ 1.0 & 0.25 \leq \cos \leq 0.70 \quad \text{(最优语义距离区间)} \\ 0.8 & 0.70 < \cos \leq 0.80 \quad \text{(太远低段)} \\ 0.5 & \cos > 0.80 \quad \text{(太远高段)} \end{cases}$$

排序键 = $\cos \times \text{ibFactor}$，取 top-K（默认 K=15）。

该分段函数遵循的设计原则是：候选词与输入质心的语义距离存在最优中间区间——距离过近的候选是泛化噪声（任何输入都会靠近质心，激活收益趋零），距离过远的候选偏离语义主题（噪声占比上升）。这一原则与远程联想理论的中等关联距离最优假说（Mednick, 1962）及语义网络创造力研究（Kenett et al., 2014）一致——上式中的"最优语义距离区间"即该文献脉络中的 Goldilocks 区间，其倒 U 型非线性关系亦有近年实证支持（Orwig, 2025）。

**MODE_ACTIVE 二值开关矩阵**（路径 4 的模式激活控制）：

模式差异化遵循的设计原则是机制级开关而非权重级微调：不同场景模式激活不同的机制组合，未被激活的机制完全沉默（零贡献），而非以低权重继续参与。该原则的工程论据是：沉默机制不向融合层引入任何噪声贡献，且二值开关矩阵可枚举、可测试、可解释，优于难以审计的连续权重微调——属本系统确立的工程原则。

`buildRecallPool`（Pool 构建模块）：

```javascript
export function buildRecallPool(ctx) {
  const routes = [routeNames(ctx), routeSwow(ctx), routeNb300(ctx), routeModeRes(ctx)];
  const poolMap = new Map();
  for (const r of routes) {
    for (const c of r.words) {
      const e = poolMap.get(c.word);
      if (e) { e.sources.push(c.source); e.strength += c.strength; } // CombSUM加性累计
      else poolMap.set(c.word, { word: c.word, sources: [c.source], strength: c.strength });
    }
  }
  // 跨路径共振计票: V1"一个词被多少条独立路径召回"
  const RES_W = +(process.env.P1_POOL_RESONANCE_W || 0);
  if (RES_W > 0) {
    for (const e of poolMap.values()) {
      const srcKinds = new Set(e.sources).size;
      if (srcKinds > 1) { e.strength += RES_W * (srcKinds - 1); }
    }
  }
  // 非swow新词 merge 进 swowPool
  if (ctx.swowPool && typeof ctx.swowPool.add === "function") {
    for (const e of poolMap.values()) {
      if (!e.sources.includes("swow") && !ctx.swowPool.has(e.word)) {
        ctx.swowPool.add(e.word);
      }
    }
  }
  return { swowPool: ctx.swowPool, poolMap, trace: { ... } };
}
```

Goldilocks ibFactor 核心（`routeNb300`，Pool 构建模块）：

```javascript
function routeNb300(ctx) {
  const centroid = ctx.inputCentroid;
  const pool = ctx.nbPool;
  // ...
  for (const [w, vec] of pool) {
    if (own.has(w) || (swow && swow.has(w))) continue;
    let dot = 0, norm2 = 0;
    for (let i = 0; i < vec.length; i++) { dot += centroid[i] * vec[i]; norm2 += vec[i] * vec[i]; }
    const cos = dot / Math.sqrt(norm2);
    if (cos < _NB_FLOOR) continue;           // 极低区截断
    let ib = 1.0;
    if (cos < _NB_NEAR) ib = _NB_IB_NEAR;           // 太近 → 0.7
    else if (cos > _NB_FAR_HI) ib = _NB_IB_FARHI;   // 太远高段 → 0.5
    else if (cos > _NB_FAR_LO) ib = _NB_IB_FARLO;   // 太远低段 → 0.8
    cands.push({ word: w, cos, ib });
  }
  cands.sort((a, b) => (b.cos * b.ib) - (a.cos * a.ib));
  return { words: cands.slice(0, K).map(c => ({ word: c.word, source: "nb300",
           strength: +(c.cos * c.ib).toFixed(4) })), ... };
}
```

#### 设计决策

1. **为什么是四路而非单路？** 002 号审查打回了最初仅 SWOW 单路的设计（候选池覆盖不足）。原始设计即为多路发散合并到一个池统一打分，SWOW 单路严重不足（chat 以外模式联想覆盖率低）。
2. **为什么 CombSUM 而非乘法？** 系统加性融合铁律（见上）——乘法链中任一因子为零则整条坍缩（过早误诊 / 万金油），加性保留各路独立贡献。
3. **为什么 Goldilocks 用软降权而非硬截断？** 铁律 #48："软降权不是硬过滤"——cos 极低词仍可进池但贡献小（ibFactor=0.7），不会因为一个固定阈值丢掉边缘有价值的词。
4. **Sensorimotor 和 CFN 并行而非互斥**：按机制组合差异化原则（激活的是机制组合而非单一机制），SM 与 CFN 可并行激活。SM 覆盖率仅 10%（664 词集以具身名词为主），CFN 覆盖 62280 词 757 框架，两者互补。

### 4.1.2 Node-0 上下文锚点召回

#### 学术依据

Node-0 的上下文召回采用 **双信号融合**——词汇交集（集合交叉，Set Intersection）与语义向量相似度（Cosine Similarity in NB300 space）的线性组合。

这一设计兼顾了词汇层面的精确匹配和语义层面的柔性匹配，对应信息检索中 BM25 + 向量检索并用的混合检索范式：精确信号与语义信号线性融合。

逆倾向加权（Inverse Propensity Weighting, IPW）用于词级排序，出处为推荐系统中的倾向分修正文献（Schnabel et al., 2016），P1 将其适配为：高频词（BCC 频率高 = 在语料中"倾向"高）降权，低频词（特异性高）升权。

#### 公式

**句级打分**：

$$\text{combined}_s = \text{swowScore}_s + \begin{cases} \text{nbScore}_s \times 10 & \text{if } \text{nbScore}_s > 0.15 \\ 0 & \text{otherwise} \end{cases}$$

其中：
- $\text{swowScore}_s = \sum_{w \in \text{inputSwow} \cap \text{ctxSwow}_s} \text{poolMap.strength}(w)$，即输入散词池与上下文句散词池的加权交集。
- $\text{nbScore}_s = \cos(\mathbf{c}_{\text{input}}, \mathbf{c}_{\text{ctx},s})$，即输入质心与上下文句质心的 300 维余弦相似度。
- 放大门 0.15 + 放大系数 10：当语义相似度超过阈值时，将其贡献放大 10 倍计入 combined，使语义信号在词汇交集信号之上产生显著区分度。

筛选：$\text{combined}_s \geq 3$ 才入选 scoredCtx。

**词级排序**（加性公式）：

$$\text{rank}(w) = \text{combined}_{s(w)} + \text{infoW}(w) + \text{concBonus}(w)$$

其中：
- $\text{infoW}(w) = \frac{1}{\sqrt{\text{bccFreq}(w) + 1}}$（IPW 逆倾向加权）
  - 高频词 549541 → 0.001，中频词 1604 → 0.025，低频词 10 → 0.30，零频 → 0
- $\text{concBonus}(w)$（具体度加分，默认 off）= $\frac{5 - \text{concreteness}(w)}{4} \times \text{weight}$

**锚点强度**：

$$\text{strength}(w) = \left(0.3 + 0.05 \times \min(\text{combined}_{s(w)}, 8)\right) \times \text{bccPenalty}(w)$$

$$\text{bccPenalty}(w) = \begin{cases} 0.05 & \text{bccFreq}(w) > 300000 \\ 1.0 & \text{otherwise} \end{cases}$$

#### 核心代码

`recallNode0`（Node-0 上下文召回模块），关键段落：

#### 设计决策

1. **为什么召回"不主导"？** 设计设定的硬边界是：召回结果仅作发散锚点、不主导方向——锚点 strength 上限约 0.7，作为下游发散的约束辅助而非主力方向。
2. **为什么只看 6 句？** 设计边界规定发散仅消费最近 6 句上下文、不读数据层——短窗口避免远期对话噪声稀释当前语义。
3. **IPW 替代自编公式**：最初版本使用 $1/(1 + \log_{10}(1 + f/1000))$ 的自编公式，后被资源库中的 IPW $1/\sqrt{f+1}$ 替代——IPW 对高频词的惩罚更陡（549541 → 0.001 vs 旧版 0.27），作为加性项时影响更精准。
4. **乘法 → 加性**：最初版本 rank = combined * infoW（乘法），按加性融合铁律改为加性 rank = combined + infoW，使各维度独立贡献、combined 主导、infoW 做边界微调。

### 4.1.3 Node-0-data 数据层召回

#### 学术依据

Node-0-data 是 P1 记忆层召回的落地实现，采用 **Generative Agents 范式**（Park et al., 2023）的多维打分框架——将语义（dSem）、词汇信息量（dLex）、重要性（dImp）三个独立维度归一化后等权相加。

IDF 计算采用 **sklearn 口径**：$\text{idf}(w) = \log\frac{N+1}{\text{freq}(w)+1}$，其中 N = 3.79 亿（BCC 总词频公开统计量）。

#### 公式

**三维打分**：

$$\text{score}(e) = \hat{d}_{\text{Lex}}(e) + \hat{d}_{\text{Sem}}(e) + \hat{d}_{\text{Imp}}(e)$$

各维度原始值：
- $d_{\text{Lex}}(e) = \sum_{w \in \text{hits}(e)} \text{idf}(w) = \sum_{w \in \text{hits}(e)} \log\frac{3.79 \times 10^8 + 1}{\text{bccFreq}(w) + 1}$
- $d_{\text{Sem}}(e) = \cos(\mathbf{c}_{\text{input}}, \mathbf{c}_{\text{entry}})$（entry 级 NB300 质心余弦）
- $d_{\text{Imp}}(e) = \text{LAYER\_W}[\text{layer}(e)]$，其中 hot=1.0, warm=0.85, cold=0.7

归一化：各维度 min-max 归一化后等权 CombSUM。

**锚点强度**（有上限约束）：

### 4.1.4 IDF / IPW 加权排序

P1 召回侧在两个独立节点中使用了两种信息量加权机制：

**1. IPW（逆倾向加权）** —— Node-0 词级排序

$$\text{infoW}(w) = \frac{1}{\sqrt{\text{bccFreq}(w) + 1}}$$

这是推荐系统中 Inverse Propensity Weighting 的适配形式。在 P1 的加性排序公式 rank = combined + infoW 中，IPW 作为加法项对高频无信息词（如"明白""接下来""觉得"）施加连续衰减，而非二元黑名单。

设计遵循铁律 #48"连续量非断崖"——不用黑名单硬删，而是让每个词按其 BCC 频率获得连续的信息量分数。其设计语义是定位而非惩罚：加权的目标不是压制高频词，而是为每个词补充一个"信息量定位"维度，使区分度作为独立信号参与加性排序。这与词项特异性的信息论解释一脉相承——区分度本身是词的一项可度量属性，而非对词的处罚（Sparck Jones, 1972）。

**2. IDF（逆文档频率）** —— Node-0-data 条目级排序

$$\text{idf}(w) = \log\frac{N + 1}{\text{bccFreq}(w) + 1}, \quad N = 3.79 \times 10^8$$

采用 sklearn 标准口径。"沙盘"BCC 频率低 → idf 约 12（强信号）；"明白"BCC 频率 3.6 亿 → idf 约 0.05（几乎不贡献）。信息量决定排名，而非频率决定排名。

**两者的区别**：IPW 在加性公式中做边界微调（combined 仍主导），IDF 在三维 CombSUM 中做 dLex 维的绝对贡献。

## 4.2 发散算法

发散是 P1 管线从阶段 2 到阶段 7 的核心过程，将召回阶段产出的 30-40 个散词池词汇，经过六轴定位、47 子轴坐标命中、空间投票、二次发散等多层处理，最终产出核心层 4-5 个、连同擦边层至多 15 个的分层方向词集合。

**规划中的前置定位层**：在发散之前，系统规划由小型语言模型（Qwen3.5:2B）先做语义定位——理清方向、标注落点，不做任何创造性内容（与 LLM 在 P1 中"标方向、标 QKV、拆分对话"的一贯职责边界一致）。当前纯词典/向量定位链路是无 LLM 线路（线路 1）的形态；LLM 置于 SWOW 前/后/双位置的线路 2/3/C 已在 lab 实装、未合主线（三线路架构详见第三章 3.1.1 节）。本节以下描述的均为现行词库路径。

### 4.2.1 SWOW QKV 池交汇（Node-2）

#### 学术依据

SWOW（Small World of Words）是比利时 KU Leuven 的 De Deyne 等人（2019）构建的大规模人脑自由联想网络。中文版本 SWOW-ZH24 包含 10,024 个 cue 词，每个 cue 词对应多个联想响应词及其强度。

Node-2 的 QKV 池交汇发散借鉴了 **注意力机制**（Vaswani et al., 2017）的 Query-Key-Value 结构：
- Q = 输入词 NB300 质心（查询向量）
- K = SWOW 全部 10,024 cue 的 NB300 向量（键空间）
- V = 交汇 cue 的联想响应词（值空间）

需要说明的是，这一 QKV 结构是**系统层的代理实现**：设计上，"QKV 理解"被判定为需要 LLM 才能胜任的难点，属于规划中 LLM 标注层（H5 LoRA）的核心职责——设计者确立的职责边界是：LLM 在 P1 中仅负责 QKV 理解、方向纠正与方向标注，不承担任何创造性内容生成；将其判定为难点的依据是人类语言逻辑的复杂性，使纯词表/向量方法难以完成深层语义解析。Node-2 的 NB 质心点积仅在无 LLM 线路（线路 1）下承担 QKV 交汇的近似，不代表 QKV 理解问题已被 300 维向量点积解决。

#### 公式

**质心计算**：

$$\mathbf{c}_{\text{input}} = \frac{1}{\|\bar{\mathbf{v}}\|_2} \cdot \bar{\mathbf{v}}, \quad \bar{\mathbf{v}} = \frac{1}{|\mathcal{V}|} \sum_{w \in \text{inputWords}} \mathbf{v}_w$$

其中 $\mathbf{v}_w$ 为词 $w$ 的 NB300 向量，$\mathcal{V}$ 为有向量的输入词集合，最终 L2 归一化。

**QKV 交汇**（需 $\geq 2$ 个输入词才启动，防止单词输入退化为逐词发散）：

$$\text{top cues} = \mathop{\text{topK}}\limits_{k=3} \left\{ \text{cue} \in \text{SWOW-ZH24} \mid \mathbf{c}_{\text{input}} \cdot \mathbf{v}_{\text{cue}} \right\}$$

每个交汇 cue 再调 swowDiverge 取 3 个联想词，经 `_isNonInfoN2` 六级过滤后进池。

**distance 门控**（SWOW 近义过滤，已转正默认 on）：

$$\cos(\mathbf{v}_{\text{anchor}}, \mathbf{v}_{\text{assoc}}) \geq 0.85 \Rightarrow \text{丢弃}$$

这是基于实测铁证的红线：distance=1 同义扩散导致 beilu recall 0.684 → 0.162（-76%），MRR -55%。根因：同义噪声记录排到真实对话结果之上。

#### 核心代码

`divergeNode2`（Node-2 SWOW 发散模块）：

1. **逐词发散已删**：系统红线（2026-06-03 确立）禁止逐词发散——即每个种子词独立发散后对结果简单求和，该操作会产生叠加噪声：高连接度联想节点被多个种子重复激活而系统性胜出，机理与扇出效应（Fan Effect, Anderson, 1974）同源。QKV 池交汇是整体性的：从输入词的语义质心出发找交汇 cue，而非每个词独立发散。
2. **QKV_MIN_INPUTS = 2**：单词输入时 QKV 退化为逐词发散（质心 = 该词自身向量），违反禁令，故要求至少 2 个输入词。

### 4.2.2 NB300 质心发散

### 4.2.3 六轴面真发散（Node-3 axisDiverge）

#### 设计意图与实现偏差

在展开算法之前必须先厘清六轴定位的设计语义：**一条轴对一个词的定位产出是多个信息点（该词在此轴上关联的概念集 + 信息范围），而非单一标量分数**。定位结果转移至词库后，一个词携带的是"信息 + 信息范围"的结构化数据，供后续细化与发散消费。六轴的职能是**定位 + 细化 + 发散信息点**。这一"轴上定位产出为信息点集合而非标量"的设计与概念空间理论一致：概念在语义空间中占据的是区域而非点（Gardenfors, 2000），单一标量投影必然丢失区域结构。

当前实现将每词每轴压缩为单一标量（`allAxes[axis] = v`）再按标量排序取面词，属于对设计的降维执行（信息流失），是已识别的待重构项。本节以下描述的是当前代码行为。

#### 学术依据

Node-3 将输入定位到六大心理-信息学轴（psychology, informatics, sociology, logic, linguistics, cognitive），并在每个轴上独立进行"真发散"——从该轴的高权面词（face words）出发，在 NB300 空间中搜索靶空间内的语义近邻，吐出新的候选词。

靶空间由两部分构成：
- **AT 术语**：activation_terms 词库中带 axes_47 坐标的术语
- **桥接库词**：p1_coord_bridge.json 预计算的物理库词（来源 DLUT 情感词汇、narrative 叙事词、cn_daily 日常词、Domain 各域词）

轴衰减公式来自 **Rank-based 衰减**（Cormack et al., 2009, SIGIR; RRF）：

$$\text{axisDecay}(\text{axis}) = e^{-\text{rank} \times \beta}$$

其中 rank 为各轴按面词 $\sum v$ 降序排列的名次（0 = 主方向轴），$\beta = 0.5$（env P1_AXIS_DECAY_BETA）。

#### 公式

**轴关联度与衰减**：

$$\text{axisRelevance}(\text{axis}) = \sum_{w \in \text{face}(\text{axis})} v(w)$$

$$\text{axisRank}(\text{axis}) = \text{降序名次}(0 = \text{主方向轴})$$

$$\text{axisDecay}(\text{axis}) = e^{-\text{axisRank} \times 0.5}$$

**发散截止条件**：

$$\frac{\text{axisRelevance}(\text{axis})}{\text{topRelevance}} < 0.40 \Rightarrow \text{该轴不发散}$$

关联度低于 40%（P1_AXIS_CUTOFF）的轴停止发散，但原有面词保留（软停非硬删）。

**轴感知门控**（P1_AXIS_AWARE_DIVERGE，默认 on）：

候选词只取 axes_47 主组（argmax 组）== 本轴组的靶词。例如 psychology 轴只取 psy_* 组主导的术语，清除跨轴污染。

### 4.2.4 47 子轴坐标命中（Node-4）

**设计定位**：6 主轴给出词的粗定位（落在哪个学科方向），47 子轴刻画该粗定位内部沿各细分方向的语义变化率，承担方向细化定位，驱动定向发散与扩充产出。两级轴系统再连接外部资源层（SWOW / ConceptNet / Numberbatch / 词林 / CFN 等），构成"6 轴 → 47 子轴 → 资源"的多层互联结构：词的激活按层级传导、加性汇聚，逐级被定位、细化、发散。

### 4.2.5 IDW 空间投票（Node-6）

#### 学术依据

Node-6 是 P1 管线的**主排名层**——所有信息池词汇在此汇入一个多维空间，通过 IDW（Inverse Distance Weighting，Shepard 1968）加权的多对一累加投票，确定方向词候选的排名。

IDW 是地理统计学中的经典空间插值方法，Shepard（1968）提出的原始公式为 $w_i = 1/d_i^p$。P1 采用其变体 $\text{idw} = 1/(1 + d^2 \cdot \text{steep})$，用 steep 参数控制衰减陡度。

温度画圆遵循的设计原则是：温度参数在向量空间中定义了以输入质心为圆心的几何搜索圆，候选按其与圆心的距离筛选——距离过近与过远的候选均被抑制，仅中间区间的候选有效参与投票。这与 Mednick（1962）远程联想理论的核心思想一致——创造性联想存在于"不太近、不太远"的最优语义距离区间（即 4.1.1 节的 Goldilocks 区间）；温度对搜索范围的调节则参照玻尔兹曼分布的温度语义（见第二章 2.14 节）。

#### 公式

**IDW 加权投票**：

$$\text{idw}(d) = \frac{1}{1 + d^2 \cdot S}$$

其中 $d = 1 - \cos(\mathbf{a}, \mathbf{b})$（空间距离），$S$ = IDW 陡度参数（默认 10，env P1_NODE6_IDW_STEEPNESS）。

**投票累加**（全程纯加性，无除 N，无乘法链）：

$$\text{totalVote}(t) = \sum_{i \in \text{candidates}} w_i \cdot \text{idw}(d_{i \to t})$$

其中 $w_i$ = 候选词 $i$ 的 score（来自 Node-3 面权重）。

该投票机制遵循三条铁律级设计原则：(1) **空间化汇聚**——全部候选汇入同一向量空间，以内容在空间中的分布形态完成投票，而非路径间的两两硬匹配；(2) **加性融合**——票值累加而非相乘，避免乘法链的 AND 门坍缩（对应 CombSUM 的 OR 门语义，Fox & Shaw, 1994）；(3) **圆内匹配、圆外衰减、不取均值**——匹配以距离带界定（实现上为 IDW 连续衰减而非硬排除），且累加值不除以票数，保证多证据源的贡献单调累积（对应 Hough 变换的多对一累加投票范式，Hough, 1962）。

**温度分档**：

$$T = \begin{cases} 1.5 & |\text{inputWords}| < 5 \quad \text{(短句高温大圆)} \\ 0.7 & |\text{inputWords}| > 10 \quad \text{(长句低温小圆)} \\ 1.0 & \text{otherwise} \end{cases}$$

**几何圆半径**（随温度缩放）：

$$r = r_{\text{base}} \times T, \quad r_{\text{base}} = 0.12$$

圆内（$d \leq r$）：匹配保留；圆外（$d > r$）：不硬删，IDW 自然衰减使远距离贡献趋近于零。

**锚点提取（多密度峰 + NoveltyBonus）**：

$$\text{effDensity}(v) = \text{totalVote}(v) \times \frac{1}{\sqrt{\text{sameAxisCount} + 1}}$$

NoveltyBonus 公式出自 82 号设计 MD:L61：同一轴内已选锚点越多，后续同轴候选的新颖性奖励越低 → 自然降权，平票被拉开，无需硬阈值。

按轴分组各取密度峰，落实框架的多锚点要求——避免全部锚点集中于单一语义方向（万金油根因）。

```javascript
    if (dim === 0) continue;
    const d = 1 - cos;
    if (cos < o.circle.voteCosFloor) continue;  // 太远不投
    const inCircle = d <= radius;
    const idw = 1 / (1 + d * d * _P1_NODE6_IDW_STEEPNESS);
    let vote = w * idw;                          // 加性票
    // 域信号加分（加法项，非乘法）
    if (domainSignals) { vote += domainBonus; }
    rec.totalVote += vote;                       // 累加，无 /N
    if (inCircle) rec.voterCount++;
  }
}
```

#### 设计决策

1. **baseRadius 不控制票值分布**：200case A/B 实验证实 radius 不改票值，inCircle 只影响排序/锚点筛选——0.09 约等于 0.12，0.18 导致恒出恶化。真正控制票值分布的是 IDW_STEEPNESS。
2. **CN 关系边投票作为并行通道**：与 47D 空间投票共用同一累加器，CN 票也是 $w \times \text{cnVoteWeight}$（权重 0.5），双通道并行不替换。
3. **拒绝乘法链补丁**：代码注释明确标注"见结果不对千万别加 score*=X / vote*= 质量系数当补丁"——连乘 = 硬匹配 = 对加性融合铁律的直接违反。

### 4.2.6 二次发散五路径（Node-7）

Node-7 位于 Node-6 空间投票（主排名）之后、Node-9（选方向词）之前，是 P1 的**第一增量发散层**。五条路径从不同角度扩展候选词池，加性并入 Node-9 投票，不替换 Node-9 自身的 Hough 投票。

所有五路径共享：
- `_n7TermMap`：去重图（含 face/Node-6 已有词）
- `_faceMed`：face 中位数尺度（统一归一基准）
- `_n7Push`：统一 push 助手，将 raw 分归一到 face 中位尺度

#### 路径 1：PPR（Personalized PageRank 多跳发散）

**学术依据**：Topic-Sensitive PageRank（Haveliwala, 2002, WWW）+ HippoRAG（Gutierrez et al., 2024, arXiv:2405.14831）。

**公式**：

$$\mathbf{r}^{(t+1)} = (1 - \alpha) \cdot A \cdot \mathbf{r}^{(t)} + \alpha \cdot \mathbf{s}$$

收敛解：$\mathbf{r}^* = \alpha (I - (1 - \alpha) A)^{-1} \mathbf{s}$

其中 $A$ 为列归一化邻接矩阵，$\mathbf{s}$ 为个性化向量（seed 词的 one-hot），$\alpha = 0.15$，迭代 15 轮收敛。

**KG 构建**（`_buildKG`）：
- 节点：T:（AT 术语）/ C:（concepts）/ W:（trigger 词）
- 边：T ↔ C（术语的 concepts 前 8 个）；W ↔ T（TI 中 trigger→术语）；C ↔ C（CN 概念间关系）

**seed 选择**：200case A/B 实验判定 anchors 版判负（锚点集稳定导致同一批词反复恒出，airp 恒出率 86%），words 版保留默认——seed = 输入词 = per-case 变化源，天然多样。

**量纲对齐**：原始 PPR 分（~0.003-0.067）比 face 词（中位 0.26-0.73）小 10-100 倍，必须按相对排名线性归一到 face 中位尺度。

**核心代码**（`_runPPR`，Transfer 模块）：

```javascript
function _runPPR(graph, seedNodes, alpha, maxIter) {
  let scores = new Map();
  for (const s of seedArr) if (graph.has(s)) scores.set(s, teleport(s));
  for (let iter = 0; iter < maxIter; iter++) {
    const next = new Map();
    for (const s of seedArr) if (graph.has(s)) next.set(s, (next.get(s) || 0) + alpha * teleport(s));
    for (const [node, score] of scores) {
      const neighbors = graph.get(node);
      if (!neighbors || neighbors.size === 0) continue;
      const share = (1 - alpha) * score / neighbors.size;
      for (const nb of neighbors) next.set(nb, (next.get(nb) || 0) + share);
    }
    scores = next;
  }
  return scores;
}
```

#### 路径 2：hop2（二跳发散）

**学术依据**：扩散激活理论（Collins & Loftus, 1975, Psychological Review, 82:407-428）。

**算法**：Node-6 锚点 → concepts → CN 关系词/概念 → 再查 TI → AT 术语。PPR 只走 KG 内路径，hop2 补 KG 外路径。

$$\text{score}(w) = \sum_{\text{seed} \to c \to w} e(\text{seed}, c) \cdot \gamma \cdot I_{\text{disc}} \cdot \cos_w$$

其中 $\gamma = 0.75$（每跳衰减），$I_{\text{disc}}$ = 异轴 1.0 / 同轴 0.5（学科切换奖励），$\cos_w$ = NB cosine 防噪声扩散（<0.05 → *0.1，<0.1 → *0.3）。单 bridge 词 cap=2 命中（限制单一 bridge 词的重复计票，抑制同义路径的票数累积），万金油排除（SWOW 入度 >150）。

#### 路径 3：causal 归因发散

**学术依据**：ConceptNet（Speer & Havasi, 2012, AAAI）+ ATOMIC（Hwang et al., 2021, AAAI, arXiv:2010.05953）。

**算法**：Node-6 锚点 → concepts → CN 因果关系链（Causes / HasProperty / CapableOf / MotivatedByGoal）→ TI → AT 术语。路径接力降权：已覆盖 dim *0.5，同轴 >3 个术语时 *0.7。

$$\text{raw}(w) = \text{seedW} \times \gamma_C \times I_{\text{disc}} \times \text{relayWeight}$$

$\gamma_C = 0.75$，causalCap = 20。

#### 路径 4：analogy 类比发散

**学术依据**：结构映射理论（Gentner, 1983, Cognitive Science, 7:155-170）+ Information Bottleneck（Tishby et al., 1999, physics/0004057）。类比发散的设计定义是跨域结构同构：同一抽象关系骨架在不同学科域中的不同表现即互为类比。这与结构映射理论的核心主张——类比是关系结构的映射而非表层属性的相似（Gentner, 1983）——一致。

**算法**：主轴锚点 NB 向量 → 其他轴 AT 术语 NB cosine 最优区间 [0.2, 0.7]；正反双向（主轴 → 次轴 + 次轴 → 主轴）。（注：此类比路径最优区间 [0.2, 0.7] 与召回侧 Goldilocks 最优语义距离区间 [0.25, 0.70]（见 4.1.1 节）是两个独立参数，均为 cosine 相似度口径，勿与"语义距离"d = 1 − cos 口径混用。）

**倒 U 最优区间门控**：

$$\text{cosWeight}(\cos) = \begin{cases} 0.1 & \cos < 0.1 \quad \text{(太远不收)} \\ 0.3 & 0.1 \leq \cos < 0.2 \\ 1.0 & 0.2 \leq \cos \leq 0.7 \quad \text{(最优区间)} \\ 0.3 & \cos > 0.7 \quad \text{(太近冗余)} \end{cases}$$

**ranked 模式**（2026-07-03 200case A/B 判正转正）：全收集 → rawW 降序 → per-anchor cap（3）→ 截 ANCAP（15）。解决旧版单一锚点占满全局配额的问题（第一个有 NB 向量的锚扫描整个列表即占满全局 cap = 逐词发散变体）。

#### 路径 5：六度路径（BFS 跨域发散）

**学术依据**：小世界现象（Milgram, 1967）——社交网络中任意两人平均六步可达。设计上将跨框架类比与六度路径统一：跨域的结构关联被建模为概念网络上的多跳可达性问题——语义上相距遥远的两个学科概念，可经由少数几跳的中介概念桥接。这一设计同时呼应弱连接理论（Granovetter, 1973）：跨域桥接边（弱连接）比域内强连接更可能引入新信息。

**算法**：Node-6 锚点 → concepts → CN 全关系（非仅因果）1-2 跳 → AT 术语。

$$\text{pathDecay} = \gamma \times I_{\text{disc}} \times \text{HOP\_DECAY}[\text{hop}]$$

其中 $\gamma = 0.75$，HOP_DECAY = [1.0, 0.4, 0.1]，pathDecay < 0.15 自停。

**跨域加成**（SixDegreeBonus）：

$$\text{SixBonus} = \min(1.6,\ 1.0 + 0.2 \times (\text{domainCount} - 1))$$

关键实现细节：使用**独立 _sdSeen** walk 去重——若共用 _n7TermMap，98.9% AT 词已被其他路径占 → 产出恒 0。walk 用 _sdSeen（可穿过已见词找跨域新词），push 仍 dedup _n7TermMap（避免池内重复投票）。

sdCap = 30。

## 4.3 自更新机制

P1 的自更新/自学习是一个**三层架构**：实时层（每轮对话后异步写盘）、整理层（P9 元 AI 批处理校准）、热插拔层（30 秒 mtime polling 检测词库变化自动重载）。

---

### 4.3.1 轴统计累积 accumulateAxisStats

#### 触发时机

Pipeline 模块的 `runPipeline()` 完成后，异步 fire-and-forget 调用。

#### 算法

自学习模块（轴统计累积）：

```javascript
// 每轮对话 P1 召回后调用
// 读/改/写 vocab/user/axis_stats.json
// schema: {axis: {sum, count, avg}}
// 主AI引用的记忆权重x2 ("主AI实际选了的更说明该轴有用")
// withFileLock 串行化（消除并发 lost-update）
```

累积每个轴的使用统计——被引用次数、加权总分、滑动平均。供 P9 校准层读取，判断哪些轴在该用户的实际对话中被频繁激活。

### 4.3.2 词频学习 accumulateWordFreq

#### 算法

自学习模块（词频学习部分）同时累积三份文件：

1. **word_freq.json**：`{词: {c: 次数, t: 天序号}}`
   - 记录用户输入词的出现频率
   - 消费端：P1 发散时常用词升权（用户高频输入词在排序中前移）

2. **user_cooccur.json**：`{"w1|w2": count}`
   - 相邻词共现对统计
   - 用于 per-user 共现补充

3. **new_words.json**：`{word: {count, first}}`
   - P1 词库缺失的词检测（maxNewWords=500）
   - 供 P9 联网补充新词入库

**词频升权公式**（`userFreqBoost`，自学习模块）：

$$\text{boost}(w) = \min(0.3,\ \log(1 + \text{count}) \times 0.1)$$

次线性 TF 阻尼，上界 0.3，保证用户词频只作次要加成、不主导排名。在 dLex 维消费时作为 $(1 + \text{boost})$ 乘数，最大提升 30%。

该机制的设计参照是输入法的用户词频记忆：用户高频输入的词被持续记录，并在后续排序中获得升权。其认知科学对应物是 ACT-R 的基础水平激活（base-level activation）——记忆单元的激活值随使用频率与近因累积（Anderson et al., 2004），本机制以次线性 TF 阻尼实现了同一思想的工程化。

---

### 4.3.3 P9 校准层 calibrateAxisWeights

#### 算法

自学习模块（P9 校准部分）：

$$w_{\text{new}}(\text{axis}) = w_{\text{old}}(\text{axis}) \times (1 - \eta) + w_{\text{target}}(\text{axis}) \times \eta$$

其中：
- $\eta = 0.3$（学习率：新统计数据的权重）
- $w_{\text{target}} = \max\left(0.5,\ \min\left(2.0,\ \frac{\text{stat.avg}}{\text{globalMean}}\right)\right)$（目标权重：该轴统计均值 / 全局均值，限制在 [0.5, 2.0] 防极端）
- $\text{minSamples} = 20$（数据不足时保留旧值）

产出 `vocab/user/axis_weights.json`，被 P1 各轴权重消费。

这是一个**指数移动平均**（EMA）更新机制，使轴权重平滑地向用户实际使用模式靠拢，同时通过上下界约束防止过拟合。

### 4.3.4 热加载 mtime polling

#### 机制

Pipeline 模块中检测词库文件 mtime 变化、触发级联清缓存的核心逻辑：

```javascript
const _HOT_RELOAD_INTERVAL = Number(process.env.P1_HOT_RELOAD_INTERVAL) || 30000;

function _checkHotReload(mode) {
  if (now - _lastHotReloadCheck < _HOT_RELOAD_INTERVAL) return; // 30s 节流
  const files = [`activation_terms_${m}.json`, `transfer_index_${m}.json`];
  for (const name of files) {
    const mt = fs.statSync(fp).mtimeMs;
    if (prev !== undefined && prev !== mt) dirty = true;
  }
  if (dirty) {
    clearTransferCaches(); // 级联清全部生产缓存
  }
}
```

每 30 秒检查一次 AT/TI 词库文件的 mtime。变化 → 级联清缓存 → 下次 getter 自动重载新词库。不重启即生效。

**级联清缓存链路**：`clearTransferCaches()` → 清 transfer 内 AT/TI 缓存 + 清 axis 缓存 + 清 recall 缓存 + 清桥接缓存 + 清极性缓存。

该机制落实的是设计规划中的离线-在线分工：P9 以离线批处理产出新词库，P1 运行侧以 mtime 轮询感知变更并级联清缓存重载，实现不停机的词库更新。

**自更新体系总览**。下表汇总实时层、整理层、热插拔层、离线层、反馈层五类机制各自的触发时机与读写关系：

|---|------|------|------|---------|
| 实时层 | accumulateAxisStats | 每轮 runPipeline 后异步 | axis_stats.json | P9 校准 |
| 实时层 | accumulateWordFreq | 每轮 runPipeline 后异步 | word_freq.json 等 | userFreqBoost 升权 |
| 整理层 | calibrateAxisWeights | P9 元 AI 调用 | axis_weights.json | P1 各轴权重 |

### 4.3.5 频率反馈回路（ACT-R 频率衰减）

Transfer 模块维护一个跨 session 累积的 `freq_stats.json`，记录每个术语被选为方向词的次数。高频术语自动降权，防止同一用户反复输入相近话题时总出同样的词。

$$\text{freqDecay}(w) = \max\left(0.15,\ \frac{1}{1 + 0.15 \times (\text{count}(w) - 1)}\right)$$

设计者指定采用 ACT-R 频率衰减作为理论方向（Anderson, 1993），具体公式与系数为实现层拟合的起始值。

评测/连跑时可通过 `P1_DISABLE_FREQ=1` 关闭频率反馈回路，使同输入连跑产出完全一致（800case 逐 case 对比的前置条件）。

**原子写保护**（`_saveFreqStats`）：唯一 tmp 名（pid+时间+随机）→ rename 原子替换。进程内写串行（`_freqWriteInFlight`标记），防多次 writeFile 高频重叠交错。

这是从实际翻车中修复的（T33 复发根因：旧版固定 ".tmp" 被多进程共用 → 交错污染 → rename 装入损坏文件）。

## 本章小结

P1 管线的召回与发散算法体系展现了几个贯穿始终的设计原则：

1. **加性不相乘**：从 CombSUM 池合并到 IDW 空间投票到二次发散并入，全链路纯加性累加，无乘法链——任一维度为零不会导致全局坍缩。

2. **软降权不硬删**：从 Goldilocks ibFactor 到 BCC 软降权到轴衰减，所有信号通过连续函数降权而非二元阈值硬删——保留边缘有价值的弱信号通道。

3. **多路独立后合并**：四路召回池、六轴独立发散、五路二次发散——各路径独立产出后统一进入空间投票，避免单一路径主导。

4. **空间多锚点不坍缩**：IDW 投票的多密度峰 + NoveltyBonus 确保锚点分布在多个语义方向，防止全部锚点集中于单一语义方向（万金油根因）。

5. **全参数 env 化**：所有魔法数字均可通过环境变量 A/B 测试而无需改代码，配合 200-800 case 的全量评测集做实验驱动的参数定档。
