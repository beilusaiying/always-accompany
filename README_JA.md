## このプロジェクトを作った理由

『Detroit: Become Human』や『プラスティック・メモリーズ』を見たことがあるかもしれません。作中の人型 AI はとても賢く、仕事と寄り添いが一体になっています。そこで——自分にも一つ作ってみることにしました。

**最初に解決すべき問題は記憶でした。**

今の AI のコンテキストは平気で数百万トークンに達し、記憶ストレージツールや圧縮ツールも数多くあります。しかしそれらは平板すぎるか、時間が経つほど積み上がっていくものばかりです。AI パートナーにあなたとの記憶を忘れてほしくないと思っても、既存の方式ではそれはほぼ不可能です。

では、記憶とは一体何でしょうか？人間の記憶は実はとても短命です——2日前の細部はもうほとんど曖昧になっています。しかし一つのキーワードを与えられれば、対応する、あるいは関連する記憶をすぐに思い出せます。ここから二つの方向が導かれます：**記憶をどう保存するか、記憶をどう見つけるか。**

人は細部をすべて覚えているわけではなく、選択的に忘れていきます。しかし今の AI はそうではありません——力ずくで圧縮するか、ベクトルストアに詰め込むかのどちらかです。これは記憶の本質に反しています：直近に起きたことを即座に忘れることはできませんし、この数年間やってきたことを毎日すべて思い返すこともできません。

そこでこの発想に沿って、以下の仕組みを作りました。

## 記憶システム — 人のように保存し、人のように忘れる

> 📖 詳しい図解チュートリアル：[オンライン Wiki · 記憶システム](https://beilusaiying.github.io/always-accompany/#ja/memory/overview.md)

**data テーブル**は当日の記憶と永久保存の記憶を蓄えます——初恋の相手の名前や、一緒にした最初の出来事、告白した日のことを、あなたがずっと覚えているように。

その上には時間的な距離で分けられた3つの層があり、人間の選択的忘却をシミュレートします（記憶形成の階層メカニズム＋エビングハウスの忘却曲線）：

```
📋 data テーブル — 当日の記憶 + 永久記憶（chat / code / work それぞれ独立）
🔥 熱層（週単位）— 毎日の data を自動アーカイブ、AI が時間・出来事・プロセスごとに整理
🌤️ 温層（月単位）— 二次圧縮、キーワード抽出——目次のような役割
❄️ 冷層（年単位）— 深層アーカイブ、検索がヒットすれば到達可能
```

**注入時の重みは階層ごとに逓減**：コンテキスト＞data（永久記憶・繰り返し登場する項目）＞熱層＞温層＞冷層、さらに top-k も行います——直近の呼び出し状況に応じて各層内で二次的に並べ替え、層と層の間にはバッファ層もあります。完全なシミュレーション記憶想起階層＋一つの動的層です。

AI が実際に data を記録する状況と毎日のアーカイブ最適化から推計すると、1年間運用しても毎ターンの注入量は依然として 1万トークン未満に収まります（推計値：data 1件 ≈20文字、1日あたり100回のやり取り、日次 AI サマリー最適化による見積もり。熱層の実測値は毎ターン約 7,000〜11,000 トークン）。一部の難所を除き、この仕組みは**純粋なプロンプト＋純粋な JSON ドキュメント駆動**です——アーカイブ戦略、テーブルの意味、検索スタイルを変えたければ、プロンプトを変更するだけで済みます。ストレージコストはほぼゼロです。

長いコンテキストは万能薬ではありません：実験的な証拠（[Lost in the Middle](https://arxiv.org/abs/2307.03172) / [RULER](https://arxiv.org/abs/2404.06654) / [NoLiMa](https://arxiv.org/abs/2502.05167)）は、コンテキストの利用率が長さと位置によって減衰することを示しています——すべて詰め込む ＝ すべて見えている、ではありません。約1万トークンの厳選された記憶が、10万トークン超の履歴に相当する情報量を担います。

熱層にはドキュメントや関連記憶も紐付けられます——ロールプレイにおける装備や、他のキャラクターのパラメータなど。

## 記憶の想起 — 検索ではなく、発散＋検索

> 📄 アルゴリズムと実験の全容：[P1 技術論文](docs/p1-paper/README.md) · 📖 [オンライン Wiki · P1 特集](https://beilusaiying.github.io/always-accompany/#ja/p1-recall/preface.md)

「キーワード一つですぐに関連する記憶を思い出す」——これは単純なキーワード検索ではありません。認知心理学の知見によれば、人間の記憶は意味のネットワークであり、一つの概念が活性化されると関連の辺に沿って隣接概念へ広がり、遠いほど弱まります（拡散活性化理論、Collins & Loftus 1975）。「医者」が出た後は「看護師」の認識が速くなります（プライミング効果、Meyer & Schvaneveldt 1971）。人間の想起は瞬時性が非常に強い一方で、深さと広さの両方をコントロールしています（ワーキングメモリ容量 4±1 チャンク、Cowan 2001）。

既存の方式と比較すると：単純な検索では広さが出せません。補助 AI に任せる場合は先に発散してから探す必要があり、瞬時性が出せません。しかも記憶が増えるほどコストも増大します。

**現在の本番方式（AI P1）**：専任の検索 AI がまず記憶を探し、見つけたものだけを返信 AI に引き渡します——それぞれが自分の役割に専念し、注意力が薄まりません。BM25 による粗選別＋正規表現による精密マッチング、検索には無料の軽量モデルも使えます。

**現在改良中の次世代（自律駆動 P1）**：完全な純アルゴリズムパイプラインで、LLM ゼロ・ネットワークゼロです：

```
ユーザーの発話 + 直近5ターンのコンテキスト + data
  → 分かち書き（BCC コーパス、「彼の／こういう」などの機能語を除外）
  → SWOW 連想発散 + NB300 六次拡散モード ×2（work モードでは領域リソースを追加）
  → 六軸で位置特定（心理/情報/社会/論理/言語/認知）→ 47 サブ軸で方向を細分化 → 温度パラメータで想起半径を制御
  → 空間投票（IDW 加重による多対一の累積）→ BLQ スコアリング → 想起 + 方向語の注入
```

六軸は粗い位置づけ（単語がどの学問分野の方向に落ちるか）を与え、47 サブ軸はその粗い位置づけの内部で各細分方向に沿った意味変化率を描きます——役割としてはリー微分（指定した方向に沿った変化率を求める）に近いものです。一本の軸が一つの単語に対して出す位置づけは、**単一のスコアではなく複数の情報点**です（概念は意味空間の中で点ではなく領域を占める、Gärdenfors の概念空間理論 2000）。6軸 → 47サブ軸 → リソース層（SWOW / ConceptNet / Numberbatch の30万語ベクトル / 感情・領域辞書）は多層相互接続構造を構成しており、活性化は階層を伝わって加算的に集約されます——リソースライブラリとニューラルネットワークを組み合わせたような構造です。

BLQ スコアリングは加算的な融合です（CombSUM を参照、Fox & Shaw 1994）：6つの証拠次元を足し合わせ、4つのペナルティ項を差し引きます——加算は OR ゲートで証拠が補い合い、乗算は AND ゲートで 0.3 が一つあるだけで連鎖全体が崩れてしまいます。

**実測**：コンシューマー向け構成（VRAM 8GB＋メモリ 32GB）で完全な想起1回あたり約 200ms——すべての対話の裏側に、巨大な瞬時記憶が控えています。27 バージョンの反復を経て、発散品質スコアは +100% 以上向上し、無難で当たり障りのない回答の比率は 74%→4% に低下しました。実験データはすべて [Wiki P1 特集](https://beilusaiying.github.io/always-accompany/#ja/p1-recall/ch5-evolution.md)と[論文第6章](docs/p1-paper/en/06_experiments_evaluation.md)で公開しています。

## 発散 — AI 自身では思いつけない方向を与える

ニューラルネットワークとアテンション機構は本質的に**収束**的です：AI が大量の記憶を見てから今の話題を考えると、効果が下がり過学習しやすくなります。そこで私たちは**外部発散**を作りました：毎ターン 100 トークン未満の方向性コンテンツを注入します——どれも過学習した AI 自身では思いつけない方向です。少量の方向語だけで生成方向を有意に誘導できます（方向性刺激プロンプティング DSP、NeurIPS 2023）。外部の仕組みが発散を担い、LLM が収束を担う方が、LLM 自身に発散させるより優れています（外部足場に関する研究、2025）。

**関連性発散**——車に乗っていて、ふと車のドアを開けてみたくなったとします。映画のシーンなら主人公は転がり出て擦り傷程度で済みますが、あなたの安全教育はそれが命取りになりかねないと教えています。あなたは考え始めます——なぜ映画はああいう演出をするのか？——心理学、視覚表現、映画学。なぜ命に関わるのか？——物理学、生物学。こんな短い時間で、これだけの学問分野を横断しています。創造的な連想はまさに「近すぎず遠すぎない」最適な意味的距離帯に存在します（遠隔連想理論 Mednick 1962；Orwig et al. 2025）。

**構造的発散**——まったく異なる二つの領域でも、機能やプロセスが似ていれば関連づけられます：工場の生産ラインと Agent は、どちらもサンプル→安定化→モジュール化された産出という流れです（構造写像理論、Gentner 1983）。

実際の出力（200例のバッチ実行の生ログ）：

| ユーザー入力 | システムの発散方向 | 越境した学問分野 |
| --- | --- | --- |
| 「もう限界かもしれない、生きるってどうしてこんなに難しいの？」 | 今この瞬間の気づき / **実在の本質とは何か** | 心理学 → **実存主義哲学** |
| 「ユニコーン企業の面接に備えている、深みのある質問をどう用意すればいい？」 | 根本原因分析 / **最近接発達領域** | 経営学 → **教育心理学** |
| 「データベースクエリがとても遅いのをどう最適化する？」 | 不変性と状態更新 / **単一責任原則（SRP）** | 運用 → **ソフトウェア工学の方法論** |
| 「剣士が雪山で敵に遭遇する物語」 | **チェーホフの銃** / ユング的元型 | 物語 → **物語論 + 分析心理学** |
| ユーザーの自作詩「光が来る前に私は死んだ」 | **可能世界と並行宇宙** | 詩 → **物理学の多世界解釈** |

語彙採用基準：**メインモデルが素で読むだけで思いつける単語は無駄な単語**——発散が解決すべきことは二つだけです。過学習と、AI の発散能力の解放です。

## 詳細な仕組み

<details>
<summary><strong>🗜️ 圧縮 — ファイル単位まで細かい粒度</strong></summary>

正直なところ、なぜ誰も細分化された圧縮分類を作らなかったのか分かりません——特にコードのシーンでは、ほとんどが力ずくの圧縮とワンクリック非表示です。

調査の結果：AI のコンテキストが積み上がる主な原因は、繰り返し読み込まれるファイル、thinking、ツールのフィードバックです。そこで私たちは、極めて細かい粒度の完全な圧縮機構を作りました：

- **ファイルレベル**——AI が読み込むファイル一つひとつに、逐一トークンの明細をつける
- **作業レベル**——thinking とツールのフィードバックを、各ラウンドごとに自動削除
- **コンテキストレベル**——対話・サブエージェントの注入・AI の読み込みをそれぞれ個別に管理し、AI の発言だけを非表示にしてユーザーの発言は残すこともできる

**あなたの情報 = 消失ゼロ**：すべての「クリーンアップ」は送信対象から外すだけで、原文はディスク上に残りいつでも復元できます。さらにプロンプトが MD ファイルへの記録を促すため、IDE モードで 100MB 級の大規模プロジェクトであっても、AI はあなたの最初の一言を見続けられます——これは AI の「タスク属性のすり替わり」問題（作業しているうちに最初の目的を忘れてしまうこと）を直接的に減らします。

AI には自律的な圧縮能力もあります：システムが使用量のシグナルを注入し（50% で推奨/70% で警告/85% で緊急）、AI は `<contextClean>` を使ってどのファイルが不要かを自分で判断します。

キャッシュ効率の実測値（Opus + DeepSeek チャネル、AI の人格切り替え+自律圧縮を含む）：**70%–80%**。

→ [Wiki · コンテキスト圧縮](https://beilusaiying.github.io/always-accompany/#ja/memory/compression.md)

企業レベルのデプロイシーンを考慮し、CC 攻撃、DDoS、Slowloris への防御を備えています。

<details>
<summary><strong>🏗️ アーキテクチャ — コア機能はプラグイン化、拡張は本体を変更しない</strong></summary>

バックエンドはコア機能をプラグインとして実装し、中間には情報ハブ（伝導層）があり、フロントエンドは表示と操作のみを行います：

```
AIRP ─→ 入力/キャッシュ/処理（隔離）─┐
Code ─→ 入力/キャッシュ/処理（隔離）─┤→ 情報ハブ（伝導層）→ フロントエンド表示
Work ─→ 入力/キャッシュ/処理（隔離）─┘
```

そのため拡張性は非常に高く、機能を追加したければ拡張を作るだけでよく、JS / Python などに対応しています。

**隔離レベル**：
- **ウィンドウレベル**——code、work、chat、airp、ゲーム同伴、bot はそれぞれ隔離（ゲーム同伴は chat の data に書き込む）
- **キャラクターカードレベル**——data、記憶、対話ファイル、正規表現はキャラクターカードごとに隔離
- **きめ細かいレベル**——世界観設定、プリセット
- **ユーザーレベル**——各種設定、キャラクターカード
- **chatid**——同一モードで複数ウィンドウを開く場合専用（code のマルチウィンドウ / bot）、マルチウィンドウのための独立した隔離軸

3層構成：**機能層**（記憶/圧縮/検索/プリセット/世界観設定/ネット接続/ファイル操作——グローバルに1つ）→ **伝導層**（各ウィンドウがそれぞれ独自に接続し、id で隔離、本質的に非同期）→ **インターフェース層**（Web/Bot/デスクトップペット/VSCode 拡張——インターフェースを変えても能力は変わらない）。

</details>

<details>
<summary><strong>👑 プロンプトエンジン + 世界観設定の動的注入</strong></summary>

**TweakPrompt の3ラウンド**が全モジュールの出力を統一的に引き継ぎます：Round 1 で収集 → Round 2 で5段構成のメッセージ構造（beforeChat / injectionAbove / chatHistory / injectionBelow / afterChat）を再構築+マクロ置換 → Round 3 でスナップショット。

**世界観設定の3つの発動モード**：常時（毎ターン注入）/ 正規表現（キーワードでトリガー）/ 動的（記憶テーブルの数値条件を読み取ってトリガー——好感度が80を超えると特別な会話が解放される、タスク進行度が第3章に達すると世界観の描写が切り替わる、など）。

**マクロシステム**：`{{char}}` / `{{user}}` / `{{tableData}}` / `{{hotMemory}}` / `{{current_date}}` / `{{time}}` / `{{idle_duration}}` + カスタムマクロ。

→ [Wiki · 世界観設定と注入](https://beilusaiying.github.io/always-accompany/#ja/memory/worldbook-overview.md)

</details>

<details>
<summary><strong>🔭 巨大コンテキストウィンドウ時代について</strong></summary>

たとえウィンドウが 10M+ トークンまで拡張されても、私たちは階層記憶を維持し続けます：①コンテキストの利用率が長さとともに減衰することは実験的に十分裏付けられている、②約10Kトークンの厳選された記憶で10万+トークン分の履歴情報量を担え、コストは一桁違う、③構造化テーブルは散らばった対話よりもAIが正確に読み書きしやすい。

</details>

その先は？自律駆動シリーズが完成すれば、高速に伝導する、永久記憶を持つ AI になります：ゲーム業界に投入すればゲーム同伴に、仕事や医療に投入すれば、長期記憶＋いつでも使える分析と状態記録＋同じ状況での迅速な対応になります。最初の構想は実のところ本物の人型知能でした——ローカルの小型モデルがセンサーモジュールを担当し、メインの知能はネットワークを通じて伝導します。この記憶システムは、その日のために用意したものです。
