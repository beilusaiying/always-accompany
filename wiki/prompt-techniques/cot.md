# CoT 思维链

CoT（Chain of Thought，思维链）是让 AI 在输出最终内容之前，先进行分析和规划的技术。它不是一条提示词技巧，而是一种改变 AI 工作方式的方法论。

## 什么是 CoT

正常情况下，AI 收到提示词后直接输出结果。CoT 则要求 AI 先"想一想"——分析当前情境、规划接下来要做什么、梳理要注意的要点，然后再输出。

```
没有 CoT：
  提示词 → 直接输出

有 CoT：
  提示词 → 分析情境 → 规划要点 → 输出
```

这个"先想再做"的过程，会显著提升 AI 输出的质量和一致性。

## 为什么 CoT 有效

1. **引导注意力分配**：在分析阶段，AI 会重新审视提示词中的各项要求，确保不遗漏
2. **减少偏离**：规划阶段让 AI 在动笔前就确定方向，而不是写到哪算哪
3. **提升复杂任务表现**：对于需要同时满足多个条件的任务（角色扮演、代码生成、长文写作），CoT 帮助 AI 在多个约束间取得平衡

## CoT + 提示词 = 最大效力

CoT 和提示词配合使用，效果远大于单独使用任一。

### 示例：角色扮演场景

```
没有 CoT 的提示词：
────────────────
你是一个退役军医，性格沉稳。
以白描为主，对话推动情节。

→ AI 可能忽略部分设定，风格不稳定。
```

```
加入 CoT 的提示词：
────────────────
你是一个退役军医，性格沉稳。
以白描为主，对话推动情节。

在输出前，先在 <thinking> 中完成以下分析：
1. 当前场景的情绪基调是什么
2. 角色在这个情境下会有什么反应
3. 这段回复要推进什么情节点
4. 有哪些风格要求需要注意

然后再进行输出。

→ AI 会先梳理一遍要求，再写内容，风格更稳定、设定更一致。
```

### 示例：代码辅助场景

```
加入 CoT 的提示词：
────────────────
在回答编程问题前，先分析：
1. 用户的实际需求是什么（不只是表面提问）
2. 有哪些可能的实现方案
3. 各方案的优缺点
4. 推荐方案的理由

然后给出代码和解释。
```

## CoT 是检查助手

CoT 不只是让 AI 输出更好——它还是你**调试提示词**的工具。

### 怎么用 CoT 调试

当 AI 的表现不符合预期时，看它的 CoT 分析过程：

1. **AI 理解对了吗？** —— 看 CoT 中 AI 对你的提示词的解读，是否和你的意图一致
2. **AI 在关注什么？** —— CoT 中 AI 重点分析了哪些方面，忽略了哪些
3. **AI 在哪里偏了？** —— 如果最终输出有问题，从 CoT 中找到它开始偏离的那个环节

### 调试示例

假设你要求 AI "写一段节奏紧凑的打斗场景"，但 AI 输出了大段慢镜头描写。

查看 CoT 你可能会发现：

```
AI 的 thinking：
"用户要求节奏紧凑的打斗。我需要详细描写每一个动作，
 展现打斗的精彩程度......"
```

问题定位到了：AI 把"紧凑"理解成了"详细"。这时你就知道该怎么改提示词：

```
修改前：写一段节奏紧凑的打斗场景。

修改后：写一段打斗场景。使用短句，
一个动作一句话，不展开描写每个动作的细节，
保持段落在三行以内。
```

## 在 beilu 中使用 CoT

beilu 的[预设系统](../presets/overview.md)支持在系统提示词中嵌入 CoT 引导。你可以：

- 在角色卡的末尾添加 CoT 分析步骤
- 在预设条目中配置 thinking 指引
- 利用尾部注入放置当前场景的 CoT 提示

放在尾部效果最好（参考 U 型注意力原则），因为 CoT 引导是"当前要做的事"，属于高注意力区域。

## 注意事项

- CoT 会增加 AI 的输出长度（分析部分也算 token），注意 token 用量
- 不是所有场景都需要 CoT。简单问答、日常闲聊不需要，复杂创作、多约束任务才需要
- CoT 的分析步骤不要太多，3-5 步为宜。太多步骤反而让 AI 在分析阶段就偏了
- 某些模型支持内置 thinking 功能（如 Claude 的 extended thinking），可以与提示词中的 CoT 引导配合使用
