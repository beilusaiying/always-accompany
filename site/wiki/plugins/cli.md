# CLI 工具后端：不打开 IDE，也能让模式使用本地工具

beilu-cli 是随本体分发的工具执行后端。它适合希望在贝露本体里使用文件、搜索、命令和文档工具，但不想把 IDE 当作必需入口的用户。

它不是另一个聊天界面，也不替代 Code/Work 模式。模式负责理解任务、组织提示词和记忆；CLI 负责实际执行被允许的工具。

## 它替代什么

| 原来的限制 | CLI 带来的变化 |
|---|---|
| 只有打开 IDE 扩展时才有本地工具 | 本体启动时可单独拉起工具后端 |
| 工具状态只能从终端猜 | 设置面板返回运行状态、实际端口、工作区和最近日志 |
| 子进程崩溃后需要手工重开 | 可自动重启，并在连续崩溃后熔断 |
| CLI 与 YonBan 同时占资源 | 可选择共存，也可设置为互斥让位 |

如果你已经始终在 YonBan/IDE 中工作，并且不需要脱离 IDE 的本体工具后端，CLI 可以关闭自动启动。

## 默认状态与生命周期

- 默认端口是 8931；若实际绑定发生变化，运行注册表中的端口才是真值；
- 默认自动启动、自动重启；
- 默认允许与 YonBan 共存；
- 手动停止不会被自动重启；
- 手动启动或重启代表用户明确选择，会覆盖自动互斥判断；
- 插件卸载或本体退出时，会沿同一条关停链停止子进程。

## 完整链路

```text
Code / Work 产生工具调用
  → IDE 连接层选择可用后端
  → WebSocket 连接 CLI server
  → token 与端口注册表完成发现
  → 工具按 beilu-files 工作区和安全设置执行
  → 结构化结果回到原任务与 chatId
```

CLI 的配置文件位于项目数据目录；运行时端口/token 注册表和检查点位于用户及工作区的 `.beilu` 目录，而不是写入插件源码目录。

## 在哪里控制

在本体的 CLI 连接/设置区域可以：

- 启动、停止、重启；
- 修改首选端口；
- 开关自动启动、自动重启；
- 选择是否与 YonBan 共存；
- 查看 running、healthy、lifecycleState、实际端口、PID、工作区和最近日志；
- 修改部分工具提示文本。

端口修改后需要重启 CLI 才会生效。

## 工作区与安全边界

CLI 复用 beilu-files 的设置，而不是另建一套文件权限。最重要的不是端口，而是：

- workspaceRoot 是否正好覆盖你要操作的项目；
- 命令执行是否启用；
- 写入、删除和高风险命令是否需要审批；
- 连接方是否使用运行注册表中的 token；
- 工具返回是否回到正确的窗口和 chatId。

不要通过扩大工作区根来解决单个文件访问问题；那会同时扩大所有文件工具的权限面。

## CLI 和 YonBan 怎么选

| 场景 | 更适合 |
|---|---|
| 只打开贝露本体，也要使用工具 | CLI |
| 需要 IDE 编辑器、侧栏和扩展交互 | YonBan |
| 机器资源充足，需要两个入口 | 开启共存 |
| 希望同一时间只保留一个工具后端 | 关闭共存，使用自动让位 |
