# 配置 AI 服务源

AI 服务源决定你用哪家 AI、哪个模型来生成回复。beilu 自己不产生回复——它是车，服务源是油。这一页把"加油"这件事讲透，尤其是新用户最容易卡住的那个下拉框。

## 先想明白：这里其实是"两层选择"

配 AI 源时你要做的决定，本质上是两层——先弄懂这个，后面所有选项都不会晕。

**第一层：走哪条路（生成器）。** 想象你要寄一个包裹（你的消息）给 AI。beilu 提供了六条路：

- **官方直营通道**：claude、claude-api、gemini、grok、ollama——每条路只通往一家，走各家自己的格式，稳定省心；
- **万能中转站**：proxy——它说的是"OpenAI 格式"这门通用语。市面上绝大多数中转站、一键 API、聚合服务，无论背后卖的是 Claude 还是 DeepSeek 的模型，对外都讲这门通用语。所以"我买的是第三方 API"的用户，走的几乎都是这条路。

**第二层：说哪种方言（渠道）——只有走中转站才需要选。** "OpenAI 格式"是通用语，但各家服务商都有自己的小方言：Claude 的参数有独家讲究、DeepSeek 的推理模型有特殊字段、通义千问的思考模式必须配流式……渠道就是告诉中转站"包裹按哪家的方言打包"，beilu 会自动处理掉这些细节差异。渠道下拉里有约十种 OpenAI 兼容变体（Claude / OpenRouter / DeepSeek / 通义千问 / OpenAI / 通用兼容等）。

**为什么渠道里找不到 Ollama？** 因为 Ollama 是第一层的选项（一条独立的直营路），不是中转站里的一种方言。两层各管各的，这是新用户最常见的困惑，现在你已经免疫了。

## 你实际会看到的界面

理解了两层，再看界面就简单了——**beilu 的设置面板把两层合并成了一个「API 类型」下拉**，帮你把两层一次选完：

- 选「Google Gemini（原生）」「Ollama（本地原生）」→ 等于选了第一层的直营路；
- 选「Claude」「DeepSeek」「OpenAI 兼容（自动检测）」等其余选项 → 等于选了"中转站 + 对应方言"的组合套餐。

所以下拉里会出现**两个 Gemini**：「Google Gemini（原生）」是官方直营路，「Gemini（OpenAI 兼容）」是中转站里的 Gemini 方言——用官方 Key 选前者，用中转站选后者。

部分选项旁边还带一句坑提示（比如 Claude 的参数限制、千问必须开流式），那些是踩过坑之后写下来的，值得看一眼。

## 跟着做：添加一个服务源

1. **打开面板**：右上角齿轮（或 `Ctrl + ,`）→ 左侧闪电图标「AI服务源」（[设置 → AI服务源](beilu:settings/api)）→ 点「添加」。
2. **填名称**：自己起，比如"我的中转站"或"官方Gemini"，纯粹用来区分。
3. **选 API 类型**：按上面的思路选。拿不准就记住万能公式——*是中转/一键 API，就先试「OpenAI 兼容（自动检测）」*。
4. **看服务地址**：选完类型会自动填入该渠道的默认地址。用中转站的话，把它换成中转站给你的完整地址。
5. **填 API Key**：服务商或中转站给你的密钥，原样粘贴。
6. **选模型**：点「获取模型列表」，下拉里挑一个。列表拉不出来通常说明地址或 Key 有问题。
7. **保存**，然后在左栏（或底栏）的模型选择器里确认已选中这个源。

## 常见场景速查

| 你手上有的 | API 类型选什么 |
|------|---------|
| 中转站 / 一键 API / 聚合服务 | 对应服务商的渠道；找不到就选「OpenAI 兼容（自动检测）」 |
| Claude 官方或 Claude 系中转 | Claude 渠道 |
| Gemini 官方 API Key | Google Gemini（原生） |
| DeepSeek 官方或中转 | DeepSeek 渠道 |
| 本地跑的 Ollama | Ollama（本地原生），地址填你本机的 Ollama 服务地址 |
| OpenRouter | OpenRouter 渠道 |

## 可以配好几个源

服务源不止能配一个，而且很值得多配：

- **不同角色绑不同 AI**：角色卡编辑里可以给每个角色单独指定源；
- **不同模式用不同模型**：写代码用强模型、闲聊用便宜模型，子模式可独立绑定；
- **主源挂了切备用**：中转站抽风时一秒换路。

详见 [支持的 AI 服务商](beilu:wiki/ai-service/providers.md)。

## 验证与排错

配好后发条消息试试，能回复就成了。不通的话按这个顺序查：

1. [后台监控](beilu:settings/monitor) 看错误日志——401 是 Key 错，404 多半是地址错，模型不存在就是模型名不对；
2. 中转站用户确认地址填的是**完整端点**（一般以 `/v1/chat/completions` 结尾，中转站文档里都写了）；
3. 换个渠道试试——有些中转站对特定方言支持不佳，「OpenAI 兼容（自动检测）」常常是救星。

## 常见坑 FAQ

**问：渠道列表里为什么没有我用的服务商？**
答：只要它兼容 OpenAI 格式（绝大多数都兼容），选「OpenAI 兼容（自动检测）」即可，beilu 会自动探测细节。

**问：两个 Gemini 到底选哪个？**
答：官方 API Key → 原生；中转站买的 → OpenAI 兼容那个。

**问：Extended Thinking（扩展思考）开关是干嘛的？**
答：让支持思考的模型先"想一会儿"再回答，面板里可以开关并调思考预算。不确定就先不动，默认值是安全的。

**问：模型列表拉不出来，但我确定 Key 是对的？**
答：多半是地址少了或多了路径段。对照中转站文档把完整地址粘一遍，注意首尾不要带空格。
