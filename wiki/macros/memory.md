# 记忆系统宏

beilu-memory 插件在构建记忆提示词时使用的专用占位符。记忆注入阶段自动替换为实际记忆数据。

> **注意**：记忆系统宏由记忆系统在自己的链路里替换（主对话注入链与记忆子 AI 链各有替换点），不依赖预设宏引擎；个别宏（如 `{{lastUserMessage}}`）在预设宏引擎上下文中同样可用。

## 记忆数据宏

| 宏 | 说明 | 内容来源 |
|----|------|----------|
| `{{tableData}}` | 当前模式的记忆表格数据 | 记忆表格（结构化记忆） |
| `{{hotMemory}}` | 热层记忆 | forever/appointments/user_profile 等持久数据 |
| `{{workHotLayer}}` | 工作模式热层记忆全文（**仅记忆 AI 预设可用**） | `work/active/` 下 md 全文（同 `{{codeHotLayer}}` 范式，上限 `injection.work_hot_max_chars` 默认 30000） |
| `{{chat_history}}` | 最近 N 条聊天记录 | 聊天历史 |
| `{{lastUserMessage}}` | 用户最后一条消息 | 当前对话 |
| `{{contextSummary}}` | 上下文压缩摘要 | 记忆系统的自动摘要 |

### {{tableData}}

记忆表格是 always-accompany 记忆系统的核心数据结构之一。不同的记忆模式（如日常模式、冒险模式）有不同的表格列定义。`{{tableData}}` 会被替换为当前模式对应的表格内容。

### {{hotMemory}}

热层记忆包含多种持久化的记忆数据：

- **forever**：永久记忆条目
- **appointments**：日程/约定
- **user_profile**：用户画像信息
- 以及其他由记忆系统管理的热层数据

### {{chat_history}}

注入最近的 N 条聊天消息，让记忆 AI 了解当前对话的上下文。具体条数由记忆系统配置决定。

### {{lastUserMessage}}

用户在当前对话中发送的最后一条消息。记忆 AI 用它来判断需要更新哪些记忆。

### {{contextSummary}}

当对话过长时，记忆系统会生成上下文压缩摘要。这个宏引用该摘要内容。

## 辅助信息宏

| 宏 | 说明 |
|----|------|
| `{{presetList}}` | 记忆 AI 可选的预设列表 |
| `{{current_date}}` | 当前日期（记忆系统内部使用） |

### {{presetList}}

列出可供记忆 AI 选择的预设清单。记忆系统在某些场景下需要知道有哪些预设可用。

### {{current_date}}

提供当前日期信息给记忆 AI，帮助它正确处理与时间相关的记忆（如日程、时间线事件）。

## 运行链路

记忆系统宏的替换流程如下：

```
用户发消息
  -> beilu-memory 插件激活
  -> 加载记忆提示词模板（含宏占位符）
  -> 从记忆存储中提取数据
  -> 将 {{tableData}}、{{hotMemory}} 等替换为实际数据
  -> 组装完成的记忆提示词
  -> 注入到主提示词中发给 AI
```

这个过程与主宏引擎是**并行独立**的——记忆系统自行处理自己的宏，处理完的结果作为一个整体被注入到主提示词里。

## 使用场景

记忆系统宏主要在以下场景中使用：

| 场景 | 涉及宏 | 说明 |
|------|--------|------|
| 记忆整理提示词 | `{{tableData}}` `{{hotMemory}}` `{{chat_history}}` `{{lastUserMessage}}` | 告诉记忆 AI 当前有哪些记忆、对话说了什么 |
| 上下文压缩 | `{{contextSummary}}` | 为记忆 AI 提供长对话的摘要 |
| 记忆格式说明 | `{{presetList}}` `{{current_date}}` | 辅助信息 |

## 注意事项

- 记忆系统宏**不能**在普通预设或角色卡中使用——它们只在 beilu-memory 的内部模板中生效
- 这些宏由 beilu-memory 插件**独立替换**，不经过后端核心宏引擎
- 如果需要在预设中引用记忆数据，应通过记忆系统的注入机制，而不是直接写记忆宏
