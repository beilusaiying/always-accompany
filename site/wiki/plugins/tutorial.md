# 教程 / 视觉小说：把功能说明做成可互动的流程

beilu-tutorial 不只是 Wiki 阅读器。它提供教程和视觉小说序列的存储、编辑与播放能力，可组合角色立绘、分支对话、UI 元素引导、文字节奏、选项和音效。

它适合把“看完一长篇说明”改成“跟着做一遍”，也可以用于角色开场、功能演示和互动剧情。

## 什么时候值得用

- 新用户第一次配置服务源、模式或插件；
- 一个操作必须按顺序完成，纯文字容易漏步骤；
- 需要在真实 UI 元素旁边给出提示；
- 需要角色化的 onboarding 或视觉小说体验。

如果内容只是两三句话、没有交互和分支，普通 Wiki 更容易维护。

## 完整链路

```text
教程 JSON
  → 教程列表与编辑器
  → 解析 block / scene / dialogs
  → 角色、文本面板、选项、UI 引导和音效
  → 用户选择下一步或分支
```

教程可以新建、更新和删除。ID 只接受字母、数字、下划线和连字符，并限制长度，避免把任意路径当成文件名。

## 存储与共享边界

- 教程脚本保存在 `data/tutorials/`；
- 当前教程脚本是全局共享数据，不按用户分桶；
- `_defaults.json` 可覆盖编辑器的默认能力和数值范围；
- 下划线开头的系统文件不会出现在普通教程列表；
- 图片包复用 Eye 的图片包接口，不在教程插件里复制一套来源；
- 删除教程会删除对应 JSON，修改前请保留需要的副本。

## 音效的两层来源

1. 插件内置、允许随项目分发的声音；
2. 用户本地 `data/tutorials/sounds/`，同名时覆盖内置声音。

编辑器可从外部音效站下载补充素材到用户数据层。这个动作会联网，素材不会因为下载到本地就自动获得再分发许可；公开发布教程前仍需检查每个素材的许可证。

## 设计一篇有效教程

1. 开头先说明完成后用户能得到什么；
2. 每个场景只要求一个动作；
3. UI 引导绑定真实元素，界面变化后及时更新；
4. 分支只用于用户确实有不同目标的地方；
5. 结尾让用户完成一次真实任务，而不是只点“下一步”；
6. 同时保留一篇可搜索的 Wiki，方便以后直接查答案。
