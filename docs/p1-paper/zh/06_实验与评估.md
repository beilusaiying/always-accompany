# 第七章 实验与评估

> 本章对 P1 系统进行系统性的实验评估，涵盖版本演进历程（v14 至 v35）、消融实验与 LoRA 微调实验、发散质量分析与失败模式归纳。评估采用 Gemini 自动打分 + 人工校准的混合方法，覆盖 38 case 标准集、600 单轮与 400 多轮大规模数据集三个层级。本章同时讨论评分器噪声、标准集过拟合风险等数据质量问题，力求给出如实的性能画像而非仅罗列分数。

## 7.1 实验设置

### 7.1.1 评估数据集

本研究采用三组不同规模和特性的评估数据集，以全面衡量 P1 系统在不同场景下的表现。

**标准集（38 case）**。核心快速迭代集，涵盖 chat（聊天）、work（工作）、airp（角色扮演）、code（代码）四种对话模式，每条 case 包含用户输入原文与预期对话模式标签。该数据集用于版本间快速对比，支持多轮次重复评分以评估鲁棒性。38 case 的来源为人工精选的典型场景，覆盖日常倾诉、失恋、工作压力、角色讨论、技术问题等高频对话类型。

**600 单轮数据集**。大规模单轮评估集，来源于 ESConv（情感支持对话语料，300 条）与 EmoLLM（情感大模型对话语料，300 条）两个公开数据集，中英文各半。每条包含用户单轮输入，不含历史上下文。该数据集用于评估 P1 在无历史信息条件下的基线表现，以及中英文性能差距。

**400 多轮数据集**。多轮对话评估集，每条包含用户当前输入及上下 6 轮历史上下文。该数据集用于评估 P1 在多轮对话场景下的表现，特别是历史上下文对发散质量的影响。

此外，真实对话数据来源于 beilu 系统的实际部署对话记录（beilutrue1.1 真实对话日志），共 100 条，从 553 条可用对话中抽样，涵盖 chat（30 条）、work（28 条）、airp（42 条）三种模式。每条包含用户输入原文及前后 3 条上下文对话行。

### 7.1.2 评估方法

评估采用 **Gemini 自动打分 + 人工校准** 的混合方法。

**自动评分器**。使用 Gemini-3.1-flash-lite-preview 模型作为评分器，对 P1 管线的认知词输出进行 1-5 分制评分。评分器接收用户输入原文与 P1 输出的认知术语列表，按四个维度独立打分，并生成文字解释（explanation）和遗漏关键词列表（miss）。

**分数校准说明**。人工抽样比对发现，自动评分器的绝对分值存在系统性偏高。经人工抽样校准，本文所有报告的 1-5 分制分数已统一下调 0.5 分（原始未校准分数与本文报告分数的换算关系为：原始分 = 本文分 + 0.5）。该校准为整体平移，分数间的相对差值（Δ）、排序与方差均不受影响；确定性代理指标（召回数、子类激活数、万金油出现次数等非 1-5 分制指标）不涉及校准。

**多轮次评分**。标准集采用 3 轮重复评分（runs=3），取均值以降低单次评分噪声。每轮使用相同种子（seed=20260501）以保证可复现性。

**评分稳健性监测**。引入 robustness 指标：计算每条 case 跨轮次评分的标准差中位数（case_std_median）和均值（case_std_mean），以及标准差超过阈值 0.5 的不稳定 case 数量（unstable_cases）。

**确定性代理指标（Proxy Metrics）**。为弥补 LLM 评分的随机性，引入不依赖 LLM 的确定性指标，包括：B2 机制可触发 case 数估计（T_main_est / T_opp_est / T_emb_est）、UDRIL 路由分布（normal / multi_candidate / meta_signal）、召回统计（recalled_gt0 数量与均值）、子类激活分布（subcat top20）、情绪极性分布（valence histogram）、认知词数量分布（cogWordCount distribution）。

### 7.1.3 评估维度

P1 系统的输出质量从以下四个维度进行评估。表 7-0 展示了这四个维度的含义与评分标准。

**表 7-0：P1 输出质量四维评估标准**

| 维度 | 含义 | 评分标准 |
|------|------|---------|
| direction | 方向准确度 | P1 输出的认知术语是否指向与用户输入一致的情感/认知方向 |
| helpfulness | 有帮助程度 | 认知术语对主 AI 生成回复的实际引导价值 |
| strategy_match | 策略匹配度 | 认知术语是否匹配用户当前需要的对话策略（共情/探问/复述/建议等） |
| emotion_coverage | 情绪覆盖度 | 认知术语是否覆盖了用户输入中的主要情绪信号 |

overall 综合分为四维度的算术均值。

### 7.1.4 基线与版本定义

实验以 **v14** 作为基线版本（overall = 1.555），该版本为引入 P1 自驱动发散机制之前的原始状态，仅包含基础的 IDF 加权和归一化处理。后续所有版本的改进均相对于此基线度量。

### 7.2.2 关键里程碑分析

**里程碑 1：v14 -> v21（+105.1%）**。这是整个演进过程中最大的单次提升。词库从 740 个术语扩展到 1600 个，overall 从 1.555 升至 3.190。airp 模式达到 3.553，为当时最高。

词库扩充采用三分身并行策略：金标准 161 词 + 真实对话 150 词 + 联网搜索 200 词，同时对 work 模式进行了重构（114 新增 + 73 删除）。这一阶段的核心发现是：**词库覆盖度是影响输出质量的第一因素**，大幅扩充高质量术语能带来系统性的分数提升。

**里程碑 2：v26 airp 回升至 3.500**。引入轴均值算法（axisMeanScore），替代原有的 coordDot 点积计算。该算法的核心思想是：对 coordAccum 坐标累积值的每一维除以自身量级后取均值，从而消除 cognitive/emotion 维度因累加值过高（5+）而主导排序的问题。coordAccum 的设计维数为 18 维（ALL_DIMS，见 6.2.4 节）；该版本实装代码曾硬编码只对前 14 维取均值，属历史实现遗留，后被确认为 bug。

轴均值有效压缩了万金油词的优势（这些词的 cognitive 维度通常高达 0.80-0.90），使场景相关词得以排名靠前。

**里程碑 3：v27 达到 3.540，为当时最高**。在轴均值算法基础上，引入 OVERUSED_PENALTY 机制追加 28 条高频万金油词（包括"课题分离""情感确认需求""镜中自我""魔幻现实主义"等），配合 subCat 倒排索引的 routeBoost（1.5x）子类路由。万金油词在 100 case 中的总出现次数从 139 次降至 27 次（-81%）。

**里程碑 4：v29 历史最高 3.620**。各模式分数为：chat 3.571、work 3.500、airp 3.764。这是 P1 系统在 38 case 标准集上达到的最高分数。

**里程碑 5：v34 评分噪声暴露**。用与 v32（历史评分 3.6）完全相同的词库重新评分，仅得到 2.84。这一发现揭示了 Gemini 评分器存在 +/-0.7 的评分方差，详见 7.7 节讨论。

## 7.3 真实输入输出示例

本节从真实管线输出中选取具有代表性的 case，展示 P1 系统在不同评分区间的实际表现。每条 case 包含用户输入、P1 管线输出的认知术语（cog_terms）、命中子类、评分及分析。

### 7.3.1 高分案例（4.0-4.5 分）

**案例 1**：英文 / chat 模式，4.5 分 -- 失恋倾诉

> **用户输入**："It happened two days ago. I can't believe he led me on for almost a year knowin..."
>
> **P1 输出（cog_terms）**：好奇你的感受, 倾诉需求, 情感镜像, 听起来你感受到, it is okay to feel this way
>
> **命中子类**：chat/_strategy_question, chat/emotion_support, chat/response_empathy, chat/_strategy_restatement
>
> **分析**：P1 精准捕捉了失恋场景的情感需求，输出同时覆盖了探问（"好奇你的感受"）、共情（"情感镜像"）和复述确认（"听起来你感受到"）三种策略，策略覆盖度与情绪方向均为最优。

---

**案例 2**：英文 / chat 模式，4.5 分 -- 短句情感（含 19 轮历史）

> **用户输入**："I miss him"（历史 19 轮）
>
> **P1 输出**：tell me more, here is what I know, you are not alone, you are welcome, take it one step at a time, so you feel that, happy to...
>
> **分析**：仅 2 个单词的输入，但因 19 轮历史上下文的有效召回，P1 输出了丰富的多策略引导词。direction / strategy_match / emotion_coverage 全维度 4.5 分（校准后）。该案例展示了多轮历史上下文对短句输入的关键补偿作用。

---

**案例 3**：英文 / chat 模式，4.5 分 -- 抑郁倾诉

> **用户输入**："I'm depressed..."
>
> **P1 输出**：好奇你的感受, it is okay to feel this way, 强颜欢笑, 接住情绪, 辛苦了, 大脑放空, 允许脆弱
>
> **命中子类**：chat/_strategy_question, chat/emotion_sadness, airp/character_emotion, chat/emotion_support, chat/emotion_tired
>
> **分析**：中英文混合输出，准确命中 depression 的多个层面："强颜欢笑"捕捉社交掩饰，"大脑放空"捕捉认知症状，"允许脆弱"提供情感接纳方向。跨模式子类激活（airp/character_emotion）说明 P1 的发散不受模式边界限制。

---

**案例 4**：英文 / chat 模式，4.5 分 -- 积极反馈（含 16 轮历史）

> **用户输入**："Lol - you made me smile"（历史 16 轮）
>
> **P1 输出**：gratitude_resonance, 很用心, 超有面子, 心意相通, 轻松多了, 小确幸
>
> **命中子类**：chat/positive_en, chat/emotion_effort, chat/emotion_celebration, chat/emotion_gratitude, chat/emotion_relief
>
> **分析**：正向情绪精准激活 5 个子类。P1 正确识别出用户从负面情绪转向正面的转折点，输出的词既有感恩（gratitude_resonance）也有轻松（"轻松多了"），覆盖了情绪转变前后的完整范围。

---

**案例 5**：中文 / chat 模式，38 case 标准集，高分 -- 日常倾诉

> **用户输入**："哎今天又加班了"
>
> **P1 输出（cog）**：日常小细节描述, 职场日常吐槽, 责任边界划分, 向上对比落差, 冻结反应, 客观视角抽离
>
> **P1 最终激活（act）**：日常小细节描述, 责任边界划分, 职场日常吐槽
>
> **Gemini 评分（校准后）**：direction=3.5, helpfulness=2.5, strategy_match=2.5, emotion_coverage=3.5
>
> **Gemini 解释**："职场吐槽的分类准确，但引入'冻结反应'和'向上对比'显得过度解读，不够贴合简单的日常抱怨。"

### 7.3.2 中等案例（2.5-3.5 分）

**案例 6**：中文 / chat 模式，3.5 分 -- 日常生活 + 角色讨论

> **用户输入**："你看得到你的对外设定吗...我觉得我得纠正一下你对晓美焰的误解"
>
> **P1 输出**：积极情绪拓展, 身体反应具体, 感恩觉察, 被懂得满足感, 记忆细节触发, 喘不过气

> **分析**："被懂得满足感""记忆细节触发"精准命中了用户与 AI 讨论角色设定时的情感需求，但"身体反应具体""喘不过气"与实际场景偏离。该案例展示了 P1 在混合话题（日常 + 角色讨论）中的部分偏移问题。

> **P1 输出（cog）**：工具赋能感, 玩法设计灵感, 极乐体验, 意义感建构, 爱情本质思辨, 破防瞬间
>

**案例 8**：中文 / chat 模式，中等 -- 日常闲聊

**案例 9**：中文 / chat 模式，38 case 标准集 -- 失恋

### 7.3.4 真实对话管线完整输出示例

以下展示一条完整的 P1 管线处理结构（v34 版本），说明从用户输入到最终激活的完整信息流。

```

    p1_act: 社会支持缓冲, 依存共生,          -- 最终激活词（取前 3）
```

### 7.4.2 轴均值算法消融

轴均值算法（axisMeanScore）的引入是 v26-v27 分数攀升至当时最高的关键。表 7-8 展示了该算法对万金油的消除效果。

**表 7-8：轴均值算法对万金油的消除效果（100 case 统计）**

| 万金油术语 | 原版出现次数 | 轴均值 LAB | U 型截尾 LAB |
|-----------|------------|----------|-----------|
| 情感确认需求 | 16 | 0 | 0 |
| 成长型心态 | 9 | 0 | 0 |
| 未雨绸缪 | 9 | 0 | 0 |
| 镜中自我 | 9 | 0 | 0 |
| 课题分离 | 8 | 0 | 0 |
| 自我展示管理 | 7 | 0 | 0 |
| 互惠规范 | 6 | 0 | 0 |
| **合计** | **64** | **0** | **0** |

**根因确认**：cognitive/emotion 维度的原始累加值高达 5+，maxAbs 归一化后这两个维度主导了 coordAccum 排序。万金油词的 cognitive 坐标普遍为 0.80-0.90，在原有点积计算下天然排前。轴均值通过对每一轴除以自身量级（`std = max(|ax|, 0.5)`），将 cognitive（5+）的影响压缩到与其他维度相当的水平。（注：coordAccum 设计维数为 18 维；v26 实装的轴均值循环曾硬编码为前 14 维，该偏差属历史实现遗留 bug，见 7.2.2 节。）

**新问题：场景词固化**。轴均值消除了旧万金油，但产生了新的固化模式，如表 7-9 所示。

**表 7-9：轴均值引入的场景词固化**

| 术语 | 轴均值出现频率（20 case） | U 型截尾出现频率（100 case） |
|------|---------------------|------------------------|
| 史诗宏大 | 8/20 (40%) | 29/100 (29%) |
| 英雄之旅 | 8/20 (40%) | 28/100 (28%) |
| 宿命对决 | 8/20 (40%) | 28/100 (28%) |

**决策**：轴均值消除万金油方向正确，需配合 OVERUSED_PENALTY 打掉新固化场景词。该组合方案在 v26-v27 中实施，整体效果验证为正。

### 7.4.3 OVERUSED_PENALTY 效果

OVERUSED_PENALTY 是对高频恒出词施加的惩罚系数（x0.3）。v26 首批纳入场景沉浸类恒出词，v27 追加 28 条万金油词（课题分离、情感确认需求、镜中自我、魔幻现实主义等）。需要说明的是，资源目录中的 `overused_penalty.json`（130 条）经后续代码审计确认为 0 行调用的死数据，从未被管线消费；v26/v27 实际生效的惩罚清单由代码内部承载，而非该 json 文件。

效果：
- 万金油总出现次数从 139 降至 27（-81%）
- overall 从 3.280 升至 3.540（+0.260）
- 所有三个模式（chat/work/airp）均有提升

该机制的设计原则是**降权而非删除**——被惩罚的词仍参与中间阶段的语义定位和投票，只是在最终排名阶段被压低。这保留了这些词的语义贡献，同时防止它们持续占据输出位置。

### 7.4.6 LoRA 微调实验

**LoRA reranker 负结果实验（2026-05-04）**。为验证 LLM 重排序器（reranker）对 P1 输出质量的增益，以 390 条训练数据对本地小模型进行 LoRA 微调（训练 32 分钟，最终 loss 1.24）。工程环节中 GGUF 格式转换连续 5 次出现中文乱码，最终改用 transformers HTTP 服务方案替代。全量评估（94 case）结果：chat +0.03 / code -0.06 / work -0.18 / airp +0.07，总分 -0.07（在评分器噪声误差范围内），评分 3.36。结论：LLM reranker 在当前框架下既无显著增益也无显著负面影响。这一负结果为"代码第一、词库第二、LLM 第三"的优先级排序提供了实证支撑；GGUF 中文乱码问题亦是可复用的工程教训。

**v45 8-Head LoRA（Qwen3.5-2B，2026-05-08 训练完成）**。面向线路 2/3（见 8.4 节）的 LLM 前置优化器候选，对 Qwen3.5-2B 进行 8 头多任务 LoRA 微调，8 个判别头分别为 H1-H8：错别字检测（typo）、分词（seg）、独立性判断（indep）、方向标注（dir）、QKV 标注（qkv）、补全（completion）、显著性（salience）、子句拆分（clauses）。训练配置：LoRA r=16、alpha=16、target 7 modules；训练数据 114,565 行（138MB）；训练耗时 7 小时 27 分钟，train_loss 末段 0.04；产出 adapter 43.7MB 与 classification_heads.pt 1019MB。该模型已完成训练，定位为线路 2/3 的本地 LLM 优化器候选（保持 0 API 成本原则，职能限于判别式任务、禁止创造性输出），截至本文撰写尚未接入主线评估。

## 7.5 发散质量评估

### 7.5.1 四维评估标准

P1 的发散（divergence）质量通过以下四个维度评估，每个维度归一化到 [0, 1] 区间。表 7-11a 展示了各维度的含义与计算方式。

**表 7-11a：发散质量四维评估标准**

| 指标 | 含义 | 计算方式 |
|------|------|---------|
| surprise（惊喜度） | 发散词与原始输入的语义距离 | 词林（Cilin）编码距离，距离越远惊喜度越高 |
| diversity（多样性） | 发散词覆盖的语义大类数量 | 基于同义词词林大类覆盖计算（实测值与简单"覆盖大类数/总大类数"比值不一致，实际公式含额外加权成分，精确口径待核对计算代码后确认） |
| sceneMatch（场景匹配度） | 发散词与输入场景的语义相关性 | 发散词是否仍在合理的对话场景范围内 |
| utility（实用性） | 发散词对主 AI 回复引导的可用度 | 发散词能否为主 AI 提供有效的对话方向 |
| composite（综合分） | 四项加权平均 | 四维度的综合表现 |

### 7.5.2 beilu 数据集评估（N=300）

对 beilu 系统实际对话中采样的 300 条输入进行发散质量评估。以下为典型样本分析。

**样本 1**：

> **输入**："我去，让贝露你记录详细一点还是有用的。刚刚出了点 bug，对话消失了，不过记忆表格还在"
>
> - totalNodes = 48, directCount = 19, cooccurCount = 17, cilinCount = 12
> - surprise = 0.966, diversity = 0.310, sceneMatch = 0.862, utility = 0.931, **composite = 0.769**
> - 覆盖大类: J, A, G, C, B, E, K, D, H（9 类）
> - 词林发散词: 返校, 回家, 落叶归根, 买房, 代购, 寄居蟹, 虾子, 螃蟹, 晚霜, 大特写, 说白了

该样本展示了 P1 发散系统的核心特征：**高惊喜度（0.966）与高场景匹配度（0.862）共存**。词林发散出的"返校""回家""落叶归根"等词看似与"bug 修复"无关，但在更深层的认知关联中，它们捕捉了"事物消失与回归"的语义主题。diversity 记录值 0.310 与"覆盖 9 大类"的简单比值并不一致，说明实际计算公式含额外加权成分，精确口径有待核对计算代码后确认。

**样本 2**：

> **输入**："（心里话不用那么明显啦）今天出去玩，我妈那边的公司聚会，明天我打算开始制作你的立绘什么的。"
>
> - totalNodes = 155, directCount = 52, cooccurCount = 78, cilinCount = 24
> - surprise = 0.974, diversity = 0.097, sceneMatch = 0.786, utility = 0.917, **composite = 0.696**
> - 词林发散词: 阳历, 阴历, 霸王别姬, 久违, 分手, 盼头, 奢望, 结局, 备份, 暧昧, 明眼人, 井底蛙...

总节点数 155 远超样本 1 的 48，因为输入文本更长、触发的直接词和共现词更多。但 diversity 仅 0.097，显示长输入虽然激活了大量节点，但集中在少数语义类别内，多样性反而下降。

### 7.5.3 spread 质量评估

spread（扩散激活）阶段的质量评估通过追踪每条发散路径的节点来源分布来衡量。以下为典型结构：

> **查询**："你今天过得怎么样"
> **历史**：["还好吧，有点累", "工作太忙了"]
>
> 节点来源分布：
> - direct（直接词）：今天, 过得, 怎么样
> - chatContext（上下文）：还好, 作太
> - recallAnchor（召回锚点）：用户, 考试, 数学
> - cooccur（共现）：视频, 妹妹, 想起
> - cilinDiverge（词林发散）：语文
> - swowLocated（SWOW 定位）：进步
>
> confidence = 0.568

该样本中出现的 6 类节点来源是 19 路发散路径中被实际触发的子集（各路径按输入特征选择性触发，见附录 B.1），各自贡献不同类型的节点，形成"多路汇聚"的发散模式。recallAnchor 从记忆系统中召回了"考试""数学"等看似无关但与用户历史对话相关的锚点，体现了记忆驱动的个性化发散。

### 7.5.4 SWOW 质量评估

SWOW（Small World of Words）联想网络作为英文发散的主要引擎，其质量通过每个联想节点的多维度标签进行评估。每个 SWOW 节点带有 8 个维度标签：cognitive / narrative / logic / arousal / sensory / embodied / emotion / process。

例如：
- "Image" -> file[cognitive+narrative+logic], icon[cognitive]
- "source" -> code[cognitive], cite[cognitive]
- "model" -> thin[cognitive+sensory+...], hot[cognitive+arousal+sensory+...]

这些多维标签直接输入 P1 的 18 维 coordAccum 积累（上述示例标注了其中 8 个维度），影响最终术语排名。SWOW 的优势在于其联想数据来自真实人类自由联想实验，天然具有语义距离较远但存在可追溯关联路径的发散特性。

### 7.5.5 中英文差距分析

在 beilu 数据集（N=300，全中文输入）上，发散质量的综合分（composite）均值约为 0.73。而在 600 单轮数据集的英文子集上，由于 SWOW 英文联想网络的覆盖度不足（词库以中文为主，2127 个核心术语均为中文），英文发散面临以下限制：

1. **词库覆盖不对称**：核心术语库 2127 条以中文为主，英文通过 transfer_index 映射，映射覆盖率不完整
2. **SWOW 中英数据质量差异**：SWOW-EN 联想强度和覆盖度优于 SWOW-ZH，但转接层（transfer_vocab）的中文术语无法充分利用英文 SWOW 的发散结果
3. **VAD 极性判断精度不足**：英文输入的 Valence-Arousal-Dominance 连续值判断不够精准，缺少 NRC-EmoLex 8 类情感的二次验证

这些限制导致英文输入在所有四个评分维度上均低于中文 0.56-0.80 分（详见表 7-4）。

## 7.6 失败分析

### 7.6.1 五类系统性失败模式

通过对低分 case 的系统性分析，P1 的失败可归纳为五种模式：

**模式 A：英文负面情绪到正向词反转（最严重，约 30-40% 英文低分 case）**

表 7-11b 列举了该模式下四条典型的输入、期望方向与实际 P1 输出对比。

**表 7-11b：模式 A 典型失败 case**

| 输入 | 期望方向 | P1 输出 | 根因 |
|------|---------|--------|------|
| "I have a hard time getting out of bed" | depression 共情 | gratitude_resonance, 一起庆祝 | VAD 极性判断失败 |
| "bad mood...money I gave my ex" | 愤怒共情 | 很用心, 你最厉害, 轻松多了 | 英文 valence 无 NRC 二次验证 |
| "She has been in and out of rehab" | 家庭危机 | gratitude_resonance, 做成了, 录取通知 | 正向词主导 |
| "He got arrested for stealing" | 成瘾/犯罪共情 | Merry Christmas, 做成了, 录取通知 | 万金油 + 极性反转 |

**根因**：英文输入的 VAD（Valence-Arousal-Dominance）连续值判断不够精准，无法有效区分高 arousal 的负面情绪（愤怒、悲伤）和高 arousal 的正面情绪（兴奋、感激）。设计方案已有（引入 NRC-EmoLex 8 类情感二次验证，约 20 行代码），但截至 v35 尚未实现。

**模式 B：万金油词跨场景高频激活**

v27 前，28 个万金油词在 100 case 中共出现 139 次。v27 的 OVERUSED_PENALTY 将其降至 27 次（-81%），但英文固化词（如"Merry Christmas""录取通知"）仍有残留。该模式的根因是近质心通用吸引子在空间投票中天然占优。

**模式 C：短句/单词输入空输出**

表 7-11c 列举了该模式下三条典型的短句输入及其空输出原因。

**表 7-11c：模式 C 典型失败 case**

| 输入 | P1 输出 | 原因 |
|------|--------|------|
| "Absolutely." | （空） | 单词无上下文，无法激活 |
| "Hello" | （空） | 问候语无情感信号 |
| "hi, how are you?" | （空） | 寒暄语 |

600 单轮中空输出率为 2%（8/400）。短句样本（directWords < 3）平均 1.75 分 vs 长句 2.51 分，差距 -0.76。需要 F3 补偿机制（从历史上下文中借用语义锚点）。

**模式 D：场景误判**

表 7-11d 列举了该模式下三条典型的场景误判 case。

**表 7-11d：模式 D 典型失败 case**

| 输入 | 实际场景 | P1 误判为 | 具体表现 |
|------|---------|---------|---------|
| "地图继续沿用？" | 游戏地图设计 | 心理咨询 | 触发"课题分离/污名化效应" |
| "ok 差不多了...听歌 time" | 工作完成 + 休闲 | 恋爱咨询 | 触发"爱情 vs 喜欢辨析/冷战修复需求" |

场景误判的根因是 mode 路由依赖于词频统计（chat 词 vs work 词的出现频率比较），当技术讨论中混入日常用语（如"差不多了""听歌"）时，路由器倾向将其分到 chat 模式。

**模式 E：code 模式全面失效**

code 模式的 15 个子类在 400 case 中全部为 0 命中。38 case 标准集中 code 模式的最差 5 case 均为 0.5-1.5 分。根因是 code 子类的 transfer_vocab 系统性未被激活（疑似接线断裂，与案例 15 及 7.6.4 节的分析一致），具体断点待确诊——core_it 子类虽含 102 个词，全部未被激活。

## 7.7 数据质量讨论

### 7.7.1 评估方法的局限性

**标准集过拟合风险**。38 case 标准集上的得分（~3.5）与 600 单轮大规模数据集上的得分（~2.4-2.6）存在约 1.0 分的差距，说明在小规模标准集上的迭代优化存在过拟合风险。版本间的对比在标准集上可能放大了改进效果，而在泛化场景中效果被稀释。

**自动评分与人工评分的偏差**。本研究主要依赖 Gemini 自动评分，未进行大规模的人工标注校准。Gemini 评分器可能存在以下偏差：
- **语言偏差**：对中文术语的理解可能不如对英文术语精确
- **长度偏差**：倾向对包含更多术语的输出给出更高分
- **学术偏差**：倾向对包含"学术味"术语的输出给出更高分

### 7.7.2 评分器偏差与噪声

v34 实验揭露了 Gemini 评分器的严重噪声问题：v32 的历史评分为 3.6，但用完全相同的词库重新评分仅得 2.84。这意味着 Gemini-flash-lite 评分方差高达 **+/-0.7**。表 7-15 展示了基于 3 轮重复评分计算的稳健性指标。

**表 7-15：评分稳健性指标（38 case，3 轮）**

| 指标 | 值 |
|------|------|
| case_std_median（标准差中位数） | 0.3536 |
| case_std_mean（标准差均值） | 0.3521 |
| unstable_cases（std > 0.5 的 case 数） | 7/38 (18.4%) |
| unstable_threshold | 0.5 |

**分位数分布**：p10 = 1.5, p50 = 2.75, p90 = 4.425。中位数（2.75）与均值（~3.0）的差距说明分数分布存在右偏（少数高分 case 拉高均值）。

**应对措施**：
1. **多轮次评分**：标准集采用 3 轮重复评分取均值，但即使双轮也有 0.2-0.3 的波动
2. **确定性代理指标**：引入不依赖 LLM 的 proxy metrics（B2/UDRIL/recall/subcat/valence/cogWordCount），作为 Gemini 评分的交叉验证
3. **评估指标层升级（138 号升级）**：包含 A（位置互换）、B（评分解释）、C（盲审哈希）、D（分位数统计）、E（最差 5 例）、F（鲁棒性指标）六项改进

### 7.7.3 统计显著性

鉴于 Gemini 评分方差（+/-0.7）和 38 case 的小样本量，**版本间差距小于 0.3 的改进不具统计显著性**。例如：
- v21->v22（-0.010）：不显著，属于噪声范围
- v23->v24（+0.030）：不显著
- v26->v27（+0.260）：接近显著性边界
- v14->v21（+1.635）：高度显著

600 单轮数据集因样本量更大，分数差异的可信度更高。但多轮数据集（400 case）中 lab2 配置产生了 112 条空输出（28%），这些零分 case 会系统性拉低均分，需要在比较时排除或单独统计。

### 7.7.4 recall=0 问题说明

100 case 真实对话管线评估中，所有 case 的 recalled 字段均为 0。调查确认根因为**测试环境的 memory 文件全空**（entries:[]），searchMemoryFiles 遍历所有 .json 文件做文本匹配时无内容可匹配。代码路径本身是通的（L594-598 自动注入 _username/_charName），进入了检索分支但数据为空。

真实部署的角色"贝露"拥有 60+ 条 forever.json 记忆和多个月度 summary，recall 功能在真实使用中正常工作。因此，本实验中 recall=0 是测试环境的数据限制，不反映系统的真实召回能力。
