# プリセットとモードの連動

always-accompany のモードシステム（[チャットモード](beilu:mode/chat) / Code / [ワークモード](beilu:mode/work) / [Bot管理](beilu:mode/bot)）はプリセットエンジンと深く連動しています。各モードに独立したプリセットをバインドでき、モード切り替え時にシステムが自動的にプリセットを切り替えて、異なる作業シーンで AI が適切な指示を受けられるようにします。

## バインディングデータ構造

### mode_preset_bindings

モードのバインド関係は記憶システムのグローバル設定（`_config.json` の `mode_preset_bindings` フィールド）に保存されています：

```
mode_preset_bindings: {
  chat: "プリセット名A",
  code: "プリセット名B",
  work: "プリセット名C",
  bot:  "プリセット名D"
}
```

各モードには1つのプリセット名のみバインドされます。特定のモードでプリセットを選択すると、このバインディングが自動的に更新されます。

### active_preset_map

モードレベルのバインディングに加えて、各対話ウィンドウに個別にプリセットをバインドできます。`active_preset_map` は対話 ID（またはモード+キャラクターの複合キー）をインデックスとして、各対話が使用するプリセットを記録します：

```
active_preset_map: {
  "abc1234": "プリセット名X",         // ある対話が使用するプリセット
  "chat:キャラクター名": "プリセット名Y",      // chat モードでの特定キャラクターのプリセット
  "code:キャラクター名": "プリセット名Z"       // code モードでの特定キャラクターのプリセット
}
```

## プリセット選択の優先順位

特定の対話でどのプリセットを使用するか決定する際、以下の優先順位で解決されます：

```
対話レベル active_preset_map[chatId]
    ↓ なし → モード+キャラクター複合キー active_preset_map[mode:charName]
    ↓ なし → モードバインディング mode_preset_bindings[mode]
    ↓ なし → グローバルデフォルト active_preset
```

## モード切り替え時の連動

ユーザーがモードを切り替えた後、プリセットエンジンの動作は以下のとおりです：

1. フロントエンドがバックエンドにモード切り替えを通知します（switchMode）
2. バックエンドが対象モードのアクティブな対話（using ポインタ）を読み取ります
3. active_preset_map からその対話のプリセットを解決します
4. 対話に個別プリセットがない場合、mode_preset_bindings にフォールバックします
5. 対応するプリセットをエンジンに読み込み、以降の対話で新しいプリセットを使用します

## サブモードバインディング

Code と Work モードにはそれぞれ 11 個のサブモードがあります。各サブモードには以下を個別にバインドできます：

- プリセット
- AI サービスソース
- モデル名
- サンプリングパラメータ（temperature など）

サブモードのパラメータは TweakPrompt Round 2 の段階でエンジンパラメータをオーバーライドします。オーバーライドチェーン：

```
サブモードパラメータ > runtime model_overrides_by_char > グローバル runtime_params > プリセット eng.modelParams
```

サブモード情報は beilu-memory の extension を通じてプリセットエンジンに渡され（`sub_mode_*` フィールド）、プリセットエンジンがそれに基づいてパラメータをマージします。

## P1 プリセット切り替えシグナル

記憶システムの P1 パイプラインは実行時にプリセット切り替えをトリガーできます。extension に `preset_switch_to` フィールドが出現すると、プリセットエンジンは以下の処理を行います：

1. TweakPrompt Round 1 でシグナルを検出します
2. 指定されたプリセットに切り替えます
3. 永続化して書き込みます（saveConfigToDisk）
4. 正規表現プリセットを同期します（`_resyncPresetRegex`）
5. 以降のターンで新しいプリセットを使用します

これにより、AI は対話内容に基づいてプリセットを自動切り替えできます（例：チャットプリセットからコードプリセットへ）。

## Bot モードのプリセット解決

Bot モードのプリセット解決には特別なロジックがあります：

- Bot の対話は `resolveBotModeFromRequest` 単一ソース関数でモードを解決します
- Bot のプリセットマッピングキーは `bot:キャラクター名` 形式を使用します
- Bot モードは chat バックエンドモードを共用しますが、プリセットバインディングは独立しています

## データの永続化

| データ | 保存場所 | 説明 |
|------|---------|------|
| mode_preset_bindings | 記憶システム _config.json | モードレベルバインディング |
| active_preset_map | プリセット config.json | 対話/キャラクターレベルバインディング |
| active_preset | プリセット config.json | グローバルデフォルトプリセット |

プリセットの config.json はユーザーごとに分離されており（`data/users/<user>/presets/config.json`）、各ユーザーが独立したプリセット設定を持ちます。

## クリーンアップ機構

対話を削除すると、システムが active_preset_map からその対話 ID に対応する残留キーを自動的にクリーンアップし、設定ファイルに孤立した条目が蓄積されるのを防ぎます。
