# 预设分类与选择

## 切换和筛选预设

### 按使用场景选

| 你想做的事 | 推荐分类 | 理由 |
|-----------|---------|------|
| 日常聊天 / 陪伴 | chat | 轻量级指令，自然对话 |
| 写代码 | code | 编程流水线角色、代码规范、工具使用指令 |
| 任务管理 / 文档 | work | 任务分解、格式要求、工作流水线角色 |
| 派分身干活 | clone | 分身角色预设（调查/改码/测试等） |
| Bot 平台会话 | bot | 平台交互规则、短消息风格 |
| 做 PPT | ppt | PPT 制作工作流 |
| 自定义场景 | 自建预设 | 完全按你的需求定制 |

### 按角色/对话独立设置

每个角色和每个对话窗口可以独立绑定预设。系统通过 **active_preset_map** 记录每个对话使用的预设，互不干扰：

- 和角色 A 聊天用预设 X
- 和角色 B 聊天用预设 Y
- 切换对话窗口时，预设自动恢复

## 管理预设

### 查看已安装预设

在预设管理面板中可以看到所有已安装的预设，按 bucket 分组显示。每个预设显示名称、描述和当前状态。

### 导入预设

支持导入 SillyTavern 格式的预设 JSON 文件。导入时系统会：

1. 解析预设 JSON，提取条目和参数
2. 注册到 registry.json
3. 如果携带 bucket 字段，归入对应分类
4. 如果携带 model_params，保存模型参数

### 导出预设

可以将当前预设导出为 SillyTavern 兼容的 JSON 文件，方便分享或备份。也可以通过[导入导出](beilu:settings/import-export)面板批量操作。导出包含全部条目、排序、参数和分类信息。

### 删除预设

删除内置预设实际上是标记为"已删除"（记录在 config.json 的 deleted_builtins 中），可以随时恢复。用户自建的预设删除后需要重新导入。

## 分类逻辑

always-accompany 通过 **bucket（分组桶）** 对预设进行分类管理。每个预设在注册时会标记所属 bucket，前端按 bucket 分组展示。

### 内置分类（7 大类）

| Bucket | 标签 | 说明 | 适用模式 |
|--------|------|------|---------|
| chat | 🎭聊天 | 日常对话 / 陪伴类预设 | Chat / AIRP 模式 |
| code | 💻编程 | 编程辅助类预设（含流水线角色） | Code / IDE 模式 |
| work | 📋工作 | 工作流类预设（含流水线角色） | Work 模式 |
| clone | 🤖分身 | 分身作业角色预设 | 派分身时 |
| bot | 📨Bot | Bot 平台会话预设 | Bot 平台接入 |
| ppt | 📊PPT | PPT 制作预设 | PPT 工作流 |
| p9 | 📚P9词库 | P9 词库维护子模式配套预设 | P1 词库维护 |

各分类下的具体预设清单和数量以预设管理面板实际显示为准（数量会随版本增减，这里不写死）。

### 二级子分类（路径式写法）

bucket 值支持 `一级/二级` 的路径式写法，在大类下再分小组：

- `code/流水线` — 编程流水线角色们
- `code/前端` — 前端美化专家
- `work/流水线` — 工作流水线里的角色
- `bot/通用`、`bot/办公` — Bot 下按用途细分
- `ppt/工作` — PPT 工作类

前端的分类页签、分组下拉都按一级分组，二级作为组内小节标题显示。二级组名是自由文本，想怎么细分就怎么细分（比如 `code/大型项目`、`code/小项目`），加新的二级不需要任何配置。

### 分类的来源（判定链）

前端给一个预设定分类时按这个顺序：

1. **你的自定义分类**（在界面上手动指定的，存在本地）——最优先
2. **registry.json 里的 bucket 字段**（预设注册表，分组的权威单源）
3. 旧版 tags 标记（历史兼容）
4. 预设名称关键词回退匹配
5. 都对不上 → 归入聊天

导入预设时如果 JSON 文件携带了 bucket 字段，会自动注册到对应分类。

## 预设选择的优先级

系统确定当前对话使用哪个预设时，按以下优先级（**没有全局默认这一级**）：

1. **对话+模式精确记录**：这个对话在这个模式下切过的预设（active_preset_map 的 `对话:模式` 精确键）
2. **对话级旧记录**：只按对话记录的预设（旧数据兼容，只读）
3. **子模式默认**（仅编程/工作模式）：当前生效子模式绑定的默认预设
4. **诚实空**：都没有 → 不注入预设，等你第一次切换时才建立记录

以前存在的"全局当前预设"回退已经移除：它曾经是个隐形污染源——导入/删除预设会改动它，导致所有没有自己记录的对话窗口在用预设一起变。现在每条线（每个对话每个模式）的状态完全独立。
