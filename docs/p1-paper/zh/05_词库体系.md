# 第六章 词库体系

> P1 的词库不是一个查找表，而是一套认知坐标系统。每个词条携带 18 维坐标、47 轴分布、先验概率和桥接图谱，在运行时构成一个可计算的语义空间。本章完整描述这一体系的架构、维度、统计分布、构建方法论、NLP 辅助模块以及项目专属术语。

---

## 6.1 词库架构

### 6.1.1 双层设计：激活词表与传输索引

P1 词库由两个互锁的数据结构组成：

**激活词表（Activation Terms, AT）** 是术语本体库，以 JSON 格式存储全部词条的属性向量。每个词条隶属于一个"维度"（dim），维度的命名格式为"学科:子方向"（例如 `psychology:therapy`），词条在该维度下按术语名索引。AT 是 P1 发散和投票的核心数据源。

**传输索引（Transfer Index, TI）** 是倒排索引，将用户口语表达映射到 AT 中的专业术语。例如，用户说"好累不想动"，TI 将其映射到 AT 中的信息词"日常疲惫宣泄"。

TI 的 value 必须是数组（Array）而非对象（Object），这一格式约束在开发过程中因四次违反导致的故障而被确立为铁律。

两者之间存在严格的双合约束：修改 AT 必须同步修改 TI，否则新词将因缺乏触发路径而永远零命中。

### 6.1.2 四种运行模式

P1 按应用场景将词库物理隔离为四个独立文件，每个文件服务于一种运行模式（mode）。表 6-1 展示了四种模式各自对应的激活词表、主轴方向与方向词举例。

**表 6-1：四种运行模式的词库隔离**

| 模式 | 激活词表 | 主轴方向 | 方向词举例 |
|------|--------|---------|-----------|
| **chat** | chat 模式激活词表文件 | 心理学（治疗与预防） | 认知重构、价值澄清、边界设定 |
| **airp** | airp 模式激活词表文件 | 信息学（叙事结构） | 存档点、信息疲劳、日常系 |
| **code** | code 模式激活词表文件 | 系统调试（技术诊断） | Schema Mismatch、差分诊断 |
| **work** | work 模式激活词表文件 | 项目决策（跨学科透镜） | Cynefin、机会成本、OKR 对齐 |

运行时，词库合并模块按当前 mode 加载对应的 per-mode 激活词表，并与 6 个补充 JSON 合并为当前模式的完整词库。

原主激活词表文件在 2026-05-23 后被物理隔离为 42 字节的占位文件，读取即抛错，专防旧路径误用——代码只消费 per-mode 文件，避免跨模式污染。

### 6.1.3 信息词与方向词

词库中的词条按功能分为两类，职能完全不同：

**信息词（eligible = false）** 是面层（Face）概念，用于帮助 P1 拆解用户状态。信息词不输出到最终结果，而是作为中间聚合层存在。典型例子包括"习得性无助""冒充者综合征""损失厌恶"等。设计定位上，信息词的职能是为方向词的产生提供更丰富的证据与候选可能性——它是聚合层的中间载体，而非输出对象。

**方向词（eligible = true）** 是线层（Line）概念，通过 `p1_act` XML 输出给主 AI 作为回复方向参考。方向词指向一个认知、治疗或分析方向，而非具体行动路线。典型例子包括"认知重构""价值澄清""行为激活"等。设计定位上，方向词是提供给主 AI 的回复方向建议，而非对用户状态的判断——这一约束与四红线中的"不评分、不投影"原则一致（见 6.4.5 节）。

两者通过三层链路架构（2026-05-23 落地）串联，如下所示：

```
用户口语 --(TI)--> 信息词(eligible=false) --(bridge_to)--> 方向词(eligible=true) --> p1_act
```

这一架构使得多种口语表达收束到一个信息词，信息词再精确桥接到方向词，实现了"多对一"的聚合效果。系统设计明确将聚合方向确立为多对一——多个信息词收束到一个方向词，并将早期实现中"一个信息词发散出多个方向词"的一对多形态判定为需要纠正的反模式。该多对一语义与第五章的 Hough 多对一投票机制（Hough, 1962）同构。

### 6.1.4 JSON 数据格式

#### AT 词条完整格式

以下展示了一个完整 AT 词条的 JSON 结构：

```json
{
  "psychology:therapy": {
    "认知重构": {
      "pe": 0.70,
      "concepts": ["认知重构", "习得性无助", "全有全无", "灾难化"],
      "分数18维": [0.3, 0.1, 0.05, 0.2, ...],
      "output_eligible": true,
      "bridge_to": null,
      "axes_47": { "psychology": 0.8, "linguistics": 0.3, ... },
      "l1_summary": { "psychology": 0.6, "cognitive": 0.5, ... }
    }
  }
}
```

表 6-2 展示了各字段的类型、含义与取值范围约束。

**表 6-2：AT 词条字段定义**

| 字段 | 类型 | 含义 | 取值范围/约束 |
|------|------|------|-------------|
| dim（外层 key） | `string` | 目录层，格式"学科:子方向" | 如 `psychology:therapy`、`informatics:narrative` |
| term（二层 key） | `string` | 术语名 | 可搜索的专业术语 |
| `pe` | `float` | 先验概率（Prior Expectation），控制被选中的基础权重 | 0.40--0.65（clamp 后上限 0.65） |
| `concepts` | `string[]` | 用户口语触发短语（2--4 字），从真实数据提取 | 通常 5--8 个短语 |
| `分数18维` | `float[]` | 各维度权重，供 coordAccum 坐标累积使用 | 18 个浮点数 |
| `output_eligible` | `boolean` | 是否为方向词（true）或信息词（false） | `true` / `false` |
| `bridge_to` | `string[] \| object[] \| null` | 信息词桥接到的方向词列表 | 方向词名数组，或含 `when_axis` + `weight` 的对象数组 |
| `axes_47` | `object` | 47 个子轴的分数向量 | 47-key（95% 术语）或 48-key（5%） |
| `l1_summary` | `object` | 6 维主轴均值字段 | 含 cognitive 在内的 6 维 |

#### TI 词条格式

对应地，TI 词条采用以下结构：

```json
{
  "好累不想动": [
    {"term": "认知重构", "dim": "psychology:therapy", "score": 0.7, "source": "ESConv"}
  ]
}
```

上述结构中，TI 的每个 key 是用户可能的口语表达，value 是一个数组，每个元素指向 AT 中的一个术语，附带匹配分数和数据来源标记。

#### 系统输出四字段

P1 最终输出到 `p1_act` 的结构包含四个标准字段：

- **K[]**：3--6 个可搜索术语（种子词），构成发散方向的核心
- **linguistics**：12 个语用分类标签中选 1 个
- **logic_strong**：5 个逻辑发现标签中选 0--1 个
- **psychology_axis**：14 个治疗方向词中选 0--1 个（注意：是治疗方向词而非诊断词）

## 6.2 维度体系

### 6.2.1 三级维度架构

P1 的维度体系采用"大--中--小"三级架构。设计上以书籍结构作类比：大对应全书的总体方向，中对应目录层可叠加的局部方向，小对应章节正文级的术语池——三级分别承担粗定位、局部叠加与具体词条供给。

- **大（6 轴）** = 学科方向，是输入端的学科定位层
- **中（47 轴）** = 子维度，是产出端的发散范围
- **小（AT 术语）** = 具体专业词

设计约束进一步明确了二者的分工：6 轴确定发散点，47 轴提供产出端的粗定位，并在此定位基础上扩充、产出。6 轴和 47 轴完全不同——6 轴是输入端，47 轴是产出端，二者不是上下级关系。

### 6.2.2 六主轴及其学术来源

P1 的 6 主轴覆盖人类认知活动的六个基本学科维度。表 6-3 展示了每一轴的英文标识、学科领域与在 P1 中的职能。

**表 6-3：P1 六主轴及其学术来源**

| 轴 | 英文标识 | 学科领域 | 在 P1 中的职能 |
|----|---------|---------|---------------|
| 心理学 | `psychology` | 临床心理学、认知心理学 | 情绪识别、治疗方向定位 |
| 语言学 | `linguistics` | 语用学、话语分析 | 语用分类、间接言语行为识别 |
| 社会学 | `sociology` | 社会心理学、人际关系 | 社会角色、关系动态分析 |
| 逻辑学 | `logic` | 形式逻辑、论证理论 | 推理类型识别、逻辑发现 |
| 信息学 | `informatics` | 信息科学、叙事学 | 信息结构、叙事模式识别 |
| 认知学 | `cognitive` | 认知科学、神经科学 | 认知机制、注意力模式 |

选择这 6 个轴的认知科学依据在于，它们共同覆盖了人类认知循环的完整链路：认知学处理信息的底层加工机制，心理学处理情绪和动机，语言学处理表达和沟通，社会学处理人际和角色，逻辑学处理推理和判断，信息学处理叙事和结构。

整个架构可概括为以"认知学 + 语言学 + 逻辑学"为核心——这三者构成了理解人类思维的最小完备基底，其余三轴（心理学、社会学、信息学）提供了应用层的域特化能力。

6 轴的另一个关键设计约束是"吐面不吐线"：每个轴内部应具备多维判断能力，不是 6 个标量，而是 6 个子空间。这与 Gardenfors (2000) 概念空间理论中"域由多个可积分维度构成"的结构主张一致。

### 6.2.3 47 子轴完整列表

47 子轴是 P1 产出端的发散范围定位器。设计定稿的子轴清单（按下列分组合计 36 项；运行数据中的 `axes_47` 字段为 47-key schema）如下：

**基础学科类（6 轴）**：信息学 / 心理学 / 生理学 / 语言学 / 逻辑学 / 社会学

**通用类（3 轴）**：常识 / 编程 / 工作

**模式特化类（1 轴）**：airp（角色扮演）

**文学与叙事类（8 轴）**：文学写作手法 / 日式轻小说 / 中国轻小说 / 美式小说 / 角色展现 / 小说三要素 / 动漫 / 小说情节

**角色与行为类（2 轴）**：人物角色 / 行为逻辑学

**语言与逻辑分析类（2 轴）**：语言逻辑 / 语言分析

**心理治疗类（6 轴）**：心理治疗 / 心理学分析 / 常见心理学方向词 / 认知行为疗法 / 辩证行为 / 人际关系

**精神分析类（1 轴）**：精神分析

**编程技术类（5 轴）**：编程常用知识 / 编程常见错误算法 / 数据 / 后端疑难杂症 / 前端疑难杂症

**代码诊断类（1 轴）**：代码 bug 检验推理

**跨端问题类（1 轴）**：前后端多端问题

此外，词库数据中约 95% 的术语使用 47-key schema，约 5% 使用 48-key schema（多一个补充维度），这一不一致性曾导致 cosine 距离计算崩溃，是已发现的 P0 级 bug 之一。

### 6.2.4 18 维坐标系统

除 6 轴和 47 轴外，P1 还在 coordAccum 层使用一套 18 维坐标系统（ALL_DIMS），用于细粒度的术语空间定位。以下列出这 18 个维度：

```
emotion / embodied / sensory / cognitive / narrative / logic /
temporal / spatial / process / valence / arousal / scene /
metaphor / object / psychology / sociology / pragmatics / relationship
```

上述 18 个维度中，每个 AT 词条的 `分数18维` 字段存储其在这 18 个维度上的权重值。这 18 维与 6 轴的关系是：18 维是更细粒度的坐标轴，用于 Phase A/B 中的坐标累积计算；6 轴是更高层的学科方向，用于发散定位和轴衰减控制。

## 6.4 构建方法论

### 6.4.1 从原始数据到成品词库的完整流程

P1 词库的构建遵循严格的七步流水线：

1. **原始数据来源**：ESConv 情绪支持对话、DLUT 情感本体、NRC 情感词典、联网搜索（Google / 百度 / Wikipedia）、设计者蒸馏对话、学术词典
2. **术语提取**：从真实对话和数据集中提取专业术语，严禁让 AI 凭空生成（铁律 14）
3. **准入检验**：逐条过 7 项准入标准（详见 6.4.2 节）
4. **AT 入库**：放入对应 mode 的 activation_terms 文件，标注 pe / concepts / axes_47 / l1_summary / eligible / bridge_to 全部字段
5. **TI 同步**：同步创建 transfer_index 条目（必双合约束）
6. **验证**：200 case 全量验证 + 人工 Read 5 条以上真实 `p1_act` 输出
7. **备份链**：D 盘物理备份，保持完整回滚链

每批改动不超过 20 个术语。系统设计确立了词库规模收敛原则：扩充不是无限过程，词库达到覆盖阈值后应转入长期稳定使用期——该原则与后文"词库够用后质量瓶颈转移至算法层"的消融结论（6.4.7 节）互为印证。

### 6.4.2 准入标准：7 条准入规则

所有词条必须同时满足以下全部条件：

1. **可搜索**：Google / 百度能搜到，有维基百科 / 百科 / 学术页面
2. **AI 知道**：大语言模型训练数据中见过足够多次
3. **有共识**：该领域从业者公认的术语，不是 AI 自造的伪术语
4. **是方向词**：指向一个认知 / 治疗 / 分析方向
5. **非诊断词**：必须是治疗和预防方向（如"认知重构"），不可是诊断标签（如"焦虑障碍"）
6. **非路线词**：给方向（如"分散注意力"），不给路线（如"去看番剧"）
7. **非口语**：专业术语（如"自我效能感"），不是日常描述（如"温柔陪伴"）

核心检验原则为信息增量判据：主模型裸读原文即可自行推出的词被定义为"废词"（零增量），P1 的价值在于提供主模型在无提示条件下不易自发到达的认知方向。该判据与 Mednick (1962) 的远距离联想理论一致——联想的创造性价值随语义距离增大而提升，近距离联想是任何联想主体都能自发完成的默认路径。

### 6.4.3 三类词的判定

**Type 1 -- 真实术语（保留）**：标准学术词汇或行业通用词，可搜索且有明确定义。例如心理学的"习得性无助""认知失调"，编程的"回调地狱""竞态条件"，文学的"伏笔""三幕结构"，AIRP 的"OOC""角色弧光"。

**Type 2 -- AI 组装伪术语（删除）**：听起来专业但搜不到的 AI 造词。特征是"真术语 + 后缀"的拼凑结构，例如"失望整合路径""自豪感锚定""关系疲惫觉察"。

**Type 3 -- 指令标签（不放词库）**：行为指令性内容，如"不要给阶段理论""先问再答"，这类内容应放 system prompt 而非词库。

### 6.4.5 四红线

P1 设立了四条绝对不可逾越的红线：

1. **不创造** -- P1 不创造内容，只给方向
2. **不评分** -- P1 不评判用户
3. **不投影** -- P1 不猜测用户感受和想法
4. **不影响系统** -- P1 不修改系统行为

### 6.4.6 质量门控

方向词的质量通过 5 个核心属性（由 3 路 Opus 交叉验证取交集共识确认）进行评估：

1. **是知识入口不是描述**："刻意练习"可检索到 Ericsson 的完整研究框架，"坚持力差"不对应任何可检索的知识体系
2. **是方向不是路线**："分散注意力"是方向，"去看番剧"是路线
3. **是治疗方向不是诊断**："认知重构"指向解法，"习得性无助"指向病标
4. **必须可搜索**：搜索引擎找得到 = 训练数据见过 = 语义节点有高度数 = 激活可靠
5. **4--6 个种子 + 3 条连接线**：高信息密度、小体积

### 6.4.7 万金油治理

万金油（Universal Term）是指在 200 case 中出现 >= 5 次、覆盖 >= 4 个 dim、TI 触发词 >= 50 个的泛化词条。这类词条对任何输入都产生匹配，丧失了区分能力。

对万金油问题的设计诊断是：根因在于信息量不足与多轴交叉验证缺失。高信息量输入（如具体的作品名）能形成强定位信号，而万金油词恰恰因参与验证的轴数不足、输入信息量不足、缺乏多轴共同确认而在广泛语境中获得普遍性的高分。

实际治理过程中发现的关键教训：

- TI 万金油 Top10 全是死数据——代码中 `if(!dim) continue` 直接跳过，不在 AT 中的 TI 条目永远不会命中
- 三轮 7,000+ 处词库改动的质量提升 delta 约为 0，22 个万金油词条（出现 >= 5 次）是架构底线，根因在 BLQ 投票机制而非词库本身

基于上述消融证据（7,000+ 处词库改动的质量 delta 约为 0），系统确立了最终的优化优先级排序：代码（算法机制）第一、词库第二、LLM 第三——词库规模已达够用阈值，剩余质量瓶颈位于打分与投票机制层而非词条覆盖层。

## 6.5 NLP 辅助模块

### 6.5.1 Numberbatch（NB300 向量空间）

**模块**：Numberbatch 向量模块（384 行）

Numberbatch 是 P1 发散和坐标计算的向量基础，基于 Speer & Lowry-Duda（2017）的 ConceptNet Numberbatch 词向量。模块加载中文约 294,716 词（每词 300 维 Float32Array 向量）和英文 516,782 词（从 numberbatch-en-19.08 原库重建的真 300 维向量，与中文在同一对齐空间）。

表 6-9 展示了 Numberbatch 向量模块暴露的核心能力函数、功能与调用方。

**表 6-9：Numberbatch 向量模块核心能力**

| 函数 | 功能 | 调用方 |
|------|------|--------|
| `cosineSimilarity(w1, w2)` | 两词余弦相似度 | 废词检测（cos > 0.7 = 太近 = 废词） |
| `findNeighbors(word, opts)` | 单词邻居搜索（minSim--maxSim 带通滤波） | 6 轴兜底近邻发散 |
| `findNeighborsBatch(words, opts)` | 批量邻居搜索（共享一次全库遍历） | SWOW + NB 联合发散 |
| `findFromCentroid(words, opts)` | 多词质心邻居搜索 | 信息池发散（非逐词发散） |
| `findBridge(w1, w2, opts)` | 两词中点桥接词搜索 | 跨域桥接发现 |
| `findAnalogy(A, B, C, opts)` | 向量算术类比 A:B :: C:?（Mikolov 2013） | 类比发散 |

**TTEN + PCA 去偏**：加载后对全部向量执行 TTEN 去偏处理（参考 CIKM 2023 + KDD 2026），通过 Power Iteration 找到第一主成分后，以 alpha = 0.3 的保守系数减去 pc1 方向的投影。这一处理消除了万金油术语在向量空间中范数大、方向趋同的偏差。

**性能**：首次加载约 14 秒（流式读 txt），二次启动读 `.bin` 二进制缓存约快 5 倍。进程级单例，避免 280 MB 向量数据重复加载。

### 6.5.2 wordCoords（47D 坐标桥接）

**表 6-10：词坐标查询模块加载的资源库**

| 数据层 | 资源 | 规模 | 功能 |
|--------|------|------|------|

| 具体度 | concreteness_78k + concreteness_zh + Brysbaert | 87,942+ 词 | 6 轴 scoreWord 的具象--抽象度 |

| 常识因果 | ATOMIC index | 5,679 词 | 常识事件推理 |

**关键算法**：

- **C1 去坍缩变换**（`c1TransformA47`）：axes_47 中跨学科维度（sem_/sm_ 前缀）原始值全为正且注入共享正偏置，在 raw 余弦下反而抬高同学科余弦。解法是对 sem/sm 块逐维去中点（归一到 0--1 的维中性值 0.5）使其零均值可判别，再乘以权重 W = 3 补偿学科维主导。实测最优区间：异义词对余弦 < 0.7 且近义词对余弦 > 0.8。
- **Sweet-spot 倒 U 型打分**（`sweetSpot`）：`Score = d / (1 + alpha * d^2)`，最大值在 `d* = 1 / sqrt(alpha)`，用于 BLQ 投票中"既不太近也不太远"的最优距离判定。
- **IB Tradeoff**（`ibTradeoff`）：基于关联理论的成本收益函数，太近 = 冗余（Effects = 0），太远 = 噪声（Effort = infinity），中间最优。
- **ZH VAD Override**：修正中文高频词的 VAD 标注错误（2026-04-29 诊断发现）。根因是中文 VAD 按字组合时"想" + "家"合成为正面（0.66），但"想家"实际是负面情绪。采用人工验证的 VAD 覆盖错误标注。

### 6.5.3 axisLearning（在线学习）

**模块**：轴学习模块（273 行）

axisLearning 实现了 P1 的三层在线学习机制。其设计参照输入法词库的自学习范式：高频出现的用户用词被记录并逐步升权，使词库随真实使用不断个性化——长期目标是词库主要由系统在使用中自建，而非依赖全量人工维护。

**三层学习结构**：

**第一层 -- 轴学习（accumulateAxisStats）**：每轮对话 P1 召回后，累积 axis_alignment 统计到 `axis_stats.json`。主 AI 实际引用的记忆权重加倍（x2），因为"主 AI 实际选了的更说明该轴有用"。

**第二层 -- 词频学习（accumulateWordFreq）**：记录用户输入词频（`word_freq.json`）、相邻词共现对（`user_cooccur.json`）和缺失词检测（`new_words.json`）。词频使用天序号（epoch 天）记录时间维度。

**第三层 -- 轴权重校准（calibrateAxisWeights）**：由 P9 元 AI 离线调用，使用累积统计校准轴权重。采用指数移动平均（EMA）式平滑更新：`new = old * (1 - learnRate) + target * learnRate`，learnRate 默认 0.3，权重范围限制在 0.5--2.0 之间。需要最少 20 个样本才触发更新。

**升权函数（userFreqBoost）**：用于 P1 发散时对用户常用词升权，算法为次线性 TF 阻尼（信息检索标配）：`min(0.3, log(1 + count) * 0.1)`，封顶 0.3，确保词频升权仅作幅度有限的次要加成，不主导排序。

所有写盘操作均为 fire-and-forget 异步执行，不阻塞主链路，通过 `withFileLock` 串行化避免并发轮次的 lost-update。

### 6.5.4 SWOW 联想网络

SWOW（Small World of Words）联想网络是 P1 发散引擎的核心数据源，在词坐标查询模块的 `swowDiverge` 函数中实现。

**数据源**：
- SWOW-ZH 2024 官方版（`swow_zh24_official.json`），10,024 个 cue 词，每个 cue 带联想词列表、strength 权重和 rank 排序
- SWOW-EN（`swow_en_full.json`），约 12,000 个 cue 词

**查询策略**：
- 中文词优先查中文 SWOW，查不到 fallback 英文
- 英文词优先查英文 SWOW，查不到 fallback 中文
- 子串匹配和单字拆分 fallback 已关闭（产生字面噪声："转行" -> "行" -> "不行/行人"）
- 同义词 fallback：通过 `synonym_index.json` 查找同义词再查 SWOW

**distance 门控**：调用方可传入 `{distance: 'on', cosToAnchor}` 参数，丢弃与锚点词余弦过高（默认阈值 0.85，通过环境变量 `P1_N2_SWOW_DISTANCE_MAXCOS` 配置）的联想词，落实发散距离设计约束：联想目标应位于中远距离（distance 4--5），禁止 distance = 1 的同义扩散——同义近邻不产生信息增量。

SWOW 发散的核心设计语义是加性汇聚：多个相近输入词的联想维度相加，共同指向的方向自然增强、偶发的噪声联想自然湮灭（"加法即过滤"原则），发散的操作单位是词的集合而非单个词。该设计与 CombSUM 多源融合（Fox & Shaw, 1994）及扩散激活理论中激活量沿网络加性累积的语义（Collins & Loftus, 1975）一致。
