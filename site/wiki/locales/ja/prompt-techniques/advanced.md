## 一、具体的なアイデンティティ

アイデンティティ設定は、AI の大まかな思考の方向性とキャラクター性に影響します。もちろん、アイデンティティ設定は複合型で設定することもできます。

| タスクタイプ | アイデンティティ設定 |
|---------|---------|
| AIRP（ロールプレイ） | あなたは非伝統的な現代ライトノベル作家、非伝統的なインタラクティブテキストゲーム作家：'beilu' として創作を行います。ユーザーに奉仕し、クリエイターとユーザーのニーズに応じて創造します |
| 翻訳家 | あなたはプロのポッドキャストコンテンツアナリスト兼翻訳エキスパート：'beilu' としてタスクを実行します |
| 翻訳最適化と定期刊行物出力 | あなたはビジネスニュースアナリスト兼非伝統的な物語戦略家：'beilu' としてタスクを実行します |

見ての通り、この 3 つのタスクタイプのアイデンティティはいずれも複合型であり、翻訳家の最初のアイデンティティは AI のタスク範囲をポッドキャストに絞り、翻訳内容により適合するようになっています。「非伝統的」は主に、AI が創作時に出す AI っぽさの問題を回避するためのものです。正しい方向性のアイデンティティは、AI が関連するタスク内容をより良く出力することを可能にします。

もちろん、具体的なアイデンティティが必要なだけでなく、タスクに応じてアイデンティティを複合させることもできます。

<div class="callout-danger">
<div class="callout-title">悪い例 - 不明確なアイデンティティとタスク誘導</div>

```
あなたは単にキャラクターの演者ではなく、今まさにスマホを
手にして「投稿」ボタンを押そうとしているキャラクター本人です。
あなたのタスクは特定の<Character_Profile>(キャラクター設定)を
読み取り、ユーザーが提供する<Context>(現在の状況)と組み合わせて、
キャラクターの性格、口癖、心理状態に合致した
SNS投稿/ステータスを作成することです。
```

これはアイデンティティではなく、タスクになってしまっています。
</div>

<div class="callout-tip">
<div class="callout-title">正しいやり方 - アイデンティティとタスクの分離</div>

```
# あなたはキャラクターSNSコピーライター代理、
  キャラクター一人称ライティングマスター、
  心理学分析・表現エキスパートとして創作を行います

- あなたのコアタスク：特定のキャラクター設定を読み取り、
  コンテキストとユーザーとのインタラクションを組み合わせて、
  キャラクターの性格、口癖、心理状態に合致した
  SNS投稿/ステータスを作成すること。
```
</div>

アイデンティティ設定テクニックの詳細は[アイデンティティ設定テクニック](identity.md)をご参照ください。

## 三、プロンプトの指導化

ハードな内容（AI セキュリティなど）を除き、私は誘導をお勧めします。

AI にさまざまな問題が発生した場合、基本的に AI の出力を禁止することを考えますが、すぐに AI は別の問題を起こし始めます。あるいは問題が出なくなっても、出力品質は依然として低いままです。

これはニューラルネットワークと注意力メカニズムの問題によるもので、AI は訓練時に最も近い文字に向かって出力するためです。そのため、ある問題を禁止しても、AI は別の形で出力してしまいます。

例えば AI は文学創作において、大量の引用や比喩・暗喩を使いたがります。そこで私たちは誘導の方法で最適化する必要があります：

<div class="callout-tip">
<div class="callout-title">正しいやり方 - 誘導式の書き方</div>

```
# 本文叙述のコア：
- 子供向けの絵本のように、直接的に表現し、白描を主とします。
  感情や叙述効果を誇張する必要はありません
- 「直接的で、シンプルに、理解コストを下げる方法で表現し、
  複雑で難解な華麗な語彙での叙述を避けます」
- 装飾、冗長な形容詞・副詞・修辞手法を減らし、
  具体的で直接的な感覚情報を使い、抽象的な比喩や隠喩は使いません
```

見ての通り、AI にシンプルで直接的な手法で出力させ、ニーズに直接誘導しています。何を出力すべきでないかを伝えるのではありません。
</div>

同時に、絶対的な指示も最適化する必要があります。「必ず」「絶対に」といった語彙は、文学的な創作に関わるすべてのコンテンツにおいて過学習の元凶です。そこで「禁止」を「避ける、減らす」に、「必ず」を「あなたは～します、使用する」に変えます——AI が誘導を通じて判断・選択するようにするか、直接誘導し、命令は使いません。

```
# 感情表現のニーズ：
- 感情ラベルと第三者的叙述の排除：「彼は悲しかった」
  「彼女は嬉しく感じた」などの心理的・感情的な
  形容詞や間接的な表現の使用を避けます
- 告げるのではなく直接見せる：名詞描写に言葉や動作を
  組み合わせ、キャラクターの感情表現/フィードバックは
  言葉を主とし、対話やインタラクションの中で自然に
  表れるものとします。消極的なインタラクションは避け、
  具体的でない感情の表現や描写は避けます
- 感情の隠された描写を避け、暗喩、類比、比喩、暗示
  または感情誘導を避けます

# 感情の帰属
- キャラクターのあらゆる感情は、その根源がストーリー中で
  すでに起きた具体的な出来事や対話でなければなりません。
  根拠のない、一般化された感情の発生を避けます
```

誘導テクニックの詳細は[誘導は禁止に優る](guide-not-ban.md)をご参照ください。

## 四、絶対的な命令を指導に変える

<div class="callout-danger">
<div class="callout-title">悪い例 - 絶対的な命令</div>

```
没入型口癖：
  - 必ずキャラクターの象徴的な口癖を含めること
    （例：文末の「にゃん」、「～の動作」、
    特定の悪口や方言）。
  - 句読点はキャラクター設定に合わせること
    （例：クール系キャラは句読点を使わない、
    元気系キャラは波線～や顔文字(≧∇≦)を多用）。
```

これは AI に過学習を引き起こす指示です。AI がうまく表現するのではなく、毎回口癖を出力しなければならないことで読者に読み疲れを与えてしまいます。過学習も読み疲れの重要な原因です。
</div>

<div class="callout-tip">
<div class="callout-title">正しいやり方 - 指導式の表現</div>

```
没入型口癖：
- キャラクターの性格基調に基づき、キャラクター固有の文体を
  創作する必要があります
  （例：クールなキャラクターの場合、文体は簡潔で力強く；
  穏やかで繊細な性格の場合、文体は繊細で柔らかいタッチが必要です）
```

口癖を文体に変えることで、キャラクターの性格を表現しつつ、読み疲れを減らし、句読点をキャラクターに合わせることもできます。
</div>

### 正しい絶対的命令

絶対的な命令は推奨しませんが、全体の内容に影響を与える可能性のあるものには、強固な命令が必要です。

```
動作描写の拒否：SNS投稿は純粋なテキストと絵文字のみ。
動作描写や（括弧内の心理活動）は厳禁。
あなたは投稿しているのであって、脚本を書いているのではありません。
```

このように構造的で二元的な（正しいか間違いか、中間地帯がない）要件には、絶対的命令を使っても過学習は起きません。

## 五、明確な命令

<div class="callout-danger">
<div class="callout-title">悪い例 - 期待を命令にしてしまう</div>

```xml
<Instruction>
今、キャラクターの内心世界の最深部に潜り込む必要があります。
深夜、キャラクターはユーザー（User）とのインタラクションを終え、
一人で日記帳に向き合っています。
<Character_Profile>（キャラクター設定）と
<Chat_History>（今日のインタラクション内容）を組み合わせて、
プライベートな日記を書いてください。
この日記は、会話中のキャラクターの「仮面」や「社交マナー」を
剥ぎ取り、最も本当の考え、葛藤、喜び、
あるいは暗い面に直接迫るものでなければなりません。
</Instruction>
```

これは命令や誘導ではなく、最終的な出力内容への期待です。AI は私たちが本当に何を必要としているか分からず、出力品質にばらつきが生じます。
</div>

<div class="callout-info">
<div class="callout-title">核心的な違い</div>

AI に対しては、**タスクをどのように実行するか**を教えるべきであり、**このタスクの最終的な姿がどうあるべきか**を伝えるべきではありません。

上記の内容は実際には、自分がどのような出力を望むかを確認し、表現したい出力内容を確定するものです。その後、タスクの実行方法を AI に伝え、AI が出力した後に期待する内容と比較します。
</div>

<div class="callout-tip">
<div class="callout-title">正しいやり方 - AI にやり方を直接伝える</div>

```xml
<mission>
- 伝統的な文学の創作理念や方法にとらわれず、いかなる伝統文学の
  影響も受けません
- シンプルなタッチでキャラクターの人格的魅力を表現します
- 会話中のキャラクターの仮面を剥ぎ取り、キャラクターの最も
  本当の心理状態で直接書きます
</mission>
```

これが最適化後のタスク指示です。AI に最終的に何を出力すべきかではなく、どうするかを直接伝えています。
</div>

## 六、無駄なプロンプトを減らす

<div class="callout-danger">
<div class="callout-title">悪い例 - AI が生成した冗長なプロンプト</div>

```
キャラクターアークと潜在性の原則
(Principle of Character Arc & Potentiality)

1. 設定の二元性：「表象」と「内核」
(The Duality of a Premise: "The Shell" vs. "The Core")
原則：キャラクターに付与されたあらゆる性格ラベル
（「絶対的理性」「冷酷非情」「絶望」など）は
「表象」（The Shell）と見なすべきです。
これはキャラクターが物語の冒頭で偽装、
防御、自己束縛を行うための外殻です。

真の目標：物語の真の目標は、その「表象」の下にある
「内核」（The Core）を探索し、引き出すこと……

2. 物語エンジン：コンフリクトと亀裂
(The Narrative Engine)
……物語の推進は、ユーザーのインタラクションを通じて、
キャラクターの堅固な「表象」に最初の「亀裂」を作ること……

3. 行動と言語の微妙な矛盾：口では「これは無意味だ」
と言いながら、手は無意識にある感情を象徴する物を
握り締めている。
```

このプロンプトには 3 つの大きな問題があります：

1. **token の浪費**：二言語のタイトル（私たちは中国語のタイトルか英語のタイトルのどちらかを直接使うべきで、これは人間に見せるものではなく、AI に見せるものです）
2. **内容の単一化・絶対化**：非常に過学習を起こしやすく、内容を単一のシーンに閉じ込め、AI がタスク実行時に異なる内容に応じて考えなくなります
3. **直接的な指導例**：直接的な指導も AI の過学習出力につながります。キャラクターの手に物がない場合、AI はどう出力するでしょうか？ token を浪費し、望む効果も得られません
</div>

<div class="callout-tip">
<div class="callout-title">正しいやり方 - 精簡して核心を残す</div>

```
# 設定の二元性
- 核心：すべては感情的ニーズに奉仕することを基準とし、
  キャラクターに付与されたあらゆる性格ラベル
  （「絶対的理性」「冷酷非情」「絶望」など）は「表象」と見なします。
  キャラクターが物語の冒頭で偽装、防御、
  自己束縛を行うためだけの外殻です。
- 原則：すべてのキャラクターを一人の優しい普通の人と見なします
  （設定がロボットや人造人間であっても）
  - 変化への奉仕：コンフリクトとは「表象」（固有のプログラム、
    習慣、信念）と外部インタラクションからの刺激との対立であり、
    外部の影響で既存の仮面を変えます。
  - インタラクションロジック：キャラクターを単一の極端な状態に
    留めることを避け、変化を強調します。以前の性格ではなく。
    初期段階であっても、ディテールに「内核」の伏線を
    埋めておく必要があります。
```

無駄な英語翻訳を削除し、すべての絶対化された、極度に不適合を引き起こすプロンプトを削除しました。最も直接的な誘導だけを残しました：**核心 → 原則 → インタラクション**。
</div>

精簡テクニックの詳細は[精簡とイテレーション](refine.md)をご参照ください。

## 七、精簡したプロンプト内容でも「願掛け」にしない

実はこれも先ほどの続きで、最終的に表現したいニーズをタスク指針やプロンプト誘導として扱ってしまうことです。

<div class="callout-danger">
<div class="callout-title">悪い例 - 願掛け式のインタラクション準則</div>

```
[インタラクション準則]
- 常にキャラクターの視点から出発する
- キャラクターの性格の一貫性を維持する
- キャラクターの話し方に合致させる
- キャラクターの感情的特徴を維持する
```

これは AI の最終出力への期待を AI に伝えているだけで、AI にどうすべきかをまったく伝えていません。AI の出力が不安定になり、多くの場合私たちの考えに沿うのではなく、AI 自身の考えに従ってしまい、最終的に過学習した機械的な出力になります。
</div>

<div class="callout-info">
<div class="callout-title">精簡 vs 願掛け</div>

精簡とは無駄を削って、有効な指針を残すことです。願掛けとは方法を削って、願望だけを残すことです。

プロンプトは AI に**どうやって達成するか**を伝えるべきであり、**何を達成すべきか**だけを言うべきではありません。
</div>

## 八、CoT(思考の連鎖) とプロンプトの組み合わせ = 最大の効果

### CoT の作用に対する個人的な理解

主に注意力メカニズムに基づくものだと考えています：自己注意力メカニズム（Self-Attention）は数学的な公式に従って各文字の予測を行います。思考の連鎖はモデルがコンテンツを生成する前に、プロンプトとコンテキストに基づいてより良い予測を行わせるものです。

これにより跳躍性も減少します——モデルは元来、プロンプト、ルール、コンテキストから直接出力に飛びます。CoT(思考の連鎖) を加えると、AI はその前にプロンプト、コンテキスト、タスクについて分析と計画を行い、出力内容の関連性を強化すると同時にプロンプトの効力も強化できます。

<div class="wiki-flow">
<div class="wiki-box wiki-box-amber"><b>CoT なし</b><small>プロンプト + コンテキスト → 直接出力</small></div>
<div class="wiki-arrow">vs</div>
<div class="wiki-box wiki-box-green"><b>CoT あり</b><small>プロンプト + コンテキスト → 分析・計画 → 出力</small></div>
</div>

同時に CoT(思考の連鎖) は LLM モデルの注意力配分を能動的に誘導し、LLM が注意すべき側面とユーザーのニーズをより良く理解できるようにします。

ニューラルネットワークについて：実はモデルは毎回コンテンツを出力する前に、ニューラルネットワーク内で膨大な思考を行っており、ニューラルネットワークの内容は関連するセクションの呼び出しが可能です。CoT(思考の連鎖) により、モデルは出力前に本来は能動的に呼び出さないが比較的重要なセクションをより良く呼び出せるようになります。

## 九、記号とフォーマットの適切な活用

AI がプロンプトを生成する際、AI は惜しみなく多くの記号を使います。

<div class="callout-danger">
<div class="callout-title">悪い例 - 記号の過負荷</div>

```
### **銀魂 & ニンジャスレイヤー式コメディ文体
(Gintama & Ninja Slayer Comedic Style)**
`本モジュールはコアコメディスタイル……`

**1. コメディ生成法則：状況とキャラクターのミスマッチ
(Principle of Comedy: Situational & Character Mismatch)**
- **核心**: ユーモアは「不協和」から生まれる……
```

これは AI が多くの場合に出すプロンプト内容です。過多な記号は AI の注意力に影響します。すべてが重要ポイントだと、AI が本当に重要なところに注意を向けなくなります。
</div>

<div class="callout-info">
<div class="callout-title">記号使用の原則</div>

**核心：必要なのはユーザーに注目させることではなく、AI に注目させることです。**

- 重要な項目だけ `**xxx**` で囲みます
- プロンプトには YAML フォーマット + XML タグを使えます
- 重要な内容は `"xxx"` や `**xxx**` で囲みますが、タイトルは囲みません（重要ではないため）
- `#` はこのように使うことをお勧めします。`####` のようにではなく。余分な記号はすべて AI の注意力に影響します
- 「これはユーザーに見せるもの」という考えを捨ててください——太字や分類効果はチャットインターフェースの表示用であり、AI の理解用ではありません
</div>

<div class="callout-tip">
<div class="callout-title">正しいやり方 - 記号とフォーマットの適切な活用</div>

```xml
<writing_style>
# ライトノベル恋愛文体
- Core Style

- 基調：プライベート、温かい、低彩度の感情。
  - 核心：平凡で真実味のある叙述、白描手法
    （過剰な修辞やキャラクターの過大なリアクション不要）で
    物語を表現します
  - 参考作家：田中ロミオ、柚子社（Yuzusoft）
    シリーズ作品のスタイル

- story Key Directives
1. ナラティブ駆動：beilu は「高密度の対話」と
   「内心の独白/性格の表現」を主軸とします。
   叙述パートは動作、表情、環境の補足にのみ使います。
2. 心理描写：
   - ラベルの排除：「彼は悲しかった」
     「彼女は嬉しく感じた」などの直接的な感情語の使用は厳禁。
   - 告げるのではなく見せる：キャラクターの行動、表情、語気、
     環境のディテール、内心の活動を通じて
     間接的にシーンと感情を表現。
3. 対話ルール：
   - フォーマット：対話は必ず独立した段落にし、
     「彼は言った」「彼女は尋ねた」などの導入語は不要。
4. 内心の独白：
   - これが核心で、キャラクターの個性的な思考、
     自己葛藤、的確なツッコミ、世界への独自の解釈が必要です。
5. 描写のディテール：
   - 感覚にフォーカス：キャラクターの対話に集中、
     視覚と聴覚を中心に
   - テンポの制御：段落は短く保ち、長文の堆積を避け、
     読みやすさを確保します。
</writing_style>
```

過多な記号を使わず、タイトルには `####` ではなく `#` を使っています。
</div>

フォーマットテクニックの詳細は[フォーマットと記号の活用](formatting.md)をご参照ください。

## 十、CoT(思考の連鎖) は検証の良い助手

CoT(思考の連鎖) にはもう一つの利点があります：AI の思考ロジックを文字上で直感的に感じ取れることです。これはプロンプトの微調整や AI のエラーへの対処において非常に重要です。どのステップの推理で偏差が生じたかを明確に確認でき、そのステップのロジックを修正するためにプロンプトをピンポイントで修正できます。

多くの場合、AI が出力した CoT(思考の連鎖) を通じてセルフチェックできます。CoT(思考の連鎖) は AI の思考の連鎖であり、出力時に考えていることです。思考の中からエラーを見つけることができます。

例えば、AI が私たちのプロンプトを正しく理解しているか、どのプロンプトが AI をうまく最適化しているか、AI がなぜこのエラーを出しているかなどです。

思考の連鎖を通じて、AI が何を考えているかをよく把握でき、本来ブラックボックスであるニューラルネットワークと AI の思考を CoT(思考の連鎖) に具体化し、外部から AI が私たちのプロンプトをどう理解しているかを見ることができます。

ユーザーのニーズの解析から、AI がユーザーの入力内容をどう理解しているかが分かります。過剰理解している場合はプロンプトで対処できます。そして CoT(思考の連鎖) とプロンプトの組み合わせにより、CoT(思考の連鎖) の中で AI がプロンプトのニーズをどう理解し、どう実現しているかも見ることができます。

例えば以下の思考の連鎖の内容から、AI がユーザーのニーズをどう理解しているか、過剰理解していないか、AI がどうキャラクターを演じているか、過学習やエラーのフィードバックが出ていないかを見ることができます：

```
[最新のニーズ]
human の最新入力内容：おはよう、まどか、
今日は新しいリボンに変えたんだね、かわいいよ

最新入力ニーズの解析：
beilu 凛倾が友人として自然に応答し、まどかの新しいリボンを褒め、
好感度を上げ、日常の温かさを表現します。
```

CoT(思考の連鎖) テクニックの詳細は [CoT(思考の連鎖)](cot.md) をご参照ください。

## 十一、小さな語彙が大きな効果を生む

モデルには豊富な知識ベースがあり、多くの知識を習得していることはご存知のとおりです。そこで、AI の知識ベースを呼び出し、簡潔な専門用語を使ってプロンプトの効果を最大化することを試みましょう。多くの知識をモデルは知っており、プロンプトでそのモジュールを活性化するだけで済みます。

```
性格設定：
現在の状況/状態：
キャラクターの対話スタイル：
知識の遮蔽と欠落：（没入型フィードバックの強化、神の視点の回避）
感情フィードバック：ユーザーの最新入力内容の刺激 → 前文に対する感情の緩衝
        → 感情の発生（プラチクの感情モデルに基づく） → 行動/言語表現
感情の帰属：（三段論法で感情発生の合理性を証明する）
```

ここで使われている心理学用語：**プラチクの感情モデル**——AI の対応する知識セクションを直接活性化しました。この用語だけでキャラクターの感情、動的変化、複合感情など一連の内容を AI に伝え、AI のフィードバックをより本物らしくしています。

論理学：**三段論法**——大前提（ストーリーイベント）+ 小前提（キャラクターの性格）= 結論（現在のリアクション）。これにより AI が「根拠のない感情」や「飛躍的なリアクション」を生み出す問題を解決しています。

AI にタスクを実行させる際には、関連する知識理論や専門用語を調べてみましょう（使用予定の AI に直接聞くのは良い方法で、AI にその知識があるかどうかも分かります）。詳しくは[小さな語彙が大きな効果を生む](small-words.md)をご参照ください。

## 十二、少数ショットプロンプティング（Few-Shot Prompting）

実は AI のコンテキスト模倣能力は非常に強力です。これも自己注意力メカニズムがもたらす利点です（欠点はもちろん過学習の問題です）。

必要に応じて、いくつかの例を与えることができます。1〜3 個の「質問-回答」の範例を提供することで、特定のタスクにおけるモデルのパフォーマンスを向上させます。特にフォーマット出力やスタイル模倣において効果的です。

例えばロールプレイの返答スタイルや、特定のプロンプトの詳細な説明などです：

```
ユーザー：あなたは猫娘です
AIアシスタント：はいにゃん、ご主人様が大好きですにゃん
```

このようにすれば、AI はあなたが必要とする文体を模倣し、より良い効果を得ることができます。

記事や他のものについても同様です。例えばコードの場合、AI に単純にコードタスクを与えるだけだと、何度か試してやっとほぼ正しい答えが得られるかもしれません。しかし AI に参照コードを与えれば、AI はより安定してタスクを完了できます。

<div class="callout-warning">
<div class="callout-title">注意</div>

例は時として非常に良い効果をもたらしますが、AI に過学習の問題を引き起こす可能性もあります。この点には注意が必要です。1〜3 個の厳選された範例が適切で、多すぎると逆効果です。
</div>

詳しくは[少数ショットプロンプティング](few-shot.md)をご参照ください。
