# 记忆归档与检索

记忆归档是记忆系统的"新陈代谢"——将不再活跃的记忆从热层自动搬迁到温层和冷层，同时提供召回引擎在需要时将相关记忆拉回。这保证了热层不会无限膨胀，同时历史记忆不会真正丢失。

## 三层搬迁路径

```
hot（热层）
  ↓ 自动搬迁（条目老化/容量管理）
warm（温层）
  ↓ 进一步老化
cold（冷层/归档）
```

### hot → warm 搬迁

触发条件：
- 记忆条目超过一定时间未被访问
- 热层总容量接近上限
- P2 总结归档后，原始细节条目降温

搬迁后，条目从每轮自动注入变为**按需召回**。

### warm → cold 搬迁

触发条件：
- 温层条目继续老化，长时间未被召回
- 温层容量管理需要

搬迁后，条目进入长期归档，仅在**主动搜索**时可达。

## 搬迁的例外

以下内容**不参与搬迁**，始终留在热层：

- `forever.json` 中的永久记忆
- 当前活跃的表格条目（正在使用的表格行）
- 系统级配置信息

## 召回引擎

召回引擎是 P1 自驱动管线的核心组件，负责从 warm/cold 层中找到与当前对话相关的记忆条目并拉入上下文。

### 召回流程

```
用户发送消息
    ↓
NLP 分词：提取用户消息的关键词
    ↓
联想扩展：对关键词进行语义联想
    例："下雨" → "雨、天气、伞、淋湿、潮湿"
    ↓
多词共现匹配：在 warm/cold 层中搜索
    - 查找同时包含多个关键词/联想词的条目
    - 多词共现比单词匹配更精确
    ↓
四维打分（对每个候选条目）：
    ↓
排序取 top-N 条目
    ↓
注入本轮上下文
```

### 四维打分细节

| 维度 | 评估内容 | 说明 |
|------|----------|------|
| **semantic** | 语义相关度 | 条目内容与当前话题在语义层面的匹配程度 |
| **lexical** | 词汇匹配度 | 关键词的直接文本匹配，精确度高 |
| **recency** | 时间近度 | 越近期的记忆得分越高，体现"越近越容易想起" |
| **importance** | 重要性 | 被标记为重要的记忆得分更高，体现优先级 |

四个维度各自计算得分后加权求和，最终排序。权重配置可调。

### 多词共现

多词共现是召回精度的关键机制。单个关键词匹配会召回大量不相关的条目，而要求多个关键词同时出现在条目中，可以显著提升相关性：

- 用户说"上次在公园遇到那只猫" → 提取关键词"公园"、"猫"
- 只含"公园"的条目和只含"猫"的条目不会被优先召回
- 同时含"公园"和"猫"的条目会获得高分

## 快照管理

在[记忆管理](beilu:mode/memory)中点击工具栏的 **snapshot** 按钮，或在记忆运维区切换到"快照"子 Tab，可管理记忆快照。

快照分为两类：

### 记忆快照

- **创建**：点击创建按钮，可附带说明文字描述本次快照的目的
- **恢复**：从快照列表中选择一条，确认（confirm）后恢复到该快照时的记忆状态
- **列表**：按时间倒序展示所有已创建的记忆快照

### Git 快照

- **创建**：点击创建按钮，输入 label 作为标签标识
- **恢复**：选择一条 Git 快照恢复；系统会在恢复前自动创建一个 pre-restore 保险快照，防止误操作导致数据丢失
- **列表**：按时间倒序展示所有已创建的 Git 快照

## 归档工具栏

在[记忆管理](beilu:mode/memory)的文件浏览器中，顶部归档工具栏提供以下批量操作：

| 操作 | 说明 |
|------|------|
| 归档临时记忆 | 将临时记忆条目从热层搬迁到温层 |
| 结束当天 | 执行当天的收尾归档流程 |
| Hot 转 Warm | 手动将选中的热层条目搬迁到温层 |
| Warm 转 Cold | 手动将选中的温层条目搬迁到冷层 |
| 归档已完成任务 | 将标记为已完成的任务记忆归档 |

这些操作是自动搬迁机制的手动补充，适用于需要立即整理记忆层级的场景。

## 检索配置

在[记忆管理](beilu:mode/memory)中点击工具栏的 **retrieval** 按钮，或在检索/诊断区切换到"检索"子 Tab，可调整召回引擎的运行参数：

- **P1 自动触发 toggle**：开关 P1 每轮对话前的自动召回
- **引用聊天条数**：控制召回时参考的近期聊天轮数（分模式独立配置）
- **最大搜索轮数**：P1 多轮搜索的上限
- **超时**：搜索超时时间设置

## 格式检查

在[记忆管理](beilu:mode/memory)中点击工具栏的 **format** 按钮，或在记忆运维区切换到"格式"子 Tab，可对记忆文件进行格式合规检查。

- **扫描**：点击扫描按钮启动检查
- **统计**：显示符合 / 警告 / 错误 / 总计四项计数
- **按文件统计**：每个文件的检查结果分别列出
- **问题清单**：展示前 20 条格式问题的详细信息
- **一键升级**：对可自动修复的格式问题执行批量升级

## 对使用者的影响

- 归档和召回都是自动进行的，使用者无需手动操作
- AI "忘了"某件事，可能是因为该记忆已搬迁到冷层且未被召回引擎触发
- 通过在对话中提及相关关键词，可以帮助召回引擎找到冷层中的相关记忆
- 特别重要的信息建议让 AI 标记为"永远记住"，进入 forever.json 免于搬迁

## 对开发者的说明

- 搬迁的时间阈值和容量阈值在配置中可调
- 召回的 top-N 数量影响上下文占用，需要平衡召回质量与上下文空间
- 四维打分的权重可以根据实际效果调整
- 联想扩展的质量直接影响召回覆盖率，是召回性能的瓶颈之一
- 冷层存储没有容量限制，但搜索性能需要关注
