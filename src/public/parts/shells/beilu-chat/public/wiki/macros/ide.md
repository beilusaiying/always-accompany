# IDE/编程宏

[编程模式（IDE）](beilu:mode/files)下的专用宏，为 AI 提供子模式信息、代码文件内容、工具描述和执行结果等编程上下文。在预设引擎构建提示词条目时替换。

## 模式信息宏

| 宏 | 说明 | 示例输出 |
|----|------|----------|
| `{{sub_mode}}` | 当前子模式的名称 | `code_review` |
| `{{sub_mode_desc}}` | 当前子模式的描述 | `代码审查模式：分析代码质量...` |

编程模式下有多个[子模式](beilu:wiki/modes/submodes.md)（代码编写、审查、调试等）。这两个宏告诉 AI 当前处于哪个子模式及其行为描述。

## 记忆与文件宏

| 宏 | 说明 |
|----|------|
| `{{codeHotLayer}}` | 编程热层记忆全文（**仅记忆 AI 预设可用**） |
| `{{code_file:文件名}}` | 引用指定的 md 文件内容 |
| `{{code_files_list}}` | 当前活跃文件列表 |

### {{codeHotLayer}}

编程模式的热层记忆**全文**：把 `code/active/` 下的 md 文件内容拼接展开（`_` 开头的元文件如 `_index.md` 跳过）。存储编程上下文——项目结构、技术栈、任务笔记等。

**用在哪**：只在**记忆 AI 预设**（P1/P2… 这类记忆系统预设）里生效。主对话 AI 的预设里写它会替换成空字符串。

> **为什么主对话 AI 拿不到**（2026-07-26 定案）：热层动辄数万字符，若每轮无条件塞进主 AI 会挤占上下文，且用户无法控制。现在热层只对记忆 AI 开放——由记忆 AI 读取、检索、按需把相关部分交给主对话。此前主 AI 侧有一条硬编码注入（绕过 INJ 面板、无开关、排在最前），已整条删除。
>
> 容量上限沿用 `injection.hot_md_max_chars`（默认 40000）；超出的文件整份跳过，不截断。

**相关**：只要文件名列表用 `{{code_files_list}}`；要单个文件全文用 `{{code_file:文件名}}`；跨层数据清单用 `{{available_data}}`。

### {{code_file:文件名}}

直接将指定的 markdown 文件内容嵌入到提示词中。用于向 AI 提供特定的参考文档、代码规范、项目说明等。

示例：
```
{{code_file:coding_guidelines}}
```
会读取对应的 `coding_guidelines.md` 文件内容并替换到此位置。

### {{code_files_list}}

列出当前编程会话中活跃的文件清单。让 AI 知道用户正在处理哪些文件。

## 工具与环境宏

| 宏 | 说明 |
|----|------|
| `{{client_env}}` | 客户端环境信息 |
| `{{ide_workspace}}` | IDE 工作区信息 |
| `{{ide_tools}}` | 从可执行 `IDE_TOOLS` 注册表确定性生成的静态工具名与参数签名；不含连接态、工作区、权限或运行值，可放在历史前缓存区 |
| `{{ide_read_cache}}` | 本会话已读文件/分身结果缓存清单（编号+时间+大小），IDE 未连接时为空 |
| `{{clone_list}}` | 分身简表（首个启用分身+4项权限概览） |
| `{{clone_configs}}` | 全部启用分身的完整配置（模型/权限/职责） |
| `{{clone_runtime}}` | 最近一轮分身/并行委派的运行态快照（谁·状态·产出摘要） |
| `{{sub_modes_all}}` | 全部模式组的子模式清单（跨 chat/code/work） |
| `{{chat_rename_cmd}}` | 当前对话显示名（与重命名写侧同源） |

> 工具的自然语言调用规则仍放在可编辑的 INJ-2 / INJ-2-code；`{{ide_tools}}` 只补注册表静态签名。已退役的 `{{ide_tool_results}}` 会替换为空，因为工具执行结果作为真实消息进入对话尾部，不走宏通道。

### {{client_env}}

注入客户端的环境信息，如操作系统类型、浏览器信息等。帮助 AI 给出与用户环境匹配的建议（如 Windows vs macOS 的路径差异）。

### {{ide_workspace}}

注入当前 IDE 工作区的信息，让 AI 了解自己所处的工作区上下文。

## 运行链路

IDE 宏在预设引擎构建提示词时被替换：

```
用户在编程模式下发送消息
  -> 预设引擎（PresetEngine）构建提示词条目
  -> 读取当前子模式配置
  -> 收集活跃文件、环境信息
  -> 替换 {{sub_mode}}、{{code_file:x}}、{{ide_workspace}} 等宏
  -> 组装完成的提示词发给 AI
```

## 注意事项

- IDE 宏仅在编程模式下生效，在普通对话模式下这些宏没有数据源
- `{{code_file:文件名}}` 引用的文件需要在项目的指定目录中存在
- IDE 宏由预设引擎在构建条目时替换，属于后端宏替换的一部分
- 工具指令与工具结果不走宏：工具说明在可编辑注入条目（INJ-2 / INJ-2-code）中维护，执行结果作为真实消息进入对话
