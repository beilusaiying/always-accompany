# 正则与渲染条目

世界书条目中正则匹配和 GENERATE/RENDER 标记的用法。

## 正则表达式匹配

当条目设置 `useRegex: true` 时，key 和 keysecondary 中的关键词将作为正则表达式进行匹配。

### 基本用法

| 需求 | 正则写法 | 匹配示例 |
|------|----------|----------|
| 精确词 | `魔法` | "魔法师"、"学魔法" |
| 词边界 | `\b魔法\b` | 仅匹配独立的"魔法" |
| 多选一 | `魔法\|法术\|咒语` | 任一词出现即匹配 |
| 可选部分 | `魔法(师)?` | "魔法"或"魔法师" |
| 通配 | `魔.*师` | "魔法师"、"魔导师" |

### 与 selective 配合

当 `selective: true` 时，key 和 keysecondary 都使用正则匹配，两者必须同时命中才触发。

**示例**：
- key: `森林|丛林|树林`
- keysecondary: `夜晚|深夜|黑暗`
- 效果：只有当对话中同时提到"森林类"和"夜晚类"的词时，才注入关于"夜间森林"的设定

### 注意事项

- 正则表达式的特殊字符（`.` `*` `+` `?` `(` `)` `[` `]` `{` `}` `\` `^` `$` `|`）如果要作为字面字符匹配，需要反斜杠转义
- 匹配范围包括用户消息和 AI 回复的近期内容（具体扫描深度取决于配置）
- 正则匹配是大小写敏感的，需要不区分大小写时使用 `(?i)` 标志

## GENERATE 与 RENDER 标记

世界书条目的 content 中可以使用两种特殊标记来区分信息的可见对象。

### [GENERATE:*] — 仅 AI 可见

```
[GENERATE:角色内心活动指引]
当角色在森林中时，描写环境时应包含以下感官细节：
- 听觉：鸟鸣、风声、树叶沙沙
- 嗅觉：泥土、花香、腐叶
- 触觉：潮湿的空气、脚下的落叶
[/GENERATE]
```

`[GENERATE:*]` 包裹的内容只会出现在发给 AI 的上下文中，不会在用户界面上显示。适用于：

- 给 AI 的写作指导
- 角色行为规则
- 内部逻辑说明
- 不希望用户直接看到的元指令

### [RENDER:*] — 仅用户可见

```
[RENDER:场景气氛文字]
--- 阴暗的森林，月光穿过树冠洒下斑驳的光影 ---
[/RENDER]
```

`[RENDER:*]` 包裹的内容只会在用户界面上显示，不会发给 AI。适用于：

- 场景氛围描述（装饰性文字）
- UI 提示信息
- 给用户的说明文字
- 不需要 AI 处理但需要用户看到的内容

### 混合使用

一个条目可以同时包含普通内容、GENERATE 内容和 RENDER 内容：

```
这是森林区域的设定。

[GENERATE:AI写作指导]
描写森林时注意季节变化对环境的影响。
[/GENERATE]

[RENDER:用户提示]
提示：你当前位于古老森林的深处。
[/RENDER]
```

在这个例子中：
- "这是森林区域的设定。" —— AI 和用户都能看到
- GENERATE 部分 —— 只有 AI 看到
- RENDER 部分 —— 只有用户看到

### 运行链

```
世界书条目触发，content 进入注入流程
    ↓
解析 content 中的标记：
  - 找到 [GENERATE:*]...[/GENERATE] 块
  - 找到 [RENDER:*]...[/RENDER] 块
  - 剩余部分为普通内容
    ↓
构建 AI 上下文时：
  - 包含普通内容
  - 包含 GENERATE 块内容
  - 排除 RENDER 块内容
    ↓
构建用户显示时：
  - 包含普通内容
  - 排除 GENERATE 块内容
  - 包含 RENDER 块内容
```

## 开发注意事项

- 标记的语法是 `[GENERATE:名称]` 和 `[/GENERATE]` 配对，名称部分用于标识但不影响逻辑
- 标记不能嵌套（不能在 GENERATE 块里放 RENDER 块）
- 解析发生在注入时，解析失败（如缺少闭合标签）时整个 content 作为普通内容处理
- 正则匹配的扫描范围（往回看多少轮对话）影响触发的灵敏度，过大会增加误触发，过小会漏触发
