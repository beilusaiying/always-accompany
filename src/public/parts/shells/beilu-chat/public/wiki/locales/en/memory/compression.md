# Context Compression

Context Compression addresses the hard constraint of AI's limited context window. As a conversation progresses and the context token count approaches the model's limit, the system uses the P7 Compression AI to compress earlier conversation turns into summaries, freeing space for new turns.

## Why Compression Is Needed

AI models have a fixed context window limit. During a long conversation:

- System prompts, character settings, and World Book entries occupy fixed space
- Hot Layer memory is injected every turn, occupying persistent space
- Conversation history grows continuously with each turn

When the total token count of all this content approaches the limit, new messages cannot be sent unless older messages are either handled or simply truncated and lost. The compression mechanism preserves key information while freeing space.

## Processing Pipeline

```
Before each turn, the system calculates the current total context token count
    ↓
Determines whether it is approaching the model's context limit
    ↓
[Not exceeded] → Continue normally
[Approaching limit] → Trigger compression
    ↓
Select earlier conversation turns (keep the most recent N turns uncompressed)
    ↓
Send selected turns to the P7 Compression AI
    ↓
P7 generates a structured summary
    ↓
Summary is stored in context_summary.json
    ↓
Original turns are removed from the active context
    ↓
In subsequent context construction, the summary replaces the original content
```

## context_summary.json

The storage file for compression summaries. Each compression updates this file, containing:

- Summary text: a synopsis of conversation highlights generated by P7
- Coverage range: which turns this summary covers
- Generation timestamp

During context construction, the contents of context_summary.json are placed at the beginning of the conversation history, letting the AI know "what was discussed before," even though the original conversation has been removed.

## How the P7 Compression AI Works

P7 is a Preset dedicated to compression. Its objectives are:

- **Preserve key information**: events, decisions, emotional changes, important conversation content
- **Discard redundancy**: greetings, repetition, formatting artifacts
- **Structured output**: generate summaries in a format easy for AI to understand

P7's system prompt guides it to focus on "information that may need to be revisited in subsequent conversation," rather than simple full-text abbreviation.

## Impact on Users

- Compression happens automatically; users typically do not need to intervene
- After compression, the AI still "knows" what was discussed before, but details may be fuzzy
- For particularly important information, it is recommended to have the AI write it into Memory Tables (especially #8 Remember Forever), so the information remains in the Hot Layer even after conversation compression

## Notes for Developers

- The compression trigger threshold (context usage ratio) is configurable
- The number of recent turns kept uncompressed is also configurable
- context_summary.json is overwritten and updated by subsequent compressions; it does not grow indefinitely
- Compression and memory archival (P2) are independent mechanisms: P2 stores information into Memory Tables, while P7 reduces context size. Both can operate simultaneously
