# 可靠性契约、回档与发布边界

本页记录当前版本对「删除消息、回档、多窗口、IDE 执行端与提示词配置」的共同契约。它不是运行状态面板，也不承诺某台设备已经完成实测；它说明这些链路在源码中必须遵守什么，以及发布前要验证什么。

## 文档的唯一来源与发布镜像

| 角色 | 路径 | 可以做什么 |
|---|---|---|
| 文档源 | `beilu-always-accompany/site/` | 编写、审查与修改 Wiki 页面及索引 |
| 公开镜像 | `github公共仓库发送/gh-pages工作树/` | 接收已经审查的 `site/` 精确文件，并作为 GitHub Pages 部署物 |
| 发布代码接收目录 | `github公共仓库发送/al6月之后/always-accompany/` | 接收经受控同步的产品代码；不是 Wiki 的反向来源 |

因此：先改本体 `site/`，再逐文件将同一份页面和索引复制到 `gh-pages工作树/`，并比对 SHA-256；不得在镜像中单独修文档后再反向覆盖本体。两边不一致时，以本体 `site/` 的当前审查结果为准，并把镜像差异作为待同步项处理。

## 消息删除：ID 是事实，位置只是提示

删除动作会冻结当时的 `chatId`、消息 ID 与 index hint。服务端按消息 ID 重新定位，再在该对话的串行写入队列中落盘和广播。index 只用于辅助定位，不能因为前端渲染、回档或其他窗口的异步变化而当作唯一真值。

这条规则同时适用于单条删除、批量删除和多窗口页面：没有明确对话归属或稳定消息 ID 的破坏性操作必须拒绝，而不是猜测当前激活窗口。

## 回档：预览令牌、协调执行与如实结果

回档不是「先改记忆、再删聊天」的两次独立操作。用户确认前先取得预览；确认时把预览中的锚点、文件检查点集合和 IDE 路由快照一并交给协调入口：

```text
预览（锚点 + checkpointIds + expectedIdeRoute）
  → 暂停/收束该对话的生成
  → 在同一聊天写入临界区重新确认锚点
  → 回档记忆与文件检查点
  → 截断聊天记录并落盘
  → 返回完整成功、未应用或部分成功
```

- `expectedIdeRoute` 是预览时绑定的 IDE 路由快照，不只是「是否已连接」这个布尔值。执行时路由、连接代次或检查点集合发生漂移，会拒绝执行，要求重新预览。
- 文件回档、记忆回档和聊天截断不能把部分完成包装成成功。调用方必须显示 `applied` / `partial` 与失败原因；部分成功应保留恢复所需的信息。
- 正在生成时回档，会先阻止该对话的新生成和迟到写入，避免回档后旧流继续把消息写回。

## 多窗口与 YonBan / CLI

多窗口的隔离单位是对话线（`chatId`）。渲染、删除、回档和生成操作必须持有自己的对话归属，不能在异步回调中读取「当前窗口」来决定目标。

YonBan（VS Code / Cursor）与内置 CLI 都通过同一类后端契约参与文件检查点和回档：客户端携带预览得到的检查点/路由条件，服务端复核后才执行。没有可验证的绑定或路由漂移时，系统应明确失败，不应把操作投递到另一个工作区。

## 提示词必须可配置

进入模型上下文的产品提示词不能以不可修改的代码常量替代用户配置。任务清单说明文本已作为默认值收口在 `system_texts.task_plan_howto`：用户配置存在时优先使用，包含空字符串；只有未提供该配置时才使用默认文本。

这不改变标签协议或功能开关的含义。修改提示词时，应通过配置/预设入口或受控配置更新，而不是修改历史消息、缓存键或在读取链中硬塞宏。

## 发布与运行时边界

本页描述的是源码层的契约和发布门禁，不替代真实运行验证。发布前至少要按真实环境检查：

1. 单条/批量删除在多窗口下只影响目标对话；
2. 生成过程中回档不会产生迟到消息，且完整、拒绝、部分成功三类结果可见；
3. YonBan 重连、工作区绑定变化和 CLI 让位后，旧预览令牌会被拒绝而不是误路由；
4. API 首次保存、子模式绑定和提示词设置在刷新后仍保持用户选择。

若某次变更只完成静态检查，应在该次同步记录中明确写作「运行时未验证」，不能据此宣称浏览器、API、WebSocket、CLI、YonBan 或 P1 已在真实环境可用。
