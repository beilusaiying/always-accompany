# 预设分类与选择

## 切换和筛选预设

### 按使用场景选

| 你想做的事 | 推荐分类 | 理由 |
|-----------|---------|------|
| 角色扮演对话 | clone | 包含角色行为引导、对话风格控制 |
| 日常聊天 | clone 或通用 | 轻量级指令，自然对话 |
| 写代码 | code | 包含代码规范、输出格式、工具使用指令 |
| 任务管理 / 文档 | work | 包含任务分解、格式要求、审批流程 |
| 自定义场景 | 自建预设 | 完全按你的需求定制 |

### 按模式自动加载

如果你在模式设置中绑定了预设（详见 [预设与模式联动](mode-binding.md)），切换模式时会自动加载对应预设，通常不需要手动选择。

### 按角色/对话独立设置

每个角色和每个对话窗口可以独立绑定预设。系统通过 **active_preset_map** 记录每个对话使用的预设，互不干扰：

- 和角色 A 聊天用预设 X
- 和角色 B 聊天用预设 Y
- 切换对话窗口时，预设自动恢复

## 管理预设

### 查看已安装预设

在预设管理面板中可以看到所有已安装的预设，按 bucket 分组显示。每个预设显示名称、描述和当前状态。

### 导入预设

支持导入 SillyTavern 格式的预设 JSON 文件。导入时系统会：

1. 解析预设 JSON，提取条目和参数
2. 注册到 registry.json
3. 如果携带 bucket 字段，归入对应分类
4. 如果携带 model_params，保存模型参数

### 导出预设

可以将当前预设导出为 SillyTavern 兼容的 JSON 文件，方便分享或备份。也可以通过[导入导出](beilu:settings/import-export)面板批量操作。导出包含全部条目、排序、参数和分类信息。

### 删除预设

删除内置预设实际上是标记为"已删除"（记录在 config.json 的 deleted_builtins 中），可以随时恢复。用户自建的预设删除后需要重新导入。

## 分类逻辑

always-accompany 通过 **bucket（分组桶）** 对预设进行分类管理。每个预设在注册时会标记所属 bucket，前端按 bucket 分组展示。

### 内置分类

| Bucket | 说明 | 预设数量 | 适用模式 |
|--------|------|---------|---------|
| code | 编程辅助类预设 | 11+ | Code / IDE 模式 |
| work | 工作流类预设 | 12+ | Work 模式 |
| clone | 角色扮演 / 克隆类预设 | 5+ | Chat / AIRP 模式 |
| _(无分类)_ | 通用预设 | 按需 | 所有模式 |

### 分类的来源

预设的 bucket 信息记录在 **registry.json**（预设注册表）中，这是分组的单一权威源。导入预设时如果 JSON 文件携带了 bucket 字段，会自动注册到对应分类。

没有 bucket 字段的预设，前端会根据预设名称中的关键词进行回退匹配，尽量归入合适的分组。

## 预设选择的优先级

系统确定当前对话使用哪个预设时，按以下优先级：

1. **对话级绑定**：active_preset_map 中以 chatId 为键记录的预设
2. **模式级绑定**：mode_preset_bindings 中该模式的默认预设
3. **全局默认**：active_preset（全局设置的默认预设）
