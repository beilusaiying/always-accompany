# YonBan 定位（凛倾 2026-07-16 定案）

> 凛倾原话：「yonban只是插件,不是本体,只是扩展」

## 铁律

**YonBan 是插件/扩展，不是本体。** 本体 = shells（beilu-chat / beilu-home 等）+ parts 插件树的既有功能链。

由此推出的硬边界：

1. **禁以「YonBan 已有/已替代」为由自行下线、查封、注释掉本体功能——此类动向必须凛倾拍板。**
   实证案（提示词查看器）：0714 凛倾因查看器链路当时有强切预设副作用而指令查封本体查看器；副作用 0715 修除（S6 强切段删除+轮询移除）后，0716 凛倾定案回补。教训：查封注释只写了「由 YonBan 提示词预览替代」，未记录拍板出处/日期/解封条件，导致后续无法溯源、差点当成永久下线——凡查封/下线必须在注释里带凛倾拍板日期与恢复条件。
2. 功能归属判断：一个功能长在本体的使用链上（用户从 UI 可达），它就是本体功能；YonBan 侧存在相似能力 ≠ 重复 ≠ 可删。去重/迁移类任务碰到"本体 vs yonban 疑似重复"时，**默认保本体，动向要凛倾拍板**。
3. YonBan 对本体只做扩展（新增节点/管道/functions 供本体消费），不做接管：不得以迁移之名删除本体入口、监听、初始化接线。
4. 写注释时的用语约束：禁止把 yonban 称为"本体/主线/权威实现"来贬低 shells 侧为"旧版/遗留"；迁移未经凛倾定案前，shells 侧实现就是正主。

## 目录

- `core/dispatch` — 计算图·边（dispatch 派发）
- `core/functions` — 通用无状态后端功能库（memory / prompt / security …）
- `pipelines` — ModeDef 管道
- `config` / `frontend` / `data` / `_test`
