# 预设系统

在左栏下拉选预设，AI 立刻换一套行为方式——聊天模式用聊天预设，编程模式用编程预设，切换即生效。

## 切换预设

在对话界面的预设选择器中，点击即可切换当前预设。切换后立即生效，下一条消息就会使用新预设。

## 启用/禁用条目

通过 beilu-toggle 插件，在预设面板中勾选/取消勾选单个条目，实时调整 AI 收到的指令。

## 导入预设

在预设管理面板中点击导入，选择 SillyTavern 格式的 JSON 文件即可。always-accompany 完全兼容 SillyTavern 预设格式，也可以自己从零创建。

## 预设分类

always-accompany 的预设按用途分类（称为 bucket），共 **7 个一级分类**：

| 分类 | 用途 | 典型预设 |
|------|------|---------|
| 🎭聊天（chat） | 日常对话、陪伴 | 自定义聊天预设 |
| 💻编程（code） | 编程辅助 | 编程流水线角色（代码专家、纠错专家等）、前端专家 |
| 📋工作（work） | 工作流 | 任务确认、流程组装、提示词设计等工作流水线角色 |
| 🤖分身（clone) | 分身作业 | 调查追踪、代码更改、测试实验等分身角色 |
| 📨Bot（bot） | Bot 平台会话 | Bot 通用、办公助理 |
| 📊PPT（ppt） | PPT 制作 | PPT 制作五步工作流 |
| 📚P9词库（p9） | P1 词库维护 | P9 词库维护子模式配套预设 |

分类还支持**二级细分**：bucket 值可以写成"一级/二级"路径式，比如 `code/流水线`、`code/前端`、`bot/办公`——同一个大类下再分小组，方便预设多了以后精细管理。二级组名完全自由，你自己起。

详见 [预设分类与选择](categories.md)。

## 预设与模式的联动

每个对话在每个模式（[聊天模式](beilu:mode/chat) / Code / [工作模式](beilu:mode/work) / [Bot管理](beilu:mode/bot)）下各自记录「当前正在使用的预设」，互不干扰：

- 聊天模式用聊天预设 → AI 表现得像陪伴角色
- 编程模式用编程预设 → AI 表现得像编程助手
- 工作模式用工作预设 → AI 表现得像工作搭档

切换预设即改「正在使用」，即改即生效。**没有全局默认预设**——你（或 AI）没在这个对话/模式里切过预设时：

- 编程/工作模式 → 用当前生效**子模式**的默认预设
- 聊天模式 → 诚实空，不注入预设（首次切换才建立记录）

这样设计是为了隔离：导入或删除预设这类"无坐标"操作只影响预设库，绝不会让所有窗口的在用预设一起变。

## 双源机制：为什么我改了默认预设没生效？

预设有两份存放地，理解了就不会困惑：

- **出厂模板**（defaults）：系统自带的只读种子，跟着程序走
- **你的副本**（你的用户数据目录下的 presets）：第一次使用时系统自动从出厂模板"播种"一份给你，**之后运行时读写的全是这份副本**

所以：

- 你在界面里编辑预设 → 改的是你的副本 → 立即生效 ✅
- 你直接去改 defaults 目录里的文件 → 运行时根本不读它 → 看起来"没生效" ❌（它只在首次播种和"恢复默认"时被读取）
- 把内置预设改坏了想回退 → 用预设管理里的**恢复默认**，从出厂模板重新复制一份覆盖你的副本

播种是"已有就不覆盖"的：你已经有的同名预设不会被出厂模板悄悄冲掉。每个登录用户都有自己独立的一份副本，互不干扰。

## 深入了解

### 预设的组成

一个预设由若干**条目（Prompt Entry）**组成，每个条目是一段文字加上控制属性：

| 组成要素 | 说明 |
|---------|------|
| 条目内容 | 发给 AI 的实际文本（系统提示、角色指令、风格要求等） |
| 排列顺序 | 条目在提示词中的先后位置（越靠前，AI 越优先关注） |
| 启用状态 | 可以单独开关每个条目，不用的暂时关掉 |
| 注入深度 | 条目插入聊天历史的位置（深度 0 = 最底部，深度 4 = 往上数 4 条消息处） |
| 角色标记 | 条目以什么身份发送（system / user / assistant） |

### 预设做了什么

当你发送一条消息时，always-accompany 并不是把你的消息直接丢给 AI。在幕后，预设引擎会把角色设定、系统指令、世界书、聊天历史、插件提示等内容，按照预设定义的条目顺序组装成一份完整的提示词，然后才发送给 AI。

### 预设与模型参数

预设不仅包含提示词条目，还可以携带模型参数（temperature、top_p 等）。加载预设时，这些参数会一并生效，让每个预设拥有独立的生成风格。

参数优先级：预设自带参数 < 运行时参数面板 < 扩展层模型参数覆盖

详见 [模型参数](../ai-service/model-params.md)。也可在[AI服务源](beilu:settings/api)面板调整参数。
