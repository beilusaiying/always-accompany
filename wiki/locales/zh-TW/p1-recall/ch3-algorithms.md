# 第3章 演算法設計與形式化描述

## 3.1 引言

本章給出自驅動發散召回系統在演算法層的完整規格。該系統是一條為「發散思維」服務的外掛式處理管線：在大語言模型（LLM）之外，以規則計算、詞向量運算與輕量標注取代對大模型的額外呼叫，從而在不產生額外推理成本的前提下，為主模型提供發散方向。設計者將其定位概括為「外置的發散思維鏈」。

本章的組織遵循如下邏輯。3.2 節先建立術語基礎，對後文反覆使用的自造術語給出定義。3.3 節逐項形式化描述系統的原創演算法，每項按「設計動機—形式化定義/公式—設計依據—相關工作對照」四層展開。3.4 節給出核心評分框架 BLQ（Bilu Quality，轉接器內部的候選品質打分裝置）的完整規格。3.5 節以「消融與失敗方案」的體裁記錄演算法演進史中被實測證偽的方案，這在技術報告中是有價值的負面證據。3.6 節匯總相關工作，並給出分檔定位表。3.7 節小結。

需要預先聲明的實現現狀是：系統的發散主迴圈（runPipeline）與記憶召回組件（recallMemories）目前處於組件態，即演算法已實現但尚未接回線上主鏈路，線上檢索暫由模型預設集承擔；本章描述的是這套已實現、待接回的組件庫演算法。本章所有具體數值均按來源級別標注：凡經受控實驗校準並鎖定者標注為「經實驗校準的定檔值」，凡為初始取值而未經系統性調優者標注為「初始預設值」。所有公式均逐字保留其原始形狀，未作改寫；每個公式配以變數定義表。

## 3.2 術語定義

為使不具備本系統背景的讀者能夠零上下文理解後文，先定義本章反覆使用的自造術語。

- **資訊詞（information word）**：發散過程產生的中間語義單元。它不直接輸出給主模型，而是作為下游收攏的原材料。例如「習得性無助」「職業倦怠」這類中間概念。
- **方向詞（direction word）**：由多個資訊詞經「多對一收攏」後輸出的最終語義單元，作為提供給主模型的「知識入口種子」，指示思考方向而非給出具體路線。例如「認知重構」「價值澄清」。
- **廢詞（null word）**：主模型僅憑裸讀上下文即可自行推出的詞。此類詞對主模型無資訊增益，其價值被定義為零並予以剔除。
- **BLQ（Bilu Quality）**：轉接器內部的候選品質打分裝置。它在多個標注維度上對候選詞一次性加性出分，用於降權、篩除廢詞與紅線剔除，本身不承擔「選擇方向」的職能。
- **萬金油問題（over-general hub problem）**：指少數高連接度的樞紐詞（hub word）在發散過程中把大量不相關候選吸附到自身周圍，導致輸出泛化、失去方向性的現象。「萬金油詞」即這類過度通用、對任何輸入都會被高頻召回的詞。
- **紅線詞（redline word）**：違反輸出準則、命中即被硬性移出候選（而非降權）的詞，包括給出具體路線、替使用者下判斷、代替使用者表達、把使用者判定為病症四類。
- **軸（axis）**：一條獨立並行的學科發散維度。系統採用心理、資訊、社會、邏輯、語言、認知六條學科軸。
- **點位（子軸）**：產出端的子方向坐標。系統在產出端設置子方向坐標空間，輸入激活其中的子集以完成「定位」，此步只定位不打分。
- **0-token 原則**：整個發散步驟不呼叫大語言模型、全程可白盒觀測的設計立場。發散由規則計算、向量運算與小模型標注完成。

後文涉及具體程式碼實現處，僅以模組名（如 node8、node10、axisDecay 等）作為實現標識，不展開實現細節。

## 3.3 原創演算法逐項形式化描述

本節逐項描述系統的原創演算法設計。每項給出：設計動機、形式化定義或公式（配變數表）、設計依據、以及與相關工作的對照。相關工作的分檔口徑統一在 3.6.1 節定義，此處僅引用分檔結論。

### 3.3.1 三段機制：收縮—發散—收縮

**設計動機。** 大語言模型在產生時傾向於收攏到單一路徑，難以自發進行廣域發散。本系統認為發散能力必須由模型之外的機制承擔：先以記憶召回錨定上下文（收縮），再進行兩次聯想發散（發散），最後收攏為方向詞注入提示詞（收縮）。

**結構（形狀級）。**

```
輸入 → [收縮] 記憶召回 + 上下文錨定
     → [發散] 聯想網路第一次發散 → 空間投票 → 第二次發散產資訊詞
     → [收縮] 多對一投票收攏為方向詞 → 注入提示詞
```

**設計依據。** 收攏階段以擦邊、大量的方式召回記憶以錨定語境；發散階段的目的是讓主模型在後續思考中不被困死於單一點位；系統本身只提供框架、記憶與發散路徑，收攏、聚合與思考仍交由主模型完成。就設計定位而言，本系統面向的是回溯與發散，而非續寫或複現大語言模型的產生能力。

**實現摘錄（節選，摘自 p1_pipeline.mjs 主入口 runPipeline，節選）。** 上述「收縮—發散—收縮」三段在主迴圈 `runPipeline` 中以串聯的節點呼叫落地，與上文的形狀級結構逐段對應：括號雙信道前置層（Step -1）先於分詞，隨後依次經召回、六軸、資源確認、空間投票、多對一收攏與紅線剔除。為便於閱讀，此處僅保留呼叫骨架，省略降級回退、白盒 trace 與熱插拔輪詢等實現雜項。

```javascript
export async function runPipeline(inputText, chatHistory, mode, userCtx) {
  // Step -1 括號雙信道前置層（早於分詞，主/副信道不取均值保留張力）
  const _bracket = _P1_BRACKET ? splitBracketChannels(inputText) : { main: inputText, sub: null, ... };
  const _mainText = _bracket.main || inputText;
  // 階段1 [收縮] recallV2：分詞 + SWOW 發散 + 召回錨點 + 輸入質心
  const recallResult = callNode("recall", [_mainText, chatHistory, seenNodes, { ... }], { ... });
  const swowPool = recallResult.swowPool || new Set(inputWords);
  // …（略：副信道另跑一次 recallV2，Set union 並入 swowPool）
  // 階段2 [發散] node3 六軸面 + node4 47 子軸定位
  const _axis6  = callNode("node3", [_pool, mode, inputWordSet, ...], { ... });
  const _axis47 = callNode("node4", [_pool, mode, inputWordSet, _axis6.wordProfiles], { ... });
  // 階段3 [發散] transfer：node5 資源確認 → node6 空間投票 → node9 多對一選方向詞
  const transferResult = callNode("transfer", [[...swowPool], mode, confirmedAxisResult, ...], { ... });
  // 階段4 [收縮] node10 refineDirectionWords + isRedlineWord → 方向詞
  _dwPool = refineDirectionWords(_dwPool, { ... });
  const p1_act = topDirectionWords.slice(0, 15).map(d => d.term);
  return { p1_act, /* …（略） */ };
}
```

需說明實現與設計稿的一處對應關係：設計稿的「第一次發散→空間投票→第二次發散」在實現中並非三個獨立節點，而是收斂進 `transfer` 一個模組內串聯的 node5→node6→node9 三步，六軸（node3）與 47 子軸（node4）在其上游先行定位。

**相關工作對照。** 分檔 B（觀念層）。「LLM 需外掛腳手架以分離發散與收斂」這一核心主張在 CreativeDC（arXiv 2512.23601，2025-12）與 Scaffolding Creativity（arXiv 2510.26490，2025-10）中已先行公開並有理論支撐。但這兩項工作均在單模型內部以兩階段 prompt/溫度或 persona 切換實現，不含記憶召回錨定、空間投票與多對一收攏；觀念在先，實現路徑不同。

### 3.3.2 空間相加投票（反距離加權與溫度畫圓）

**設計動機。** 候選詞的收攏不應採用線性相乘或硬匹配，而應在詞向量空間中按內容分佈做加性投票，以避免任一維度的低分對整體的乘法式否定。

**公式（形狀級）。**

```
idw = 1 / (1 + d² · k)          # 反距離加權，d = 語義距離，k = 縮放係數
邊界圓半徑 = 溫度係數 T 縮放     # T 大→半徑大→更多候選；T 小→半徑小→精確
投票 = Σ 加性累加（禁乘法鏈）
```

**變數定義。**

| 符號 | 含義 | 來源級別 |
|------|------|----------|
| `idw` | 單候選的反距離加權投票貢獻 | — |
| `d` | 候選與查詢在詞向量空間的語義距離 | — |
| `k` | 距離縮放係數 | 經實驗校準的定檔值 |
| `T` | 溫度係數，控制邊界圓半徑 | — |

**實現摘錄（節選，摘自 p1_node6_spaceVote.mjs，節選）。** 上文形狀級公式 `idw = 1/(1+d²·k)` 與「投票為加性累加、禁乘法鏈」在節點6 的投票內迴圈中逐字落地，`k` 即程式碼中的陡度係數 `_P1_NODE6_IDW_STEEPNESS`（屬經實驗校準的定檔值，此處以符號代之）。省略溫度圓半徑縮放、內圈排除等分支：

```javascript
const d = 1 - cos;                              // 空間距離，d = 1 − cosine
// …（略：太遠不投的下限門、溫度圓內/外判定）
const idw = 1 / (1 + d * d * _P1_NODE6_IDW_STEEPNESS);   // 反距離加權，k = 陡度係數
let vote = w * idw;                             // 加性票 vote = w·idw，非乘法鏈
// …（略：域信號 domainBonus 加成，累加器取鍵）
rec.totalVote += vote;                          // 累加，全程無 /N（空間相加不相乘）
```

其中 `rec.totalVote += vote` 直接對應形狀級公式的「投票 = Σ 加性累加（禁乘法鏈）」，累加過程不除以票數 N、不連乘，體現「多維標注是空間而非相乘」這一設計原則。

**設計依據。** 系統採用空間加性投票而非線性相乘：候選在向量空間中按內容分佈投票，結果匯總到同一候選池；發散方向應表現為「沿空間走」而非落在孤立的點。

**相關工作對照。** 分檔介於 C 與 B 之間。反距離加權本體為 Shepard（1968）經典空間插值公式，屬通用零件；「語義空間按距離選候選」亦為通用專利套路（如 US 11086920 等，2018–2021）。但「反距離加權投票 + 溫度係數縮放半徑圓做邊界 + 全程加性禁乘法鏈」這一具體組合未找到公開對應，在組合層可判為 D。

### 3.3.3 多對一方向詞投票（Hough 式）

**設計動機。** 若由單個中間詞直接產出方向詞，易受該詞偶然性影響。本系統令多個中間資訊詞對同一目標術語獨立投票，以票數收攏選出最終方向詞，從結構上抑制「單詞直噴」。

**公式（形狀級）。**

```
每個資訊詞 wᵢ → 對候選方向詞 t 投票 vote(wᵢ, t)
方向詞得分 = Σᵢ vote(wᵢ, t)      # 多對一累積投票（Hough voting 範式）
→ 票數峰值 = 最終方向詞
```

**變數定義。**

| 符號 | 含義 |
|------|------|
| `wᵢ` | 第 i 個中間資訊詞 |
| `t` | 候選方向詞 |
| `vote(wᵢ, t)` | 資訊詞 wᵢ 對方向詞 t 的投票貢獻 |
| 方向詞得分 | 對某方向詞的累積票數，取峰值者為最終方向詞 |

**理論支撐。** 該設計與 Condorcet 陪審團定理同構：設 N 個獨立投票者、每個正確率大於 50%，則多數投票的正確率約為 1 − (1/2)^N，隨 N 指數增長——3 票時約大於 87.5%，5 票時約大於 96.9%，而單票僅約 50%（故單票應降權）。這為「多票高置信、單票低置信」提供了數學依據。

**實現摘錄（節選，摘自 p1_node9_dirword.mjs，節選）。** 上文形狀級公式「方向詞得分 = Σᵢ vote(wᵢ, t)」在節點9 以一個共享累加器 `_voteAcc` 落地：每個資訊詞對同一候選方向詞獨立投票，票值加進 `totalVote`，投票者計數進 `voterCount`（即峰值判定所依據的「被多少資訊詞共同指向」），最終得分為累積票乘以該軸衰減。省略範圍門、通道合并與金字塔分層等分支：

```javascript
// 每個資訊詞 wᵢ 對同一 eligible 方向詞 t 獨立投票（真正的多對一）
const vote = iwWeight * (relW + _domainW + ...);   // vote(wᵢ, t)，加性
_entryTotalVote += vote;                           // 單靶累積：Σᵢ vote(wᵢ, t)
_entryVoterCount++;                                // 投票者計數（多對一的「多」）
// …（略：過 47D 範圍門、極性/溫度校準）
const rec = _voteAcc.get(key);                     // 統一累加器（Hough/CN/bridge_to 共匯於此）
rec.totalVote  += _entryTotalVote;                 // 空間相加，非相乘
rec.voterCount += _entryVoterCount;
// …（略：排序、取 topN）→ 每個方向詞最終得分：
score: cand.totalVote * Math.max(nd, _houghDecayFloor) * _resW,   // 累積票 × 軸衰減 nd
```

其中 `rec.totalVote += _entryTotalVote` 是「多對一累積投票（Hough voting 範式）」的直接實現；末行 `cand.totalVote × 軸衰減` 說明多對一得分在產出端還乘上了 3.3.5 節的軸衰減係數——這一點在形狀級公式中未顯式給出，屬實現在設計稿基礎上的接線細節（軸衰減經 node3 導出、node9 消費）。

**設計依據。** 關聯資料中的詞本質是「點」，系統需將點轉換為「線」，發散即線的延展；產出方向詞應基於多個相近詞的多維加法收攏，而非依賴單個詞。

**相關工作對照。** 分檔 C（遷移層為 D）。Hough 投票範式極為成熟（Hough 1962；VoteNet，ICCV 2019），但既有工作全部集中於電腦視覺與點雲領域。經多輪檢索，未找到將 Hough 式投票遷移到自然語言處理中關鍵詞/方向詞產生的公開工作；將該範式遷移至詞選擇任務並賦予「防直噴」的結構性動機，是本系統較為獨特的一處。

### 3.3.4 兩次發散架構

**設計動機。** 單次發散難以兼顧廣度與相關性。本系統採用異質兩跳結構：第一次發散後先以空間投票收窄，再進行第二次發散產出資訊詞，最後收攏為方向詞。

**結構（形狀級）。**

```
發散₁（聯想網路）→ 空間投票（收窄）→ 發散₂（產資訊詞）→ 多對一收攏（方向詞）
```

**設計依據。** 系統的發散以「合并」為錨點展開：先檢索既往關聯與記憶，再基於聯想網路（結合注意力式的查詢—鍵—值機制）發散，然後轉接進入下一跳。

**相關工作對照。** 分檔 D。「兩次發散、中間夾一層空間投票收窄、再發散產資訊詞」的特定兩跳架構未找到公開對應。Tree-of-Thoughts（ToT）是概念鄰居（C），但其為同質分支搜尋加評估回溯，本系統為異質兩跳（發散—投票—發散—收攏），結構不同。

### 3.3.5 六軸面發散

**設計動機。** 面向人物扮演式回饋的應用需要多學科支撐，單一維度的發散不足以覆蓋心理、社會、語言等不同側面。本系統令六條學科軸（心理、資訊、社會、邏輯、語言、認知）並行獨立發散，每軸輸出多維的「面」而非單一分數，軸間以軟衰減實現隔離而非硬切斷。

**公式（形狀級，軸衰減 axisDecay）。**

```
各軸關聯度 axisRelevance[axis] = Σ(該軸 face 詞貢獻值)
按關聯度降序排名 → axisRank，rank0 = 主方向軸
軸衰減 axisDecay[axis] = exp(-rank · β)
  rank0 → exp(0) = 1.0（主軸）
  rank1 → exp(-0.5) ≈ 0.607
  rank2 → exp(-1.0) ≈ 0.368
```

**變數定義。**

| 符號 | 含義 | 來源級別 |
|------|------|----------|
| `axisRelevance[axis]` | 某軸的關聯度，等於該軸各面詞貢獻值之和 | — |
| `axisRank` | 各軸按關聯度降序的排名，rank0 為主方向軸 | — |
| `β` | 軸衰減率 | 經實驗校準的定檔值（取 0.5） |
| `axisDecay[axis]` | 該軸的衰減係數，隨排名指數衰減但恆大於 0 | — |

**實現摘錄（節選，摘自 p1_node3_axis6.mjs，節選）。** 上文形狀級公式的三行——關聯度求和、按關聯度降序取排名、`axisDecay = exp(-rank·β)`——在 `_computeAxisDecay` 中逐字對應，`β` 即程式碼常量 `AXIS_DECAY_BETA`（經實驗校準的定檔值，取 0.5）。省略 AXIS_CUTOFF 軟停與白盒 trace：

```javascript
for (const axis of AXES) {                        // 各軸關聯度 = 該軸 face 詞貢獻值之和
  axisRelevance[axis] = fw.reduce((s, x) => s + (x.v || 0), 0);
}
const ranked = AXES.slice().sort((a, b) => axisRelevance[b] - axisRelevance[a]);   // 按關聯度降序
ranked.forEach((axis, rank) => {                  // rank0 = 主方向軸
  axisRank[axis] = rank;
  // 衰減如 exp(-rank·β)：rank0（主軸）= 1.0，遠軸指數衰減但 >0 永不刪
  axisDecay[axis] = axisRelevance[axis] > 0 ? +Math.exp(-rank * AXIS_DECAY_BETA).toFixed(4) : 0;
  // …（略：AXIS_CUTOFF 軟停判定、cutoffRatio 記錄）
});
```

`Math.exp(-rank * AXIS_DECAY_BETA)` 與形狀級公式 `exp(-rank·β)` 完全一致，其中一處實現約定值得注明：關聯度為 0 的軸其衰減取 0（而非 `exp(0)=1`），以避免未激活軸被誤當主軸，此為公式在實現中的邊界處理。

遠軸的衰減係數指數下降但永不歸零，實現「軟隔離」：遠離主方向的軸仍保留微弱貢獻，允許適度擦邊而不輸出完全不相關的內容。

**設計依據。** 人物扮演回饋需要寫作、心理學、語言學、邏輯學等多學科並行支撐；發散允許擦邊，但不應輸出完全不相關的內容。學科軸數經由四軸、五軸到六軸的演進確定，設計者否決了進一步降維壓縮的方案。

**相關工作對照。** 分檔 C（數字/概念撞名）。Biber 的多維分析（MDA，1988）、LIWC（2001）及認知科學的「六支撐學科」均使用了「多維」「六」這類詞，但沒有一項是「六條學科軸並行獨立發散、每軸產多維面而非分數、軸間軟衰減」的機制（機制層可判 D）；且學科清單亦不同，本系統含資訊、邏輯、認知軸，而無哲學、人類學、神經等軸。

### 3.3.6 子軸激活定位（只定位不打分）

**設計動機。** 在產出端需要一個高解析度的方向坐標空間，用於把輸入映射到具體的子方向；此步的職能是「定位」而非「評分」，二者應明確分離。

**結構（形狀級）。**

```
產出端 = 子方向坐標空間（子軸集合）
激活子集 = 輸入命中的子方向（聚光燈式注意：照向某方向則該方向變亮）
→ 定位（不打分）
```

**設計依據。** 產出端子方向坐標數量較大，其行為可類比統計物理中的系綜——大量粒子疊加湧現出宏觀態。產出端子軸與六條學科軸是相互分離的兩層，子軸並非六軸的下級切片。

**相關工作對照。** 分檔 D（概念鄰居 C）。「激活子集定位、只定位不打分」這一明確區分「定位」與「打分」的產出端子軸坐標機制未找到公開對應。Axis-Aligned Subspace 貝葉斯最佳化（arXiv 2504.06111，2025-04，打分驅動）與神經元多義性研究（arXiv 2505.07831）是遠概念鄰居，用途與機制均不相符。

### 3.3.7 括號雙信道

**設計動機。** 在對話文字中，括號內容常承載與正文不同層次的元語言資訊（如動作、旁白、語氣標注）。若將其與正文混合並取均值，會消解二者之間的張力。本系統將括號內容作為元語言副信道，與正文主信道分離處理。

**結構（形狀級）。**

```
正文 → 主信道處理
括號內容 → 元語言副信道（獨立處理）
兩信道不混合、不取均值 → 保留張力
```

**設計依據。** 兩信道不取均值，以保留對立信號之間的張力，避免降維式的均值化把相互衝突的信號抹平。

**相關工作對照。** 分檔 C。「多信道分離不混合」「保留張力」等概念詞在全雙工語音的使用者流路由（User-Stream Routing，arXiv 2605.10199，2026-05）與敘事張力研究（arXiv 2604.09854，2026-04）中出現，但「把對話括號內容當作元語言副信道、與正文主信道分離、不取均值」這一具體做法未找到公開對應（機制層 D）；相關工作亦多在 2026 年 4、5 月，晚於或平行於本系統設計期。這是本系統較為獨特的一處。

### 3.3.8 大量擦邊召回

**設計動機。** 與追求精確的檢索增強產生（RAG）不同，本系統的召回是為下游發散服務的：它採用低門檻、大量、模糊的召回策略，召回結果僅作錨點，不主導發散方向。

**公式（形狀級，加權線性召回打分）。**

```
composite = 0.45×relevance + 0.20×recency + 0.20×attention + 0.15×weight
scoreRecord = max-pool（對所有查詢節點取最強同向節點）
```

**變數定義。**

| 符號 | 含義 | 來源級別 |
|------|------|----------|
| `relevance` | 語義相關度 | — |
| `recency` | 時間新近度 | — |
| `attention` | 注意力集中度 | — |
| `weight` | 記憶重要度權重 | — |
| 權重係數 0.45/0.20/0.20/0.15 | 各分量的線性組合權重 | 經實驗校準的定檔值 |
| `scoreRecord` | 一條記憶的最終得分，對該記憶所有查詢節點取最大值 | — |

**設計依據。** 召回以擦邊、大量的方式進行；其機制為「上下文加注意力集中加多軸」去匹配既往內容（如資料層、熱層、冷層）並取出，不要求很智慧的判斷——本質是關鍵詞匹配，這也是「召回不消耗大模型 token」這一原則的來源。

**相關工作對照。** 分檔 B（手段層）。「低門檻、高召回、關聯式模糊召回」作為技術手段，在 HippoRAG（arXiv 2405.14831，2024-05）、SYNAPSE（arXiv 2601.02744，2026-01）、Predictive Associative Memory（2026-02）中均已實現且早於或接近本系統。但這些系統的目的是提升檢索準確率或多跳問答表現，追求「準」；本系統的召回目的與角色相反——召回只做發散錨點、不主導、故意保持模糊以撐開候選，為下游發散提供燃料，追求「廣而糊」。手段層撞車（B），目的與角色層不同。

需要特別指出，SYNAPSE（2026-01-06，早於本系統）與本系統共享擴散激活、側抑制、扇出效應三個術語，但用途正交（前者用於檢索問答準確率，後者用於發散產生）。僅憑公開摘要無法排除實現級更深層的相似，此項列為需人工複核的重點之一。

### 3.3.9 查詢—鍵—值池交汇發散

**設計動機。** 孤立、無聯繫的候選詞會導致發散漂移過大。本系統借鑒注意力機制的查詢—鍵—值（QKV）結構，將其改造為一條外掛發散管線，用注意力過濾控制漂移。

**公式（形狀級）。**

```
Q = 輸入詞向量質心
K = 聯想網路 cue（收攏錨點 = 輸入關鍵詞 + recallAnchors）
V = 交汇 cue → 鏈式再聯想 → 注入 XML 的發散詞
attention(Q, K) = softmax(Q · Kᵀ / √d)     # 低 attention 候選過濾（漂移控制）
```

**變數定義。**

| 符號 | 含義 |
|------|------|
| `Q` | 查詢，取輸入詞向量的質心 |
| `K` | 鍵，取聯想網路線索（輸入關鍵詞與召回錨點的收攏） |
| `V` | 值，取交汇線索並鏈式再聯想產出發散詞 |
| `d` | 詞向量維度，`√d` 為縮放因子 |
| `attention(Q, K)` | 注意力權重，用於過濾低注意力候選以控制漂移 |

**設計依據。** 發散基於收攏後的內容進行；孤立無聯繫的詞彙會導致漂移過大，故引入注意力機制，同時參考語義相近的詞與召回錨點，以錨定發散範圍。

**相關工作對照。** 分檔 C（概念類比撞名）。「注意力即檢索/關聯記憶」是自 2017 年起的通用解讀（現代 Hopfield 網路等價於注意力，Ramsauer 2020）；「查詢質心」在鍵值加速工作（CSAttention，2026-04）中撞名。但「Q 取詞向量質心、K 取聯想網路線索、V 取交汇線索做鏈式再聯想」這一把 QKV 三元組改造成外掛發散管線的具體用法未找到公開對應（管線化用法層 D）。

### 3.3.10 大中小三級路由

**設計動機。** 全域打分容易被萬金油詞與高連接度樞紐詞主導。本系統以倒排索引的三級路由（大類方向、中類局部、小類術語）取代全域打分，從結構上治理萬金油/樞紐詞問題。

**結構（形狀級）。**

```
觸發詞 → 倒排激活子類別（中類）→ 局部精排（小類術語池）
= 書本類比：目錄（大）→ 章節（中，可疊加）→ 文字（小，術語）
```

**設計依據。** 大類為大致方向，中類為方向的局部（可疊加），小類為術語池並落到具體術語；其類比是書本的目錄、章節與文字，其中目錄（中類）內容可相互結合。此三級劃分的目的是避免樞紐詞把一切吸附過去。

**相關工作對照。** 分檔 B（結構層）。「粗到細、大中小分級路由加倒排索引」是成熟的資訊檢索範式（HRR，arXiv 2503.02401，2025-03；CITADEL，2022-11；倒排索引，1970 年代），均早於本系統。但「觸發詞經倒排激活子類別再局部精排、且明確以治理萬金油/樞紐詞為設計目標」的動機未找到直接對應——通用分級檢索面向效率與精度，本系統面向「避免樞紐詞把一切吸過去」這一發散品質動機。

### 3.3.11 熱插拔詞庫作為額外發散軸

**設計動機。** 系統希望透過增加詞庫檔案來直接擴展發散能力：新增一個詞庫檔案即等價於系統多出一條發散軸，且支援執行時熱載入。

**結構（形狀級）。**

```
三層詞庫（優先級 learned > packs > core，類比輸入法）：
  core/    內置隨部署不可刪（swow / cooccur / cilin / cogmech）
  packs/   可插拔執行時生效（如 acg-chinese 27878 詞 / medical / airp-techniques 等）
  learned/ 逐使用者從對話自學
mtime 30s 檢查 → 改檔案 30s 內自動 reload
打字式升權 userBoost(word) = log(1+freq[word]) × 0.1   （上限 +0.3）
```

**變數定義。**

| 符號 | 含義 | 來源級別 |
|------|------|----------|
| `freq[word]` | 某詞在使用者對話中的出現頻次 | — |
| `userBoost(word)` | 打字式升權量，隨頻次對數增長 | — |
| 係數 0.1、上限 +0.3 | 升權縮放係數與封頂值 | 初始預設值 |
| mtime 檢查週期 30s | 檔案修改時間輪詢週期 | 初始預設值 |

**設計依據。** 系統追求詞庫熱插拔與使用適應性，使其行為如打字般隨使用者習慣調整；由模型依據對話自行構建與調整詞庫，被視為更優的路徑。

**相關工作對照。** 分檔 C（基建撞名）。「熱載入詞庫/外掛」是極常見的基建（如 Elasticsearch 詞典熱載入，2020-11；Obsidian Hot-Reload；各類監聽重載機制），檔案修改時間輪詢撞名。但「每加一個詞庫檔案即等價於系統自動多出一條發散計算軸」這一把詞庫檔案等同於發散維度的語義未找到公開對應（D）。SillyTavern 的 World Info 是最近的生態鄰居（可熱載入關鍵詞詞庫），但其機制為「觸發即注入固定文字」，而非「新增發散軸」，機制不同。

### 3.3.12 二級詞彙體系與廢詞判據

**設計動機。** 系統需要區分兩類語義單元並施加資訊增益約束：中間產出的資訊詞不外洩，經多對一收攏為方向詞後才輸出；同時以「主模型是否已能自行推出」作為詞價值的判據，剔除無資訊增益的廢詞。

**結構（形狀級）。**

```
資訊詞（中間、不輸出）→ 多對一收攏 → 方向詞（輸出、知識入口種子）
廢詞判據：主模型裸讀能推出的詞 = 廢詞 = 價值 0
方向詞准入 6 條全滿足：可搜尋 + 有共識 + 是方向詞 + 非診斷詞 + 非路線詞 + 非口語
```

系統以「點—線—面—體」的幾何模型刻畫資訊層級：

- 體 = 使用者一次對話的完整資訊（輸入加記憶資料）；
- 面 = 召回、聯想發散與資訊詞（如「習得性無助」「職業倦怠」），不輸出；
- 線 = 輸出的方向詞（如「認知重構」「價值澄清」），輸出；
- 點 = 主模型據方向詞組織的最終回覆。

**設計依據。** 聯想資料中的詞是「點」，需將點轉為「線」，發散即線的延展；系統應給主模型的是「方向」而非「路線」。方向詞的組織遵循四項優先原則：體驗詞優先於術語、口語錨點優先於抽象、經歷詞優先於需要詞、合并時保留錨點。

**相關工作對照。** 分檔介於 C 與 D 之間。「種子詞/啟動（priming）」鬆散撞概念（Seeding priming，2023–24）。但「資訊詞（中間、不輸出）與方向詞（輸出、多對一收攏）的二級詞彙體系，加上『主模型裸讀能推出的詞即廢詞、價值為零』這一資訊增益判據」未找到任何公開對應。以「基礎模型是否已能推出」定義詞價值為零的廢詞判據，是相當獨特的判據設計（D），為本系統明顯原創的一處。

### 3.3.13 BLQ 多維加性打分框架

**設計動機。** 候選詞的綜合評分若採用乘法鏈，等價於一個「與門」（AND 門）：任一維度低分即對整體形成否定，導致候選被單維度扼殺。本系統在多個標注維度上統一採用一次性加性出分（CombSUM），輔以側抑制與最大邊際相關性（MMR）配額，使評分呈「或門」（OR 門）語義。

**公式（形狀級，詳見 3.4 節）。**

```
additive = W_SPATIAL·dSpatial + W_TF·dTf + W_PATH·dPath
         + W_NB·dNb + W_SPEC·dSpec + W_CONFIRM·dConfirm   （加權 CombSUM，不連乘不取均值）
blqScore = max(additive · FLOOR, additive − Σpenalty)      （抑制維加性扣分 + 軟地板）
```

**設計依據。** 多維標注構成的是一個「空間」而非相乘關係；早期曾表述為「多軸打分後取均值，不達標則刪除」，但取均值的方案後被否決，改為加性——因為取均值會歸零維度間的張力。

**相關工作對照。** 分檔 B（組件層）。三大組件——CombSUM（Fox & Shaw 1994）、MMR（Carbonell & Goldstein 1998）、側抑制——均為數十年歷史的經典資訊檢索/神經科學零件，遠早於本系統；SYNAPSE（2026-01）亦將側抑制用於記憶。但未找到「CombSUM + 側抑制 + MMR 配額三件套統一組裝、並明確以『加性即或門、對抗乘法鏈即被單維否定的與門』為設計論據」的公開完整框架。本系統的原創性主張在於「為何必須加性而非乘法」的論據與三件套的特定編排，而非單個零件。該框架的完整規格見 3.4 節。

### 3.3.14 0-token 白盒立場（橫切原則）

**設計動機。** 這是一條橫切整個發散步驟的設計原則而非單一演算法：整個發散過程不呼叫大語言模型、全程可白盒觀測，以規則計算、向量運算與小模型標注完成，避免為單次發散耗費大模型 API 成本。

**設計依據。** 系統一貫以零成本為目標，不將高成本大模型用於發散這類步驟；觀測上採用白盒立場，直接檢視實際輸出而非依賴代理評分工具。

**相關工作對照。** 分檔 D（競爭格局層）。在最接近的若干方案對比中，本系統是唯一實現「0-token、發散步不需大模型」的方案（SA-RAG、FS-RAG、LWOW、MAD 均需大模型參與發散或檢索）。相關研究（MAD 與 LiveIdeaBench）還表明「大模型的發散能力與其通用智慧分數不相關」，即投入更多大模型算力並不能解決發散問題，這從側面支持了本系統外掛式 0-token 路線的合理性。就該原則統領下的具體機制而言，多學科坐標定位（第二步）與沿坐標再發散（第三步）是較為新穎的組合。

**小結（3.3 節）。** 逐項核查表明：在「機制高度相似且早於本系統設計期（2026-04）」的嚴格意義上，上述原創項均未與公開工作撞車。撞到的多為通用零件（B 檔）或概念/術語撞名（C 檔）。本系統的原創性主張普遍落在「把成熟零件組裝成一條為發散服務的外掛管線、在產生任務上的遷移用法、以及若干具體判據」這一層，而非單個零件本身。分檔定義與匯總見 3.6 節。

## 3.4 BLQ 評分框架完整規格

本節給出 BLQ 評分框架的完整規格。BLQ 的職能定位為轉接器內部的候選品質打分裝置，而非發散引擎或選擇器：方向的「選擇」由空間投票與多對一投票承擔，BLQ 在選擇之後只做降權、篩除廢詞與紅線剔除。

### 3.4.1 接線現狀

在完整規格之前需誠實聲明各組件的接線狀態。BLQ 打分核心（calcBLQ）實現了完整的多維加性框架，程式碼存在且可逐行審讀，但目前尚未接入發散主迴圈——線上資訊詞打分實際由空間投票與軸衰減承擔；方向詞精排組件（node10）使用的是打分核心的簡化版本，僅執行高斯衰減與紅線剔除，不執行完整的六維 CombSUM；紅線硬剔組件與方向詞精排組件目前為線上活躍狀態。本節描述的完整六維框架屬「已實現、待接回」的組件庫演算法。據此，具體權重與係數均按來源級別標注。

### 3.4.2 六個加分維（CombSUM）

BLQ 打分核心的結構為：六個加分維加權線性相加（CombSUM），再減去若干抑制維的加性扣分。設計鐵律為不作全乘積、不取均值。六個加分維如下。

| 維 | 名稱 | 公式（逐字保留） | 權重 | 權重來源級別 |
|----|------|-----------------|------|------|
| N1 | 空間距離 dSpatial | `const dSpatial = Math.tanh(rawScore);` | `W_SPATIAL: 1.0`（主信號） | 經實驗校準的定檔值 |
| N2 | BM25-TF 飽和 dTf | `const dTf = _bm25Tf(tf);`，其中 `_bm25Tf(f) = f/(f+k1·(1-b+b))`（本情境平均文件長度為 1，退化為 `f/(f+k1)`） | `W_TF: 0.6`；`BM25_K1: 1.5`；`BM25_B: 0.75` | 經實驗校準的定檔值 |
| N3 | 跨學科路徑和諧 dPath | `const dPath = Math.log(1+disc)/Math.log(1+6);`（對數歸一，六軸為上限） | `W_PATH: 0.4` | 經實驗校準的定檔值 |
| N4 | 鄰域相關性 dNb | `const dNb = nbCos != null ? Math.max(0, nbCos) : 0.3;`（無鄰域資訊時取中性值 0.3） | `W_NB: 0.5` | 經實驗校準的定檔值 |
| N5 | 特異性 dSpec | `const dSpec = spec;`（越具體越加分，抑制泛化的萬金油詞） | `W_SPEC: 0.4` | 經實驗校準的定檔值 |
| N6 | 資源確認 dConfirm | `const dConfirm = _confirmCount>0 ? Math.log(1+_confirmCount)/Math.log(1+6) : 0;`（六通道上限歸一） | `W_CONFIRM: 0.3` | 經實驗校準的定檔值 |

**變數定義。**

| 符號 | 含義 |
|------|------|
| `rawScore` | 空間投票的原始得分，經 tanh 壓縮至 [0,1) 以防單一空間票壟斷 |
| `tf` | 候選詞頻，經 BM25 飽和函數處理 |
| `k1`, `b` | BM25 的詞頻飽和與長度歸一參數 |
| `disc` | 候選覆蓋的不同學科數 |
| `nbCos` | 候選與鄰域中心的餘弦相似度 |
| `spec` | 候選的特異性度量 |
| `_confirmCount` | 候選在各資源通道被確認的次數 |
| `W_*` | 各維的加權係數 |

一項結構性約束是：跨學科路徑和諧（N3）僅在此處計入一次，不得在外層再次相乘。歷史上曾存在「內層排名與外層各乘一次」的做法，會導致全乘積式坍縮，已被否決。

### 3.4.3 加性匯總（CombSUM）

六維加權匯總的實現逐字如下：

```javascript
const additive =
  CFG.W_SPATIAL * dSpatial +
  CFG.W_TF * dTf +
  CFG.W_PATH * dPath +
  CFG.W_NB * dNb +
  CFG.W_SPEC * dSpec +
  CFG.W_CONFIRM * dConfirm;
```

即加權線性和（Fox & Shaw 1994 提出的 CombSUM），不連乘、不取均值。這是「多維標注是空間而非相乘」這一設計原則的直接落地。

### 3.4.4 四個抑制維（加性扣分）

每個抑制門先計算一個乘子 `m ∈ (0,1]`，再轉換為加性扣分 `penalty_d = additive · (1 − m_d)`。各門只此一處，不構成舊式全乘積鏈。

| 抑制門 | 觸發條件 | 乘子常量 | 來源級別 |
|--------|----------|----------|----------|
| mOverused（萬金油） | 命中萬金油懲罰詞表（130 條手工標注）或候選自帶過用標記 | `OVERUSED_PENALTY: 0.35` | 經實驗校準的定檔值 |
| mPolarity（極性不匹配） | 輸入為正向而候選為負向（或反之） | `POLARITY_MISMATCH: 0.3` | 經實驗校準的定檔值 |
| mNbIrrelevant（無關） | `nbCos < NB_IRRELEVANT_COS`（閾值 0.05） | `NB_IRRELEVANT_PEN: 0.15` | 經實驗校準的定檔值 |
| mIsolatedNoise（孤立雜訊） | 需消費資源確認但確認計數為 0 | `ISOLATED_NOISE_PEN: 0.5` | 經實驗校準的定檔值 |

最終得分的實現逐字如下：

```javascript
const penaltySum = penOverused + penPolarity + penNbIrrelevant + penIsolatedNoise;  // 各 = additive·(1−m)
const blqScore = Math.max(additive * CFG.BLQ_SUPPRESS_FLOOR, additive - penaltySum);
```

**變數定義。**

| 符號 | 含義 | 來源級別 |
|------|------|----------|
| `m_d` | 第 d 個抑制門的乘子，取值於 (0,1] |
| `penalty_d` | 第 d 個抑制門的加性扣分，等於 `additive·(1−m_d)` |
| `penaltySum` | 四個抑制門扣分之和 |
| `BLQ_SUPPRESS_FLOOR` | 軟地板係數，取 0.1，多門疊扣時不硬歸零 | 經實驗校準的定檔值 |
| `blqScore` | BLQ 最終得分 |

該設計的兩個性質值得說明。其一，單門觸發時 `additive − additive·(1−m) = additive·m`，與舊式單門連乘等價；多門觸發時為線性疊扣，不發生指數坍縮。其二，軟地板保證多門疊扣不硬歸零，體現「大量擦邊」下的軟隔離原則。系統另設抑制維聚合模式開關，預設採用加性模式，乘法連乘模式僅保留用於對照實驗。

### 3.4.5 紅線硬剔（isRedlineWord）

紅線剔除為硬性移除：命中即移出候選池，不進入產出，而非降權。四類紅線的正規表示式種子屬結構常量，非可調數值。

- **R1 路線詞**：給出「應該怎麼做」的動作、方法、步驟（如「建議」「應該」「方法」「步驟」「策略」及英文 technique/strategy/step 等）。設計準則是只給方向不給路線。
- **R2 誘導詞**：替使用者下判斷的引導語（如「你需要」「你必須」「一定要」「快去」及英文 you must/you need to 等）。
- **R3 主觀體驗/代替使用者表達**：形如「你（很/好/真/太/是/覺得/感到……）」「我覺得」「感覺很……」的表達。設計準則是不代替使用者表達。
- **R4 診斷詞**：把使用者判定為障礙或病症的詞（如「障礙」「患者」「抑鬱症」「焦慮症」「確診」及英文 disorder/syndrome 等）。其中裸「症」字以「症(?!狀)」排除「症狀」，因為「症狀」是描述而非診斷——此細化系由白盒觀測實際輸出時發現。

萬金油、配額、極性、高斯衰減等均為降權（不刪除），只有 R1–R4 為硬剔除。

### 3.4.6 兩級精排的差異（node8 篩資訊詞 vs node10 篩方向詞）

系統在兩個層級各設一套精排邏輯，二者職能不同。

| 維度 | node8 篩資訊詞 | node10 篩方向詞 |
|------|----------------|-----------------|
| BLQ 打分 | 執行完整六維 CombSUM | 不跑六維；僅 `node9 得分 × 高斯衰減` |
| 側抑制 | 有（鄰域餘弦超閾值判近義並壓制） | 無 |
| MMR 多樣性 | 有（`λ·rel − (1−λ)·maxSim`，λ=0.7） | 無 |
| 配額 | 有（單軸配額 8、單維配額 3，超配額降權） | 無 |
| 相關性衰減 | 無（衰減在 BLQ 抑制維內） | 高斯漸變 `_gaussDecay(cos, PEAK=0.45, SIGMA=0.25, FLOOR=0.15)`（算位置而非壓分） |
| 斷崖棄權 | 無 | 有（前詞大於後詞乘以斷崖比 3 且序位不小於 5 時斷崖，突破「填滿 15 詞」的天花板） |
| 輸出上限 | 30（資訊詞） | 15（方向詞，契約為長度 15 的字串陣列） |
| 輸出紅線 | 不做（資訊詞不外洩給主模型） | 標注紅線，由紅線硬剔組件執行 |
| 接線狀態 | 組件態（無生產呼叫） | 線上活躍 |

一句話概括：node8 是「完整 BLQ 精排引擎（六維加側抑制加 MMR 加配額）」，目前為組件態；node10 是「輕量選後處理（高斯衰減加紅線標注加斷崖）」，目前線上活躍。node10 不複用完整六維打分，僅保留「衰減」與「紅線」兩件事，且不奪多對一投票（node9）的權——多對一投票的次序為主導，node10 只做降權、衰減與紅線。

### 3.4.7 可公開的原創口徑

BLQ 框架的三大組件（CombSUM、MMR、側抑制）均為經典標準件，本系統不主張發明它們。可對外主張的原創限於三點：其一，「加性即或門、對抗乘法鏈即被單維否定的與門」這一設計論據；其二，三件套加六加分維加四抑制維的特定編排；其三，軟地板軟隔離機制。所有權重係數、懲罰係數、衰減率與截斷參數均為經實驗校準或初始預設的具體取值，屬參數細節，發布時以結構為主而不鎖定具體值。

### 3.4.8 打分核心實現摘錄（節選）

前幾節以逐維公式與變數表描述了 BLQ 的結構，此處補充打分核心 `calcBLQ` 的連續骨架，以呈現「六加分維一次性 CombSUM、再減若干加性扣分、末以軟地板托底」這一形狀在實現中的整體樣貌。摘自 p1_node8_10_blq.mjs，節選，六個加分維的歸一表達式已在 3.4.2 表內逐行給出，此處僅保留聚合與抑制主幹，省略白盒 trace、極性推斷分支與邊界回退：

```javascript
// ── 六加分維加權 CombSUM（加法聚合，不連乘、不取均值）──
const additive =
  CFG.W_SPATIAL * dSpatial + CFG.W_TF * dTf + CFG.W_PATH * dPath +
  CFG.W_NB * dNb + CFG.W_SPEC * dSpec + CFG.W_CONFIRM * dConfirm;
// ── 四抑制維：各門先算乘子 m∈(0,1]，再轉加性扣分 penalty = additive·(1−m)（各門只此一處）──
const penOverused      = additive * (1 - mOverused);
const penPolarity      = additive * (1 - mPolarity);
const penNbIrrelevant  = additive * (1 - mNbIrrelevant);
const penIsolatedNoise = additive * (1 - mIsolatedNoise);
const penaltySum = penOverused + penPolarity + penNbIrrelevant + penIsolatedNoise;
// ── 軟地板托底：多門疊扣不硬歸零（軟隔離）──
const blqScore = Math.max(additive * CFG.BLQ_SUPPRESS_FLOOR, additive - penaltySum);
```

其中權重 `W_*`、四個懲罰乘子常量與軟地板係數 `BLQ_SUPPRESS_FLOOR` 均為經實驗校準的定檔值，此處以符號保留而不鎖定具體取值。該骨架逐字印證 3.4.3/3.4.4 節的兩條主公式：加分維走加法（`additive` 為純加權和），抑制維走「乘子轉加性扣分」（`penalty = additive·(1−m)`），單門觸發時等價於舊式單門連乘 `additive·m`，多門觸發時為線性疊扣而非指數坍縮。

節點10 的方向詞輕量精排不複用上述六維打分，僅以高斯衰減取代（對應 3.4.6 節「算位置而非壓分」）。其核心函數摘錄如下（摘自 p1_node8_10_blq.mjs，節選）：

```javascript
function _gaussDecay(cos, peak, sigma, floor) {   // 落最優帶→~1.0，偏離→漸降到 floor（不歸零）
  if (cos == null) return 1.0;
  const g = Math.exp(-((cos - peak) ** 2) / (2 * sigma * sigma));
  return floor + (1 - floor) * g;
}
```

`peak/sigma/floor` 為該函數的最優帶中心、帶寬與下限（經實驗校準的定檔值，以符號代之）。`floor + (1-floor)·g` 的結構保證再遠也不歸零，與 BLQ 主框架的軟地板同為「軟隔離」原則在不同層級的兩次落地。

## 3.5 消融與失敗方案

本節以「消融與失敗方案」的體裁記錄演算法演進史中被實測證偽的方案。在技術報告中，負面證據具有獨立價值：它標明了設計空間中哪些「看似更合理」的方向已被實證排除，可避免後續重複踩坑。本節所列公式多為歷史方案，不是目前實裝，讀者不應將其當作現行系統行為。

### 3.5.1 打分公式的三代演進

**第一代：十三因子乘積（已廢棄，作為反面教材列出）。**

早期（2026-05-05 版）的收縮打分採用十三因子全乘積：

```
finalScore = vote^1.2
           × dynamicPE          × ibApprox         × crossFaceBonus
           × valCoh             × nbBoost          × dimOverlapPenalty
           × stageBoost         × routeBoost       × crossoverBoost
           × memAnchorBoost     × registerBoost    × modeDirBoost
```

其被判為反面教材的原因有三：其一，十三因子全乘積等價於一個與門，任一因子偏低即導致全域崩潰；其二，各因子並非相互獨立（如投票項與交叉項高度相關），違背了樸素貝葉斯乘積所要求的獨立性假設；其三，若干因子各自的定義另有缺陷，如動態驚喜度存在跨使用者污染、某加權項虛增投票、維度重疊懲罰項 `0.55^(dims-2)` 會消滅樞紐詞，與「小詞激活大模組」的設計取向相反。

**第二代：軸均值（已重寫）。**

其後改為十四維坐標點積後取均值，首次突破 4.0 分（4.050）：

```
score = Σ[(coordAccum[i] × termCoords[i]) / max(|coordAccum[i]|, 0.5)] / 14
```

該方案對應「萬金油主要是因為部分軸分數過高、故應取均值」的早期設想，但取均值後被否決：取均值歸零了維度間的張力，導致萬金油詞增加約 25%。由此演進到第三代加性投票。

**第三代：加權線性/加性投票（目前方向）。**

召回側目前採用加權線性組合：

```
composite = 0.45×relevance + 0.20×recency + 0.20×attention + 0.15×weight
```

其中權重係數為經實驗校準的定檔值。該方案是「不要簡化」這一紅線之下唯一被批准的演算法簡化，因為它是增強而非退化。實測表明該方向在多個資料集上帶來顯著收益。相應的紅線包括：不回退乘積（乘積方案實測導致召回率大幅下降）、不刪去 softmax 歸一化、以及權重的具體數值可調而「加權線性方向」本身鎖定。

系統另保留一套舊的乘積式單節點打分供除錯使用：

```javascript
ebbinghaus = record.freq × (1 / (1 + days × 0.1));            // Ebbinghaus 遺忘曲線
importance = record.weight × Math.max(0, 1 - days / 60);      // 60 天外完全消失
axisOverlap = Σ cosineSim(qVec, kVec) / |axes|;               // 多軸投影同向（歸一化）
spreadDecay = Math.pow(0.6, spreadDistance);                  // 0/1/2/3 → 1.0/0.6/0.36/0.216
scorePerNode = ebbinghaus × importance × axisOverlap × spreadDecay;
scoreRecord = max(scorePerNode)  // max-pool：一條記憶一個維度極強即召回
```

並有一套三因子置信度用於閘門判斷（不參與排序）：

```
confidence = 0.5×max(score) + 0.3×(命中數/2 clamp[0,1]) + 0.2×軸一致性
閘門閾值：chat/airp 0.5 / game 0.6 / work/bot 0.7 / code·memory 不跑發散
```

上述三因子權重與閘門閾值均為經實驗校準的定檔值。

### 3.5.2 十九路擴散激活表（歷史快照）

### 3.5.3 置信度路由（歷史，手調閾值無統計基礎）

早期的置信度路由如下：

```
confidence = F1×0.45 + F2×0.35 + F3×0.20    （F1 豐富度 / F2 分差 / F3 歷史）
≥0.55       → normal (6 詞)

<0.30       → meta_signal (0 詞靜默)
```

其中 0.55/0.30 為手調閾值，缺乏統計基礎，屬初始預設值，規劃以保形預測（Conformal Prediction）類方法取代。

### 3.5.4 遠距聯想的距離帶（現行參照）

系統採用一個「甜蜜區」距離帶控制發散的遠近，作為現行參照：

```
semDist < 0.15 → blq × 0.4   (太近，同義詞冗餘)
semDist < 0.25 → blq × 0.7
semDist > 0.80 → blq × 0.5   (太遠，隨機雜訊)
semDist > 0.70 → blq × 0.8
```

甜蜜區為 `0.15 < semDist < 0.80`，其中各衰減係數為經實驗校準的定檔值。一條相關紅線是：距離為 1 的同義擴散實測導致召回率與排序指標顯著下降，故「類比是跨域同構，不做同義擴散」被列為紅線。

### 3.5.5 完整認知激活方程（未實裝）

系統曾規劃完整的 ACT-R 激活方程，但目前僅接入了其中的扇出懲罰項，基礎激活與擴散激活部分未實裝：

```
基礎激活: B_i = ln(Σ_j t_j^{-d})            d = 0.5（衰減率）        ← 未實裝
擴散激活: S_ji = S - ln(fan_j)              S = 2.0（最大聯想強度）  ← 未實裝
         W_j = 1.0 / len(context_chunks)                            ← 未實裝
完整方程: A_i = B_i + Σ_j(W_j × S_ji) + ε_i  ε = 0.5（雜訊）        ← 未實裝
檢索閾值: τ = -2.0    延遲: T = 0.35 × e^{-A_i}
```

目前實裝的僅為扇出懲罰 `fanPenalty = 0.015 × log(fan(term))`（對應 ACT-R 的扇出效應，Anderson 1974），完整激活方程約五十行未接。其中衰減率、最大聯想強度、雜訊、檢索閾值等均為規劃中的初始預設值。

### 3.5.7 歷史統一公式設計稿（乘法版，非現行實裝）

演進中曾出現一份七因子的統一公式設計稿，採用乘法形式：

```
F(w) = Activation(w) × IB-tradeoff(w) × (1+λ·Sys(w))
     × LogicScore(w) × PathHarmony(w) × NoveltyBonus(w) × Σαₐ·scoreₐ(w)
```

其中各分項定義為：激活 `A(w) = A₀·∏[γ·wₖ·I_disc(k)]`（γ 取 0.7–0.85，鏈長 K 不超過 3，學科切換指示 I_disc 在跨學科時為 1、同學科時為 0.5，激活低於 0.15 時停止）；資訊瓶頸權衡 `Score(w) = d(w)/(1+α·d(w)²)`，最優距離 `d* = 1/√α`（倒 U 型，中間值最優）；結構映射 `Sys = 0.5·H(高階關係) + 0.3·R(一階) + 0·A(屬性不計分)`；路徑和諧 `log(1+不同學科數) × 連貫性`，連貫性等於 `1 − (切換次數−學科數)/總步數`；新穎度 `1/√(historical_count+1)`（置信上界的簡化版）。

需強調：此設計稿為七因子乘法版本，與 3.4 節目前實裝的加性 CombSUM 版本不同。它是演進過程中被「加性優於乘法」論據取代的中間態，非現行實裝。

### 3.6.3 需人工複核的重點

有三處相似度較高，列為需人工複核的重點。

其二，一套熱/溫/冷三層記憶結構（arXiv 2603.00037，2026-03-18）不僅同名，且同樣以實體檔案目錄分層、同樣有日期命名日誌；本系統的三層設計起始時間據專案記錄早約數日，但差距僅數日、機制高度相似——這是相似度最高的一項，需核對專案記錄以確認獨立平行發明。

其三，系統中的部分變數更新與範本引擎能力來自 SillyTavern 生態的移植（如變數更新機制及提示詞範本引擎），發布時須致謝相應上游專案；本系統在此之上的原創擴展限於執行依賴鏈的編排與服務端整合。

### 3.6.5 全域事實層小結

綜合來看，可得如下事實層結論。第一，演算法線無一項在「機制高度相似且早於 2026-04」的意義上撞車（A=0）；框架/系統線僅三層記憶一項相似度極高（差數日、同名加實體檔案）。第二，本系統的原創性主張普遍落在「組裝/遷移/設計論據」層，而非單個零件——所涉零件（反距離加權、Hough 投票、CombSUM、MMR、側抑制、激活擴散、粗到細路由、熱載入詞庫等）多為 1990 年代至 2020 年代的成熟技術，本系統不主張發明它們；未找到公開對應的是「把它們編排成一條為發散服務的外掛管線」以及若干具體判據與遷移（Hough 遷移至方向詞產生、括號雙信道、廢詞判據、詞庫檔案即發散軸、加性對抗乘法的與門論據）。第三，上述三處高相似項需人工複核。

## 3.7 小結

本章形式化描述了自驅動發散召回系統的演算法設計。核心可歸納為三層。在機制層，系統以「收縮—發散—收縮」的三段結構外掛於大語言模型之外，透過兩次異質發散、六軸面並行、空間加性投票與多對一收攏，把孤立的關聯點轉換為可供主模型使用的方向詞。在評分層，BLQ 框架以加權 CombSUM 的加性打分對抗乘法鏈的單維否定，輔以側抑制、MMR 配額、軟地板與紅線硬剔，形成一套完整而可白盒審讀的候選品質裝置；其中資訊詞精排引擎目前為組件態，方向詞輕量精排為線上活躍態。在原則層，全流程遵循 0-token 白盒立場，不為單次發散呼叫大語言模型。

從相關工作對照看，系統所用的單個演算法零件多為成熟技術，其原創性主張落在編排、遷移與設計論據三個層面；逐項核查未發現在「機制高度相似且早於設計期」意義上的撞車，僅有若干高相似項需進一步人工複核。演進史中被證偽的方案——以十三因子乘積、軸均值、乘法版統一公式為代表——共同支撐了目前「加性優於乘法、軟隔離優於硬歸零」的設計取向，構成本系統演算法設計的負面證據基礎。
