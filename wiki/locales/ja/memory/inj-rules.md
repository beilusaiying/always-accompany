# INJ ルール設定

各 INJ ルールのフィールド定義、ゲートロジック、排他関係について説明します。

## INJ ルールのフィールド説明

各 INJ ルールは以下のフィールドで定義されます：

| フィールド | 型 | 説明 |
|------|------|------|
| **name** | 文字列 | ルール名の識別子（例：INJ-1-chat） |
| **content** | 文字列 | インジェクションするコンテンツテンプレート、`{{macro}}` マクロ置換をサポート |
| **autoMode** | 列挙 | ゲートモード：chat/code/work/bot/always/all/manual/file（カスタムモードのドメイン名も可） |
| **depth** | 数値 | インジェクション深度：999=システムレベル, 0=最新メッセージ後, N=第 N ターン前 |
| **role** | 列挙 | メッセージロール：system/user/assistant |
| **enabled** | ブール | 有効かどうか |

## デフォルト INJ ルールの詳細

### INJ-1-chat

- **autoMode**: `chat`
- **depth**: `999`（システムプロンプトレベル）
- **role**: `system`
- **機能**: chat モードでの記憶テーブルシステムを AI に説明します。内容には #0-#9 各テーブルの名称、格納内容、書き込みフォーマット、および `<tableEdit>` タグの構文説明が含まれます。

**動作チェーン**: ユーザーが chat モードにいる → autoMode がマッチ → INJ-1-chat の content が system メッセージとしてコンテキストの最前部にインジェクション（depth 999）→ AI が記憶テーブルの使い方を把握します。

### INJ-1-write-code

- **autoMode**: `code`
- **depth**: `999`
- **role**: `system`
- **機能**: code モードでの記憶テーブルシステムを AI に説明します。内容には C0-C5 各テーブルの名称、格納内容、書き込みフォーマットが含まれます。

### INJ-1-work

- **autoMode**: `work`
- **depth**: `999`
- **role**: `system`
- **機能**: work モードでの記憶テーブルシステムを AI に説明します。内容には W0-W4 各テーブルの名称、格納内容、書き込みフォーマットが含まれます。

### INJ-2

- **autoMode**: `file`（ファイル層設定により決定）
- **depth**: 設定可能
- **role**: `system`
- **機能**: キャラクターファイルやプリセットからの追加 AI プロンプトをインジェクションします。キャラクター固有の行動指針、文体要件などが含まれる場合があります。

**排他**: IDE 接続時はシステムが INJ-2 の代わりに INJ-2-code バリアントを使用します。両方が同時に有効になることはありません。

### INJ-3

- **autoMode**: `bot`
- **depth**: 設定可能
- **role**: `system`
- **機能**: Bot プラットフォーム（Telegram、Discord など）専用のプロンプトをインジェクションします。プラットフォーム固有のインタラクションルール、メッセージフォーマットの制約などが含まれます。

## autoMode ゲートロジック

```
メッセージを受信し、現在の環境を確定
    ↓
すべての INJ ルールを走査
    ↓
各ルールの autoMode をチェック：
  chat   → 現在は chat モードか？（airp エイリアスドメインを含む）
  code   → 現在は code モードか？
  work   → 現在は work モードか？
  bot    → 現在は Bot プラットフォーム接続か？
  always / all → 無条件通過（全モード）
  manual → オンであれば有効
  file   → 現在はファイル/IDE モードか
    ↓
ゲートを通過した INJ がインジェクションキューに入る
    ↓
排他関係をチェック、競合するものは 1 つだけ保持
    ↓
マクロ置換を実行 → depth でソート → コンテキストにインジェクション
```

## depth とコンテキスト位置

depth 値はコンテキスト内の物理的な位置を決定します。depth を理解するにはまずコンテキストの構造を理解する必要があります：

```
[depth 999] システムプロンプト領域
  ├─ キャラクター設定
  ├─ INJ-1 テーブル説明（depth 999）
  └─ その他のシステムレベル INJ
    ...
[depth N] チャット履歴領域
  ├─ 第 N ターンの会話
  ├─ ...（ワールドブック atDepth エントリはここに挿入）
  ├─ 第 2 ターンの会話
  ├─ 第 1 ターンの会話
[depth 0] 最新メッセージ領域
  └─ ユーザーの最新メッセージ
```

depth 値が大きいほど前方（システムレベル）、小さいほど最新メッセージに近くなります。

## 排他ルールの詳細

### INJ-1 シリーズの排他

3 つの INJ-1（chat / write-code / work）は autoMode により自然に排他されます——同時に 1 つのワークモードしかないため、1 つの INJ-1 の autoMode だけがマッチします。

### INJ-2 vs INJ-2-code

INJ-2 と INJ-2-code は同じ位置の 2 つのバリアントです：

- **INJ-2**：標準のファイル層プロンプト、通常の会話シーンに適用
- **INJ-2-code**：IDE 接続時のファイル層プロンプト、コード関連の追加ガイドが含まれる場合あり

切替ロジック：システムが IDE 接続を検知 → INJ-2-code を使用；未接続 → INJ-2 を使用。

## マクロ置換の詳細

マクロは INJ の content 内で `{{マクロ名}}` の形式で記述し、インジェクション時に実際の値に置換されます。

**よく使われるマクロの分類**：

| 分類 | マクロ例 | 説明 |
|------|--------|------|
| キャラクター情報 | `{{char}}`、`{{charName}}` | 現在のキャラクター名 |
| ユーザー情報 | `{{user}}`、`{{userName}}` | 現在のユーザー名 |
| 時間情報 | `{{time}}`、`{{date}}`、`{{weekday}}` | 現在の時刻・日付 |
| システム情報 | `{{model}}`、`{{maxTokens}}` | 現在のモデルと設定 |
| 記憶情報 | `{{tableContent_N}}`、`{{memoryCount}}` | 記憶テーブル関連 |

マクロ置換の完全なリストは約 30 種類あります。詳しくはマクロシステムのドキュメントをご参照ください。

## カスタム INJ ルール

組み込みの複数の INJ のほかに、カスタムルールの追加もサポートしています。カスタムルールでは以下を指定する必要があります：

1. 一意の name 識別子
2. content 内容（マクロ対応）
3. autoMode ゲート条件
4. depth インジェクション位置
5. role メッセージロール

カスタムルールはデフォルトルールと同じゲートおよびインジェクションロジックに従います。

## デバッグのヒント

- INJ が有効かどうかを確認：autoMode が現在のモードとマッチしているか、enabled が true であるかを確認します
- インジェクション位置を確認：depth 値が期待通りかを確認します
- マクロ置換を確認：`{{macro}}` が正しく置換されているか確認します（スペルミスのマクロは置換されず、そのまま残ります）
- 排他の競合を確認：期待する INJ が有効にならない場合、排他ルールにより除外されていないかを確認します
