cd always-accompany
run.bat          # Windows

Откройте в браузере `http://localhost:1314` → настройте источник AI-сервиса → импортируйте карточку персонажа → начните общение. Трёхслойная рекурсивная память (архивирование день → месяц → год, чистый JSON, вместимость 260 лет) + AI предварительной выборки (выделенный ИИ, который только ищет релевантные воспоминания и передаёт их AI-ответчику — каждый занимается своим делом) + послойная очистка контекста (очистка означает лишь то, что информация больше не отправляется повторно; исходный текст остаётся и всегда может быть восстановлен). Эти три элемента работают вместе так, что ИИ продолжает помнить каждое сказанное вами слово, не будучи ограничен окном контекста. На этой основе мы построили чат/ролевую игру, режим программирования IDE, рабочий режим (включая создание слайдов силами ИИ), настольного питомца Live2D (осознание экрана + игровое сопровождение), голосовой ввод, Discord-бота и интеграцию внешних инструментов через MCP — все точки входа используют одну и ту же память, поэтому смена окна никогда не заставляет ИИ забыть вас. Сейчас дорабатывается: движок поиска нового поколения (чисто алгоритмический конвейер из 21 узла, ноль LLM, ноль сети, миллисекундная скорость, цель — внимание на уровне предложения).

## Подробные механизмы

<details>
<summary><strong>🧠 Трёхслойная рекурсивная память — зачем разбивать на слои</strong></summary>

Если сваливать всю историю в один большой пул, поиск замедляется — и экспериментальные данные это подтверждают ([Lost in the Middle](https://arxiv.org/abs/2307.03172) / [RULER](https://arxiv.org/abs/2404.06654) / [NoLiMa](https://arxiv.org/abs/2502.05167)): даже если информация там есть, модель может её попросту не увидеть. Опираясь на то, как гиппокамп формирует воспоминания, и на кривую забывания Эббингауза, мы разделили информацию на три слоя по временной дистанции:

```
🔥 Горячий слой — автоматически внедряется каждый ход: профиль пользователя / постоянные воспоминания / незавершённые задачи / недавние воспоминания
🌤️ Тёплый слой — извлекается по запросу (последний месяц): ежедневные сводки / временные архивы / месячный индекс
❄️ Холодный слой — глубокое извлечение (старше месяца): месячные сводки / исторические ежедневные сводки / годовой индекс
```

Горячий слой занимает всего около 7 000–11 000 токенов за ход (5–9% от окна в 128K). Затухание памяти заимствовано у кривой забывания Эббингауза: `score = weight × (1 / (1 + days × 0.1))`. Полностью управляется промптом — чтобы изменить стратегию архивирования, смысл таблиц или стиль поиска, достаточно отредактировать промпт, код трогать не нужно.

</details>

<details>
<summary><strong>🎯 AI предварительной выборки P1 — зачем разделять на два ИИ</strong></summary>

Если бы AI-ответчику пришлось самому выбирать релевантные фрагменты из сотен записей истории, он одновременно искал бы и отвечал, и его внимание распылялось бы между двумя задачами. Поэтому мы вынесли «поиск воспоминаний» в отдельный небольшой ИИ:

```
Пользователь отправляет сообщение → AI поиска P1 (< 5K токенов, сфокусирован только на поиске) → отобранные воспоминания + текущий разговор → AI-ответчик (сфокусирован только на ответе)
```

Грубая фильтрация BM25 + точное сопоставление regex, достигает цели максимум за 3 раунда. Поиск отлично работает на бесплатной лёгкой модели, поэтому реальная стоимость на один разговор фактически равна одному вызову AI-ответчика. P1 также отвечает за автоматическое переключение пресетов (с 5-ходовым охлаждением для предотвращения колебаний).

</details>

<details>
<summary><strong>🗜️ Управление контекстом — детализация сжатия × уровни × автономная очистка ИИ</strong></summary>

Пока ИИ работает, постоянно накапливается процессный контент (повторное чтение одного и того же файла, устаревшие результаты поиска, старые результаты инструментов). Наша очистка всегда лишь скрывает — всё можно восстановить в любой момент.

**Автономная очистка ИИ**: система выдаёт ИИ сигналы о собственном использовании контекста (50% — рекомендация / 70% — предупреждение / 85% — срочно), и ИИ использует команды `<contextClean>`, чтобы самостоятельно облегчить контекст. Перед очисткой всё сохраняется, поэтому ошибка всё равно обратима.

**Тонкая настройка пользователем**: три уровня (полная очистка в один клик / по типу / построчный ручной выбор) × четыре степени детализации (сообщения чата / построчный счёт токенов при чтении файлов / пять отмечаемых категорий системных инъекций / автоматически облегчаемый процессный контент).

Измеренный процент попаданий в кэш (Opus + DeepSeek, включая переключение персоны ИИ + автономное сжатие): **75%–80%**.

![Панель сжатия](imgs/screenshots/compression-multi.png)

</details>

<details>
<summary><strong>🔬 Самоуправляемый P1 — движок поиска без LLM в активной разработке</strong></summary>

ИИ P1 должен отправлять API-запрос каждый ход — а это задержка, стоимость и невозможность работы офлайн. Мы построили полностью алгоритмический конвейер (21 узел, ~9 000 строк), нацеленный на миллисекундную скорость, нулевую зависимость от сети и внимание на уровне предложения.

**Основа данных**: [китайская ассоциативная сеть SWOW](https://smallworldofwords.org/) / [300-мерные векторы слов ConceptNet Numberbatch](https://github.com/commonsense/conceptnet-numberbatch) (~300 тыс. слов) / китайский граф отношений ConceptNet / THUOCL и другие мультиисточниковые словари. Лексикон был собран через веб-поиск ИИ + 2 дня самопроверки, при почти нулевой стоимости сборки.

**Конвейер**: токенизация → ассоциативная дивергенция SWOW (диффузия синонимов запрещена — её включение измеримо снижает качество на 55–76%) → параллельная оценка по шести осям (психологической / информационной / социальной / логической / лингвистической / когнитивной) → локализация по 47 поднаправлениям → перекрёстное подтверждение из нескольких ресурсов → ранжирование пространственным голосованием (аддитивный IDW, не мультипликативный) → вторичная дивергенция (5 независимых путей) → оценка BLQ (со ссылкой на аддитивное слияние CombSUM, с самостоятельно разработанными весами измерений) → выбор направляющего слова → инъекция в контекст. Все 21 узел — чисто алгоритмические, ноль LLM.

**Эксперименты**: 27 итераций версий; оценка дивергенции выросла с 2,01 до 4,05 между v9 и v26 (+101%, из 5 баллов, оценивалось вручную слово за словом); процент попаданий при отзыве ~90%; общий средний балл ~3,5. Доля универсальных «шаблонных» ответов упала с 74% до 4%.

**Реальный вывод** (сырые записи по итогам пакетного прогона на 200 кейсах):

| Ввод пользователя | Дивергентное направление системы | Дисциплина, в которую перешли |
| --- | --- | --- |
| «Больше не могу держаться, почему жить так тяжело?» | Осознанность настоящего момента / интероцептивное осознавание / **какова природа реального** | Психология → **философия экзистенциализма** |
| «Готовлюсь к собеседованию в компанию-единорог, как придумать по-настоящему глубокие вопросы?» | Анализ первопричин / **зона ближайшего развития** | Менеджмент → **педагогическая психология** |
| «Вернуть ушедших пользователей в собственном трафике при ограниченном бюджете» | **Активация сети пассивного режима работы мозга** / **BDNF (нейротрофический фактор мозга)** | Маркетинг → **когнитивная нейронаука** |
| «Запросы к базе данных ужасно медленные, как оптимизировать» | Неизменяемость и обновления состояния / **SRP (принцип единственной ответственности)** | Эксплуатация → **методология разработки ПО** |
| «История о фехтовальщике, встретившем врага на заснеженной горе» | **Ружьё Чехова** / архетипы Юнга | Художественная проза → **нарратология + аналитическая психология** |
| Оригинальное стихотворение пользователя «Я умер до того, как пришёл свет» | **Возможные миры и параллельные вселенные** | Поэзия → **многомировая интерпретация в физике** |

Критерий допуска в лексикон: **слово, которое основная модель и так могла бы вывести, просто прочитав исходный ввод, — бесполезное слово**. Ценность P1 в том, чтобы давать модели направления, до которых она сама бы не додумалась.

</details>

<details>
<summary><strong>👑 Движок промптов + динамическая инъекция world book</strong></summary>

**Три раунда TweakPrompt** единообразно перехватывают вывод всех модулей: Round 1 — сбор → Round 2 — пересборка 5-сегментной структуры сообщения (beforeChat / injectionAbove / chatHistory / injectionBelow / afterChat) + подстановка макросов → Round 3 — снимок.

**У world book 3 режима активации**: постоянный (внедряется каждый ход) / regex (срабатывает по ключевому слову) / динамический (срабатывает при чтении числовых условий из таблиц памяти — например, симпатия > 80 разблокирует особый диалог, или прогресс квеста при достижении 3-й главы меняет описание мира).

**Система макросов**: `{{char}}` / `{{user}}` / `{{tableData}}` / `{{hotMemory}}` / `{{current_date}}` / `{{time}}` / `{{idle_duration}}` + пользовательские макросы.

</details>

<details>
<summary><strong>🏗️ Архитектура системы</strong></summary>

Три слоя: **функциональный слой** (память / сжатие / вспоминание / пресеты / world book / сеть / файловые операции… единая глобальная копия) → **транспортный слой** (каждое окно тянет свою собственную линию, изолированную по id, естественно асинхронную и неблокирующую) → **слой интерфейса** (веб / бот / настольный питомец / расширение VSCode — смена интерфейса без потери каких-либо возможностей).

Изоляция данных: уровень пользователя (AI-источники / глобальные настройки) / уровень карточки персонажа (память / чат / world book / regex) / уровень разговора (история чата / режим / подрежим).

Все 22 плагина растут по единой спецификации, MCP подключает внешние инструменты, а хост плагинов уровня пользователя монтирует Python/Node-программы — расширения никогда не трогают код ядра.

</details>

<details>
<summary><strong>🔭 Об эпохе гигантских окон контекста</strong></summary>

Даже если окна контекста расширятся до 10M+ токенов, мы всё равно сохраняем послойную память: ① есть надёжные экспериментальные доказательства, что использование контекста деградирует с ростом длины; ② ~10K токенов отобранной памяти несут объём информации, эквивалентный 100K+ токенам сырой истории, при на порядок меньшей стоимости; ③ структурированные таблицы легче точно читать и писать ИИ, чем информацию, разбросанную по разговору.

</details>

## Использованные технологии и ресурсы

- **Транскрипция речи**: [MOSS-Transcribe-Diarize](https://huggingface.co/ICTNLP/MOSS-Transcribe-Diarize) (локальное развёртывание с разделением говорящих; модель, ~1,8 ГБ, скачивается автоматически при первом использовании)
- **Векторы слов**: [ConceptNet Numberbatch](https://github.com/commonsense/conceptnet-numberbatch) (Speer & Lowry-Duda, 2017)
- **Ассоциативные данные**: китайский ассоциативный датасет [SWOW (Small World of Words)](https://smallworldofwords.org/)
- **Токенизация и словари**: THUOCL / CoreNatureDictionary / Chinese-Synonyms и другие открытые ресурсы
- **Мост поисковой системы**: [ddgs](https://pypi.org/project/ddgs/) (слой TLS-фингерпринтинга на Python, решающий проблему понижения приоритета «сырых» fetch-запросов поисковыми системами)
