# 記憶歸檔與檢索

記憶歸檔是記憶系統的「新陳代謝」——將不再活躍的記憶從熱層自動搬遷到溫層和冷層，同時提供召回引擎在需要時將相關記憶拉回。這保證了熱層不會無限膨脹，同時歷史記憶不會真正丟失。

## 三層搬遷路徑

```
hot（熱層）
  ↓ 自動搬遷（條目老化/容量管理）
warm（溫層）
  ↓ 進一步老化
cold（冷層/歸檔）
```

### hot → warm 搬遷

觸發條件：
- 記憶條目超過一定時間未被存取
- 熱層總容量接近上限
- P2 總結歸檔後，原始細節條目降溫

搬遷後，條目從每輪自動注入變為**按需召回**。

### warm → cold 搬遷

觸發條件：
- 溫層條目繼續老化，長時間未被召回
- 溫層容量管理需要

搬遷後，條目進入長期歸檔，僅在**主動搜尋**時可達。

## 搬遷的例外

以下內容**不參與搬遷**，始終留在熱層：

- `forever.json` 中的永久記憶
- 目前活躍的表格條目（正在使用的表格列）
- 系統級設定資訊

## 召回引擎

召回引擎是 P1 自驅動管線的核心元件，負責從 warm/cold 層中找到與目前對話相關的記憶條目並拉入上下文。

### 召回流程

```
使用者發送訊息
    ↓
NLP 分詞：提取使用者訊息的關鍵詞
    ↓
聯想擴展：對關鍵詞進行語義聯想
    例：「下雨」→「雨、天氣、傘、淋溼、潮溼」
    ↓
多詞共現比對：在 warm/cold 層中搜尋
    - 查找同時包含多個關鍵詞/聯想詞的條目
    - 多詞共現比單詞比對更精確
    ↓
四維打分（對每個候選條目）：
    ↓
排序取 top-N 條目
    ↓
注入本輪上下文
```

### 四維打分細節

| 維度 | 評估內容 | 說明 |
|------|----------|------|
| **semantic** | 語義相關度 | 條目內容與目前話題在語義層面的比對程度 |
| **lexical** | 詞彙比對度 | 關鍵詞的直接文字比對，精確度高 |
| **recency** | 時間近度 | 越近期的記憶得分越高，體現「越近越容易想起」 |
| **importance** | 重要性 | 被標記為重要的記憶得分更高，體現優先級 |

四個維度各自計算得分後加權求和，最終排序。權重設定可調。

### 多詞共現

多詞共現是召回精度的關鍵機制。單個關鍵詞比對會召回大量不相關的條目，而要求多個關鍵詞同時出現在條目中，可以顯著提升相關性：

- 使用者說「上次在公園遇到那隻貓」→ 提取關鍵詞「公園」、「貓」
- 只含「公園」的條目和只含「貓」的條目不會被優先召回
- 同時含「公園」和「貓」的條目會獲得高分

## 快照管理

在[記憶管理](beilu:mode/memory)中點擊工具列的 **snapshot** 按鈕，或在記憶運維區切換到「快照」子 Tab，可管理記憶快照。

快照分為兩類：

### 記憶快照

- **建立**：點擊建立按鈕，可附帶說明文字描述本次快照的目的
- **恢復**：從快照清單中選擇一條，確認（confirm）後恢復到該快照時的記憶狀態
- **清單**：按時間倒序展示所有已建立的記憶快照

### Git 快照

- **建立**：點擊建立按鈕，輸入 label 作為標籤標識
- **恢復**：選擇一條 Git 快照恢復；系統會在恢復前自動建立一個 pre-restore 保險快照，防止誤操作導致資料丟失
- **清單**：按時間倒序展示所有已建立的 Git 快照

## 歸檔工具列

在[記憶管理](beilu:mode/memory)的檔案瀏覽器中，頂部歸檔工具列提供以下批次操作：

| 操作 | 說明 |
|------|------|
| 歸檔臨時記憶 | 將臨時記憶條目從熱層搬遷到溫層 |
| 結束當天 | 執行當天的收尾歸檔流程 |
| Hot 轉 Warm | 手動將選中的熱層條目搬遷到溫層 |
| Warm 轉 Cold | 手動將選中的溫層條目搬遷到冷層 |
| 歸檔已完成任務 | 將標記為已完成的任務記憶歸檔 |

這些操作是自動搬遷機制的手動補充，適用於需要立即整理記憶層級的情境。

## 檢索設定

在[記憶管理](beilu:mode/memory)中點擊工具列的 **retrieval** 按鈕，或在檢索/診斷區切換到「檢索」子 Tab，可調整召回引擎的運行參數：

- **P1 自動觸發 toggle**：開關 P1 每輪對話前的自動召回
- **引用聊天條數**：控制召回時參考的近期聊天輪數（分模式獨立設定）
- **最大搜尋輪數**：P1 多輪搜尋的上限
- **逾時**：搜尋逾時時間設定

## 格式檢查

在[記憶管理](beilu:mode/memory)中點擊工具列的 **format** 按鈕，或在記憶運維區切換到「格式」子 Tab，可對記憶檔案進行格式合規檢查。

- **掃描**：點擊掃描按鈕啟動檢查
- **統計**：顯示符合 / 警告 / 錯誤 / 總計四項計數
- **按檔案統計**：每個檔案的檢查結果分別列出
- **問題清單**：展示前 20 條格式問題的詳細資訊
- **一鍵升級**：對可自動修復的格式問題執行批次升級

## 對使用者的影響

- 歸檔和召回都是自動進行的，使用者無需手動操作
- AI「忘了」某件事，可能是因為該記憶已搬遷到冷層且未被召回引擎觸發
- 透過在對話中提及相關關鍵詞，可以幫助召回引擎找到冷層中的相關記憶
- 特別重要的資訊建議讓 AI 標記為「永遠記住」，進入 forever.json 免於搬遷

## 對開發者的說明

- 搬遷的時間閾值和容量閾值在設定中可調
- 召回的 top-N 數量影響上下文佔用，需要平衡召回品質與上下文空間
- 四維打分的權重可以根據實際效果調整
- 聯想擴展的品質直接影響召回覆蓋率，是召回效能的瓶頸之一
- 冷層儲存沒有容量限制，但搜尋效能需要關注
