# MCP 外部工具

MCP（Model Context Protocol）是给 AI「外接工具」的通用插座标准：天气查询、数据库、浏览器自动化……只要一个服务实现了 MCP 协议，就能接进来变成 AI 手里的新工具。always-accompany 内置了 MCP 导入器，并在它外面包了一整套安全层——**默认拒绝危险动作，一切由你批准**。

## 导入一个 MCP 服务器

1. 进入编程模式，点击活动栏的 **mcp** 按钮打开 MCP 面板
2. 把 MCP 服务器的 JSON 配置粘进去（就是各家文档里常见的 `{"mcpServers": {...}}` 格式）
3. 每个服务器会变成一个**独立插件**，出现在面板列表里，可以单独启用 / 禁用

一份配置里有多个服务器也没关系，会被拆成多个插件分别管理。

## 命令型服务器：先过你的批准闸

MCP 服务器分两类：

| 类型 | 配置特征 | 风险 |
|------|---------|------|
| **远程型** | 配置里是 `url` | 走网络连接远程服务 |
| **命令型** | 配置里有 `command` | **在你的电脑上启动一个子进程**——等于运行一段任意程序 |

命令型服务器导入后**不会立刻启动**。因为「导入一段 JSON 就能在你电脑上跑任意命令」是典型的远程代码执行风险，所以系统默认拦下 spawn，面板上显示「待批准」状态，并弹出确认卡片让你看清它要执行的命令。

- 只有实例 owner 点击**批准**后，子进程才会真正启动
- 批准后立即生效，不需要重启整个服务
- 不批准就一直安全地躺在列表里，随时可以删

这和[审批与权限](approval.md)是同一个设计哲学：危险的事，AI 和第三方都做不了主，你做主。AI 发起的 `mcpConnect` 也只是**登记一条待人工审查的请求**——AI 不能替你批准。

## 面板状态是真值巡检，不是"配置了就当健康"

MCP 面板显示的连接状态来自运行时真值巡检（runtime registry），按 `configured（已配置）→ approved（已批准）→ connected（已连接）/ error（出错）` 聚合展示，并显示每个服务器实际提供的工具数（toolCount）。服务器工具清单变化时（MCP 原生 `tools/list_changed` 通知）状态自动刷新——面板说"已连接"就是真连着，说"出错"就能看到错在哪，不会出现"显示健康实际不通"的假状态。

## 环境变量白名单：不把你的密钥交出去

命令型 MCP 服务器是第三方程序。如果把你整台机器的环境变量原样传给它，你的 API 密钥、各种 Token 就全暴露了。所以：

- **默认只透传基础变量**（PATH、HOME、TMP 这类程序运行必需项）+ 你在该服务器配置里**显式写的 `env` 字段**
- 某个服务器确实需要读你的某个宿主变量时，两种放宽方式：
  - 全局：设环境变量 `BEILU_MCP_ENV_ALLOWLIST`，逗号分隔要放行的变量名
  - 单个服务器：在其配置里写 `envAllowlist` 数组

换句话说：第三方工具想拿什么，得你亲手递给它。

## 其他内置防线

这些不需要你操作，了解即可：

- **防内网探测**：多用户 server 部署模式下，远程型 MCP 的地址会经过出站安全检查，拒绝指向内网 / 云元数据的地址（防止有人借你的服务器探测你的内网）
- **防伪装**：远程服务器提供的工具名、描述和返回结果都会做尖括号中性化处理——防止它在内容里伪造系统协议标签，冒充「系统指令」骗过 AI
- **防目录穿越**：导入配置里的服务器名会被净化，不能借 `../` 之类的名字把文件写到插件目录之外

## 工具怎么出现在 AI 手里

导入并启用后，注入给 AI 的内容分两层：

| 层 | 内容 | 谁维护 |
|----|------|--------|
| 数据层 | 该服务器的工具 / Prompts / Resources 清单 | 系统实时自动生成，你不用管 |
| 提示词层 | 「怎么用这些工具」的引导文案 | 你可以在面板里自己改，不改就用默认文案 |

两层拼在一起，通过 `{{mcp_tools}}` 宏进入 AI 的上下文。之后 AI 就会在回复里用 `<mcp-tool>` 等标签调用这些工具，执行结果自动注入下一轮对话——和 IDE 工具走同一条结果回传链路（见[执行链路](architecture.md)）。

## 已知限制

- 面板里的「移除」目前只是**把服务器从当前对话卸下**，并不会真正卸载它——插件本体仍保留在插件目录和默认插件集里。想彻底清掉需要到插件管理里处理。
