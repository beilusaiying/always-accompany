# 権限と認証

always-accompany の認証システム（auth.mjs）は JWT、API Key、ユーザー CRUD、ブルートフォース防御をカバーしています。

## 認証体系

always-accompany の認証システム（auth.mjs）は5つのコア機能ドメインを網羅しています：

1. JWT の発行 / 検証 / リフレッシュ / 失効
2. 認証ミドルウェア（ルート保護）
3. API Key の管理と scope 体系
4. ユーザー CRUD（登録/ログイン/名前変更/アカウント削除/パスワード変更/セキュリティ質問によるパスワードリカバリー）
5. ブルートフォース防御

## 初期化フロー

サーバー起動時に `initAuth()` が以下の初期化を完了します：

- ES256 鍵ペアの読み込み（JWT 署名検証用）
- Argon2 ウォームアップ（パスワードハッシュアルゴリズム。Rust FFI 実装を優先し、利用不可の場合は純 JS にフォールバック）
- ユーザーデータのクレンジング

## 認証パス

リクエストが保護されたエンドポイントに到達すると、`try_auth_request` が優先度順に4つの認証パスを試行します：

| 優先度 | 認証方式 | ソース | 説明 |
|--------|---------|------|------|
| 1 | API Key | `x-api-key` header | SHA256 ハッシュテーブルで検証 |
| 2 | API Access Token | `cookies.apiAccessToken` | JWT api タイプ（scopes を透過し、ロンダリングを防止） |
| 3 | Access Token | `cookies.accessToken` | JWT 標準検証（本人セッション、scope=['*']） |
| 4 | Refresh Token | `cookies.refreshToken` | リフレッシュトークン更新（ローテーション + 永続化で再起動時のロスを防止） |

最初にヒットした時点で返却し、後続のパスは試行しません。

## ミドルウェア

### authenticate

標準認証ミドルウェアです。未認証のリクエストは 401 を返します。ログインが必要なすべてのエンドポイントがこのミドルウェアを使用します。

### requireOwner

Owner 権限ミドルウェアです。owner でないユーザーには 403 を返します。セキュリティポリシーの変更エンドポイント（セキュリティ関連設定の変更など）に使用されます。

### auth_request

内部認証リクエスト関数で、Express ルート以外のシーン（API v1 ルートなど）で使用されます。

## Owner 体系

### インスタンス Owner

最初に登録したユーザーが自動的にインスタンスの owner になります（`config.ownerUsername` に永続化）。Owner は最高権限を持ちます：

- セキュリティポリシーの変更（デプロイモード、セキュリティ関連設定）
- 他のユーザーアカウントの管理
- すべての owner-only エンドポイントへのアクセス

### ローカル単一ユーザー

ローカルデプロイの場合、唯一のユーザーが owner となり、すべての owner 権限が自然に付与されます。

## JWT 実装

### 署名アルゴリズム

ES256（ECDSA P-256）アルゴリズムを使用します。鍵ペアは初回起動時に自動生成され永続化されます。秘密鍵は config.json には保存されず（セキュリティ分離）、モジュール変数が保持します。

### Token 有効期限

| Token タイプ | 有効期限 |
|-----------|--------|
| Access Token | 1 日 |
| Refresh Token | 30 日 |

### Token リフレッシュ

Refresh Token はローテーション機構に対応しています：Refresh Token で更新するたびに古い Token が失効し、新しい Token が発行されます。Refresh Token はディスクに永続化され、サービス再起動によるユーザーのログアウトを防ぎます。

### Token キャッシュ

JWT 検証結果はメモリにキャッシュされ（直近 32 件）、繰り返し検証の暗号学的オーバーヘッドを削減します。

## API Key

### 管理

Owner は API Key を作成でき、各 Key は特定の scope（権限範囲）に紐付けされます。Key は SHA256 ハッシュ形式で保存され、平文は作成時に1回のみ表示されます。

### SEC-T6 Scope 体系

API Key の scope は、アクセス可能なエンドポイントの範囲を決定します。`requireApiKeyScope` ミドルウェアがエンドポイントレベルの scope チェックを行い、低権限 Key による高権限機能へのアクセスを防ぎます。

API Access Token（API Key から発行された JWT）は scopes フィールドを透過し、scope のロンダリングを防止します（JWT リフレッシュ時に元の scopes を保持）。

## ブルートフォース防御

### アカウントロック

ログインが連続 5 回失敗すると、アカウントが 10 分間ロックされます。

### ハニーポット機構

ブルートフォース試行がしきい値（8 回）を超えると、システムは一定確率（1/3）で「偽の成功」レスポンスを返します。これにより攻撃者は本物のパスワードと偽の成功を区別できなくなり、解析の難度が上がります。

### タイミング攻撃保護

ログイン検証は定数時間比較を使用し、レスポンス時間の差異からパスワードの正否を推測されることを防ぎます。

## パスワード保存

ユーザーパスワードは Argon2id ハッシュで保存されます。`@node-rs/argon2`（Rust FFI 実装、パフォーマンスに優れる）を優先し、利用不可の場合は純 JavaScript 実装にフォールバックします。

## セキュリティイベント

auth モジュールはユーザーライフサイクルイベントで以下のイベントをトリガーし、他のモジュールがリッスンできます：

| イベント | タイミング |
|------|------|
| BeforeUserDeleted | ユーザー削除前 |
| AfterUserDeleted | ユーザー削除後 |
| AfterUserRenamed | ユーザー名変更後 |

## Cookie セキュリティ

Cookie オプションは接続タイプに応じて動的に設定されます：

- HTTPS 接続：`Secure` フラグを設定（リクエストプロトコルに基づいて動的に判定）
- 常に `HttpOnly` を設定（JavaScript からの読み取りを防止）
- `SameSite=Lax` を設定（クロスサイトの送信を制限しつつ、トップレベルナビゲーションとの互換性を確保）
