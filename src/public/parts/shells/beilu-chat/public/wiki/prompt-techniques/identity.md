# 身份设定技巧

身份设定是提示词的起点。AI 需要知道"我是谁"，才能决定"我该怎么说话、怎么做事"。一个好的身份设定，能让 AI 的整体表现方向对、风格稳。

## 具体的复合型身份

### 为什么不能笼统

"你是一个作家"——这太模糊了。AI 会套用它训练数据中"作家"的平均表现，结果就是毫无特色的通用输出。

身份设定要**具体**，最好是**复合型**的，用多个限定词叠加出一个精确的画像。

### 正确 vs 错误示例

```
错误：你是一个小说作家。

正确：你是一个非传统中国现代轻小说作家。
```

拆解这个复合身份：
- **非传统** —— 告诉 AI 不要走套路，避免模板化的"AI 味"写作
- **中国现代** —— 限定文化语境和时代背景
- **轻小说** —— 限定体裁风格，轻小说有自己的叙事节奏和对话密度

每多一个限定词，AI 的输出就更聚焦一层。

### 更多复合身份示例

| 场景 | 笼统身份 | 复合身份 |
|------|---------|---------|
| 角色扮演 | 你是一个 AI 助手 | 你是一个经历过战争的退役军医，性格沉稳但偶尔流露黑色幽默 |
| 写作辅助 | 你是一个编辑 | 你是一个专注于网文节奏把控的责任编辑，擅长砍掉拖沓段落 |
| 代码助手 | 你是一个程序员 | 你是一个偏好函数式编程、注重代码可读性的后端工程师 |

### "非传统"的妙用

在创作类场景中，加上"非传统"或类似的反套路限定词，可以有效减少 AI 的模板化倾向。AI 被训练了大量"传统"写法，如果不加限定，它会默认输出最"安全"的风格——而这往往就是最没有特色的。

```
效果对比：

"你是一个言情小说作家"
→ AI 倾向于：华丽辞藻、大量心理描写、套路化情节

"你是一个非传统现代言情作家"
→ AI 倾向于：更克制的表达、更日常化的对话、更意外的情节走向
```

## 功能模块化：AIRP 结构

当身份设定变复杂时，不要把所有内容挤在一段话里。用模块化的方式组织，每个模块负责一个方面。

### AIRP 结构

一套经过验证的提示词组织结构，适用于角色扮演和创作场景：

| 模块 | 内容 | 作用 |
|------|------|------|
| **A - 身份 (Actor)** | 角色的身份定义 | 告诉 AI "我是谁" |
| **I - 任务 (Instruction)** | 当前要做什么 | 告诉 AI "我该做什么" |
| **R - 用户画像 (Reader)** | 用户的偏好和特征 | 告诉 AI "我在和谁交流" |
| **P - 避免事项 (Pitfalls)** | 需要规避的表现 | 告诉 AI "什么不该做" |

在角色扮演场景中，还可以扩展更多模块：

| 扩展模块 | 内容 |
|---------|------|
| 角色扮演指导 | 角色的行为模式、说话习惯 |
| 叙事风格 | 第几人称、时态、节奏 |
| 戏剧风格 | 冲突处理、情绪表达方式 |
| 写作风格 | 用词偏好、修辞手法 |
| POV（视角） | 谁的视角叙述 |

### 模块化示例

```
错误：一段式堆砌
────────────────
你是一个非传统轻小说作家，要写校园日常故事，
用户喜欢轻松搞笑的风格，不要用太多比喻，
对话要自然，用第一人称，注意节奏不要拖沓，
角色说话要有口癖......
```

```
正确：模块化组织
────────────────
## 身份
你是一个非传统中国现代轻小说作家。

## 任务
围绕校园日常场景展开叙事，以对话推动情节。

## 用户画像
偏好轻松幽默的基调，喜欢角色之间的自然互动。

## 避免事项
避免大段心理独白和过度修辞。

## 叙事风格
第一人称，现在时态，节奏明快，场景切换干脆。

## 写作风格
以白描和对话为主，用词日常化，角色语言体现各自口癖。
```

模块化的好处：
- **易于维护**：哪里效果不好，改对应模块就行，不用通篇重写
- **层次清晰**：AI 能更准确地理解每个维度的要求
- **可复用**：好用的模块可以跨角色、跨场景复用

## 在 beilu 中的应用

beilu 的[预设系统](../presets/overview.md)本身就是模块化的——每个预设条目就是一个独立模块，可以自由组合。你在写角色卡或自定义预设时，可以直接参考 AIRP 结构来组织内容，把不同维度的指引放在不同的预设条目中。角色卡可在[编辑界面](beilu:editor/persona-edit)中编辑。
