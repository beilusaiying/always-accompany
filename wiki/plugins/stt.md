# 语音转录 (beilu-stt)

beilu-stt 让你**说话代替打字**：点一下麦克风，说完话，文字自动出现在输入框里。

它是**本地部署**的语音转文字——用的是 MOSS-Transcribe-Diarize 模型，在你自己的电脑上跑推理，不是云端语音 API。支持 50+ 语言、说话人分离、时间戳。

注意方向：这是"你说 → 变文字"（STT）。目前**没有**"AI 文字 → 变语音"（TTS）的反向能力，语音链路是单向的。

## 怎么用

1. 在扩展面板找到"语音转录"页，打开启用开关。
2. 首次使用需要下载模型权重（见下节）。
3. 聊天输入框会出现麦克风图标——点击开始录音，再点一下停止。
4. 录音结束后自动转录，文字回填到输入框，你确认后发送。

服务是**自动连接**的：点麦克风时如果后台转录服务还没启动，会自动拉起并等待就绪，你不需要手动"连接服务"。冷启动（第一次加载模型）可能需要一两分钟，期间界面会显示启动进度。

## 首次使用：下载模型

模型权重约 **1.8GB**，不随程序分发，需要在面板内联网下载一次。下载源有三个，适配各地区网络：

| 源 | 说明 |
|----|------|
| 自动选源（推荐） | 并行测速 HuggingFace 直链 / hf-mirror 镜像 / ModelScope 三个源，自动选最快的 |
| HuggingFace 直链 | 官方源 |
| hf-mirror 镜像 / ModelScope 魔搭 | 直链慢或不通时的替代源 |

下载支持**断点续传**——中断了不用从头来；单个源反复失败还会自动切换到下一个源接着下。模型默认存放在仓库根的 `moxin/` 目录。

## 后端录音 vs 浏览器录音

录音有两条路，默认走后端：

- **后端录音**（默认）：由转录服务直接采集系统麦克风。好处是能采到浏览器采不到的设备——比如 NVIDIA Broadcast、Voicemeeter 这类虚拟声卡，浏览器经常只能录到静音，后端直采没这个问题。还可以在设置里指定录音设备、开启服务端降噪。
- **浏览器录音**（自动降级）：如果后端录音暂时不可用（比如刚更新还没重启），会自动落回浏览器自带的录音，保证功能不断。

转录时还支持**热词**（提高专有名词识别率）和**降噪**开关。

## 桌宠也能用

桌宠（beilu-eye）的麦克风入口和主聊天共用同一个转录服务——对着桌宠说话，用的是同一套模型、同一份设备/降噪设置。

## 常见问题

**模型下载失败？** 换一个下载源再试（面板里可手动指定），已下载的部分会断点续传。

**点了麦克风没反应？** 看面板里的"环境检测"卡片——它会告诉你 Python 环境、依赖是否就绪。转录服务是 Python 进程，需要本机有可用的 Python。

**第一次录音等很久？** 冷启动要加载 1.8GB 模型进显存/内存，属正常现象；之后的录音就是秒级响应了。

**换了录音设备桌宠没生效？** 设备和降噪设置对聊天和桌宠是同一份配置，改完稍等几秒会同步到桌宠端。
