# 编程模式 (Code / IDE)

## 进入编程模式

| 方式 | 操作 |
|------|------|
| 顶部模式选择器 | 点击「Code」标签 |
| 键盘快捷键 | `Ctrl+3` 或 `Alt+3` |

## 不装编辑器也能用：两套后端

编程模式有两条路可走，AI 用的工具集完全一样：

| 后端 | 需要装什么 | 适合谁 |
|------|-----------|--------|
| **CLI**（内置） | 什么都不用装，随本体自动启动 | 只想让 AI 读写项目文件、跑命令，不开 IDE |
| **VSCode / Cursor**（YonBan 扩展） | 在扩展市场装 always-accompany | 想让 AI 直接操作你正在用的编辑器 |

**两者自动互斥**：编辑器窗口在线时 CLI 自动让位停机，编辑器全关后 CLI 自动恢复。看到「CLI 启动几秒又停了」不是 bug，是让位——详见 [AI 操作后端](beilu:wiki/yonban/overview.md)。

## 从零连接你的编辑器（完整步骤）

第一次把 AI 接进 VSCode/Cursor，走这四步：

1. **装扩展**：在 VSCode 或 Cursor 的扩展市场搜索 **always-accompany**，安装 YonBan 扩展。装好后它会在本地开一个 WebSocket 服务（默认端口 8931，被占用会自动换），并把端口和认证 Token 写进 `~/.beilu/` 发现文件——你不需要手动配任何地址。
2. **确认连上**：回到 beilu，点击活动栏的 **connections** 按钮打开 IDE 接口面板。本体会按发现文件自动找到编辑器并握手，状态灯变绿、显示编辑器版本号即为成功；没连上可点「连接 / 重连」，面板里也有「指南」按钮。
3. **选权限档**：点击活动栏的 **control** 按钮打开控制面板，选择权限等级。第一次建议用默认的「读写需审批」（L2）——AI 读文件畅通，改文件逐条问你。各档位含义见[审批与权限](beilu:wiki/yonban/approval.md)。
4. **体验第一次审批**：在对话里让 AI 改个文件试试。AI 发出写操作后，前端会弹出**审批卡片**，展示它要改什么——点「批准」才真正执行，点「拒绝」AI 会收到你的拒绝并调整思路。这就是编程模式的安全底座：AI 的每个危险动作都过你的手。

连接后 AI 就能直接操作你的编辑器：读代码、改文件、跑命令、查 Git。断线后可点击「重连」。

**开多个编辑器窗口？** 完全支持——每个对话可以绑定到一个具体窗口（自动跟随或在「＋号」里手动指定），各项目互不串门。详见 [AI 操作后端](beilu:wiki/yonban/overview.md)的多窗口一节。

## 你想做什么

| 想做什么 | 用哪个面板 | 活动栏按钮 |
|---------|-----------|-----------|
| 浏览/编辑项目文件 | 文件管理器 | explorer |
| 和 AI 对话 | AI 对话 | ai-chat |
| 调整权限/自动化设置 | 控制面板 | control |
| 连接 MCP 服务 | MCP | mcp |
| 切换历史对话 | 对话历史 | conversations |
| 回退 AI 操作 | 操作时间线 | timeline |
| 连接 VSCode/Cursor | IDE 接口 | connections |
| Git 操作 | Git 管理 | git |
| 切换子模式 | 子模式 | submodes |

点击活动栏按钮切换对应侧边栏面板，再次点击同一按钮可折叠侧边栏。

## 控制面板

点击活动栏的 control 按钮打开。集中管理编程模式的运行参数：

| 控件 | 类型 | 说明 |
|------|------|------|
| 权限等级 | 下拉菜单 | L0 ~ L5，控制 AI 可执行的操作范围（L5 为全部放行档，需红色弹窗二次确认，见[审批与权限](beilu:wiki/yonban/approval.md)） |
| 清理模式 | 下拉菜单 | 选择代码清理策略 |
| 手动清理 | 按钮 | 立即执行一次清理 |
| 自动保存 | 开关 | 开启后文件修改自动保存 |
| 自动继续 | 开关 + 延迟设置 | AI 完成一步后自动继续下一步，可设置等待延迟 |
| 完成提示音 | 开关 | AI 完成任务时播放提示音 |

## 文件浏览器

点击活动栏的 explorer 按钮打开。

- **打开文件夹** — 选择本地目录作为工作区
- **打开文件** — 直接打开单个文件
- **目录树** — 树形展示项目文件结构，右键菜单提供新建/重命名/删除
- **多标签编辑器** — 打开的文件以标签页形式排列，支持 `Ctrl+S` 保存
- **AI 审批队列** — AI 请求修改文件时进入审批队列，可逐条允许或拒绝

## Git 面板

点击活动栏的 git 按钮打开。

- **分支栏** — 当前分支、ahead/behind 计数、新建/切换/合并/stash 操作
- **提交区** — 提交信息输入框 + 提交按钮
- **变更列表** — 已暂存/未暂存/未跟踪文件，点击查看 Diff 预览
- **提交历史** — 浏览历史提交记录和变更内容

## 操作时间线

点击活动栏的 timeline 按钮打开。

- 记录 AI 执行的所有工具调用和代码状态快照
- 可查看每次操作的输入参数和返回结果
- 支持回退到任意历史节点，防止 AI 修改导致的意外破坏

## 子模式（11 个）

编程模式内置 11 个子模式，覆盖软件开发全流程：

| 子模式 | 用途 |
|--------|------|
| 任务确认师 | 理解需求，联网查类似方案 |
| 前置设计师 | 读取具体代码进行设计，精确到代码行 |
| 框架审查员 | 以代码框架和整体流程审查合理性 |
| 深度思考师 | 算法设计、框架逻辑、线路逻辑，实验验证 |
| 代码专家 | 专注于代码实现 |
| 前置错误生产师 | 检查语法、HTML 标签错误，审查流程 |
| 测试专家 | 通过脚本工具和浏览器后台实际测试 |
| 纠错专家 | 查看整体再专注单体，快速排查修复 |
| 任务交接员 | 做成 md 文件并与人类确认 |
| 大项目协调 | scope 锁定、依赖链排序、多分身编排 |
| 前端美化 | 前端设计与美化 |

每个子模式可独立绑定预设、API 源、模型和采样参数，切换子模式时自动加载对应配置。详见 [子模式与切换](beilu:wiki/modes/submodes.md)。

## 界面布局

编程模式采用类 IDE 布局：

- **活动栏**（最左侧）：图标按钮，切换侧边栏面板
- **侧边栏**：对应面板内容
- **主区域**：AI 对话区 + 代码/Diff 查看区

与聊天模式的布局差异：

| 聊天模式 | 编程模式 |
|---------|---------|
| 三栏对称布局 | IDE 样式非对称布局 |
| 左右栏可折叠 | 活动栏常驻 + 侧边栏可切换 |
| 以对话为中心 | 以文件和工具操作为中心 |

## 其他说明

- 进入编程模式时，INJ-2 注入规则自动启用（编程场景专用上下文），无需手动配置
- 编程模式对应后端模式值 `code`，前端 Tab 为 `files`
