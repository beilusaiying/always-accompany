# 第3章 アルゴリズム設計と形式的記述

## 3.1 引言

本章では、自己駆動発散リコールシステムのアルゴリズム層における完全な仕様を示します。本システムは「発散思考」に特化した外付け処理パイプラインです。大規模言語モデル（LLM）の外部において、規則計算・語ベクトル演算・軽量ラベリングにより追加のモデル呼び出しを不要とし、追加の推論コストなしにメインモデルへ発散方向を提供します。設計者はその位置づけを「外付けの発散思考チェーン」と総括しています。

本章の構成は以下の論理に従います。3.2節では術語の基盤を確立し、後文で繰り返し使用する自造術語を定義します。3.3節では各原創アルゴリズムを逐項形式的に記述し、各項を「設計動機—形式的定義/公式—設計依拠—関連工作対照」の四層で展開します。3.4節ではコアスコアリングフレームワーク BLQ（Bilu Quality、アダプター内部の候補品質スコアリング装置）の完全仕様を示します。3.5節では「消融と失敗方案」という体裁で、アルゴリズム進化史の中で実測により反証された方案を記録します。これは技術報告において独立した価値を持つ負の証拠です。3.6節では関連工作をまとめ、分類対照表を示します。3.7節は小括です。

事前に宣言すべき実装現状は次の通りです。システムの発散メインループ（runPipeline）と記憶リコールコンポーネント（recallMemories）は現在コンポーネント態にあります。すなわちアルゴリズムは実装済みですが、まだオンライン主チェーンへ接続されておらず、オンライン検索は現在モデルのプリセットが担当しています。本章が記述するのは、この実装済みで接続待ちのコンポーネントライブラリアルゴリズムです。本章のすべての具体的数値はその出典レベルとともに標記します。制御実験により校正・確定されたものは「経実験校正の定档値」、初期取値で体系的な調整未実施のものは「初期デフォルト値」と標記します。すべての公式は原形のまま逐字保存し、書き換えは行いません。各公式には変数定義表が付きます。

## 3.2 術語定義

本システムの背景知識を持たない読者がコンテキストなしで後文を理解できるよう、本章で繰り返し使用する自造術語を先に定義します。

- **情報語（information word）**：発散プロセスが生成する中間語義単位。メインモデルに直接出力されず、下流での収束のための原材料として機能します。例えば「学習性無力感」「職業疲弊」といった中間概念です。
- **方向語（direction word）**：複数の情報語を「多対一収束」した後に出力される最終語義単位。メインモデルへの「知識入口シード」として提供され、具体的なルートではなく思考方向を示します。例えば「認知再構造化」「価値明確化」などです。
- **廃語（null word）**：メインモデルが文脈を素読みするだけで自力で推出できる語。このような語はメインモデルへの情報増益がゼロとされ、除去されます。
- **BLQ（Bilu Quality）**：アダプター内部の候補品質スコアリング装置。複数のラベリング次元で候補語に一括加算スコアを付与し、降権・廃語除去・レッドライン除去に使用します。それ自体は「方向の選択」機能を持ちません。
- **汎用語問題（over-general hub problem）**：少数の高接続度ハブ語が発散プロセスで大量の無関係候補を吸着し、出力が汎化して方向性を失う現象。「汎用語」はどの入力に対しても高頻度でリコールされる過度に通用的な語を指します。
- **レッドライン語（redline word）**：出力基準に違反し、命中した時点でハードに候補プールから除去される語（降権ではなく）。具体的なルートの提示、ユーザーの代わりに判断を下すこと、ユーザーに代わって表現すること、ユーザーを病症と判定することの四類が含まれます。
- **軸（axis）**：独立並列の学科発散次元。システムは心理・情報・社会・論理・言語・認知の六学科軸を採用しています。
- **点位（サブ軸）**：産出端のサブ方向座標。システムは産出端にサブ方向座標空間を設け、入力によりそのサブセットを活性化して「定位」を完了します。このステップは定位のみで採点は行いません。
- **0-tokenの原則**：発散ステップ全体でLLMを呼び出さず、全工程をホワイトボックス観測可能とする設計方針。発散は規則計算・ベクトル演算・小規模モデルラベリングによって完成します。

後文で具体的なコード実装に言及する箇所では、モジュール名（node8、node10、axisDecayなど）を実装識別子として用いるのみで、実装の詳細には踏み込みません。

## 3.3 原創アルゴリズム逐項形式的記述

本節では、システムの原創アルゴリズム設計を逐項記述します。各項について、設計動機・形式的定義または公式（変量表付き）・設計依拠・関連工作との対照を示します。関連工作の分類口径は3.6.1節で統一定義します。本節では分類結論の引用のみを行います。

### 3.3.1 三段メカニズム：収縮—発散—収縮

**設計動機。** 大規模言語モデルは生成時に単一経路へ収束する傾向があり、広域発散を自発的に行うことが困難です。本システムは発散能力をモデル外部のメカニズムが担うべきと考えます。まず記憶リコールでコンテキストをアンカーとして固定し（収縮）、次に二段階の連想発散を行い（発散）、最後に方向語として収束させてプロンプトへ注入します（収縮）。

**構造（形状レベル）。**

```
入力 → [収縮] 記憶リコール + コンテキストアンカー
     → [発散] 連想ネットワーク第一次発散 → 空間投票 → 第二次発散で情報語生成
     → [収縮] 多対一投票で方向語に収束 → プロンプト注入
```

**設計依拠。** 収束段階では擦辺的・大量的な方法で記憶をリコールしてコンテキストをアンカーとします。発散段階の目的は、主モデルが後続の思考で単一点位に閉じ込められないようにすることです。システム自体はフレームワーク・記憶・発散経路を提供するのみで、収束・集約・思考はメインモデルに委ねます。設計上の位置づけとして、本システムは回溯と発散を指向しており、LLMの生成能力を続写または再現することを目的としていません。

**実装摘録（節選、p1_pipeline.mjs のメインエントリ runPipeline より、節選）。** 上記「収縮—発散—収縮」三段はメインループ `runPipeline` においてノードを連続呼び出すことで実装されており、上文の形状レベルの構造と逐段対応します。括弧デュアルチャンネル前置層（Step -1）が分詞に先立って実行された後、リコール・六軸・リソース確認・空間投票・多対一収束・レッドライン除去が順次実行されます。可読性のため、呼び出しの骨格のみを保留し、グレードダウン・フォールバック・ホワイトボックストレース・ホットスワップポーリングなどの実装補足事項は省略します。

```javascript
export async function runPipeline(inputText, chatHistory, mode, userCtx) {
  // Step -1 括号双信道前置层（早于分词，主/副信道不取均值保留张力）
  const _bracket = _P1_BRACKET ? splitBracketChannels(inputText) : { main: inputText, sub: null, ... };
  const _mainText = _bracket.main || inputText;
  // 阶段1 [收缩] recallV2：分词 + SWOW 发散 + 召回锚点 + 输入质心
  const recallResult = callNode("recall", [_mainText, chatHistory, seenNodes, { ... }], { ... });
  const swowPool = recallResult.swowPool || new Set(inputWords);
  // …（略：副信道另跑一次 recallV2，Set union 并入 swowPool）
  // 阶段2 [发散] node3 六轴面 + node4 47 子轴定位
  const _axis6  = callNode("node3", [_pool, mode, inputWordSet, ...], { ... });
  const _axis47 = callNode("node4", [_pool, mode, inputWordSet, _axis6.wordProfiles], { ... });
  // 阶段3 [发散] transfer：node5 资源确认 → node6 空间投票 → node9 多对一选方向词
  const transferResult = callNode("transfer", [[...swowPool], mode, confirmedAxisResult, ...], { ... });
  // 阶段4 [收缩] node10 refineDirectionWords + isRedlineWord → 方向词
  _dwPool = refineDirectionWords(_dwPool, { ... });
  const p1_act = topDirectionWords.slice(0, 15).map(d => d.term);
  return { p1_act, /* …（略） */ };
}
```

実装と設計稿の対応関係について一点補足します。設計稿の「第一次発散→空間投票→第二次発散」は実装では三つの独立ノードとしてではなく、`transfer` 一モジュール内に直列接続されたnode5→node6→node9の三ステップとして収束しており、六軸（node3）と47サブ軸（node4）がその上流で先行して定位を行います。

**関連工作対照。** 分類B（観念層）。「LLMには発散と収束を分離するための外部スキャフォールドが必要」というコアの主張は、CreativeDC（arXiv 2512.23601，2025-12）と Scaffolding Creativity（arXiv 2510.26490，2025-10）において先行して公開・理論的裏付けがなされています。しかしこれら二つの工作はいずれも単一モデル内部で二段階プロンプト/温度またはペルソナ切り替えにより実装されており、記憶リコールアンカー・空間投票・多対一収束は含まれていません。観念は先行しており、実装経路が異なります。

### 3.3.2 空間加算投票（逆距離加重と温度円描画）

**設計動機。** 候補語の収束に線形乗算またはハードマッチングを採用すべきではなく、語ベクトル空間においてコンテンツ分布に基づく加算投票を行うことで、いずれかの次元の低スコアが全体を乗法的に否定することを防ぎます。

**公式（形状レベル）。**

```
idw = 1 / (1 + d² · k)          # 逆距离加权，d = 语义距离，k = 缩放系数
边界圆半径 = 温度系数 T 缩放     # T 大→半径大→更多候选；T 小→半径小→精确
投票 = Σ 加性累加（禁乘法链）
```

**変数定義。**

| 記号 | 意味 | 出典レベル |
|------|------|----------|
| `idw` | 単一候補の逆距離加重投票寄与 | — |
| `d` | 候補とクエリの語ベクトル空間における語義距離 | — |
| `k` | 距離スケーリング係数 | 経実験校正の定档値 |
| `T` | 温度係数、境界円半径を制御 | — |

**実装摘録（節選、p1_node6_spaceVote.mjs より、節選）。** 上文の形状レベルの公式 `idw = 1/(1+d²·k)` と「投票は加算累積、乗法チェーン禁止」は、ノード6の投票内ループにおいて逐字実装されています。`k` はコード中の急峻係数 `_P1_NODE6_IDW_STEEPNESS`（経実験校正の定档値、ここでは記号で示します）に対応します。温度円半径スケーリング・内圏除外などの分岐は省略します。

```javascript
const d = 1 - cos;                              // 空间距离，d = 1 − cosine
// …（略：太远不投的下限门、温度圆内/外判定）
const idw = 1 / (1 + d * d * _P1_NODE6_IDW_STEEPNESS);   // 反距离加权，k = 陡度系数
let vote = w * idw;                             // 加性票 vote = w·idw，非乘法链
// …（略：域信号 domainBonus 加成，累加器取键）
rec.totalVote += vote;                          // 累加，全程无 /N（空间相加不相乘）
```

その中で `rec.totalVote += vote` は形状レベル公式の「投票 = Σ加算累積（乗法チェーン禁止）」に直接対応しており、累積過程では票数Nでの除算も連乗も行わず、「多次元ラベリングは空間であり乗算ではない」という設計原則を体現しています。

**設計依拠。** システムは線形乗算ではなく空間加算投票を採用します。候補はベクトル空間においてコンテンツ分布に基づいて投票し、結果は同一候補プールに集約されます。発散方向は「空間に沿って進む」ものであり、孤立した点に落ちるものではありません。

**関連工作対照。** 分類CとBの間。逆距離加重本体はShepard（1968）の古典的空間補間公式であり、汎用部品に該当します。「語義空間において距離で候補を選ぶ」も汎用的な特許ルーティン（US 11086920等、2018–2021）です。しかし「逆距離加重投票 + 温度係数スケーリング半径円で境界設定 + 全工程加算・乗法チェーン禁止」という具体的な組み合わせについては対応する公開工作が見つかっておらず、組み合わせ層ではDと判定できます。

### 3.3.3 多対一方向語投票（Hough式）

**設計動機。** 単一の中間語が直接方向語を産出すると、その語の偶然性の影響を受けやすくなります。本システムでは複数の中間情報語が同一のターゲット術語に対して独立に投票し、票数で収束して最終方向語を選出することで、「単語直噴」を構造的に抑制します。

**公式（形状レベル）。**

```
每个信息词 wᵢ → 对候选方向词 t 投票 vote(wᵢ, t)
方向词得分 = Σᵢ vote(wᵢ, t)      # 多对一累积投票（Hough voting 范式）
→ 票数峰值 = 最终方向词
```

**変数定義。**

| 記号 | 意味 |
|------|------|
| `wᵢ` | 第i個の中間情報語 |
| `t` | 候補方向語 |
| `vote(wᵢ, t)` | 情報語wᵢの方向語tへの投票寄与 |
| 方向語スコア | ある方向語への累積票数。最大値を取ったものが最終方向語となります |

**理論的支持。** この設計はCondorcetの陪審定理と同型です。N個の独立した投票者がそれぞれ50%を超える正解率を持つ場合、多数決の正解率は約1−(1/2)^Nとなり、Nとともに指数的に増大します。3票では約87.5%超、5票では約96.9%超であるのに対し、1票では約50%にすぎません。これが「多票高信頼、1票低信頼」に対する数学的根拠を提供しています。

**実装摘録（節選、p1_node9_dirword.mjs より、節選）。** 上文の形状レベル公式「方向語スコア = Σᵢ vote(wᵢ, t)」はノード9において共有累積器 `_voteAcc` によって実装されています。各情報語が同一の候補方向語に対して独立に投票し、票値が `totalVote` に加算され、投票者数が `voterCount` に記録されます（「何個の情報語から同時に指されたか」というピーク判定の根拠）。最終スコアは累積票に軸衰減を乗じたものです。範囲ゲート・チャンネル合算・ピラミッド階層化などの分岐は省略します。

```javascript
// 每个信息词 wᵢ 对同一 eligible 方向词 t 独立投票（真正的多对一）
const vote = iwWeight * (relW + _domainW + ...);   // vote(wᵢ, t)，加性
_entryTotalVote += vote;                           // 单靶累积：Σᵢ vote(wᵢ, t)
_entryVoterCount++;                                // 投票者计数（多对一的"多"）
// …（略：过 47D 范围门、极性/温度校准）
const rec = _voteAcc.get(key);                     // 统一累加器（Hough/CN/bridge_to 共汇于此）
rec.totalVote  += _entryTotalVote;                 // 空间相加，非相乘
rec.voterCount += _entryVoterCount;
// …（略：排序、取 topN）→ 每个方向词最终得分：
score: cand.totalVote * Math.max(nd, _houghDecayFloor) * _resW,   // 累积票 × 轴衰减 nd
```

その中で `rec.totalVote += _entryTotalVote` は「多対一累積投票（Hough votingパラダイム）」の直接実装です。末行の `cand.totalVote × 軸衰減` は、多対一スコアが産出端でさらに3.3.5節の軸衰減係数を乗じることを示しています。この点は形状レベル公式では明示されておらず、実装が設計稿を基礎として行う接続の詳細です（軸衰減はnode3で導出され、node9で消費されます）。

**設計依拠。** 連想データ中の語は本質的に「点」であり、システムは点を「線」に変換する必要があります。発散とは線の延伸です。産出方向語は複数の近接語の多次元加算収束に基づくべきであり、単一の語に依存すべきではありません。

**関連工作対照。** 分類C（移転層はD）。Hough投票パラダイムは極めて成熟しています（Hough 1962；VoteNet，ICCV 2019）が、既存工作はすべてコンピュータビジョンと点群領域に集中しています。複数回の検索を経ても、このHough式投票を自然言語処理のキーワード/方向語生成に移転した公開工作は見つかっていません。このパラダイムを語選択タスクに移転し、「単語直噴防止」という構造的動機を付与したことは、本システムの比較的独自な点の一つです。

### 3.3.4 二段発散アーキテクチャ

**設計動機。** 一段階の発散では広さと関連性を両立させることが困難です。本システムは異質二ホップ構造を採用します。第一次発散後に空間投票で絞り込み、再度第二次発散を行って情報語を産出し、最後に方向語へ収束します。

**構造（形状レベル）。**

```
発散₁（連想ネットワーク）→ 空間投票（絞り込み）→ 発散₂（情報語産出）→ 多対一収束（方向語）
```

**設計依拠。** システムの発散は「統合」をアンカーポイントとして展開します。まず既往の連想と記憶を検索し、次に連想ネットワーク（アテンション式のクエリ—キー—バリューメカニズムを取り入れた）に基づいて発散し、その後次のホップへ移行します。

**関連工作対照。** 分類D。「二段発散、中間に空間投票絞り込みを挟み、再発散して情報語を産出する」という特定の二ホップアーキテクチャについては対応する公開工作が見つかっていません。Tree-of-Thoughts（ToT）は概念上の近隣（C）ですが、ToTは同質な分岐探索と評価回溯であるのに対し、本システムは異質二ホップ（発散—投票—発散—収束）であり、構造が異なります。

### 3.3.5 六軸面発散

**設計動機。** キャラクターロールプレイ式フィードバックを対象とするアプリケーションには多学科の支援が必要であり、単一次元の発散では心理・社会・言語などの異なる側面を網羅するには不十分です。本システムでは六学科軸（心理・情報・社会・論理・言語・認知）が並列独立に発散し、各軸は単一スコアではなく多次元の「面」を出力し、軸間にはハード切断ではなくソフト衰減によるアイソレーションを実現します。

**公式（形状レベル、軸衰減 axisDecay）。**

```
各軸関連度 axisRelevance[axis] = Σ(該当軸のface語寄与値)
関連度降順でランク → axisRank、rank0 = 主方向軸
軸衰減 axisDecay[axis] = exp(-rank · β)
  rank0 → exp(0) = 1.0（主軸）
  rank1 → exp(-0.5) ≈ 0.607
  rank2 → exp(-1.0) ≈ 0.368
```

**変数定義。**

| 記号 | 意味 | 出典レベル |
|------|------|----------|
| `axisRelevance[axis]` | ある軸の関連度。その軸の各面語寄与値の合計 | — |
| `axisRank` | 各軸を関連度降順にランク付けしたもの。rank0が主方向軸 | — |
| `β` | 軸衰減率 | 経実験校正の定档値（0.5を取る） |
| `axisDecay[axis]` | その軸の衰減係数。ランクとともに指数的に減少するが、常に0より大きい | — |

**実装摘録（節選、p1_node3_axis6.mjs より、節選）。** 上文の形状レベル公式の三行——関連度の合計算出・関連度降順でのランク取得・`axisDecay = exp(-rank·β)`——は `_computeAxisDecay` 内において逐字対応しています。`β` はコード定数 `AXIS_DECAY_BETA`（経実験校正の定档値、0.5）に対応します。AXIS_CUTOFFソフトストップとホワイトボックストレースは省略します。

```javascript
for (const axis of AXES) {                        // 各轴关联度 = 该轴 face 词贡献值之和
  axisRelevance[axis] = fw.reduce((s, x) => s + (x.v || 0), 0);
}
const ranked = AXES.slice().sort((a, b) => axisRelevance[b] - axisRelevance[a]);   // 按关联度降序
ranked.forEach((axis, rank) => {                  // rank0 = 主方向轴
  axisRank[axis] = rank;
  // 衰减如 exp(-rank·β)：rank0（主轴）= 1.0，远轴指数衰减但 >0 永不删
  axisDecay[axis] = axisRelevance[axis] > 0 ? +Math.exp(-rank * AXIS_DECAY_BETA).toFixed(4) : 0;
  // …（略：AXIS_CUTOFF 软停判定、cutoffRatio 记录）
});
```

`Math.exp(-rank * AXIS_DECAY_BETA)` は形状レベル公式 `exp(-rank·β)` と完全に一致しています。一点実装上の取り決めを注記します。関連度が0の軸の衰減は0を取ります（`exp(0)=1` ではなく）。これにより、未活性化の軸が誤って主軸とみなされることを防いでいます。これは公式の実装における境界処理です。

遠方軸の衰減係数は指数的に低下しますが、永遠にゼロにはなりません。これにより「ソフトアイソレーション」を実現しています。主方向から遠い軸も微弱な寄与を保持し、適度な擦辺を許容しつつ、完全に無関係なコンテンツの出力を防ぎます。

**設計依拠。** キャラクタープレイのフィードバックには、文章・心理学・言語学・論理学などの多学科の並列的支援が必要です。発散は擦辺を許容しますが、完全に無関係なコンテンツを出力すべきではありません。学科軸数は四軸・五軸・六軸という進化を経て確定しており、設計者はさらなる次元削減の方案を否決しました。

**関連工作対照。** 分類C（数字/概念の名称衝突）。Biberの多次元分析（MDA，1988）・LIWC（2001）および認知科学の「六支援学科」はいずれも「多次元」「六」といった語を使用していますが、「六学科軸が並列独立に発散し、各軸がスコアではなく多次元の面を産出し、軸間にソフト衰減を設ける」という機制に該当するものはありません（機制層はDと判定可能）。学科リストも異なり、本システムは情報・論理・認知軸を含む一方、哲学・人類学・神経科学などの軸は含みません。

### 3.3.6 サブ軸活性化定位（定位のみ、採点なし）

**設計動機。** 産出端では入力を具体的なサブ方向にマッピングするための高分解能の方向座標空間が必要です。このステップの役割は「定位」であり「採点」ではなく、両者を明確に分離すべきです。

**構造（形状レベル）。**

```
産出端 = サブ方向座標空間（サブ軸集合）
活性化サブセット = 入力が命中したサブ方向（スポットライト式アテンション：ある方向を照らすとその方向が明るくなる）
→ 定位（採点なし）
```

**設計依拠。** 産出端のサブ方向座標数は大きく、その挙動は統計物理の系综——大量の粒子が重ね合わさってマクロな状態が創発する——に類比できます。産出端のサブ軸と六学科軸は互いに分離した二つの層であり、サブ軸は六軸のサブカテゴリーではありません。

**関連工作対照。** 分類D（概念上の近隣はC）。「活性化サブセット定位、定位のみで採点なし」という「定位」と「採点」を明確に区別する産出端サブ軸座標機制については対応する公開工作が見つかっていません。Axis-Aligned SubspaceベイズOptimization（arXiv 2504.06111，2025-04、採点駆動）と神経細胞多義性研究（arXiv 2505.07831）は遠概念の近隣であり、用途と機制が一致しません。

### 3.3.7 括弧デュアルチャンネル

**設計動機。** 対話テキストにおいて、括弧内コンテンツはしばしば本文とは異なる層のメタ言語情報（動作・ナレーション・語気標注など）を担います。それを本文と混合して平均値を取ると、両者の間の張力が解消されます。本システムは括弧内コンテンツをメタ言語副チャンネルとして本文のメインチャンネルとは分離して処理します。

**構造（形状レベル）。**

```
本文 → メインチャンネル処理
括弧内コンテンツ → メタ言語副チャンネル（独立処理）
両チャンネルは混合せず、平均値も取らない → 張力を保持
```

**設計依拠。** 両チャンネルは平均値を取らず、対立する信号間の張力を保持します。次元削減的な平均化によって相互に矛盾する信号を平滑化することを防ぎます。

**関連工作対照。** 分類C。「マルチチャンネル分離・非混合」「張力保持」等の概念語は、全二重音声のユーザーフロールーティング（User-Stream Routing，arXiv 2605.10199，2026-05）と叙事張力研究（arXiv 2604.09854，2026-04）に見られますが、「対話の括弧内コンテンツをメタ言語副チャンネルとして扱い、本文のメインチャンネルと分離し、平均値を取らない」という具体的な手法については対応する公開工作が見つかっていません（機制層D）。また関連工作の多くは2026年4・5月であり、本システムの設計期より遅いまたは並行しています。これは本システムの比較的独自な点の一つです。

### 3.3.8 大量擦辺リコール

**設計動機。** 精確を追求する検索拡張生成（RAG）とは異なり、本システムのリコールは下流の発散に奉仕するものです。低閾値・大量・ファジーなリコール戦略を採用し、リコール結果はアンカーポイントとしてのみ機能し、発散方向を主導しません。

**公式（形状レベル、加重線形リコールスコアリング）。**

```
composite = 0.45×relevance + 0.20×recency + 0.20×attention + 0.15×weight
scoreRecord = max-pool（全クエリノードに対して最強の同方向ノードを取る）
```

**変数定義。**

| 記号 | 意味 | 出典レベル |
|------|------|----------|
| `relevance` | 語義関連度 | — |
| `recency` | 時間的新近度 | — |
| `attention` | アテンション集中度 | — |
| `weight` | 記憶重要度ウェイト | — |
| 重み係数 0.45/0.20/0.20/0.15 | 各成分の線形結合ウェイト | 経実験校正の定档値 |
| `scoreRecord` | ある記憶の最終スコア。その記憶の全クエリノードに対して最大値を取る | — |

**設計依拠。** リコールは擦辺的・大量的な方法で行われます。そのメカニズムは「コンテキスト + アテンション集中 + 多軸」によって既往コンテンツ（データ層・ホット層・コールド層など）をマッチングして取り出すものであり、高度なインテリジェント判断を必要としません。本質はキーワードマッチングであり、これが「リコールがLLMのtokenを消費しない」という原則の由来でもあります。

**関連工作対照。** 分類B（手段層）。「低閾値・高リコール・連想式ファジーリコール」という技術手段は、HippoRAG（arXiv 2405.14831，2024-05）・SYNAPSE（arXiv 2601.02744，2026-01）・Predictive Associative Memory（2026-02）において既に実現されており、本システムより早いまたは同時期に公開されています。しかしこれらのシステムの目的は検索精度または多ホップ質問応答性能の向上、すなわち「精確さ」の追求にあります。本システムのリコールの目的と役割はその逆——リコールは発散のアンカーポイントとしてのみ機能し、意図的にファジーに保つことで候補を広げ、下流の発散に燃料を提供します。目的は「広くてぼんやりとした」ものです。手段層での衝突（B）があり、目的と役割層は異なります。

特に指摘すべき点として、SYNAPSE（2026-01-06、本システムより早い）と本システムは拡散活性化・側抑制・ファンアウト効果という三つの術語を共有していますが、用途は直交しています（前者は検索質問応答精度、後者は発散生成）。公開されている要旨のみでは実装レベルでのより深い類似を排除できないため、この項は人手による重点的な精査が必要な項目として挙げています。

### 3.3.9 クエリ—キー—バリュープール交汇発散

**設計動機。** 孤立した・つながりのない候補語は発散の漂流を招きます。本システムはアテンション機制のクエリ—キー—バリュー（QKV）構造を参考にして外付け発散パイプラインに改造し、アテンションフィルタリングで漂流を制御します。

**公式（形状レベル）。**

```
Q = 入力語ベクトル質心
K = 連想ネットワーク cue（収束アンカーポイント = 入力キーワード + recallAnchors）
V = 交汇 cue → 連鎖再連想 → XML注入の発散語
attention(Q, K) = softmax(Q · Kᵀ / √d)     # 低 attention 候選のフィルタリング（漂流制御）
```

**変数定義。**

| 記号 | 意味 |
|------|------|
| `Q` | クエリ。入力語ベクトルの質心を取る |
| `K` | キー。連想ネットワーク手がかり（入力キーワードとリコールアンカーポイントの収束）を取る |
| `V` | バリュー。交汇手がかりを取り、連鎖再連想で発散語を産出する |
| `d` | 語ベクトル次元数。`√d` はスケーリング因子 |
| `attention(Q, K)` | アテンションウェイト。低アテンションの候補をフィルタリングして漂流を制御する |

**設計依拠。** 発散は収束後のコンテンツに基づいて行われます。孤立したつながりのない語彙は漂流を招くため、アテンション機制を導入し、意味的に近い語やリコールアンカーポイントも参照することで発散範囲をアンカーします。

**関連工作対照。** 分類C（概念類比の名称衝突）。「アテンション即検索/連想記憶」は2017年以来の汎用的な解釈です（現代Hopfieldネットワークはアテンションと等価、Ramsauer 2020）。「クエリ質心」はキーバリュー高速化工作（CSAttention，2026-04）と名称が衝突しています。しかし「Qが語ベクトル質心を取り、Kが連想ネットワーク手がかりを取り、Vが交汇手がかりを取って連鎖再連想する」という、QKVの三元組を外付け発散パイプラインに改造する具体的な用法については対応する公開工作が見つかっていません（パイプライン化用法層D）。

### 3.3.10 大中小三段ルーティング

**設計動機。** グローバルスコアリングは汎用語と高接続度のハブ語に主導されやすくなります。本システムは転置インデックスの三段ルーティング（大カテゴリー方向・中カテゴリー局所・小カテゴリー術語）でグローバルスコアリングを置き換え、汎用語/ハブ語問題を構造的に解消します。

**構造（形状レベル）。**

```
トリガー語 → 転置インデックスでサブカテゴリー活性化（中カテゴリー）→ 局所精密ランキング（小カテゴリー術語プール）
= 書籍の類比：目次（大）→ 章節（中、重ね合わせ可）→ 文字（小、術語）
```

**設計依拠。** 大カテゴリーはおおまかな方向、中カテゴリーは方向の局所（重ね合わせ可）、小カテゴリーは術語プールと具体的な術語です。書籍の目次・章節・文字という類比があり、目次（中カテゴリー）の内容は互いに組み合わせ可能です。この三段の区分の目的はハブ語がすべてを吸着するのを防ぐことにあります。

**関連工作対照。** 分類B（構造層）。「粗から細・大中小分段ルーティング + 転置インデックス」は成熟した情報検索パラダイムです（HRR，arXiv 2503.02401，2025-03；CITADEL，2022-11；転置インデックス，1970年代）、いずれも本システムより早い。しかし「トリガー語が転置インデックスでサブカテゴリーを活性化して局所精密ランキングを行い、かつ明示的に汎用語/ハブ語の治理を設計目標とする」という動機については直接対応する工作が見つかっていません。汎用的な分段検索は効率と精度を指向しており、本システムは「ハブ語がすべてを吸着することを防ぐ」という発散品質の動機を指向しています。

### 3.3.11 ホットスワップ語彙ライブラリを追加発散軸として

**設計動機。** システムは語彙ライブラリファイルを追加することで直接発散能力を拡張することを目指しています。新しい語彙ライブラリファイルを一つ追加することはシステムに発散軸を一つ追加することと等価であり、実行時のホットロードをサポートします。

**構造（形状レベル）。**

```
三層語彙ライブラリ（優先度 learned > packs > core、入力方式に類比）：
  core/    内蔵、デプロイとともに削除不可（swow / cooccur / cilin / cogmech）
  packs/   プラグイン式、実行時に有効化（acg-chinese 27878語 / medical / airp-techniques 等）
  learned/ ユーザーごとに対話から自動学習
mtime 30秒チェック → ファイル変更後30秒以内に自動リロード
打鍵式昇権 userBoost(word) = log(1+freq[word]) × 0.1   （上限 +0.3）
```

**変数定義。**

| 記号 | 意味 | 出典レベル |
|------|------|----------|
| `freq[word]` | ユーザーの対話における当該語の出現頻度 | — |
| `userBoost(word)` | 打鍵式昇権量。頻度の対数に比例して増加 | — |
| 係数0.1、上限+0.3 | 昇権スケーリング係数と上限値 | 初期デフォルト値 |
| mtimeチェック周期30秒 | ファイル更新時間ポーリング周期 | 初期デフォルト値 |

**設計依拠。** システムは語彙ライブラリのホットスワップとユーザー適応性を追求し、その挙動がタイピングのようにユーザーの習慣に応じて調整されるようにします。モデルが対話に基づいて自律的に語彙ライブラリを構築・調整することが、より優れた経路と見なされています。

**関連工作対照。** 分類C（基盤設備の名称衝突）。「ホットロード語彙ライブラリ/プラグイン」は極めて一般的な基盤設備です（Elasticsearch辞書ホットロード，2020-11；Obsidian Hot-Reload；各種監視リロード機制）。ファイル更新時間ポーリングも名称が衝突しています。しかし「語彙ライブラリファイルを一つ追加するだけでシステムの発散計算軸が自動的に一つ増える」という語彙ライブラリファイルを発散次元と同等視する意味論については対応する公開工作が見つかっていません（D）。SillyTavern の World Info は最近の生態上の近隣（キーワード語彙ライブラリをホットロード可能）ですが、そのメカニズムは「トリガーで固定テキストを注入する」であり「新しい発散軸を追加する」ではなく、機制が異なります。

### 3.3.12 二段語彙体系と廃語判定基準

**設計動機。** システムは二種類の語義単位を区別し、情報増益の制約を課す必要があります。中間産出の情報語は外部に漏洩せず、多対一収束で方向語となった後に出力されます。また「主モデルが自力で推出できるかどうか」を語の価値の判定基準とし、情報増益がゼロの廃語を除去します。

**構造（形状レベル）。**

```
情報語（中間、出力なし）→ 多対一収束 → 方向語（出力、知識入口シード）
廃語判定基準：主モデルが素読みで推出できる語 = 廃語 = 価値0
方向語準入6条件すべて満足：検索可能 + コンセンサスあり + 方向語である + 診断語でない + ルート語でない + 口語でない
```

システムは「点—線—面—体」の幾何モデルで情報の階層を記述します。

- 体 = ユーザーの一回の対話の完全な情報（入力と記憶データ）
- 面 = リコール・連想発散・情報語（「学習性無力感」「職業疲弊」など）、出力なし
- 線 = 出力される方向語（「認知再構造化」「価値明確化」など）、出力あり
- 点 = メインモデルが方向語をもとに構成する最終回答

**設計依拠。** 連想データ中の語は「点」であり、点を「線」に変換する必要があります。発散とは線の延伸です。システムがメインモデルに提供すべきは「方向」であり「ルート」ではありません。方向語の組織は四つの優先原則に従います。体験語が術語より優先され、口語のアンカーポイントが抽象より優先され、経験語が必要語より優先され、統合時にはアンカーポイントが保持されます。

**関連工作対照。** 分類CとDの間。「シード語/プライミング（priming）」は概念が緩く衝突します（Seeding priming，2023–24）。しかし「情報語（中間、出力なし）と方向語（出力あり、多対一収束）の二段語彙体系」および「主モデルが素読みで推出できる語は廃語・価値ゼロ」という情報増益判定基準については対応する公開工作が見つかっていません。「基盤モデルがすでに推出できるかどうか」で語の価値をゼロとする廃語判定基準は極めて独自な設計です（D）。これは本システムの明らかに原創的な点の一つです。

### 3.3.13 BLQ多次元加算スコアリングフレームワーク

**設計動機。** 候補語の総合評価に乗法チェーンを採用すると、「ANDゲート」と等価になります。いずれかの次元の低スコアが全体を否定し、候補が単一次元によって抹殺されます。本システムでは複数のラベリング次元に対して一括加算スコアリング（CombSUM）を採用し、側抑制と最大マージナル関連性（MMR）のクォータを補助として加えることで、スコアリングが「ORゲート」の意味論を持つようにします。

**公式（形状レベル、詳細は3.4節参照）。**

```
additive = W_SPATIAL·dSpatial + W_TF·dTf + W_PATH·dPath
         + W_NB·dNb + W_SPEC·dSpec + W_CONFIRM·dConfirm   （加重 CombSUM、連乗なし・平均取りなし）
blqScore = max(additive · FLOOR, additive − Σpenalty)      （抑制次元の加算減点 + ソフトフロア）
```

**設計依拠。** 多次元ラベリングが構成するのは「空間」であり乗算関係ではありません。初期には「多軸スコアリング後に平均を取り、基準未達なら削除する」と表現されていましたが、平均を取る方案はその後否決され、加算方式に変更されました。平均を取ることで次元間の張力がゼロになるためです。

**関連工作対照。** 分類B（コンポーネント層）。三大コンポーネント——CombSUM（Fox & Shaw 1994）・MMR（Carbonell & Goldstein 1998）・側抑制——は数十年の歴史を持つ古典的な情報検索/神経科学の部品であり、本システムよりはるかに早い。SYNAPSE（2026-01）も側抑制を記憶に利用しています。しかし「CombSUM + 側抑制 + MMRクォータの三点セットを統一して組み立て、かつ明示的に『加算はORゲート、乗法チェーンは単一次元による否定のANDゲートに対抗する』という設計論拠を持つ」完全なフレームワークについては対応する公開工作が見つかっていません。本システムの原創性の主張は「なぜ乗算ではなく加算でなければならないか」という論拠と三点セットの特定の編成にあり、個々の部品にはありません。このフレームワークの完全な仕様は3.4節を参照してください。

### 3.3.14 0-tokenホワイトボックス立場（横断原則）

**設計動機。** これは発散ステップ全体に横断する設計原則であり、単一のアルゴリズムではありません。発散プロセス全体でLLMを呼び出さず、全工程をホワイトボックスで観測可能とし、規則計算・ベクトル演算・小規模モデルラベリングによって完成させます。これにより単一の発散のために大規模モデルAPIのコストを費やすことを回避します。

**設計依拠。** システムは一貫してゼロコストを目標とし、発散のようなステップに高コストの大規模モデルを使用しません。観測においてはホワイトボックスの立場を採用し、代理スコアリングツールに依存せず実際の出力を直接検査します。

**関連工作対照。** 分類D（競争格局層）。最も近い複数の方案との比較において、本システムは「0-token、発散ステップでLLMが不要」を実現する唯一の方案です（SA-RAG・FS-RAG・LWOW・MADはいずれも発散または検索にLLMの参加が必要）。関連研究（MADとLiveIdeaBench）は「LLMの発散能力は汎用インテリジェンススコアと相関しない」——すなわちより多くのLLM演算を投入しても発散問題は解決できない——ことも示しており、これは本システムの外付け式0-tokenルートの合理性を側面から支持しています。この原則の統括下にある具体的なメカニズムとして、多学科座標定位（第二ステップ）と座標に沿った再発散（第三ステップ）は比較的新颖な組み合わせです。

**小括（3.3節）。** 逐項検査の結果：「機制が高度に類似しており、本システムの設計期（2026-04）より早い」という厳格な意味において、上記の原創項はいずれも公開工作と衝突していません。衝突したものの多くは汎用部品（B分類）または概念/術語の名称衝突（C分類）です。本システムの原創性の主張は一般的に「成熟した部品を発散に特化した外付けパイプラインに組み立てること、生成タスクへの移転用法、および若干の具体的な判定基準」という層にあり、個々の部品そのものにはありません。分類定義と総括は3.6節を参照してください。

## 3.4 BLQスコアリングフレームワーク完全仕様

本節ではBLQスコアリングフレームワークの完全仕様を示します。BLQの機能的位置づけはアダプター内部の候補品質スコアリング装置であり、発散エンジンや選択器ではありません。方向の「選択」は空間投票と多対一投票が担い、BLQは選択の後に降権・廃語除去・レッドライン除去のみを行います。

### 3.4.1 接続状態

完全仕様の前に、各コンポーネントの接続状態について正直に宣言する必要があります。BLQスコアリングコア（calcBLQ）は完全な多次元加算フレームワークを実装しており、コードは存在し逐行で閲読可能ですが、現在まだ発散メインループに接続されていません。オンラインの情報語スコアリングは実際に空間投票と軸衰減が担っています。方向語精密ランキングコンポーネント（node10）はスコアリングコアの簡略版を使用しており、ガウス衰減とレッドライン除去のみを実行し、完全な六次元CombSUMは実行しません。レッドラインハード除去コンポーネントと方向語精密ランキングコンポーネントは現在オンライン活性化状態です。本節が記述する完全な六次元フレームワークは「実装済み、接続待ち」のコンポーネントライブラリアルゴリズムです。これに従い、具体的な重みと係数はすべて出典レベルとともに標記します。

### 3.4.2 六つの加点次元（CombSUM）

BLQスコアリングコアの構造は次の通りです。六つの加点次元の加重線形和（CombSUM）に、若干の抑制次元の加算減点を差し引きます。設計上の鉄則として全乗算を行わず、平均値も取りません。六つの加点次元を以下に示します。

| 次元 | 名称 | 公式（逐字保存） | 重み | 重みの出典レベル |
|----|------|-----------------|------|------|
| N1 | 空間距離 dSpatial | `const dSpatial = Math.tanh(rawScore);` | `W_SPATIAL: 1.0`（主信号） | 経実験校正の定档値 |
| N2 | BM25-TF飽和 dTf | `const dTf = _bm25Tf(tf);`、その中で `_bm25Tf(f) = f/(f+k1·(1-b+b))`（本シナリオでは平均文書長が1に退化して `f/(f+k1)`） | `W_TF: 0.6`；`BM25_K1: 1.5`；`BM25_B: 0.75` | 経実験校正の定档値 |
| N3 | 跨学科パス調和 dPath | `const dPath = Math.log(1+disc)/Math.log(1+6);`（対数正規化、六軸を上限） | `W_PATH: 0.4` | 経実験校正の定档値 |
| N4 | 近傍関連性 dNb | `const dNb = nbCos != null ? Math.max(0, nbCos) : 0.3;`（近傍情報なしの場合は中立値0.3を取る） | `W_NB: 0.5` | 経実験校正の定档値 |
| N5 | 特異性 dSpec | `const dSpec = spec;`（より具体的なほど加点、汎化した汎用語を抑制） | `W_SPEC: 0.4` | 経実験校正の定档値 |
| N6 | リソース確認 dConfirm | `const dConfirm = _confirmCount>0 ? Math.log(1+_confirmCount)/Math.log(1+6) : 0;`（六チャンネルを上限として正規化） | `W_CONFIRM: 0.3` | 経実験校正の定档値 |

**変数定義。**

| 記号 | 意味 |
|------|------|
| `rawScore` | 空間投票の生スコア。tanh圧縮により[0,1)に収め、単一の空間票による独占を防ぐ |
| `tf` | 候補の語頻。BM25飽和関数で処理される |
| `k1`, `b` | BM25の語頻飽和と長さ正規化パラメータ |
| `disc` | 候補がカバーする学科数 |
| `nbCos` | 候補と近傍中心のコサイン類似度 |
| `spec` | 候補の特異性指標 |
| `_confirmCount` | 各リソースチャンネルで候補が確認された回数 |
| `W_*` | 各次元の重み係数 |

一つの構造的制約として、跨学科パス調和（N3）はここで一度だけ計算され、外側で再度乗算されることはありません。歴史的には「内層ランキングと外層でそれぞれ一度乗算する」という手法が存在しましたが、全乗算的な崩壊を招くとして否決されました。

### 3.4.3 加算集約（CombSUM）

六次元加重集約の実装は逐字次の通りです。

```javascript
const additive =
  CFG.W_SPATIAL * dSpatial +
  CFG.W_TF * dTf +
  CFG.W_PATH * dPath +
  CFG.W_NB * dNb +
  CFG.W_SPEC * dSpec +
  CFG.W_CONFIRM * dConfirm;
```

加重線形和（Fox & Shaw 1994 が提案したCombSUM）であり、連乗なし・平均取りなしです。これは「多次元ラベリングは空間であり乗算ではない」という設計原則の直接的な実装です。

### 3.4.4 四つの抑制次元（加算減点）

各抑制ゲートはまず乗子 `m ∈ (0,1]` を計算し、それを加算減点 `penalty_d = additive · (1 − m_d)` に変換します。各ゲートはここのみで計算し、旧式の全乗算チェーンを構成しません。

| 抑制ゲート | トリガー条件 | 乗子定数 | 出典レベル |
|--------|----------|----------|----------|
| mOverused（汎用語） | 汎用語ペナルティ語表（130件の手動標注）に命中するか、候補自体に過用マークがある | `OVERUSED_PENALTY: 0.35` | 経実験校正の定档値 |
| mPolarity（極性不一致） | 入力が正向で候補が負向（またはその逆） | `POLARITY_MISMATCH: 0.3` | 経実験校正の定档値 |
| mNbIrrelevant（無関連） | `nbCos < NB_IRRELEVANT_COS`（閾値0.05） | `NB_IRRELEVANT_PEN: 0.15` | 経実験校正の定档値 |
| mIsolatedNoise（孤立ノイズ） | リソース確認が必要だが確認カウントが0 | `ISOLATED_NOISE_PEN: 0.5` | 経実験校正の定档値 |

最終スコアの実装は逐字次の通りです。

```javascript
const penaltySum = penOverused + penPolarity + penNbIrrelevant + penIsolatedNoise;  // 各 = additive·(1−m)
const blqScore = Math.max(additive * CFG.BLQ_SUPPRESS_FLOOR, additive - penaltySum);
```

**変数定義。**

| 記号 | 意味 | 出典レベル |
|------|------|----------|
| `m_d` | 第d番目の抑制ゲートの乗子。取値は(0,1] |
| `penalty_d` | 第d番目の抑制ゲートの加算減点。`additive·(1−m_d)` に等しい |
| `penaltySum` | 四つの抑制ゲートの減点の合計 |
| `BLQ_SUPPRESS_FLOOR` | ソフトフロア係数。0.1を取り、複数ゲートが重ねて減点してもハードにゼロにならない | 経実験校正の定档値 |
| `blqScore` | BLQ最終スコア |

この設計には二つの性質があります。一つ目として、単一ゲートがトリガーされたとき `additive − additive·(1−m) = additive·m` となり、旧式の単一ゲート連乗と等価です。複数ゲートがトリガーされたときは線形の重ね合わせ減点となり、指数的な崩壊は発生しません。二つ目として、ソフトフロアにより複数ゲートの重ね合わせ減点でもハードにゼロにならず、「大量擦辺」の下でのソフトアイソレーション原則を体現しています。システムはさらに抑制次元の集約モードのスイッチを設けており、デフォルトは加算モードです。乗算連乗モードは対照実験用としてのみ保持されます。

### 3.4.5 レッドラインハード除去（isRedlineWord）

レッドライン除去はハード除去です。命中した時点で候補プールから除去され、産出には入りません。降権ではなく除去です。四類のレッドラインの正規表現シードは構造定数であり、調整可能な数値ではありません。

- **R1 ルート語**：「どうすべきか」の動作・方法・手順を示す語（「提案」「すべき」「方法」「手順」「策略」および英語のtechnique/strategy/step等）。設計準則は方向のみを与え、ルートは与えないことです。
- **R2 誘導語**：ユーザーの代わりに判断を下す誘導表現（「あなたは必要だ」「あなたはしなければならない」「必ず」「早く行け」および英語のyou must/you need to等）。
- **R3 主観的体験/ユーザーに代わって表現**：「あなたは（とても/良い/本当に/すごく/だ/感じる/感じている……）」「私はそう思う」「気分がとても……」という表現。設計準則はユーザーに代わって表現しないことです。
- **R4 診断語**：ユーザーを障害や病症と判定する語（「障害」「患者」「うつ病」「不安障害」「確診」および英語のdisorder/syndrome等）。その中で裸の「症」の字は「症(?!状)」によって「症状」を除外します。これは「症状」が記述であり診断ではないためです。この詳細化はホワイトボックス観測の実際の出力時に発見されました。

汎用語・クォータ・極性・ガウス衰減等はいずれも降権（削除なし）であり、R1–R4のみがハード除去です。

### 3.4.6 二段精密ランキングの違い（node8の情報語選別 vs node10の方向語選別）

システムは二つの層にそれぞれ一套の精密ランキングロジックを設けており、両者の機能が異なります。

| 次元 | node8 情報語選別 | node10 方向語選別 |
|------|----------------|-----------------|
| BLQスコアリング | 完全な六次元CombSUMを実行 | 六次元は実行しない。`node9スコア × ガウス衰減`のみ |
| 側抑制 | あり（近傍コサインが閾値を超えた場合に同義として抑制） | なし |
| MMR多様性 | あり（`λ·rel − (1−λ)·maxSim`、λ=0.7） | なし |
| クォータ | あり（単軸クォータ8、単次元クォータ3、クォータ超過で降権） | なし |
| 関連性衰減 | なし（衰減はBLQ抑制次元内） | ガウス漸変 `_gaussDecay(cos, PEAK=0.45, SIGMA=0.25, FLOOR=0.15)`（位置算出、スコア圧縮ではない） |
| 断崖棄権 | なし | あり（前の語が後の語の断崖比3倍以上かつ順位5位以上の場合に断崖し、「15語を埋める」という上限を突破する） |
| 出力上限 | 30（情報語） | 15（方向語。契約は長さ15の文字列配列） |
| 出力レッドライン | 実行しない（情報語はメインモデルへ漏洩しない） | レッドラインを標注し、レッドラインハード除去コンポーネントが実行 |
| 接続状態 | コンポーネント態（本番呼び出しなし） | オンライン活性化 |

一言で要約すると、node8は「完全BLQ精密ランキングエンジン（六次元＋側抑制＋MMR＋クォータ）」であり現在コンポーネント態です。node10は「軽量選後処理（ガウス衰減＋レッドライン標注＋断崖）」であり現在オンライン活性化です。node10は完全な六次元スコアリングを再利用せず、「衰減」と「レッドライン」の二点のみを保持し、多対一投票（node9）の権限を奪いません。多対一投票の順序が主導であり、node10は降権・衰減・レッドラインのみを行います。

### 3.4.7 公開可能な原創口径

BLQフレームワークの三大コンポーネント（CombSUM・MMR・側抑制）はいずれも古典的な標準部品であり、本システムはそれらを発明したと主張しません。対外的に主張できる原創は三点に限定されます。一つ目は「加算はORゲート、乗法チェーンは単一次元による否定のANDゲートに対抗する」という設計論拠です。二つ目は三点セット＋六加点次元＋四抑制次元という特定の編成です。三つ目はソフトフロア・ソフトアイソレーション機制です。すべての重み係数・ペナルティ係数・衰減率・カットオフパラメータは経実験校正または初期デフォルトの具体的な取値であり、パラメータの詳細です。発表時は構造を主体とし、具体的な数値はロックしません。

### 3.4.8 スコアリングコアの実装摘録（節選）

前節では逐次元の公式と変量表でBLQの構造を記述しました。ここでスコアリングコア `calcBLQ` の連続的な骨格を補足します。「六加点次元の一括CombSUM、次に若干の加算減点を差し引き、最後にソフトフロアで底を支える」という形状が実装全体にどう現れるかを示します。p1_node8_10_blq.mjs より、節選。六つの加点次元の正規化表現は3.4.2節の表に逐行示してあります。ここでは集約と抑制の主幹のみを保留し、ホワイトボックストレース・極性推断分岐・境界フォールバックは省略します。

```javascript
// ── 六加分维加权 CombSUM（加法聚合，不连乘、不取均值）──
const additive =
  CFG.W_SPATIAL * dSpatial + CFG.W_TF * dTf + CFG.W_PATH * dPath +
  CFG.W_NB * dNb + CFG.W_SPEC * dSpec + CFG.W_CONFIRM * dConfirm;
// ── 四抑制维：各门先算乘子 m∈(0,1]，再转加性扣分 penalty = additive·(1−m)（各门只此一处）──
const penOverused      = additive * (1 - mOverused);
const penPolarity      = additive * (1 - mPolarity);
const penNbIrrelevant  = additive * (1 - mNbIrrelevant);
const penIsolatedNoise = additive * (1 - mIsolatedNoise);
const penaltySum = penOverused + penPolarity + penNbIrrelevant + penIsolatedNoise;
// ── 软地板托底：多门叠扣不硬归零（软隔离）──
const blqScore = Math.max(additive * CFG.BLQ_SUPPRESS_FLOOR, additive - penaltySum);
```

重み `W_*`・四つのペナルティ乗子定数・ソフトフロア係数 `BLQ_SUPPRESS_FLOOR` はすべて経実験校正の定档値であり、ここでは記号で保留し具体的な取値はロックしません。この骨格は3.4.3/3.4.4節の二つの主要公式を逐字検証しています。加点次元は加算（`additive` は純加重和）を採用し、抑制次元は「乗子から加算減点への変換」（`penalty = additive·(1−m)`）を採用しており、単一ゲートがトリガーされた場合は旧式の単一ゲート連乗 `additive·m` と等価となり、複数ゲートがトリガーされた場合は指数的崩壊ではなく線形の重ね合わせ減点となります。

ノード10の方向語軽量精密ランキングは上記の六次元スコアリングを再利用せず、ガウス衰減に置き換えます（3.4.6節の「スコア圧縮ではなく位置算出」に対応）。そのコア関数の摘録は次の通りです（p1_node8_10_blq.mjs より、節選）。

```javascript
function _gaussDecay(cos, peak, sigma, floor) {   // 落最优带→~1.0，偏离→渐降到 floor（不归零）
  if (cos == null) return 1.0;
  const g = Math.exp(-((cos - peak) ** 2) / (2 * sigma * sigma));
  return floor + (1 - floor) * g;
}
```

`peak/sigma/floor` はこの関数の最適帯中心・帯域幅・下限です（経実験校正の定档値、記号で示します）。`floor + (1-floor)·g` の構造により、どれだけ離れてもゼロにはなりません。BLQメインフレームワークのソフトフロアと共に、「ソフトアイソレーション」原則の異なる層への二度の落地を体現しています。

## 3.5 消融と失敗方案

本節では「消融と失敗方案」という体裁で、アルゴリズム進化史において実測により反証された方案を記録します。技術報告において負の証拠は独立した価値を持ちます。設計空間において「より合理的に見える」方向のどれがすでに実証的に除外されているかを示し、後続での同じ過ちを防ぎます。本節に挙げる公式の多くは歴史的な方案であり、現在の実装ではありません。読者はこれらを現行システムの動作として理解すべきではありません。

### 3.5.1 スコアリング公式の三世代進化

**第一世代：十三因子積（廃棄済み、反面教師として挙げる）。**

初期（2026-05-05版）の収束スコアリングには十三因子の全乗算が採用されていました。

```
finalScore = vote^1.2
           × dynamicPE          × ibApprox         × crossFaceBonus
           × valCoh             × nbBoost          × dimOverlapPenalty
           × stageBoost         × routeBoost       × crossoverBoost
           × memAnchorBoost     × registerBoost    × modeDirBoost
```

反面教師とされた理由は三点あります。一つ目として、十三因子全乗算はANDゲートと等価であり、いずれかの因子が低ければ全体が崩壊します。二つ目として、各因子は互いに独立していません（投票項と交差項は高度に相関しています）。これはナイーブベイズ積が要求する独立性仮定に違反します。三つ目として、若干の因子はそれぞれ定義上の欠陥を持っています。例えば動的サプライズ度はユーザー間の汚染を引き起こし、ある重み付き項が投票を虚増させ、次元重複ペナルティ項 `0.55^(dims-2)` がハブ語を消去しており、「小さな語が大きなモジュールを活性化する」という設計の取り向きと逆行しています。

**第二世代：軸平均（書き直し済み）。**

その後、十四次元の座標内積の平均を取る方法に変更され、初めて4.0点を突破しました（4.050）。

```
score = Σ[(coordAccum[i] × termCoords[i]) / max(|coordAccum[i]|, 0.5)] / 14
```

この方案は「汎用語の主な原因は一部の軸スコアが過度に高いため、平均を取るべき」という初期の考えに対応していましたが、平均を取った後に否決されました。平均を取ることで次元間の張力がゼロになり、汎用語が約25%増加したためです。これにより第三世代の加算投票へ進化しました。

**第三世代：加重線形/加算投票（現在の方向）。**

リコール側は現在加重線形結合を採用しています。

```
composite = 0.45×relevance + 0.20×recency + 0.20×attention + 0.15×weight
```

重み係数は経実験校正の定档値です。この方案は「単純化しない」というレッドラインの下で唯一承認されたアルゴリズムの単純化です。これは退化ではなく向上であるためです。実測では複数のデータセットにわたって著しい改善をもたらしました。対応するレッドラインには次のものが含まれます。乗積へ回帰しないこと（乗積方案は実測でリコール率が大幅に低下）・softmax正規化を削除しないこと・重みの具体的な数値は調整可能だが「加重線形の方向」そのものはロックされること。

システムはデバッグ用に旧式の乗積式単ノードスコアリングも保持しています。

```javascript
ebbinghaus = record.freq × (1 / (1 + days × 0.1));            // Ebbinghaus 遗忘曲线
importance = record.weight × Math.max(0, 1 - days / 60);      // 60 天外完全消失
axisOverlap = Σ cosineSim(qVec, kVec) / |axes|;               // 多轴投影同向（归一化）
spreadDecay = Math.pow(0.6, spreadDistance);                  // 0/1/2/3 → 1.0/0.6/0.36/0.216
scorePerNode = ebbinghaus × importance × axisOverlap × spreadDecay;
scoreRecord = max(scorePerNode)  // max-pool：一条记忆一个维度极强即召回
```

またゲート判定用（ランキングには参加しない）の三因子信頼度も設けています。

```
confidence = 0.5×max(score) + 0.3×(命中数/2 clamp[0,1]) + 0.2×轴一致性
闸门阈值：chat/airp 0.5 / game 0.6 / work/bot 0.7 / code·memory 不跑发散
```

上記の三因子重みとゲート閾値はいずれも経実験校正の定档値です。

### 3.5.4 遠距連想の距離帯（現行参照）

システムは発散の遠近を制御する「スイートスポット」距離帯を採用しています。これが現行参照となっています。

```
semDist < 0.15 → blq × 0.4   (太近，同義語冗長)
semDist < 0.25 → blq × 0.7
semDist > 0.80 → blq × 0.5   (太遠，ランダムノイズ)
semDist > 0.70 → blq × 0.8
```

スイートスポットは `0.15 < semDist < 0.80` であり、各衰減係数は経実験校正の定档値です。関連するレッドラインとして、距離1の同義拡散は実測でリコール率とランキング指標を著しく低下させるため、「類比は跨域の同型であり、同義拡散は行わない」というレッドラインが設けられています。

### 3.5.5 完全認知活性化方程式（未実装）

システムでは完全なACT-R活性化方程式を計画していましたが、現在はファンアウトペナルティ項のみが接続されており、基礎活性化と拡散活性化の部分は未実装です。

```
基础激活: B_i = ln(Σ_j t_j^{-d})            d = 0.5（衰减率）        ← 未実装
拡散激活: S_ji = S - ln(fan_j)              S = 2.0（最大連想強度）  ← 未実装
         W_j = 1.0 / len(context_chunks)                            ← 未実装
完整方程: A_i = B_i + Σ_j(W_j × S_ji) + ε_i  ε = 0.5（噪声）        ← 未実装
検索閾値: τ = -2.0    遅延: T = 0.35 × e^{-A_i}
```

現在実装されているのはファンアウトペナルティ `fanPenalty = 0.015 × log(fan(term))`（ACT-Rのファンアウト効果に対応、Anderson 1974）のみであり、完全な活性化方程式の約五十行は未接続です。衰減率・最大連想強度・ノイズ・検索閾値等はいずれも計画中の初期デフォルト値です。

### 3.5.7 歴史的統一公式設計稿（乗法版、現行実装ではない）

進化の過程でかつて七因子の統一公式設計稿が作成されており、乗法形式を採用していました。

```
F(w) = Activation(w) × IB-tradeoff(w) × (1+λ·Sys(w))
     × LogicScore(w) × PathHarmony(w) × NoveltyBonus(w) × Σαₐ·scoreₐ(w)
```

各分項の定義は次の通りです。活性化 `A(w) = A₀·∏[γ·wₖ·I_disc(k)]`（γは0.7–0.85を取り、チェーン長Kは3以内、学科切り替え指標I_discは跨学科の場合1・同学科の場合0.5、活性化が0.15を下回った場合停止）。情報ボトルネック権衡 `Score(w) = d(w)/(1+α·d(w)²)`、最適距離 `d* = 1/√α`（逆U字型、中間値が最適）。構造マッピング `Sys = 0.5·H(高次関係) + 0.3·R(一次) + 0·A(属性はノースコア)`。パス調和 `log(1+異なる学科数) × 一貫性`、一貫性は `1 − (切替回数−学科数)/総ステップ数`。新奇性 `1/√(historical_count+1)`（信頼上界の簡略版）。

強調すべきは、この設計稿は七因子乗法版であり、3.4節に示す現在実装の加算CombSUM版とは異なります。これは「加算が乗算より優れている」という論拠に取って代わられた進化過程の中間状態であり、現行実装ではありません。

### 3.5.8 廃棄/反証済み方案一覧

以下の方案はいずれも実測で反証または廃棄されており、繰り返すべきではありません。昇権上限を+0.3から+0.05に変更するとすべてゼロに帰着する。投票指数を1.2から1.0に変更すると退步する。tanhでmaxAbsを置き換えると退步する。VAD三値を直接置き換えると退步する。距離1の同義拡散が著しく退步する。オンライン学習方案で訓練が振動する。HyDEのオンライン版は0-tokenの原則に違反するとして却下される。有料ルーティング方案が却下される。词林符号化距離類比方案（出力が高度に画一化する）。ソフトウェイトモードルーティング（モードベクトルが過度に類似する）。外部モデルによる連想データの生成（レッドライン違反のため削除済み）。共起ストップワード表方案が退步する。一度も有効化されなかった遅延バインディングのデッドコード。

### 3.6.3 人手による精査が必要な重点項目

類似度が比較的高い三点を、人手による重点的な精査が必要な項目として挙げます。

一つ目として、SYNAPSE（arXiv 2601.02744，2026-01、本システムより早い）と「大量擦辺リコール」は拡散活性化・側抑制・ファンアウト効果という三つの術語を共有していますが、用途は直交しています（検索質問応答精度 vs 発散生成）。要旨の層では実装レベルでのより深い衝突を排除できないため、全文を精査して確認する必要があります。

二つ目として、ある熱/温/冷三層記憶構造（arXiv 2603.00037，2026-03-18）は名称が同じであるだけでなく、物理ファイルディレクトリで同様に分層され、日付命名のログも同様です。本システムの三層設計はプロジェクト記録によれば数日早く開始されていますが、差は数日に過ぎず機制の類似度が高い——これは類似度が最も高い項目であり、独立した並行発明を確認するためにプロジェクト記録を精査する必要があります。

三つ目として、システムの一部の変数更新とテンプレートエンジン能力はSillyTavernエコシステムからの移植です（変数更新機制やプロンプトテンプレートエンジン等）。発表時は対応する上流プロジェクトへの謝辞が必要です。本システムのこの上にある原創的な拡張は、実行依存チェーンの編成とサーバーサイド統合に限定されます。

### 3.6.4 参考借用来源リスト

システムは設計において多領域の古典的工作を参考にしています。認知科学とバイオインスパイアードの面では、実装済みの参考借用には次のものが含まれます。活性化拡散（Collins & Loftus 1975）は多路拡散活性化に対応します。ファンアウト効果（ACT-R，Anderson 1974）はファンアウトペナルティに対応します。パターン分離/補完（海馬体）は三層記憶ライブラリに対応します。補完的学習システム理論（McClelland 1995）はリコールと拡散活性化の二元構造に対応します。情報ボトルネックの逆U字型（Tishby 1999）は情報ボトルネック近似に対応します。サプライズ変調（Pearce-Hall 1980）は頻度衰減に対応します。弱連結理論（Granovetter 1973）はブリッジ経路に対応します。構造マッピングエンジン（Gentner 1983）は構造類比に対応します。スクリプト/フレーム理論（Schank 1977）はフレームパターンに対応します。システム機能言語学（Halliday 1994）は虚語処理に対応します。愛着理論（Mikulincer-Shaver）はキャラクター心理チャンネルに対応します。

### 3.6.5 全局事実層の小括

総合的に見ると、以下の事実層の結論が得られます。第一に、算法線では「機制が高度に類似しかつ2026-04より早い」という意義において衝突した項はゼロです（A=0）。フレームワーク/システム線では三層記憶の一項のみが類似度が極めて高い（数日差・同名・物理ファイル同様）です。第二に、本システムの原創性の主張は一般的に「組み立て/移転/設計論拠」の層にあり、個々の部品にはありません。関係する部品（逆距離加重・Hough投票・CombSUM・MMR・側抑制・活性化拡散・粗から細へのルーティング・ホットロード語彙ライブラリ等）の多くは1990年代から2020年代の成熟技術であり、本システムはそれらを発明したとは主張しません。対応する公開工作が見つかっていないのは「それらを発散に特化した外付けパイプラインに編成すること」および若干の具体的な判定基準と移転（Houghの方向語生成への移転・括弧デュアルチャンネル・廃語判定基準・語彙ライブラリファイル即発散軸・加算が乗算のANDゲートに対抗するという論拠）です。第三に、上記の三つの高類似項は人手による精査が必要です。

## 3.7 小括

本章では自己駆動発散リコールシステムのアルゴリズム設計を形式的に記述しました。コアを三層で帰納します。

機制層において、システムは「収縮—発散—収縮」の三段構造で大規模言語モデルの外側に外付けされ、二段の異質発散・六軸面の並列処理・空間加算投票・多対一収束により、孤立した連想点をメインモデルが利用できる方向語に変換します。

スコアリング層において、BLQフレームワークは加重CombSUMの加算スコアリングで乗法チェーンの単一次元による否定に対抗し、側抑制・MMRクォータ・ソフトフロア・レッドラインハード除去を補助として、完全かつホワイトボックスで閲読可能な候補品質装置を形成しています。その中で情報語精密ランキングエンジンは現在コンポーネント態であり、方向語軽量精密ランキングはオンライン活性化状態です。

原則層において、全工程は0-tokenホワイトボックスの立場に従い、単一の発散のためにLLMを呼び出しません。

関連工作対照から見ると、システムが使用する個々のアルゴリズム部品の多くは成熟技術であり、その原創性の主張は編成・移転・設計論拠の三層に落ちます。逐項検査では「機制が高度に類似しかつ設計期より早い」という意義での衝突は発見されず、若干の高類似項のみさらなる人手による精査が必要です。進化史において反証された方案——十三因子積・軸平均・乗法版統一公式を代表として——は共同で現在の「加算が乗算より優れており、ソフトアイソレーションがハードゼロ帰着より優れている」という設計の取り向きを支持しており、本システムのアルゴリズム設計における負の証拠基盤を構成しています。
