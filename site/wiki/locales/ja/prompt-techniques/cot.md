# CoT(思考の連鎖)

CoT（Chain of Thought、思考の連鎖）は、AI が最終的なコンテンツを出力する前に、まず分析と計画を行わせる技術です。単なるプロンプトテクニックではなく、AI の作業方法を変える方法論です。

## CoT(思考の連鎖) とは

通常、AI はプロンプトを受け取ると直接結果を出力します。CoT(思考の連鎖) では、AI にまず「考えさせる」ことを要求します——現在の状況を分析し、次に何をすべきか計画し、注意すべきポイントを整理してから出力します。

```
CoT なし：
  プロンプト → 直接出力

CoT あり：
  プロンプト → 状況分析 → ポイント計画 → 出力
```

この「考えてから行動する」プロセスにより、AI の出力品質と一貫性が大幅に向上します。

## なぜ CoT(思考の連鎖) が効果的なのか

1. **注意力配分を誘導する**：分析フェーズで、AI がプロンプトの各要件を再確認し、漏れを防ぎます
2. **逸脱を減少させる**：計画フェーズで AI が書き始める前に方向を確定し、行き当たりばったりにならないようにします
3. **複雑なタスクのパフォーマンスを向上させる**：複数の条件を同時に満たす必要があるタスク（ロールプレイ、コード生成、長文執筆）で、CoT(思考の連鎖) は AI が複数の制約間のバランスを取る手助けをします

## CoT(思考の連鎖) + プロンプト = 最大の効果

CoT(思考の連鎖) とプロンプトを組み合わせて使用すると、どちらか単独よりもはるかに大きな効果を発揮します。

### 例：ロールプレイシーン

```
CoT なしのプロンプト：
────────────────
あなたは退役軍医で、性格は沈着です。
白描を主とし、対話でプロットを推進します。

→ AI は設定の一部を無視し、スタイルが不安定になる可能性があります。
```

```
CoT を加えたプロンプト：
────────────────
あなたは退役軍医で、性格は沈着です。
白描を主とし、対話でプロットを推進します。

出力前に、まず <thinking> で以下の分析を完了してください：
1. 現在のシーンの感情的基調は何か
2. キャラクターはこの状況でどんな反応をするか
3. この返信でどのプロットポイントを進めるか
4. 注意すべきスタイル要件は何か

その後、出力してください。

→ AI がまず要件を整理してからコンテンツを書くため、
  スタイルがより安定し、設定との一致度が高まります。
```

### 例：コードアシスタントシーン

```
CoT を加えたプロンプト：
────────────────
プログラミングの質問に答える前に、まず分析してください：
1. ユーザーの実際のニーズは何か（表面的な質問だけでなく）
2. どのような実装方法が考えられるか
3. 各方法のメリットとデメリット
4. 推奨する方法の理由

その後、コードと説明を提示してください。
```

## CoT(思考の連鎖) は検証の助手

CoT(思考の連鎖) は AI の出力を改善するだけでなく、**プロンプトをデバッグ**するツールでもあります。

### CoT(思考の連鎖) でデバッグする方法

AI のパフォーマンスが期待に沿わない場合、CoT(思考の連鎖) の分析プロセスを確認します：

1. **AI は正しく理解しているか？** —— CoT(思考の連鎖) での AI のプロンプトに対する解釈が、あなたの意図と一致しているか確認します
2. **AI は何に注目しているか？** —— CoT(思考の連鎖) で AI が重点的に分析した側面と、無視した側面を確認します
3. **AI はどこで逸れたか？** —— 最終出力に問題がある場合、CoT(思考の連鎖) から逸脱し始めた箇所を見つけます

### デバッグの例

「テンポの速いアクションシーンを書いて」と要求したのに、AI がスローモーションの長い描写を出力したとします。

CoT(思考の連鎖) を確認すると、こんなことが分かるかもしれません：

```
AI の thinking：
「ユーザーはテンポの速いアクションを求めている。
 一つ一つのアクションを詳細に描写して、
 アクションの素晴らしさを見せる必要がある……」
```

問題が特定できました：AI は「テンポが速い」を「詳細」と理解してしまいました。これでプロンプトをどう修正すべきかが分かります：

```
修正前：テンポの速いアクションシーンを書いてください。

修正後：アクションシーンを書いてください。短文を使い、
1つのアクションにつき1文、各アクションの詳細は展開せず、
段落は3行以内に保ってください。
```

## beilu で CoT(思考の連鎖) を使う

beilu の[プリセットシステム](../presets/overview.md)は、システムプロンプトへの CoT(思考の連鎖) 誘導の埋め込みに対応しています。以下のことができます：

- キャラクターカードの末尾に CoT(思考の連鎖) の分析ステップを追加する
- プリセット条目で thinking の指針を設定する
- テールインジェクションを利用して現在のシーンの CoT(思考の連鎖) プロンプトを配置する

テールに配置するのが最も効果的です（U 型注意力原則を参照）。CoT(思考の連鎖) の誘導は「今やるべきこと」に該当し、高注意力領域に属するためです。

## 注意事項

- CoT(思考の連鎖) は AI の出力長を増加させます（分析部分も token としてカウントされます）。token 使用量にご注意ください
- すべてのシーンに CoT(思考の連鎖) が必要なわけではありません。単純な Q&A や日常会話には不要で、複雑な創作や多制約タスクにこそ必要です
- CoT(思考の連鎖) の分析ステップは多すぎないようにしましょう。3〜5 ステップが適切です。ステップが多すぎると、分析フェーズで AI が逸れてしまいます
- 一部のモデルは内蔵の thinking 機能に対応しています（例：Claude の extended thinking）。プロンプト内の CoT(思考の連鎖) 誘導と組み合わせて使用できます
