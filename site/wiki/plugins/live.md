# 直播接入：先筛选，再复用主对话链

beilu-live 解决的不是“再做一个直播机器人”，而是把实时弹幕变成现有聊天系统的一种输入。预设、记忆、模式、AI 服务源和流式回复仍走原来的主链。

## 什么时候值得用

- 你在直播时要从大量弹幕中挑出值得回答的内容；
- 你希望角色设定和长期记忆在直播回复里继续生效；
- 你不想让每条弹幕都触发一次模型调用；
- 你想把筛选规则、回复节奏和承载对话分开控制。

如果你只偶尔复制一两条问题，手工处理更简单。它也不是 OBS、直播推流或完整的内容审核系统。

## 当前默认状态

- 插件总开关默认关闭；安装或加载插件不会自动连接直播间。
- “已启用”与“正在运行”是两个状态：先开总闸，再执行启动。
- 当前平台注册表包含 Bilibili 接入。
- 辅助 AI 默认关闭；主路径不依赖额外的第二条生成链。

## 完整链路

```text
直播平台持续消息
  → 平台 adapter 建连并标准化消息
  → 确定性初筛：长度 / 黑名单 / 关键词 / 用户冷却 / 文本去重
  → 候选池：容量与过期时间
  → 选择器：最近用户、上次已回复用户、礼物权重
  → 按最小轮间隔组成一轮弹幕上下文
  → Live 模式进入既有主对话链
  → 预设 + 记忆 + AI 服务源生成回复
```

初筛本身不调用模型。候选池为空时可以跳过生成，避免空转；高流量时也不会按“每条弹幕一次请求”工作。

## 承载到哪一个对话

优先级是：

1. 直播配置里显式绑定的 chatId；
2. 正在运行的游戏陪伴会话；
3. 两者都没有时，启动会诚实返回缺少承载目标，而不是猜当前浏览器窗口。

这保证直播回复、记忆和历史记录回到明确的对话归属。

## 可以调什么

在[插件管理](beilu:settings/plugins)打开“直播设计”。配置按用户保存，主要分为：

- 平台、房间号和平台凭据；
- 黑名单、关键词、最短/最长长度；
- 同一用户冷却与重复文本窗口；
- 候选池容量和过期时间；
- 每轮选择数量、礼物权重和上次回复标记；
- 生成轮间隔、空池跳过；
- 心跳、重连、退避和 HTTP 超时；
- 可选辅助 AI 的频率与服务源。

修改配置不会等同于启动连接；运行状态由启动、停止和状态接口单独管理。

## 数据与凭据边界

- 每位用户的直播配置保存在自己的用户数据目录；
- 平台连接会把房间号和必要凭据发送给对应直播平台；
- 通过筛选的弹幕会进入最终提示词，因此也会发送给你选择的主 AI 服务；
- Bilibili 的公开弹幕可在不填写登录 Cookie 的情况下尝试连接；需要身份能力时才填写相应凭据；
- 凭据应只在插件配置界面填写，不要写进预设、世界书或公开日志。

## 与哪些能力组合

- **memory + P1：** 直播中提到旧事件时仍能召回相关记忆；
- **preset/worldbook：** 保持角色口吻、直播规则和栏目设定；
- **eye：** 同时加入屏幕或游戏画面感知；
- **AIRP：** 为直播回复增加场景化显示，但不改变弹幕筛选链。

## 排错顺序

1. 总开关是否开启；
2. 平台和房间号是否填写；
3. 是否存在显式承载 chatId 或运行中的陪伴会话；
4. 状态是 connecting、authed、retrying 还是 closed；
5. 过滤规则是否把全部弹幕排除了；
6. 轮间隔、候选池和空池跳过是否符合预期；
7. 最后再检查平台凭据与网络。
