# 多窗口与多开

beilu 支持同时开多个窗口一起干活：一个窗口和 AI 聊天，另一个窗口让 AI 写代码，第三个窗口跑工作任务——互不打断，各自拉自己的线。这一页讲清楚多窗口是怎么工作的、AI 怎么跨窗口叫醒对方、以及你不会错过任何一个窗口的动静。

## 窗口和模式的关系

先分清"窗口"和"模式"：

- **聊天窗口（Chat）与角色扮演（AIRP）** 共用同一个后端"chat 模式"——它们是同一套聊天引擎的两种界面。
- **Bot 管理** 也是基于 chat 模式的一层管理界面（Bot 回消息走的就是聊天引擎）。
- **Code（编程）和 Work（工作）** 各自是独立模式，有自己独立的记忆目录、表格和提示词。

所以"同时开 chat 和 code"实际是两套独立环境并行运行，天然互不干扰。

## 三级隔离：谁和谁不串门

beilu 的数据隔离像一栋楼的三层门禁：

| 层级 | 比喻 | 隔离了什么 |
|------|------|-----------|
| **用户级** | 每人一套房 | 每个登录用户有自己的设置和角色卡，互相看不见 |
| **角色卡级** | 每个角色一个大脑 | 每张角色卡有自己的记忆、表格、对话文件、正则规则——换卡就是换一套大脑 |
| **窗口级（对话线级）** | 每条对话一条线 | 同一张角色卡可以开多条对话线，每个窗口打开其中一条，各聊各的 |

## chatid 的真实角色：窗口 = 对话 = chatid

窗口本身没有"身份证"。一个窗口"是谁"，完全由它当前打开的那条对话线（chatid）决定——**窗口 = 对话 = chatid**。

chatid 就是为"同一个模式开多个窗口"服务的：想在同一模式下多开，就是开多条对话线，每个窗口占一条。模式切换、AI 的子模式切换、委派引发的角色变更，都只写入当前这条对话线，不会广播串到你其他窗口。

## 同时开 chat + code 会怎样

答案：什么都不会坏，各干各的。

- 四个主模式（chat / code / smart / work）在浏览器里各自记住"上次开的是哪条线"，是四把互不干扰的独立钥匙。
- chat 窗口正在生成回复时，code 窗口照常提问，两边各自拉自己的生成链路。
- 一个窗口切换子模式 / 委派任务，只影响它自己那条对话线。

围绕它们的几条规则：

- **防死循环**：短时间内同方向的重复唤醒会被自动跳过，防止"A 叫醒 B、B 又叫醒 A"的无限循环。
- **定时任务也能跨窗口**：Work 模式的定时任务到期后，不止能提醒当前会话，还可以按任务配置唤醒或传话到指定的其他对话线（详见 [工作模式](beilu:wiki/modes/work.md) 的定时任务一节）。
- **Bot 场景有权限门**：来自外部平台（Discord 等）的低权限触发者（档位低于 L2）无法让 AI 执行跨窗口唤醒/传话，详见 [Bot 模式](beilu:wiki/modes/bot.md) 的权限分档。

所以"AI 怎么定时提醒我"的完整答案是：在 Work 模式给它设定时任务（或让它自己输出定时标签），到期它会在对应窗口醒来；如果你人在别的窗口，配合下面的通知系统，你也不会错过。

## 不在那个窗口，怎么知道它有动静：跨模式通知

你开着 chat 窗口聊天，work 窗口在后台跑完了任务——怎么知道？

1. **页内弹窗**：右上角弹出通知卡片（约 10 秒自动消失），点"去查看"直接跳到对应窗口。
2. **通知中心**：错过了弹窗也没关系，顶栏 🔔 图标里保存最近 24 小时内最多 20 条通知历史，随时回看。
3. **桌面通知**：浏览器窗口失焦（你切去看别的软件）时，重要事件会升级为操作系统级桌面通知。

这三样各有一个独立开关——**角标 / 页内弹窗 / 桌面通知**——都在 🔔 通知中心里设置，按你的打扰耐受度自由组合（比如只留角标、关掉弹窗）。通知历史的记录不受弹窗开关影响：关了弹窗，历史照记。

## 并行组（groups）和多开窗口是两回事

容易混淆的两个概念：

| | 多开窗口 | 并行组（groups） |
|---|---------|-----------------|
| 是什么 | 你自己开多个浏览器窗口/标签页 | Work 模式内部的多角色协作机制 |
| 谁在并行 | 你的多个会话 | 一组 AI 角色（每组一个独立工人进程） |
| 入口 | 直接开新标签页 | Work 模式活动栏的 groups 按钮 |

简单说：多开窗口是"你分身"，并行组是"AI 分身"。
