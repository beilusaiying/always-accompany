# 记忆AI预设(P1-P8)

记忆系统的幕后运行着多个专用 AI 预设（Preset），各自负责记忆生命周期的不同环节。这些预设不是用户直接交互的角色 AI，而是系统级的后台工作者。

> **注意：此处的"预设"与[对话预设系统](../presets/overview.md)是两套完全独立的机制，不要混淆。** 本页讲的是 P1-P8 记忆 AI 的后台工作预设；你在左栏下拉切换的、控制主 AI 行为的那套"预设"，请看[预设系统](../presets/overview.md)。查错文档解决不了问题。

## 预设一览

| 预设 | 名称 | 职能 | 触发时机 |
|------|------|------|----------|
| **P1** | 召回 | `10` 本地 Node0–4 自驱动 / `01` 原 AI P1 / `00` 全关（互斥，不开放双开） | 每轮对话前自动 |
| **P2** | 表格总结/归档 AI | 读取已归档的临时记忆，生成精炼总结写入大总结表 | 手动按钮（2026-08 起不再随归档自动跑；物理归档仍自动） |
| **P3** | 每日总结 AI | 日终汇总当天事件，生成日总结 | 每日收尾 |
| **P4** | 热→温转移 AI | 将热层中过期/低权重的记忆移入温层 | 搬迁检查时 |
| **P5** | 月度总结/归档 AI | 为满归档期的温层月份编纂月总结 | 月度归档时 |
| **P6** | 格式检查/修复 AI | 检查并修复表格和记忆文件中的格式问题 | 格式检查/一键升级时 |
| **P7** | 压缩 AI | 上下文过长时生成摘要 | 上下文超限时 |
| **P8** | 联网搜索 AI | 调用外部搜索获取信息 | AI 判断需要外部信息时 |

## P1：召回（两条线互斥）

P1 是记忆召回引擎，每轮对话前自动运行。它有三个可用状态：`10` 本地自驱动召回（当前默认方向）、`01` 原 AI P1、`00` 全关，不开放 `11` 双开。

**`10` 自驱动 P1 运行链（本地 Node0–4 白盒链，召回阶段 0 次生成式 LLM 调用）**：

```
当前用户输入 1 条 + 最近 5 条用户消息 + Data（AI 历史输出 0 条）
    ↓
Node1 本地分词 / 词性 / 时间与专名锚点
    ↓
Node2 关联扩展（SWOW / ConceptNet / 词林 / ATOMIC）
    ↓
Node3 多证据审查（BLQ / NB300 / WordNet）
    ↓
Node4 从 Data + hot/warm/cold + 当前模式 MD 召回真实记录
    ↓
BM25 / 短语 / 时间 / 文件创建时间 / 层级 / Top / importance 融合排序
    ↓
recalledRecords + directionWords + 白盒 trace → 按位置合同注入上下文
```

**`01` AI P1**：每条消息触发一次真实 AI 子调用，由 P1 预设提示词指导它判断要不要翻记忆、翻哪些（可发 `<memorySearch>` 多轮搜索），整理后交给主 AI。

完整合同（输入、隔离、缓存、白盒）见[当前生产合同](../p1-recall/ch7-current-runtime.md)。

## P2：总结归档

P2 负责将临时记忆提炼为结构化记忆并归档到温层。**触发方式为手动**（2026-08 起：临时记忆超阈值时系统只自动执行物理归档落盘，不再自动唤起 P2；想要 AI 精炼总结，去 P 系列面板手动运行 P2）。

**运行链**：

```
（临时记忆已被自动物理归档到温层批次文件）
    ↓
用户在 P 系列面板手动运行 P2
    ↓
P2 读取归档的临时记忆内容
    ↓
提取关键信息：事件、情感、决策、新认知
    ↓
归纳为结构化条目并生成总结
    ↓
写入对应的记忆表格（通过 <tableEdit> 机制）
    ↓
归档到温层（触发搬迁检查）
```

## P3-P6：记忆生命周期维护

P3 到 P6 各自负责记忆"新陈代谢"的一个环节，在后台按时机自动运行：

| 预设 | 职能 | 说明 |
|------|------|------|
| **P3 每日总结 AI** | 日终汇总当天事件 | 在每日收尾时把当天发生的事汇总成日总结（对应 #6 日总结表） |
| **P4 热→温转移 AI** | 热层降温 | 把热层中过期或低权重的记忆条目移入温层，控制热层容量 |
| **P5 月度总结/归档 AI** | 月度归档 | 为达到归档期的温层月份编纂月总结，物理搬移由系统自动执行 |
| **P6 格式检查/修复 AI** | 格式维护 | 检查并修复表格与记忆文件中的格式问题，配合工具栏的"格式检查/一键升级" |

这些预设配合 P1（召回）、P2（归档）、P7（压缩）、P8（联网）构成完整的记忆管线，使用者通常无需手动干预。

## P7：压缩 AI

P7 在上下文接近限制时触发，生成对话摘要以释放空间。

**运行链**：

```
上下文 token 数接近模型限制
    ↓
系统触发 P7
    ↓
P7 读取较早的对话轮次
    ↓
生成压缩摘要
    ↓
摘要存入 context_summary.json
    ↓
原始对话轮次从上下文中移除
    ↓
后续对话中，摘要替代原始内容出现在上下文中
```

详见 [上下文压缩](compression.md)。

## P8：联网搜索

P8 在 AI 判断需要外部信息时触发。

**运行链**：

```
AI 判断当前问题需要外部信息
    ↓
系统调用 P8
    ↓
P8 构造搜索查询
    ↓
调用搜索接口获取结果
    ↓
将搜索结果注入当前上下文
    ↓
AI 基于搜索结果继续回复
```

## 预设间的协作

一轮典型的对话中，预设的协作顺序：

```
用户发消息
    ↓
P1 召回相关记忆 → 注入上下文
    ↓
AI 回复（可能触发 P8 联网搜索）
    ↓
AI 回复中的 <tableEdit> 写入热层
    ↓
达到阈值时自动物理归档（P2 的 AI 总结需手动运行）
    ↓
上下文过长时 P7 执行压缩
```

## P系列引擎编辑面板

在[记忆管理](beilu:mode/memory)中点击工具栏的 **pseries** 按钮，可打开 P 系列引擎编辑面板。

### 布局

- **左侧列表**：显示 P1 到 P8 全部预设，点击切换；列表下方有常驻的**「新建预设」入口**——可以创建 P1-P8 之外的自定义记忆预设（右侧就地表单填写，区分"仅创建"和"创建并设为当前"两个动作）
- **右侧详情**：展示并编辑选中预设的完整配置

### 可编辑项

| 项目 | 说明 |
|------|------|
| 启用 toggle | 控制该预设是否生效 |
| 描述 | 预设的功能说明文字 |
| AI 调用参数 | AI 源、模型、后处理、预填充、temperature 等 |
| 提示词组 | 按查看模式（chat / code / work）编辑不同的提示词集 |

### 提示词编辑

切换查看模式后，右侧展示该模式下的提示词列表。支持增删改查（CRUD）：新建提示词条目、编辑内容、调整顺序、删除条目。

## P1 自驱动面板

记忆管理的活动栏还有独立的「P1 自驱动」组，3 个入口：

| 入口 | 功能 |
|------|------|
| 运行/测试 | 手动运行一次自驱动召回并查看白盒结果（输入了什么、召回了什么、为什么） |
| 词库管理 | 查看和维护 P1 的词库资源 |
| P9 维护 | P9 词库维护子模式的操作入口（配套预设在 📚P9词库 分类下） |

另有**打字联想**：输入栏的联想提示功能，随输入实时给出联想候选；以及**运行记录卡片**：每次 P1 运行的记录可展开查看。

## 记忆AI预设交互面板

在[记忆管理](beilu:mode/memory)的检索/诊断区，或通过预设切换器进入交互面板。

### 预设切换器

切换器按"排除法"决定显示哪些预设，而不是固定区间：

- **P1 永远不显示**（自动检索不需要手动运行）
- **P7 仅编程/工作模式显示**（压缩 AI 在聊天模式隐藏）
- **其余预设（含 P8）在所有模式都显示**

也就是：聊天模式看到 P2-P6 加 P8；编程/工作模式看到 P2-P8。

点击预设名称切换到对应的交互界面。

### AI 对话交互

- **运行预设**：点击运行按钮，系统调用选中的预设，结果以气泡形式展示
- **用户输入**：在输入框中追加消息并发送，与预设 AI 进行多轮对话
- **异步运行**：长时间运行的预设可后台执行，完成后点击"查看"获取结果
- **清空**：重置当前预设的对话历史

### 提示词预览

交互面板提供三个预览标签页：

| 标签 | 内容 |
|------|------|
| 消息列表 | 按 section 分段展示最终发送给 AI 的消息结构 |
| 原始 JSON | 查看完整的原始请求数据 |
| 预设预览 | 预览预设本身的配置内容 |

### 文件树与导入导出

- **文件树视图**：以树形结构浏览预设相关的文件
- **导入导出**：支持 zip 和 json 格式的预设导入导出

## 诊断面板

在[记忆管理](beilu:mode/memory)中点击工具栏的 **diag** 按钮，或在检索/诊断区切换到"诊断"子 Tab。

面板展示以下信息：

- **插件启用状态**：记忆插件是否已启用
- **auto_trigger**：P1 自动触发是否开启
- **P1 状态**：当前 P1 引擎的运行状态
- **缓存信息**：缓存字符数与缓存时间
- **输出队列**：待处理的输出条目
- **启用预设列表**：当前已启用的预设清单
- **缓存内容**：可展开查看完整的缓存数据

## 开发注意事项

- 各预设使用独立的系统提示词，定义其行为和输出格式
- 预设的触发条件和阈值在配置中可调
- P1 的召回质量直接影响 AI 的"记忆力"表现，是性能调优的关键环节
- P2-P6 分别负责记忆生命周期的不同环节（归档、日/月总结、搬迁、格式修复），配合 P1 召回、P7 压缩、P8 联网构成完整的记忆管线
