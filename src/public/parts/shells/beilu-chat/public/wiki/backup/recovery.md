# 回档与回收站：误删了怎么救回来

beilu 对"删除"的态度是：先留后路，再动手。几乎每一种破坏性操作背后都有一层安全网，但**不同粒度的删除走的是完全不同的两条路**——搞清楚这两条路，误删时才知道去哪里找。

## 最重要的一件事：两条删除路径

记忆口诀：**删消息=先建可恢复证据，删整个=优先进回收站**。快照/回收站提供的是恢复入口，不是对每一次跨存储操作“必然完整回滚”的承诺。

## 路径一：删错了几条消息，怎么撤回

1. 打开「设置」→「备份」标签页 →「查看对话备份」。
2. 列表里混合显示两类备份：
   - **自动备份**——每次对话保存时自动滚动备份（保留最近 20 份）；
   - **删除快照**——你删单条/批量删消息前的瞬间快照（保留最近 5 份）。
3. 选中想回到的时间点，点恢复。

恢复前会尝试为“当前状态”建立保险快照。若界面或日志显示快照创建、读取、落盘失败，先停止继续删除/回档并保留错误信息；不要把空的预览或“请求已发送”当作已有可恢复点。

## 回档到此：它包含哪些层，结果怎么看

消息菜单中的“回档到此”是一次跨层操作：稳定消息锚点 → 生成静默 → 记忆/表格快照 → 已绑定 IDE 实例的文件检查点 → 对话尾部截断。开始前先做只读预览；执行时必须使用该预览返回的检查点集合和 IDE 路由令牌。如果在预览与执行之间换了 IDE 窗口、检查点集合变化或目标消息已被删，系统应拒绝执行并要求重新预览。

不要只凭“回档”按钮关闭判断结果。完整成功只在 `success=true`、`applied=true`、`partial=false` 同时成立；`partial=true` 表示至少一个层已变更但整体未完成，`indeterminate=true` 表示客户端无法确认最终状态。两种情况都应先重新读取对话/文件/记忆状态，再决定是否恢复备份或人工处理。

## 路径二：删了整个对话 / 角色卡 / 人设 / 账号 / AI 源

这类删除优先把文件送进**操作系统回收站**（Windows 的回收站）。找回方式：

1. 先去电脑的系统回收站里找。
2. 如果当时系统回收站不可用（比如某些环境送不进去），beilu 会兜底：**先把文件完整复制到数据目录的 `data/_trash_fallback/日期/` 文件夹里，复制成功后才删原件**。去这个文件夹里按日期翻。
3. beilu 产品界面内目前**没有**"回收站浏览器"页面——找回被删的整块数据，只能走上面两条路。

**特别注意"彻底删除"选项**：删角色卡、AI 源、账号时，会弹窗问你——"进回收站（可恢复）"还是"彻底删除（防留痕）"。选了彻底删除，就是真的删了，**哪里都找不回来**。这个选项是为隐私场景设计的，确定不需要留痕时才选它。

## 完整的安全网清单

除了上面两条主路径，beilu 还有几层各管一摊的备份，全家福如下：

| 安全网 | 什么时候触发 | 从哪里恢复 |
|--------|------------|-----------|
| 对话自动备份 | 每次对话保存时自动滚动（留 20 份） | 设置 → 备份 → 查看对话备份 |
| 删消息快照 | 删单条/批量删消息前（留 5 份） | 同上（列表里混合展示） |
| 记忆快照 | 记忆改动前的保护点 | 由回档机制或记忆管理使用；是否可用以真实快照结果为准 |
| 表格快照 | 表格改动前的保护点 | 由回档机制使用；快照创建/保存失败时不应假定可恢复 |
| 文件检查点 | YonBan / beilu-cli 在文件操作前建立 | 由“回档到此”或时间线使用；需通过对应执行端确认实际恢复结果 |
| Git 项目检查点 | 你或 AI 手动打的项目级快照 | 记忆工具面板的 git 快照/回档 |
| 数据域同步前备份 | 角色卡记忆/世界书整域覆盖前 | 数据目录 `data/_c2_backup/` |

## Git 回档：给整个项目上保险

在和 AI 协作改代码/改项目文件时，可以随时打一个 **git 检查点**（记忆工具面板里操作，AI 也可以主动打）。它与 YonBan/beilu-cli 文件检查点不是同一个存储层，不能相互替代：

- **打快照不打扰**：打检查点不改动你的工作区，只是悄悄记下当前状态（最多保留 20 条记录）。
- **恢复有保险**：回档前，系统会先自动给"现在的状态"打一张保险快照，再回滚——手滑回档错了也能救回来。
- **精确恢复**：恢复的一定是你选的那个检查点对应的内容，不会张冠李戴。
- **多用户安全闸**：如果 beilu 以服务器模式部署给多人用，整个项目的回滚会影响所有人，所以默认关闭，需要主用户在安全中心显式放行；自己本机用不受此限制。

## 场景速查

| 出事了 | 去哪里救 |
|--------|---------|
| 删错了几条消息 | 设置 → 备份 → 查看对话备份 → 选时间点恢复 |
| 整个对话删没了 | 系统回收站；找不到就去 `data/_trash_fallback/日期/` |
| 角色卡/人设/账号删了 | 同上（前提是当时没选"彻底删除"） |
| AI 改坏了监控文件夹里的文件 | 设置 → 备份 → 文件版本浏览 → 单文件回滚 |
| AI 改坏了整个项目 | 记忆工具面板 → git 回档（前提是之前打过检查点，建议大改前先打一个） |
| 记忆表格被 AI 改乱 | AI 侧有自动快照回滚；也可以直接在记忆表格界面手动改回来 |

## 当前边界

聊天记录的同对话写入已做顺序化，协调回档也会冻结锚点、检查点集合和 IDE 路由；但它不等于所有插件、所有外部文件系统与所有断线恢复场景已形成全局事务。尤其在 IDE/CLI 重连、磁盘异常或跨窗口切换期间，必须以结构化结果和实际读回为准。本页描述当前源码契约，运行时全链尚需在真实环境验证。
