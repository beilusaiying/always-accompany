# 注入系统 (INJ)

INJ 规则决定什么信息、以什么身份、在什么位置注入 AI 的上下文。

## 查看和编辑 INJ 规则

编辑入口在两个地方：

- **右栏注入提示词列表**：可以快速查看全部条目、一键启用/禁用
- **[注入编辑器](beilu:editor/inj-edit)**：编辑弹窗的「注入」页签，做增删改等完整编辑

另外，聊天输入区的**注入坞**可以对单个条目按「⚡这轮」——让该条目只在本轮临时注入一次，不改变它的开关状态（见下方"单次注入"）。

系统内置多条 INJ 规则，覆盖表格说明、文件层提示词、Bot 平台提示词、联网教学、历史标签等。核心的几条：

| INJ | 名称 | 功能 |
|-----|------|------|
| **INJ-1-chat** | chat 模式表格规则 | 告诉 AI chat 模式下 #0-#9 各表的用途和写入格式 |
| **INJ-1-write-code** | code 模式表格规则 | 告诉 AI code 模式下 C0-C5 各表的用途和写入格式 |
| **INJ-1-work** | work 模式表格规则 | 告诉 AI work 模式下 W0-W4 各表的用途和写入格式 |
| **INJ-2** | 文件层 AI 提示词 | 告诉 AI 如何操作项目文件（连接 IDE 时切换为 INJ-2-code 变体） |
| **INJ-3** | Bot 平台提示词 | 来自 Bot 平台（如 Telegram/Discord）的提示词 |

除上述外还有 INJ-4（全智能能力调度）、INJ-5（联网搜索教学）、聊天历史标签等内置条目。INJ-1 的三个变体根据当前工作模式互斥生效——只有对应的那一条门控匹配。

每条 INJ 规则有三个关键配置：

### autoMode（门控模式）

决定 INJ 在什么条件下生效：

| autoMode | 含义 |
|----------|------|
| **chat** | 仅 chat 模式下生效（chat 模式同时接受 airp 别名域） |
| **code** | 仅 code 模式下生效 |
| **work** | 仅 work 模式下生效 |
| **bot** | 仅 bot 模式下生效 |
| **smart** | smart 模式；smart 同时接受 chat 域的条目（行为对齐 chat） |
| **always** / **all** | 始终生效（全模式） |
| **manual** | 手动控制，开启即生效 |
| **file** | 文件门控域：进入文件/IDE 模式时生效（当前实况下等价于 code 模式） |

当前工作模式接受的注入域 = 无条件域（always / all / manual）+ 文件门控域（file，仅文件模式）+ 当前模式自己的域及其别名。一条 INJ 的 autoMode 落在这个集合里才生效。自定义模式也可以声明自己接受哪些域。

**拼错就静默失效**：autoMode 写了一个不存在的值，条目不会在任何模式生效（编辑面板保存时会校验拒绝非法值，但历史数据里的错值只会被门控拒绝）。

### platform（平台限定，可选）

条目还可以带一个 platform 字段：填了之后，这条 INJ 只在对应 Bot 平台（如 Telegram / Discord）的会话里注入，网页对话不注入。不填 = 不限平台。

### 单次注入（⚡这轮）

在注入坞对某条 INJ 点「⚡这轮」，这条会**无视所有自动门控**（开关、模式域、互斥、平台限定）在本轮强制注入一次——你点了名，自动规则就不再替你做主。**没启用的条目也可以这样临时用一轮**，不用先去开它的开关。

只影响这一轮，不落盘、不改开关；单次队列是纯内存会话态，刷新页面就清空。注入时它的 role / depth / 宏替换全部照常生效，注入的是条目**当前**内容（不是加入队列那一刻的旧内容）。

### depth（注入深度）

控制 INJ 注入到上下文的位置：

| depth 值 | 含义 |
|----------|------|
| **999** | 系统提示级——位于上下文最前端，优先级最高 |
| **0** | 最近消息之后——位于上下文最末端 |
| **N** | 第 N 轮对话之前——插入到聊天历史的指定位置 |

depth 越大，越靠近系统提示（上下文开头），AI 在处理时越早看到。

### role（角色身份）

每条 INJ 注入的消息以什么身份出现：

| role | 含义 |
|------|------|
| **system** | 系统消息，AI 视为系统级指令 |
| **user** | 用户消息，AI 视为用户说的话 |
| **assistant** | 助手消息，AI 视为自己说过的话 |

role 影响 AI 对该信息的处理方式。system 级指令通常被 AI 赋予最高优先级。

## INJ 做什么

AI 的上下文不是一个简单的"对话记录"。一个完整的上下文包含系统提示词、记忆表格、世界书条目、模式说明、文件层提示词、Bot 平台提示词和对话历史——这些内容需要按特定顺序和位置组装。INJ 系统就是这个组装的规则集。

### 运行链

```
用户发送消息
    ↓
系统开始构建上下文
    ↓
遍历所有 INJ 规则：
  1. 检查 autoMode → 当前模式/平台是否匹配
  2. 检查互斥规则 → 有冲突的 INJ 只保留一条
  3. 获取 INJ 的 content（可能包含宏替换）
    ↓
对 content 执行宏替换（~30 种 {{macro}}）
    ↓
按 depth 排序，将各 INJ 内容放入上下文的对应位置
    ↓
与角色设定、对话历史、世界书条目合并
    ↓
最终上下文发送给 AI
```

### 宏替换

INJ 的 content 中可以使用 `{{macro}}` 语法，在注入时被替换为实际值。系统提供约 30 种宏，常见的包括：

- `{{user}}`：当前用户名
- `{{char}}`：当前角色名
- `{{time}}`：当前时间
- `{{date}}`：当前日期

宏替换发生在注入时（非编辑时），确保值始终是最新的。

### 互斥规则

某些 INJ 之间存在互斥关系：

- **INJ-1 系列**：INJ-1-chat / INJ-1-write-code / INJ-1-work 三者互斥，只有当前模式对应的那条生效
- **INJ-2 系列**：INJ-2 与 INJ-2-code 是互斥的变体对——当 IDE 连接时使用 INJ-2-code 变体，否则使用 INJ-2

互斥保证同一类信息不会重复注入。

## 我的注入条目为什么没生效？

系统对每条 INJ 的裁决都带一个"原因"，编辑面板里看到的生效/不生效状态和 AI 实际收到的完全同源（同一份后端裁决）。对照下表排查：

| 现象/原因 | 含义 | 怎么处理 |
|----------|------|---------|
| 条目被关了（disabled） | enabled 开关是关的 | 在[注入编辑器](beilu:editor/inj-edit)或右栏列表打开开关 |
| 模式不匹配（scope_mismatch） | autoMode 和当前工作模式对不上，比如 code 条目在 chat 模式 | 切到对应模式，或把 autoMode 改成 always/manual |
| autoMode 拼错（unknown_automode） | autoMode 是个不认识的值，任何模式都不会生效 | 改成合法值（chat/code/work/bot/always/all/manual/file 或自定义模式名） |
| 平台不匹配（platform_mismatch） | 条目限定了某个 Bot 平台，当前会话不是那个平台 | 清掉 platform 字段，或去对应平台会话 |
| 变体在等 IDE（variant_ide_off） | -code 变体条目在 IDE 未连接时自动禁用 | 连接 IDE（VS Code/Cursor 走 YonBan），或直接用基础版条目 |
| 手动压过变体（variant_manual_base） | 你手动开启了基础版（autoMode=manual 且开启），变体自动让位 | 想用变体就把基础版的 autoMode 改回 file 等自动值 |
| 基础版让位（base_overridden） | IDE 已连接且在 code 模式，-code 变体接管，基础版自动禁用 | 这是预期行为；想强制用基础版就把它设为 manual 并开启 |

> 小提示：CLI 常驻连接**不算** IDE 连接——只有 VS Code / Cursor 这类真 IDE 接入才会触发 INJ-2 → INJ-2-code 的切换。所以只开着 CLI 时用的仍是 INJ-2。
