# 審核與權限

YonBan 的所有寫操作都經過審核系統管控。權限等級決定 AI 能做什麼，審核流程決定怎麼批准。

## 權限等級

| 等級 | 名稱 | 允許的操作 |
|------|------|-----------|
| L0 | 唯讀 | 僅 read_file、list_files、search 等讀操作 |
| L1 | 讀 | 讀操作 + 診斷 + 導覽 |
| L2 | 讀寫需審核 | 讀 + 寫操作（每次寫操作需使用者逐條審核） |
| L3 | 完整 + 命令 | 讀寫 + 命令執行（run_command / run_script） |
| L4 | 信任 | 所有操作自動放行，跳過審核 |

在程式碼模式控制面板的權限等級下拉功能表中切換。可前往[安全中心](beilu:settings/security)查看全域安全策略。

## 審核流程

寫操作從 AI 發出到實際執行，經過以下流程：

1. AI 發出寫操作請求（write_file / run_command / git_commit 等）
2. 請求進入審核佇列
3. 前端連接卡片彈出審核提示
4. 使用者選擇**批准**或**拒絕**
5. 批准 → 執行操作並回傳結果；拒絕 → 回傳拒絕原因，AI 收到後調整策略

L4 信任模式下，步驟 2-4 自動跳過。

## 五級安全閘

審核系統內部由五級安全閘串聯，任一級攔截即阻止執行：

| 級別 | 名稱 | 作用 |
|------|------|------|
| 1 | 命令閘 | 黑名單命令永久禁止（如 rm -rf /）；灰名單命令需審核（每條可設是否 L4 也確認）；能力白名單內命令按權限等級放行 |
| 2 | 規則集引擎 | 使用者自訂規則：deny（拒絕）/ ask（需審核）/ allow（放行），按優先順序比對 |
| 3 | 審核門 | 系統強制審核（L2 寫操作）/ 策略審核（規則集命中 ask）/ 信任跳過（L4） |
| 4 | 統一執行閘 | fail-closed 設計——閘異常時預設拒絕，不會漏放 |
| 5 | 審核指紋繫結 | 審核通過後為請求產生 sha256 指紋，執行時校驗指紋一致——防止審核通過後請求被篡改 |

## 命令安全

命令執行（run_command / run_script）有額外的安全層：

| 名單 | 說明 |
|------|------|
| 黑名單 | 嚴重破壞類命令永久禁止執行，無論權限等級（如格式化磁碟、遞迴刪除、擦盤/改引導）。每條可單獨啟停/刪除，權限面板可增刪 |
| 灰名單 | 需要顯式審核的命令。每條帶「L4 也問」開關：勾選=即使 L4 完全信任也彈審核（如 shutdown、reg）；不勾=最多限到 L3，L4 免審核（如 git rebase、npm uninstall） |
| 能力白名單 | 常用安全命令（如 ls、cat、git status），在 L3+ 自動放行 |

## 前端控制面板

在程式碼模式活動列點擊 control 按鈕開啟控制面板，集中管理以下設定：

| 控制項 | 類型 | 說明 |
|------|------|------|
| 權限等級 | 下拉功能表 | L0 ~ L4，控制 AI 可執行的操作範圍 |
| 自動儲存 | 開關 | 開啟後檔案修改自動儲存到磁碟 |
| 自動繼續 | 開關 + 延遲設定 | AI 完成一步後自動繼續下一步，可設定等待延遲 |
| 完成提示音 | 開關 | AI 完成任務時播放提示音 |
| 清理模式 | 下拉功能表 | 選擇程式碼清理策略 |
| 手動清理 | 按鈕 | 立即執行一次清理 |
