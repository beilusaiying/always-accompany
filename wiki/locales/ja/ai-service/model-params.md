# モデルパラメータ

モデルパラメータ（サンプリングパラメータとも呼ばれます）は、AI がテキストを生成するスタイルと動作を制御します。これらのパラメータを調整することで、AI の応答をより創造的に、より正確に、より長くまたは短くできます。[AI サービスソース](beilu:settings/api)パネルのパラメータエリアで調整できます。

## パラメータ一覧

### コアパラメータ

| パラメータ | 範囲 | 説明 |
|------|------|------|
| temperature | 0 - 2.0 | 生成温度。高いほど応答がランダムで多様に、低いほど確定的で保守的になります。0 = ほぼ常に最も可能性の高い単語を選択 |
| max_tokens | 1 - 上限なし | 最大出力トークン数。AI の応答の最大長を制限します |
| top_p | 0 - 1.0 | 核サンプリング。累積確率が top_p 以内の単語からのみ選択します。1.0 = 制限なし |

### サンプリング制御パラメータ

| パラメータ | 範囲 | 説明 |
|------|------|------|
| top_k | 0+ | Top-K サンプリング。確率が最も高い上位 K 個の単語からのみ選択します。0 = 制限なし |
| top_a | 0+ | Top-A サンプリング。最高確率 * top_a より低い確率の単語をフィルタリングします。OpenRouter 専用 |
| min_p | 0+ | Min-P サンプリング。最高確率 * min_p より低い確率の単語をフィルタリングします |

### ペナルティパラメータ

| パラメータ | 範囲 | 説明 |
|------|------|------|
| frequency_penalty | -2.0 - 2.0 | 頻度ペナルティ。正の値は既出単語の繰り返し確率を下げ、負の値は繰り返しを促進します |
| presence_penalty | -2.0 - 2.0 | 存在ペナルティ。正の値は新しいトピックについて話すことを促進し、負の値は既存のトピックに留まることを促進します |
| repetition_penalty | 0+ | 繰り返しペナルティ。1.0 = ペナルティなし、1 より大きいと繰り返しを減少。Ollama / ローカルモデル専用 |

### その他のパラメータ

| パラメータ | 説明 |
|------|------|
| seed | ランダムシード。固定値を設定すると結果を再現できます（-1 = ランダム） |

## パラメータの優先度

always-accompany ではモデルパラメータに複数のソースがあり、以下の優先度で上書きされます：

```
拡張レイヤー上書き (extension.beilu_model_params)
    ↑ 上書き
サブモードパラメータ
    ↑ 上書き
ランタイムパラメータパネル (runtimeParams)
    ↑ 上書き
プリセット付属パラメータ (eng.modelParams)
    ↑ 上書き
PARAM_SCHEMA デフォルト値
```

- **プリセット付属パラメータ**：プリセット JSON に含まれるパラメータ値
- **ランタイムパラメータパネル**：ユーザーがパラメータパネルで手動調整した値（runtime_params.json に永続化）
- **サブモードパラメータ**：Code / Work サブモードが独立して上書きするパラメータ
- **拡張レイヤー上書き**：beilu-memory やその他のプラグインが実行時に動的に注入するパラメータ

### パラメータのデフォルト値単一ソース

すべてのパラメータのデフォルト値は `PARAM_SCHEMA` によって統一的に定義されます。エンジン層のデフォルト値抽出、アプリケーション層の空窓フォールバック、フロントエンド UI の min/max/step の3箇所が同じテーブルを共用し、一貫性を確保します。

## 各プロバイダーのパラメータ対応

プロバイダーによって対応するパラメータのサブセットが異なります。always-accompany のパラメータ適用層（applyModelParams）はプロバイダーの API 形状に合わせて自動的にトリミングします：

### OpenAI 形状（proxy / grok）

すべてのサンプリングパラメータに対応します。top_a はこの形状でのみ使用可能です（OpenRouter 専用機能）。

### Gemini 形状

対応：temperature / top_p / top_k / max_tokens / frequency_penalty / presence_penalty / seed

パラメータ名は自動変換されます（例：`top_p` -> `topP`、`max_tokens` -> `maxOutputTokens`）。

### Ollama 形状

対応：temperature / top_p / top_k / repetition_penalty / max_tokens / min_p / seed

パラメータ名は自動変換されます（例：`repetition_penalty` -> `repeat_penalty`、`max_tokens` -> `num_predict`）。

### Anthropic 形状（claude-api / claude）

デフォルトではサンプリングパラメータを送信しません。Anthropic 新版モデル（Opus 4.7+）は temperature / top_p / top_k に対応していません（デフォルト以外の値を設定すると 400 エラーが返ります）。max_tokens は必須パラメータです。

## model_override（モデル切り替え）

`model_override` はサンプリングパラメータではありませんが、同じ経路で渡されます。サービスソース設定を変更せずに実行時に AI モデルを切り替えるために使用します：

- サブモードごとに異なるモデルを指定できます
- 分身の会話で異なるモデルに切り替えられます

解決優先度：`beilu_model_params.model_override` > サービスソース `config.model`

## センチネルガード

パラメータ適用層には「センチネルガード」機構があります：パラメータ値がデフォルト値と等しい場合（= ユーザーが変更していない場合）、API に送信せず、プロバイダー自身のデフォルト動作を不必要に上書きすることを避けます。

例：
- temperature = ユーザーが設定した任意の値は送信されます（0 を含む）
- top_p = 1.0 の場合は送信しません（1.0 はほとんどの API のデフォルト値）
- top_k = 0 の場合は送信しません
- seed = -1 の場合は送信しません

## パラメータ調整のアドバイス

| シーン | 推奨設定 |
|------|---------|
| ロールプレイ / 創作 | temperature 0.8 - 1.2、top_p 0.9 - 0.95 |
| 日常会話 | temperature 0.7 - 0.9 |
| コーディング支援 | temperature 0.2 - 0.5 |
| データ分析 / 正確な回答 | temperature 0 - 0.3 |
| 繰り返しを減らす | frequency_penalty 0.3 - 0.8 |
