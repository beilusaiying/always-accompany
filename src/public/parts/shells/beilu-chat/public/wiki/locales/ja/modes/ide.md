# コードモード (Code / IDE)

## コードモードに入る

| 方法 | 操作 |
|------|------|
| トップモードセレクター | 「Code」タブをクリック |
| キーボードショートカット | `Ctrl+3` または `Alt+3` |

## エディタを接続する

1. アクティビティバーの **connections** ボタンをクリックして、IDE 接続パネルを開きます
2. YonBan 拡張機能をインストールします（パネル内にガイドボタンがあります）
3. 「接続」ボタンをクリックして VSCode または Cursor に接続します
4. 接続が成功するとステータスランプが緑に変わり、エディタのバージョン番号と WebSocket アドレスが表示されます

接続後、AI がエディタを直接操作できるようになります。切断された場合は「再接続」をクリックしてください。

## やりたいこと

| やりたいこと | 使用パネル | アクティビティバーボタン |
|---------|-----------|-----------|
| プロジェクトファイルの閲覧/編集 | ファイルマネージャ | explorer |
| AI と対話 | AI チャット | ai-chat |
| 権限/自動化設定の調整 | コントロールパネル | control |
| MCP サービスへの接続 | MCP | mcp |
| 過去の対話の切り替え | 対話履歴 | conversations |
| AI 操作のロールバック | 操作タイムライン | timeline |
| VSCode/Cursor への接続 | IDE 接続 | connections |
| Git 操作 | Git 管理 | git |
| サブモードの切り替え | サブモード | submodes |

アクティビティバーのボタンをクリックすると対応するサイドバーパネルに切り替わります。同じボタンをもう一度クリックするとサイドバーが折りたたまれます。

## コントロールパネル

アクティビティバーの control ボタンをクリックして開きます。コードモードの実行パラメータを集中管理します：

| コントロール | タイプ | 説明 |
|------|------|------|
| 権限レベル | ドロップダウン | L0 ~ L4、AI が実行可能な操作範囲を制御します |
| クリーンモード | ドロップダウン | コードクリーニング戦略を選択します |
| 手動クリーン | ボタン | クリーニングを即時実行します |
| 自動保存 | スイッチ | 有効にするとファイルの変更が自動保存されます |
| 自動継続 | スイッチ + 遅延設定 | AI が1ステップ完了後に自動的に次のステップへ進みます。待機遅延を設定できます |
| 完了通知音 | スイッチ | AI がタスクを完了した時に通知音を再生します |

## ファイルブラウザ

アクティビティバーの explorer ボタンをクリックして開きます。

- **フォルダを開く** — ローカルディレクトリをワークスペースとして選択します
- **ファイルを開く** — 単一のファイルを直接開きます
- **ディレクトリツリー** — プロジェクトのファイル構造をツリー形式で表示します。右クリックメニューで新規作成/名前変更/削除ができます
- **マルチタブエディタ** — 開いたファイルがタブとして並びます。`Ctrl+S` で保存できます
- **AI 承認キュー** — AI がファイルの変更を要求すると承認キューに入ります。1件ずつ許可または拒否できます

## Git パネル

アクティビティバーの git ボタンをクリックして開きます。

- **ブランチバー** — 現在のブランチ、ahead/behind カウント、新規作成/切り替え/マージ/stash 操作
- **コミットエリア** — コミットメッセージ入力欄 + コミットボタン
- **変更リスト** — ステージ済み/未ステージ/未追跡ファイル。クリックで Diff プレビューを表示します
- **コミット履歴** — 過去のコミット記録と変更内容を閲覧します

## 操作タイムライン

アクティビティバーの timeline ボタンをクリックして開きます。

- AI が実行したすべてのツール呼び出しとコード状態スナップショットを記録します
- 各操作の入力パラメータと返却結果を確認できます
- 任意の履歴ノードにロールバックでき、AI の変更による予期しない破壊を防止します

## サブモード（11 個）

コードモードには 11 個のサブモードが内蔵されており、ソフトウェア開発の全工程をカバーします：

| サブモード | 用途 |
|--------|------|
| タスク確認師 | 要件を理解し、Web で類似案を検索します |
| 前置設計師 | 実際のコードを読み込んで設計を行い、コード行レベルまで精密に特定します |
| フレームワーク審査員 | コードフレームワークと全体フローの観点から妥当性を審査します |
| 深度思考師 | アルゴリズム設計、フレームワークロジック、経路ロジック、実験による検証 |
| コードエキスパート | コード実装に専念します |
| 前置エラー生産師 | 構文エラー、HTML タグエラーの検出、フロー審査 |
| テストエキスパート | スクリプトツールとブラウザバックグラウンドによる実際のテスト |
| デバッグエキスパート | 全体を確認してから個別に集中し、迅速に問題を特定・修正します |
| タスク引継ぎ員 | md ファイルとして作成し、人間と確認します |
| 大規模プロジェクト調整 | スコープ固定、依存チェーンの順序付け、マルチエージェント編成 |
| フロントエンド美化 | フロントエンドのデザインと美化 |

各サブモードはプリセット、API ソース、モデル、サンプリングパラメータを個別にバインドでき、サブモードを切り替えると対応する設定が自動的に読み込まれます。詳しくは[サブモードと切り替え](beilu:wiki/modes/submodes.md)をご覧ください。

## インターフェースレイアウト

コードモードは IDE スタイルのレイアウトを採用しています：

- **アクティビティバー**（最左端）：アイコンボタンで、サイドバーパネルを切り替えます
- **サイドバー**：対応するパネルの内容
- **メインエリア**：AI チャットエリア + コード/Diff ビューアエリア

チャットモードとのレイアウトの違い：

| チャットモード | コードモード |
|---------|---------|
| 3カラム対称レイアウト | IDE スタイル非対称レイアウト |
| 左右カラム折りたたみ可能 | アクティビティバー常駐 + サイドバー切り替え可能 |
| 対話が中心 | ファイルとツール操作が中心 |

## その他の説明

- コードモードに入ると、INJ-2 インジェクションルールが自動的に有効になります（プログラミングシーン専用のコンテキスト）。手動での設定は不要です
- コードモードはバックエンドモード値 `code` に対応し、フロントエンド Tab は `files` です
