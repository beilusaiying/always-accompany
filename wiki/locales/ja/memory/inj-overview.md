# インジェクションシステム (INJ)

## INJ ルールの閲覧と編集

INJ ルールは、どの情報を、どの身分で、どの位置に AI のコンテキストへインジェクションするかを決定します。システムには複数の INJ ルールが組み込まれており、テーブル説明、ファイル層プロンプト、Bot プラットフォームプロンプト、ウェブ検索ガイド、履歴タグなどをカバーしています。主要なルール：

| INJ | 名称 | 機能 |
|-----|------|------|
| **INJ-1-chat** | chat モードテーブルルール | chat モードでの #0-#9 各テーブルの用途と書き込みフォーマットを AI に伝えます |
| **INJ-1-write-code** | code モードテーブルルール | code モードでの C0-C5 各テーブルの用途と書き込みフォーマットを AI に伝えます |
| **INJ-1-work** | work モードテーブルルール | work モードでの W0-W4 各テーブルの用途と書き込みフォーマットを AI に伝えます |
| **INJ-2** | ファイル層 AI プロンプト | AI にプロジェクトファイルの操作方法を伝えます（IDE 接続時は INJ-2-code バリアントに切替） |
| **INJ-3** | Bot プラットフォームプロンプト | Bot プラットフォーム（Telegram/Discord など）からのプロンプト |

上記のほかに INJ-4（スマートモード能力ディスパッチ）、INJ-5（ウェブ検索ガイド）、チャット履歴タグなどの組み込みエントリがあります。INJ-1 の 3 つのバリアントは現在のワークモードに応じて排他的に適用されます——対応する 1 つだけがゲートにマッチします。

各 INJ ルールには 3 つの重要な設定があります：

### autoMode（ゲートモード）

INJ がどの条件で有効になるかを決定します：

| autoMode | 意味 |
|----------|------|
| **chat** | chat モードでのみ有効（chat モードは airp エイリアスドメインも受け入れます） |
| **code** | code モードでのみ有効 |
| **work** | work モードでのみ有効 |
| **bot** | Bot プラットフォームモードでのみ有効 |
| **always** / **all** | 常に有効（全モード） |
| **manual** | 手動制御、オンにすれば有効 |
| **file** | ファイル層設定により決定（IDE/ファイルモード移行時に有効） |

現在のワークモードが受け入れるインジェクションドメイン = 無条件ドメイン（always / all / manual）+ ファイルゲートドメイン（file、ファイルモード時のみ）+ 現在のモード自身のドメインとそのエイリアス。INJ の autoMode がこの集合に含まれる場合に有効となります。

### depth（インジェクション深度）

INJ がコンテキストのどの位置にインジェクションされるかを制御します：

| depth 値 | 意味 |
|----------|------|
| **999** | システムプロンプトレベル——コンテキストの最前部、最も高い優先度 |
| **0** | 最新メッセージの後——コンテキストの最末部 |
| **N** | 第 N ターンの会話の前——チャット履歴の指定位置に挿入 |

depth が大きいほどシステムプロンプト（コンテキストの先頭）に近くなり、AI が処理時により早く目にします。

### role（ロール身分）

各 INJ のインジェクションメッセージがどの身分で表示されるかを指定します：

| role | 意味 |
|------|------|
| **system** | システムメッセージ、AI はシステムレベルの指示として扱います |
| **user** | ユーザーメッセージ、AI はユーザーが言った言葉として扱います |
| **assistant** | アシスタントメッセージ、AI は自分が以前言った言葉として扱います |

role は AI がその情報をどのように処理するかに影響します。system レベルの指示は通常 AI に最も高い優先度で扱われます。

## INJ の役割

AI のコンテキストは単純な「会話記録」ではありません。完全なコンテキストには、システムプロンプト、記憶テーブル、ワールドブックエントリ、モード説明、ファイル層プロンプト、Bot プラットフォームプロンプト、会話履歴が含まれます——これらのコンテンツは特定の順序と位置で組み立てる必要があります。INJ システムはこの組み立てのルールセットです。

### 動作チェーン

```
ユーザーがメッセージを送信
    ↓
システムがコンテキストの構築を開始
    ↓
すべての INJ ルールを走査：
  1. autoMode をチェック → 現在のモード/プラットフォームがマッチするか
  2. 排他ルールをチェック → 競合する INJ は 1 つだけ保持
  3. INJ の content を取得（マクロ置換を含む場合あり）
    ↓
content に対してマクロ置換を実行（約 30 種類の {{macro}}）
    ↓
depth でソートし、各 INJ の内容をコンテキストの対応位置に配置
    ↓
キャラクター設定、会話履歴、ワールドブックエントリと統合
    ↓
最終コンテキストを AI に送信
```

### マクロ置換

INJ の content 内で `{{macro}}` 構文を使用でき、インジェクション時に実際の値に置換されます。システムは約 30 種類のマクロを提供しており、よく使われるものには：

- `{{user}}`：現在のユーザー名
- `{{char}}`：現在のキャラクター名
- `{{time}}`：現在の時刻
- `{{date}}`：現在の日付

マクロ置換はインジェクション時に発生し（編集時ではなく）、値が常に最新であることを保証します。

### 排他ルール

一部の INJ の間には排他関係があります：

- **INJ-1 シリーズ**：INJ-1-chat / INJ-1-write-code / INJ-1-work の 3 つは排他的で、現在のモードに対応するものだけが有効
- **INJ-2 シリーズ**：INJ-2 と INJ-2-code は排他的なバリアントペアです——IDE 接続時は INJ-2-code バリアントを使用し、そうでなければ INJ-2 を使用

排他により、同じ種類の情報が重複してインジェクションされることを防ぎます。
