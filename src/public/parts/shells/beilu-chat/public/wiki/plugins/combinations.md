# 插件不是菜单：按任务组合能力

如果你只看插件列表，贝露会显得像一堆功能；真正的差异出现在它们接入同一条模式、记忆、提示词、权限和消息链之后。

这页不要求你“全部学会再开始”。先选一个你现在真的想解决的问题，只启用完成它所需的最小组合；当结果已经有用，再加入下一层能力。

## 先回答：它能替代我现在的什么？

| 你现在的做法 | 最小替代组合 | 得到的变化 | 仍然需要你决定 |
|---|---|---|---|
| 每轮把旧聊天手工复制给 AI | memory + P1 | 记忆可持久化，当前相关内容可被召回，并能看到本轮用了哪些记忆 | 哪些内容该写入、P1 是否开启、召回结果是否合适 |
| 在角色卡工具里聊天，工作时再切 IDE | Chat/Code/Work + memory + preset | 同一套人物、记忆和可编辑提示词可以进入不同任务模式 | 各模式要共享什么、隔离什么 |
| 让联网 AI 给出网页摘要，但不能操作页面 | web + browser + files | 先查资料，再控制真实浏览器，最后把结果落到本地文件 | 浏览器登录态、下载和写入范围 |
| 在 IDE 之外无法让 AI 使用本地工具 | files + CLI | 不依赖 IDE，也能提供受工作区约束的工具执行后端 | 工作区根、命令权限和自动启动策略 |
| 手工从直播弹幕挑问题再复制给 AI | live + preset + memory | 弹幕先用确定性规则初筛，再进入既有主对话链 | 平台凭据、承载对话、节奏和成本 |
| 靠长提示词维护角色状态和场景 | worldbook + MVU + EJS/regex + AIRP | 设定、变量、条件逻辑和显示层分别管理，再组合成互动场景 | 状态真相源、脚本来源和渲染回退 |
| 自己写胶水把本地程序的结果塞进提示词 | plugin-host + 你的程序 | 外部程序可通过受控宿主返回短期注入或工具结果 | 子进程权限、token、TTL 与错误处理 |

## 六套可以直接理解的组合

### 1. 长期陪伴：不是“无限上下文”，而是记忆能被管理

**组合：** memory + P1 + preset + worldbook；需要场景表现时再加 AIRP/MVU。

完整链路：

```text
对话产生事实
  → 记忆表 / 热层 / 归档保存
  → P1 根据当前话题召回候选
  → 预设与世界书补充身份、规则和设定
  → 主模型回复
  → “本轮运用记忆”显示实际采用的召回项
```

它替代的是反复粘贴旧对话和只依赖超长上下文的工作方式，不是替你自动判断所有记忆都正确。P1 可以关闭；Chat、Code、Work 当前主路由使用自驱动 P1，其他模式可走不同路由。

### 2. 本地编程：把聊天、工具和项目记忆放进同一条链

**组合：** Code + files + CLI 或 YonBan + memory；调查网页资料时加 web/browser。

```text
需求与项目上下文
  → Code 模式预设
  → 记忆提供历史决策
  → 工具后端读取 / 搜索 / 修改 / 执行
  → 结果回到原 chatId 和任务
  → 工作记录继续沉淀
```

CLI 适合不想依赖 IDE 的本体使用；YonBan 适合需要 IDE 界面和扩展能力的场景。两者不是“工具越多越好”，而是两个可选择的执行后端。

### 3. 研究与交付：从“给答案”变成“留下文件”

**组合：** Work + web + browser + files；需要演示稿时加 PPT。

搜索适合找候选资料，浏览器适合处理动态页面和实际操作，文件插件负责把引用、草稿和成品留在指定工作区。这样产物不只存在于一轮聊天里。

### 4. 直播互动：复用主链，不另造一个缩水机器人

**组合：** live + Chat/Live 模式 + preset + memory；需要视觉输入时再加 eye。

直播插件不让每条弹幕都触发一次模型。它先做长度、黑名单、关键词、冷却和去重，再从候选池挑出本轮上下文，最后调用已有主对话链。你的预设、记忆、服务源和流式输出因此仍然有效。

### 5. 互动叙事：内容、状态、逻辑和显示分层

**组合：** worldbook + MVU + toggle + EJS + regex + AIRP。

- worldbook 管设定和触发条件；
- MVU 管跨轮变量；
- toggle 动态启停条目；
- EJS 负责条件和模板；
- regex 处理回复后的规则转换；
- AIRP 负责场景显示。

它的价值不是某一个插件的特效，而是每层都能单独编辑、替换或关闭。

### 6. 最小联网面：能本地就本地，需要时才外发

**组合：** memory + P1 + STT；只有任务需要时才加入 web、browser、vectordb 或外部 AI 服务。

本地并不等于所有数据永远不出机器。是否外发取决于你启用的服务：embedding 端点会收到待向量化文本，主 AI 服务会收到最终提示词，网页和平台插件会连接相应外部服务。插件组合让这些边界可选择，但不会替你消除边界。

## 推荐的学习顺序

1. 先学模式切换和插件总开关；
2. 只选一套上面的最小组合；
3. 看一次真实输入、输出和状态页；
4. 再修改预设、记忆或权限；
5. 最后才尝试 EJS、用户插件宿主和复杂自动化。

如果一个组合不能在十几分钟内让你完成一个真实小任务，先减少插件，而不是继续加开关。
