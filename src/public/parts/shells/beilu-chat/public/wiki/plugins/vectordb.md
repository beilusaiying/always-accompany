# 语义检索（beilu-vectordb）

beilu-vectordb 给记忆文件增加全文、向量和混合搜索。它适合处理“说法变了，但意思接近”的检索；它不是 P1 的替代版本，也不会在没有配置时自动得到向量能力。

## 先看是否需要它

适合：

- 记忆中存在大量同义改写和语义相近内容；
- 你已经有可信的 OpenAI 兼容 embedding 服务；
- 你愿意承担 embedding 请求、索引空间和重建成本；
- 你想把全文、向量和 P1 作为不同召回路线比较或组合。

不一定需要：

- 主要靠固定名称、关键词或世界书规则触发；
- 不希望任何记忆文本离开本机，而你又没有本地 embedding 服务；
- 只想使用自驱动 P1；
- 记忆量很小，全文搜索已经够用。

## 默认状态

- 插件目录存在，并列在新用户 defaultParts 中；
- **向量语义搜索默认关闭**；
- 默认 API 地址和 Key 为空；
- 当前代码默认模型名为 text-embedding-ada-002、维度 1536，但这只是出厂配置，不代表你的服务支持它；
- 只有模型实际输出维度与配置一致时才应建索引。

不要因为“插件已加载”就假设向量索引已经可用。设置面板会分别显示 enabled、indexReady、文档数和近期错误。

## 配置入口

在[插件管理](beilu:settings/plugins)打开 beilu-vectordb：

| 配置 | 含义 | 当前默认 |
|---|---|---|
| enabled | 启用语义搜索 | false |
| embeddingApiUrl | OpenAI 兼容 /v1/embeddings 端点 | 空 |
| embeddingApiKey | API Key | 空 |
| embeddingModel | 服务端模型标识 | text-embedding-ada-002 |
| embeddingDimensions | 模型输出维度 | 1536 |
| topK | 最大返回条数 | 10 |

API 地址与 Key 在已配置后以脱敏状态返回；面板留空表示保留旧值。

## 数据流与隐私

    记忆文件内容
      ↓ 分块
    发送到你配置的 embedding API
      ↓ 返回向量
    Orama 索引
      ↓
    <角色记忆目录>/_vector/index.json

配置文件位于：

    data/plugins/beilu-vectordb/config.json

索引按用户 / 角色记忆目录分区。插件会把记忆文本分块后发送给 embedding 端点，因此：

- 使用远程服务时，相关记忆内容会离开本机；
- API Key 不应写进公开仓库或截图；
- 多用户部署要确认配置是否符合所有用户的数据政策；
- 更换模型或维度后，旧索引可能因不匹配被弃用，需要重建。

## 三种搜索模式

| 模式 | 使用内容 | 适合 |
|---|---|---|
| fulltext | 查询词与文本 | 名称、术语、原句片段 |
| vector | 查询 embedding 与文档向量 | 同义改写、语义邻近 |
| hybrid | 词面与向量共同参与 | 同时需要精确词和语义的场景 |

混合模式拿不到查询向量时，当前实现会记录诊断并退回全文搜索；纯向量模式则返回明确错误。不要把降级后的结果误报为“向量检索成功”。

## 索引生命周期

- 新写入可以通过记忆系统的向量桥增量进入索引；
- 空索引不会在第一次查询时偷偷触发全量重建；
- 全量重建必须显式执行，并提供明确的角色记忆目录；
- 索引会持久化到对应角色的 _vector/index.json；
- 下划线开头的机制文件和目录不会作为普通记忆文本进入全量遍历；
- 维度或模型不匹配时，应先修正配置再重建。

## 它和 P1 怎样组合

| beilu-vectordb | 自驱动 P1 |
|---|---|
| 重点是文本语义相似和全文匹配 | 重点是直接线索、概念关系、联想方向、时间与模式的多阶段收拢 |
| 依赖 embedding 服务完成向量路线 | 每次召回不调用 LLM / embedding API，但需要本地服务与资源 |
| 适合对同义表达做近邻搜索 | 适合测试间接线索和关联回忆 |
| 结果质量取决于模型、分块和索引 | 结果质量取决于词库、候选、过滤和排序 |

两者可以并存，但“可以组合”不等于“组合一定更好”。正式比较需要同一语料、同一 gold labels 和一致的 topK / 成本口径。

## 常见问题

### 开启后仍显示 indexReady=false

启用只打开功能门，不会伪造索引。检查 API、模型、维度和错误列表，然后显式重建或等待真实写入产生增量索引。

### 返回维度不匹配

以 embedding 服务真实返回为准修改 embeddingDimensions。不要通过裁剪或补零掩盖模型配置错误。

### 搜索结果为空

分别确认：插件 enabled、索引文档数、查询所在角色记忆目录、搜索模式、embedding 请求错误和 layer 过滤。空结果不等于“没有相关记忆”。
