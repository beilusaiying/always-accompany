# 预设系统

在左栏下拉选预设，AI 立刻换一套行为方式——聊天模式用聊天预设，编程模式用编程预设，切换即生效。

## 切换预设

在对话界面的预设选择器中，点击即可切换当前预设。切换后立即生效，下一条消息就会使用新预设。

## 启用/禁用条目

通过 beilu-toggle 插件，在预设面板中勾选/取消勾选单个条目，实时调整 AI 收到的指令。

## 导入预设

在预设管理面板中点击导入，选择 SillyTavern 格式的 JSON 文件即可。always-accompany 完全兼容 SillyTavern 预设格式，也可以自己从零创建。

## 预设分类

always-accompany 的预设按用途分类（称为 bucket）：

| 分类 | 用途 | 典型预设 |
|------|------|---------|
| Code | 编程辅助 | 代码审查、编程助手、IDE 指令 |
| Work | 工作流 | 任务管理、文档写作、数据分析 |
| Clone | 角色扮演 | 角色卡适配、对话风格 |
| 通用 | 不限场景 | 自定义预设 |

详见 [预设分类与选择](categories.md)。

## 预设与模式的联动

每个模式（[聊天模式](beilu:mode/chat) / Code / [工作模式](beilu:mode/work) / [Bot管理](beilu:mode/bot)）可以绑定不同的预设。切换模式时，系统自动加载该模式绑定的预设：

- 聊天模式用聊天预设 → AI 表现得像陪伴角色
- 编程模式用编程预设 → AI 表现得像编程助手
- 工作模式用工作预设 → AI 表现得像工作搭档

详见 [预设与模式联动](mode-binding.md)。

## 深入了解

### 预设的组成

一个预设由若干**条目（Prompt Entry）**组成，每个条目是一段文字加上控制属性：

| 组成要素 | 说明 |
|---------|------|
| 条目内容 | 发给 AI 的实际文本（系统提示、角色指令、风格要求等） |
| 排列顺序 | 条目在提示词中的先后位置（越靠前，AI 越优先关注） |
| 启用状态 | 可以单独开关每个条目，不用的暂时关掉 |
| 注入深度 | 条目插入聊天历史的位置（深度 0 = 最底部，深度 4 = 往上数 4 条消息处） |
| 角色标记 | 条目以什么身份发送（system / user / assistant） |

### 预设做了什么

当你发送一条消息时，always-accompany 并不是把你的消息直接丢给 AI。在幕后，预设引擎会把角色设定、系统指令、世界书、聊天历史、插件提示等内容，按照预设定义的条目顺序组装成一份完整的提示词，然后才发送给 AI。

### 预设与模型参数

预设不仅包含提示词条目，还可以携带模型参数（temperature、top_p 等）。加载预设时，这些参数会一并生效，让每个预设拥有独立的生成风格。

参数优先级：预设自带参数 < 运行时参数面板 < 扩展层模型参数覆盖

详见 [模型参数](../ai-service/model-params.md)。也可在[AI服务源](beilu:settings/api)面板调整参数。
