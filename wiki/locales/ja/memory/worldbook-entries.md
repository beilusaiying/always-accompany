# エントリとトリガーメカニズム

ワールドブックエントリの完全なフィールドと 3 つのトリガーモードについて説明します。エントリは[ワールドブック編集](beilu:editor/worldbook)で作成・管理します。

## エントリの構造

各ワールドブックエントリは以下のフィールドで構成されます：

### コアフィールド

| フィールド | 型 | 説明 |
|------|------|------|
| **key** | 文字列/配列 | メインキーワード、トリガーマッチングに使用 |
| **keysecondary** | 文字列/配列 | 補助キーワード、メインキーワードと併用 |
| **content** | 文字列 | AI にインジェクションする情報コンテンツ |

### トリガー制御フィールド

| フィールド | 型 | 説明 |
|------|------|------|
| **constant** | ブール | 常駐エントリかどうか（毎ターンインジェクション） |
| **useRegex** | ブール | キーワードに正規表現マッチングを使用するかどうか |
| **selective** | ブール | 補助キーワードとの複合判定を有効にするかどうか |

### インジェクション制御フィールド

| フィールド | 型 | 説明 |
|------|------|------|
| **position** | 列挙 | インジェクション位置：before（キャラクター説明の前）/ after（キャラクター説明の後）/ atDepth（チャット履歴の指定深度）/ AN / EM |
| **depth** | 数値 | position が atDepth の場合、挿入深度を指定（第 N ターンの会話の前） |

### 確率・リズムフィールド

| フィールド | 型 | 説明 |
|------|------|------|
| **probability** | 数値(0-100) | トリガー確率、100 は必ずトリガー |
| **sticky** | 数値 | トリガー後に継続してインジェクションするターン数 |
| **cooldown** | 数値 | トリガー後のクールダウンターン数（クールダウン中は再トリガーされない） |
| **delay** | 数値 | マッチ後、実際にインジェクションするまで遅延するターン数 |

### スイッチフィールド

| フィールド | 型 | 説明 |
|------|------|------|
| **enabled** | ブール | グローバル有効スイッチ、全キャラクター共通 |
| **boundCharName** | 文字列 | キャラクターバインド、指定キャラクター使用時のみ有効 |

## 3 つのトリガーモードの詳細

### 1. constant（常駐モード）

```
constant: true
```

エントリは常にインジェクションされ、キーワードはチェックされません。以下に適しています：
- 基本的な世界観設定
- 汎用的な行動ルール
- AI が常に知っておくべき情報

### 2. regex（キーワード/正規表現マッチングモード）

```
constant: false
useRegex: true/false
selective: true/false
```

会話内容のキーワードマッチングに基づいてトリガーするかを判定します。

**マッチングロジック**：

- `useRegex: false`：キーワードをプレーンテキストとしてマッチング（含まれればトリガー）
- `useRegex: true`：キーワードを正規表現としてマッチング

**selective の役割**：

- `selective: false`：メインキーワード（key）のみを参照し、いずれかがマッチすればトリガー
- `selective: true`：メインキーワード（key）と補助キーワード（keysecondary）の両方がマッチしなければトリガーしない

selective モードはトリガー条件を精密に制御するために使用します。例えば：key を「魔法」、keysecondary を「禁忌」に設定すると、会話中に「魔法」と「禁忌」が同時に出現した場合のみ禁忌の魔法に関する設定をインジェクションします。

### 3. dynamic（動的チェックモード）

動的モードは会話テキストをチェックするのではなく、記憶テーブル内の特定の値をチェックします。例えば：

- #0 時空テーブルの「場所」フィールドが「森」かどうかをチェック
- #2 ソーシャルテーブルの「好感度」が特定の閾値を超えているかチェック

これにより、ワールドブックエントリがキャラクターの現在の状態に応じて動的に有効化されます。

## インジェクション位置の詳細

### before / after

キャラクター説明（character description）の前方または後方にインジェクションします。これらの位置はシステムプロンプトに近いため、AI がより高い注意を払います。

### atDepth

チャット履歴の指定深度にインジェクションします。depth の意味：

- `depth: 0`：最新メッセージの後
- `depth: 1`：最新メッセージの前
- `depth: N`：第 N ターンの会話の前

depth が小さいほど最新メッセージに近く、AI がより重視します。

### AN / EM

AN（Author's Note）と EM はネイティブのインジェクション位置であり、上流フレームワークで定義されています。

## 確率とリズムの制御

確率フィールドとリズムフィールドを組み合わせることで、自然な情報出現パターンを作成できます：

**例：ランダムイベント**
- `probability: 30`、`sticky: 3`、`cooldown: 10`
- 毎ターン 30% の確率でトリガー。トリガー後 3 ターン継続してインジェクション。その後 10 ターンクールダウン

**例：遅延伏線**
- `delay: 5`
- キーワードマッチ後、5 ターン遅延してからインジェクションし、「後から明かされる」効果を演出

## デュアルスイッチの相互作用

```
enabled: true  + boundCharName: ""      → すべてのキャラクターで有効
enabled: true  + boundCharName: "Alice"  → キャラクター Alice の時のみ有効
enabled: false + (任意)                  → 完全に無効
```

enabled はグローバルスイッチで、キャラクター間で状態を共有します。boundCharName はキャラクターレベルのフィルターです。両者は AND 関係です。

## 動作チェーン

```
システムがコンテキストを構築
    ↓
すべてのワールドブックエントリを走査
    ↓
各エントリに対して：
  1. enabled をチェック → false ならスキップ
  2. boundCharName をチェック → マッチしなければスキップ
  3. cooldown をチェック → クールダウン中ならスキップ
  4. トリガーモードを判定：
     - constant → 無条件通過
     - regex → 会話内容をマッチング
     - dynamic → 記憶テーブルの値をチェック
  5. probability をチェック → ランダム判定
  6. delay をチェック → 未到達なら今回はインジェクションしない
    ↓
通過したエントリを position と depth に従ってコンテキストの対応位置に配置
    ↓
sticky / cooldown カウンターを更新
```
