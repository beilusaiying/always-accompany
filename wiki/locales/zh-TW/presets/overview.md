# 預設集系統

在左欄下拉選預設集，AI 立刻換一套行為方式——聊天模式用聊天預設集，程式碼模式用程式碼預設集，切換即生效。

## 切換預設集

在對話介面的預設集選擇器中，點擊即可切換目前預設集。切換後立即生效，下一條訊息就會使用新預設集。

## 啟用/停用條目

透過 beilu-toggle 外掛，在預設集面板中勾選/取消勾選單個條目，即時調整 AI 收到的指令。

## 匯入預設集

在預設集管理面板中點擊匯入，選擇 SillyTavern 格式的 JSON 檔案即可。always-accompany 完全相容 SillyTavern 預設集格式，也可以自己從零建立。

## 預設集分類

always-accompany 的預設集按用途分類（稱為 bucket）：

| 分類 | 用途 | 典型預設集 |
|------|------|---------|
| Code | 程式碼輔助 | 程式碼審查、程式碼助手、IDE 指令 |
| Work | 工作流 | 任務管理、文件寫作、資料分析 |
| Clone | 角色扮演 | 角色卡適配、對話風格 |
| 通用 | 不限情境 | 自訂預設集 |

詳見 [預設集分類與選擇](categories.md)。

## 預設集與模式的聯動

每個模式（[聊天模式](beilu:mode/chat) / Code / [工作模式](beilu:mode/work) / [Bot管理](beilu:mode/bot)）可以綁定不同的預設集。切換模式時，系統自動載入該模式綁定的預設集：

- 聊天模式用聊天預設集 → AI 表現得像陪伴角色
- 程式碼模式用程式碼預設集 → AI 表現得像程式碼助手
- 工作模式用工作預設集 → AI 表現得像工作夥伴

詳見 [預設集與模式聯動](mode-binding.md)。

## 深入了解

### 預設集的組成

一個預設集由若干**條目（Prompt Entry）**組成，每個條目是一段文字加上控制屬性：

| 組成要素 | 說明 |
|---------|------|
| 條目內容 | 發給 AI 的實際文字（系統提示、角色指令、風格要求等） |
| 排列順序 | 條目在提示詞中的先後位置（越靠前，AI 越優先關注） |
| 啟用狀態 | 可以單獨開關每個條目，不用的暫時關掉 |
| 注入深度 | 條目插入聊天歷史的位置（深度 0 = 最底部，深度 4 = 往上數 4 條訊息處） |
| 角色標記 | 條目以什麼身份傳送（system / user / assistant） |

### 預設集做了什麼

當你傳送一條訊息時，always-accompany 並不是把你的訊息直接丟給 AI。在幕後，預設集引擎會把角色設定、系統指令、世界書、聊天歷史、外掛提示等內容，按照預設集定義的條目順序組裝成一份完整的提示詞，然後才傳送給 AI。

### 預設集與模型參數

預設集不僅包含提示詞條目，還可以攜帶模型參數（temperature、top_p 等）。載入預設集時，這些參數會一併生效，讓每個預設集擁有獨立的產生風格。

參數優先級：預設集自帶參數 < 執行階段參數面板 < 擴展層模型參數覆蓋

詳見 [模型參數](../ai-service/model-params.md)。也可在[AI服務源](beilu:settings/api)面板調整參數。
