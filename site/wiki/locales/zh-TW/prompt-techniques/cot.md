# CoT 思維鏈

CoT（Chain of Thought，思維鏈）是讓 AI 在輸出最終內容之前，先進行分析和規劃的技術。它不是一條提示詞技巧，而是一種改變 AI 工作方式的方法論。

## 什麼是 CoT

正常情況下，AI 收到提示詞後直接輸出結果。CoT 則要求 AI 先「想一想」——分析目前情境、規劃接下來要做什麼、梳理要注意的要點，然後再輸出。

```
沒有 CoT：
  提示詞 → 直接輸出

有 CoT：
  提示詞 → 分析情境 → 規劃要點 → 輸出
```

這個「先想再做」的過程，會顯著提升 AI 輸出的品質和一致性。

## 為什麼 CoT 有效

1. **引導注意力分配**：在分析階段，AI 會重新審視提示詞中的各項要求，確保不遺漏
2. **減少偏離**：規劃階段讓 AI 在動筆前就確定方向，而不是寫到哪算哪
3. **提升複雜任務表現**：對於需要同時滿足多個條件的任務（角色扮演、程式碼產生、長文寫作），CoT 幫助 AI 在多個約束間取得平衡

## CoT + 提示詞 = 最大效力

CoT 和提示詞配合使用，效果遠大於單獨使用任一。

### 範例：角色扮演情境

```
沒有 CoT 的提示詞：
────────────────
你是一個退役軍醫，性格沉穩。
以白描為主，對話推動情節。

→ AI 可能忽略部分設定，風格不穩定。
```

```
加入 CoT 的提示詞：
────────────────
你是一個退役軍醫，性格沉穩。
以白描為主，對話推動情節。

在輸出前，先在 <thinking> 中完成以下分析：
1. 目前場景的情緒基調是什麼
2. 角色在這個情境下會有什麼反應
3. 這段回覆要推進什麼情節點
4. 有哪些風格要求需要注意

然後再進行輸出。

→ AI 會先梳理一遍要求，再寫內容，風格更穩定、設定更一致。
```

### 範例：程式碼輔助情境

```
加入 CoT 的提示詞：
────────────────
在回答程式問題前，先分析：
1. 使用者的實際需求是什麼（不只是表面提問）
2. 有哪些可能的實作方案
3. 各方案的優缺點
4. 推薦方案的理由

然後給出程式碼和解釋。
```

## CoT 是檢查助手

CoT 不只是讓 AI 輸出更好——它還是你**除錯提示詞**的工具。

### 怎麼用 CoT 除錯

當 AI 的表現不符合預期時，看它的 CoT 分析過程：

1. **AI 理解對了嗎？** —— 看 CoT 中 AI 對你的提示詞的解讀，是否和你的意圖一致
2. **AI 在關注什麼？** —— CoT 中 AI 重點分析了哪些方面，忽略了哪些
3. **AI 在哪裡偏了？** —— 如果最終輸出有問題，從 CoT 中找到它開始偏離的那個環節

### 除錯範例

假設你要求 AI 「寫一段節奏緊湊的打鬥場景」，但 AI 輸出了大段慢鏡頭描寫。

檢視 CoT 你可能會發現：

```
AI 的 thinking：
「使用者要求節奏緊湊的打鬥。我需要詳細描寫每一個動作，
 展現打鬥的精彩程度......」
```

問題定位到了：AI 把「緊湊」理解成了「詳細」。這時你就知道該怎麼改提示詞：

```
修改前：寫一段節奏緊湊的打鬥場景。

修改後：寫一段打鬥場景。使用短句，
一個動作一句話，不展開描寫每個動作的細節，
保持段落在三行以內。
```

## 在 beilu 中使用 CoT

beilu 的[預設集系統](../presets/overview.md)支援在系統提示詞中嵌入 CoT 引導。你可以：

- 在角色卡的末尾新增 CoT 分析步驟
- 在預設集條目中設定 thinking 指引
- 利用尾部注入放置目前場景的 CoT 提示

放在尾部效果最好（參考 U 型注意力原則），因為 CoT 引導是「目前要做的事」，屬於高注意力區域。

## 注意事項

- CoT 會增加 AI 的輸出長度（分析部分也算 token），注意 token 用量
- 不是所有情境都需要 CoT。簡單問答、日常閒聊不需要，複雜創作、多約束任務才需要
- CoT 的分析步驟不要太多，3-5 步為宜。太多步驟反而讓 AI 在分析階段就偏了
- 某些模型支援內建 thinking 功能（如 Claude 的 extended thinking），可以與提示詞中的 CoT 引導配合使用
