第2章 系統架構與處理流程

## 2. 引言

本章描述 P1 自驅動發散召回系統的整體架構與處理流程。P1 是一個不依賴大語言模型（LLM）線上推理的聯想發散引擎，其設計目標是在對話進行時，為主對話模型提供一組「方向詞」——即主模型僅憑裸讀原文難以自發想到的關聯方向。設計者將 P1 的定位概括為「外置的發散思維鏈」：它並不替主模型作判斷，也不產生回覆內容，而是像視覺系統一樣先行掃描輸入、勾勒關聯輪廓，把一張「已標好路線的地圖」交給主模型，使其不必從空白開始思考。

需要在開篇明確一項系統狀態。本章所描述的完整「召回—發散」處理鏈，是系統組件庫內部已經實現、可逐行閱讀的演算法，但在目前線上（live）執行路徑中並未接入主鏈。根據設計記錄（2026年7月），系統的線上出詞職能暫由基於 LLM 的預設集檢索（下稱 AI 預設集檢索）承擔，而本章所述的自驅動發散管線處於「組件態」，即演算法已落地、待接回主鏈。為避免讀者混淆，本章在描述各處理環節時，會區分「設計意圖與演算法實現」和「目前線上是否啟用」兩個層面，凡未接入線上主鏈者均如實標注。

本章的組織如下：2.1 給出系統的標準處理鏈五步總綱，作為理解全流程的骨架；2.2 給出整體架構，包括十二節點處理圖、三條線路方案與 U 型注入機制，並配以正文解說；2.3 對各處理節點逐一作規格化描述，說明其輸入、處理、輸出與關鍵參數；2.4 作為附節介紹架構的歷史演進版本（標明為歷史版本，非現行實現）；2.5 為本章小結。

在術語上，本章首次出現的自造術語均先給出定義。為便於外部讀者建立整體圖景，此處先約定幾個貫穿全章的核心概念：

- **軸（axis）**：一個學科視角。系統以六個學科軸作為發散的輸入端，每個軸從其學科角度對輸入詞各自獨立地產生一組關聯資訊。
- **面與線**：設計者用「面」與「線」區分一個軸的產出形態。一個軸對一個詞若只給出單一分數（如一個純量性質），稱為吐「線」；若給出一組豐富的關聯資訊詞，稱為吐「面」。系統要求各軸吐「面」而非吐「線」。
- **池（pool）與空間（space）**：各軸產出的候選詞彙合併進入一個共享集合，稱為「池」；系統在詞向量空間中對池內內容作分佈式聚合與定位，故亦稱「空間」。設計者強調池的語義是「空間相加」而非「線性相乘」。
- **溫度（temperature）**：控制發散範圍的參數。設計者以「畫圓」作比喻——從錨點向周圍擴散出一個圓，圓過小則只得同義冗餘詞，圓過大則納入無關雜訊，需在兩者之間篩選出合適區間。
- **資訊詞與方向詞**：系統的中間產物是「資訊詞」（描述輸入相關內容的詞），最終產物是「方向詞」（供主模型參考的關聯方向）。二者經由一次「資訊詞作為池再選出方向詞」的轉換。

## 2.1 標準處理鏈五步總綱

系統的核心處理流程可歸納為一條連續的認知鏈，由五個步驟構成：六軸與各機制並行、各自獨立執行，結果匯入同一候選池，在池內打分，定位每個候選所接近的軸與點位，最後沿溫度擴散。這五步並非五個孤立演算法，而是「各機制各自並行執行 → 匯入一個池 → 在池內打分定位 → 沿溫度向邊界擴散」的一條連貫鏈路。以下逐步展開。

### 2.1.1 第一步：六軸與機制並行、獨立執行

第一步的核心原則是**機制並行，而非軸並行**。系統區分兩類並行對象：一是六個學科軸各自獨立發散（軸並行），二是若干發散機制（如情節、隱喻、類比等）各自獨立執行（機制並行）。設計者反覆強調 P1 採用的是機制並行，且發散應「沿主軸延伸，而非獨立平鋪」，唯有沿主軸延伸方能形成真正的發散與聯繫，而非彼此無關的詞彙堆疊。

六個學科軸構成系統的**輸入端**，各自並行發散，分別是：心理學、資訊學、社會學、邏輯學、語言學、認知學。其中「六軸含認知學」為目前定型形態；系統早期曾採用不含認知學的五個固定軸，認知學系後期加入，這一演化過程在 2.4 歷史版本中說明。設計者將六軸定性為「輸入端」，與產出端的定位坐標（見第三步與第四步）明確區分。

各軸發散遵循「先學科後分佈」的次序，即先由各學科視角產出候選，再在後續步驟中作空間分佈。並行的目的在於**防遺漏**：各軸走完各自路徑後再合併觀察關聯性，而非在過程中相互裁剪，從而避免過早丟棄潛在有價值的關聯。

一條貫穿本步的鐵律是「吐面不吐線」：每個學科軸對每個詞應輸出一組關聯資訊（一個「面」），而非一個模糊的性質分數（一條「線」）。即設計上要求每個學科軸對每個詞提供一組資訊，而非單一數值。相應地，每個學科軸配有其專屬的知識資源。

綜上，第一步可歸納為如下流水線：六軸各自獨立執行，心理、資訊、社會、邏輯、語言、認知各產出其候選詞面；隨後合併入一個池；池內資料對各軸的靠攏程度確定主方向（主軸）；再從主方向向其他軸發散（受跳數約束，沿主軸延伸而非平鋪）；最後施加軸衰減（主軸權重最高、次軸與遠軸依次降權，只降權不刪除）。

### 2.1.2 第二步：放入池（合並到一個池）

第二步是將各軸產出匯入一個共享池。此處的關鍵設計判斷是：**池的本質是空間疊加，不是相乘**。設計者的完整表述為：「匯總到一個池，不是相乘，而是空間，進行內容分佈投票……資訊詞再作為池與空間選出方向詞。」系統在詞向量空間中作「空間相加」，透過內容的分佈式投票確定方向，而非對各路徑分數作線性相乘，也非硬匹配。

進池的語義是**資訊疊加**。當多個詞同時進入池（例如「喜歡」與「笨蛋」的組合），系統將其內容相加、在空間中定位其合成位置，而非分別處理後取乘積。

進池遵循一條鐵律：**禁止逐詞發散後相加**。設計者明確反對「一個詞就發散出一堆、再把多個詞各自發散的結果相加」的做法，認為這樣既不準確，又是「萬金油」現象（即產出大量對任何輸入都通用、缺乏針對性的詞）的根源。正確的做法是「資訊池發散」而非逐詞發散——先形成池，再從池整體發散。

為刻畫池的空間語義，設計者引入「點、線、面、體」四層結構：點為詞彙，線為方向（詞彙的種類），面為類型（使用者對話的實際需求），體為多維空間。對應到系統結構，體是全部軸構成的總空間，面是六個學科軸（每軸吐一組資訊詞），線是更細的子方向坐標，點是具體術語。

### 2.1.3 第三步：打分（內容分佈投票）

第三步在池內對候選打分。基礎原則是**空間內容分佈投票**：候選在空間中的分佈決定其得分，而非逐詞查表得分。投票方向為**多對一**——多個資訊詞共同指向一個方向，而非一個資訊詞指向多個方向詞。

關於「取均值」存在一處需要辨析的設計張力。系統一方面有「不取均值以保留分佈張力」的原則，另一方面又有「某些軸分數過高時應取均值」的表述。這兩條並不衝突，因其作用對象不同（該辨析已於設計記錄中裁定）：

- **不取均值**，作用於**詞間票聚合**：當多條路徑命中同一個詞時，票數求和而非求均值，以保留分佈張力。這是詞級機制層的紅線。
- **應取均值**，作用於**軸間尺度校準**：不同學科軸的分數量綱天然不同，某些「大軸」分數偏高會壟斷排名，故對軸間分數作均值歸一。這是軸級尺度校準。

二者對象不同、互不矛盾，已共存於系統設計中。在打分聚合方式上，系統採用**加性投票**而非乘法。早期版本曾採用多因子連乘的評分公式，被認定為萬金油現象的根源，後重寫為加性聚合。目前打分環節的核心形式為「加性投票，得票等於權重乘以逆距離權重，不作連乘、不除以路徑數」，其演算法細節見 2.3 相應節點。

### 2.1.4 第四步：找接近的軸與點位（近軸歸屬與點位定位）

第四步在池內完成方向定位，包含兩個動作：確定接近的軸，以及在細粒度空間中定位點位。

**近軸歸屬**指：將池內資訊投射到細分子方向空間後，找出與之最接近的若干個（約三到五個）軸，再對這些軸施加衰減、發散，並將資訊詞轉換為方向詞後輸出。設計者強調細分子方向空間「原本是激活的、並非全部啟用」，即只激活與目前輸入相關的子方向，而非遍歷全部。

確定主方向的依據是**靠攏度**——池內資料對各軸的靠攏程度即主方向。例如輸入「外婆去世」時，池內心理學相關候選多且強，主方向即為心理學；輸入涉及技術程式設計內容時，池內資訊學候選占優，主方向即為資訊學。設計者並未給出靠攏度的具體數學公式，系統實現上以「投票後統計各軸累計票數確定主軸」近似之。

系統區分兩組軸：六個學科軸負責**確定發散點**（輸入端），細分子方向空間負責**大致定位、擴充與產出**（產出端）。二者不是同一事物，細分子方向也不是六個學科軸的下級子分類。設計者指出細分子方向空間的設計尚不完善，而六個學科軸的劃分是成立的。

**點位定位**採用多維坐標加錨點密度的方式：以多維坐標定位，再加溫度向左右擴散。其類比為：先透過多詞組合的空間投票確定錨點位置（類似症候群的組合模式識別），再從錨點用溫度向周圍作圓形擴散。

### 2.1.5 第五步：沿溫度擴散

第五步從錨點沿溫度向外擴散，得到最終的發散邊界。其核心設計為：溫度定義了一個以錨點為圓心的圓，候選向周圍擴散，過近與過遠均不可取，須經篩選。具體拆解為：

- **「太近」** 是圓的內邊界，用於篩除廢詞與同義冗餘（離錨點過近的詞往往是主模型自己也能想到的，缺乏發散價值）。
- **「太遠」** 是圓的外邊界，用於排除無關雜訊。
- **中間區間** 為需要保留的「甜蜜區」。

「太近」的判據由「廢詞」概念支撐：主模型裸讀原文也能推出的詞即為廢詞，而 P1 的價值恰在於提供主模型自己想不到的方向。

設計者明確區分了三個易混概念：**衰減**指定向發散、不遍歷全庫（靶向而非全做）；**溫度**指子方向空間收縮後的定向擴散範圍；**熱插拔機制**指迭代修正的自學習，既非溫度也非衰減。三者不可混為一談。

關於**衰減**，設計原則是「涉及其他軸時再加，但需衰減，不影響主力」。系統實現上採用分檔衰減：主軸權重最高，次軸與遠軸依次降低，但遠軸權重不歸零（只降權不刪除），以實現「軟隔離」。

關於**擴散的停止條件**，系統採用跳數約束（約束在數跳之內）配合軸衰減。此外有一條實驗得出的距離紅線：聯想發散的距離必須保持在中遠程區間，最近距離（同義擴散）為禁用項——實驗表明，將發散退化為同義擴散會導致召回品質大幅下降（在一項基準測試中下降約七成），故該項被鎖定為禁用。

需要指出，「太近」內邊界的一個具體實現環節曾因其閾值缺乏依據而被移除（詳見 2.3 相應節點的已知問題），目前「太近」的部分職能由後段節點的甜蜜區衰減邏輯承接，並非完全斷鏈。

### 2.1.6 五步與節點的對應關係

標準處理鏈的五步與 2.3 所述的具體處理節點存在如下對應關係：

| 標準鏈步驟 | 對應節點 | 核心設計原則 |
|---|---|---|
| ① 六軸與機制並行獨立執行 | 節點3（六軸吐面） | 先學科後分佈；六軸為輸入端各自並行發散 |
| ② 放入池 | 節點6 第一次呼叫（資訊池） | 匯總到一個池，不是相乘，而是空間 |
| ③ 打分 | 節點6 空間投票 + 節點8 打分框架 | 內容分佈投票；軸間尺度校準取均值 |
| ④ 找接近的軸與點位 | 節點4（子方向激活）+ 節點9 | 找最接近的若干軸；靠攏度定主方向 |
| ⑤ 沿溫度擴散 | 節點6 溫度圓 + 節點7 二次發散 | 加溫度畫圓，太近太遠皆篩除 |
| 輸出方向詞 | 節點9 → 節點10 | 資訊詞作為池，在空間中選出方向詞 |

**節點職能概述**：處理鏈以兩個並行入口起始——Step-1 在分詞前先識別括號這一元語言符號，將括號內外拆為主、副兩個信道分別處理；節點0 與分詞並行地作大量記憶召回，其召回結果作為後續發散的錨點。主信道經節點1 分詞收攏、節點2 聯想發散後形成散詞池，進入節點3 的六個學科軸並行發散。節點4 在細分子方向空間中作定位，節點5 作為可在多處複用的「算子」用資源庫對候選作交叉確認。節點6 是全鏈的核心，將候選匯入一個空間、作內容分佈投票並以溫度畫圓定邊界。節點7 作第二次發散擴充資訊詞，節點8 對資訊詞打分篩選。節點9 將資訊詞整體作為池、在空間中選出方向詞，是唯一的出詞路徑。節點10 作最終篩選並硬剔違規詞，輸出方向詞 XML 注入主模型。熱插拔自學習與白盒可觀測兩個機制貫穿全程（見 2.3.13、2.3.14）。

圖中標注的「◆算子」（節點5）表示該節點不是鏈上一次性的固定步驟，而是可在多個位置複用的定位細化算子；「◇」標注的兩個機制則是橫切全流程的支撐機制，而非串行鏈上的一環。

### 2.2.2 三條線路方案（LLM 最佳化器的位置）

系統在設計上預留了三條線路，其差異僅在於**LLM 最佳化器插入的位置**。此處 LLM 的角色被嚴格限定為「方向、頭部、轉換詞的最佳化器」，而非發散的來源，且受四條紅線約束（見下文）。三條線路的基礎發散引擎相同，區別在於是否引入 LLM 以及引入的時機：

- **線路1（基礎，無 LLM）**：根據對話作記憶召回與大量擦邊召回，再根據上下文作第一次聯想發散，然後由轉接器轉換再發散。全程不引入 LLM。
- **線路2（LLM 在聯想發散之前）**：在記憶召回、擦邊召回之後，先由 LLM 從整體上判斷方向、頭部、次要發散方、多頭、可能的錯別字或隱藏內容、上下文邏輯，再作聯想發散，然後轉接器轉換。
- **線路3（LLM 在聯想發散之後）**：先作記憶召回、擦邊召回與第一次聯想發散，再由 LLM 依據上下文與發散輸出最佳化頭部、方向、重要轉換詞、次要方向以及輔助識別錯別字或隱藏內容，然後轉接器轉換。
- **線路C（雙位置）**：LLM 在上述兩個位置均介入，為規劃中的測試方向。

以 ASCII 圖示三條線路（其中「實裝」表示對應環節已實現，「實驗態」表示已在實驗分支實現但未合入主鏈）：

```
                  使用者對話輸入
                       │
                       ▼
             記憶召回（大量擦邊）
                       │
                       ▼
                  上下文整合
        ┌──────────────┼──────────────┐
        ▼              ▼              ▼
   [線路1 基礎]    [線路2 A路徑]   [線路3 B路徑]
   無 LLM          LLM 在發散前     LLM 在發散後
        │              │              │
   聯想發散(實裝)   LLM 看整體(實驗) 聯想發散(實裝)
        │              │              │
   轉接器再發散     注入設定後        LLM 逐詞標注(實驗)
   (實裝)          聯想發散(實裝)     │
```

關於三條線路的**實裝狀態**：線路1 已基本實裝（無 LLM，僅走生產路徑）；線路2 與線路3 的 LLM 環節已在實驗分支實現完畢，但尚未合入主鏈，處於條件啟用狀態；線路C 為雙位置方案，實裝度最低。其中一處關鍵斷鏈在於：LLM 輸出回送至轉接器的通路尚未接通——實驗分支內已寫就 LLM 結果到二次發散的映射，但主鏈尚未消費 LLM 結果。需強調，這套三線路是系統早期單體架構時期的設計與程式碼快照，目前流水線架構的線上出詞走線路1（無 LLM 分支）；LLM 接入另有後續版本演進，屬組件態。

**LLM 的四條紅線**：LLM 在系統中被定位為「標籤產生器」而非「標注專家」（後者會引入不受控的創造性），其絕對不可逾越的四條約束為：不創造（產出以原文與召回內容為主，僅極小比例來自封閉列舉）；不評分（不產生任何數字欄位）；不投影（不推測使用者未言明的內容）；不影響系統（其輸出為標注，不改動主鏈）。

### 2.2.3 P1 在對話流程中的位置

P1 在整個對話處理流程中的位置如下。在取得提示詞階段，系統依次載入記憶資料、確定目前模式、注入表格資料、注入熱層記憶、注入提示詞鏈，隨後進入 P1 自驅動認知發散環節（非同步執行，不阻塞主流程），最後作模式專屬注入與聯網搜尋。P1 環節之後，主模型產生回覆，再由後續的歸檔與記憶遷移管線處理。

```
使用者輸入
  │
  ▼
取得提示詞階段
  ├─① 載入記憶資料
  ├─② 確定目前模式（對話/編碼/工作）
  ├─③ 表格資料注入
  ├─④ 熱層記憶注入
  ├─⑤ 注入提示詞鏈
  ├─⑥ P1 自驅動認知發散（非同步，不阻塞主流程）   ← P1 在此
  │    → 設計：置信度達閾值時輸出方向詞 XML
  │    → 設計：置信度不足時回退至 AI 預設集檢索
  │    → 目前線上：自驅動充分性判定恆為假，恆走 AI 預設集檢索
  ├─⑦ 模式專屬熱層注入
  └─⑧ 聯網搜尋（當 P1 輸出含搜尋提示時觸發）
  ▼
主模型產生回覆
  ▼
回覆處理 → 歸檔 → 日終整理 → 層級遷移 → 定期整理
```

圖中標注「目前線上：自驅動充分性判定恆為假」對應本章開篇的系統狀態聲明——線上主鏈恆走 AI 預設集檢索，本章所述自驅動發散鏈為待接回的組件態實現。

### 2.2.4 U 型注入機制

P1 的輸出在注入主模型時採用 **U 型注入**，即依據注意力的首因效應與近因效應，將最重要的內容放在序列的首端與尾端，最弱的內容放在中間。注入按深度分層：

```
深度2 → API 快取區（跨輪穩定）
深度1 → 系統提示區（快取友好）
深度0 → 對話尾部（注意力最強）  ← P1 方向詞 XML 在此注入
          ├─ 認知激活塊（按模式：對話/編碼/工作/特定情境）
          │    含認知術語 / 方向詞 / 技術信號 / 擴展 / 錨點
          └─ 記憶體動態資料
```

P1 方向詞 XML 注入於深度0（對話尾部，注意力最強處）。在方向詞 XML 內部同樣採用 U 型排列：排名第一的方向詞置於首位（首因效應），排名第二置於末位（近因效應），排名第三這一相對最弱者置於中間（最弱位置）。整個 XML 塊的各組成部分亦按此原則排列，召回記憶居首、方向詞居尾。

## 2.3 各處理節點規格化描述

本節對各處理節點逐一作規格化描述。每個節點按「設計原則 → 處理機制 → 目前實現 → 關鍵參數 → 已知問題」五層展開。各節點的程式碼實現位於系統記憶模組的 P1 子目錄下，節點模組以 `p1_node*.mjs` 命名，模組名在描述中保留作為職能標識。凡未接入線上主鏈者，均在「已知問題」中如實標注。參數標注中，「經實驗校準的定檔值」指由實驗落定的數值，「初始預設值（未經系統性調優）」指尚無實驗依據的取值。

### 2.3.1 Step-1：括號雙信道（分詞前置層）

- **設計原則**：括號是一種元語言符號，P1 必須在分詞之前先識別括號，將主信道（正文）與副信道（括號內容）分別處理，否則會丟失真實情緒。副信道常承載正文未明說的真實情緒。
- **處理機制**：在所有演算法之前、早於分詞，識別括號並拆分為主信道與副信道，二者分別處理且**不取均值、保留張力**（當正文與括號內情緒反向時，取均值會相互抵消）。序號、旁注等格式性括號予以豁免。無括號時走單信道，零額外開銷。
- **目前實現**：模組 `p1_step1_bracket.mjs` 提供括號信道拆分職能，返回主信道、副信道及是否含括號的標誌。副信道另行執行一次發散，兩個池以集合聯集方式合並（不取均值），主副散詞共同進入空間投票，反向情緒不相抵消。無括號時整段跳過。
- **關鍵參數**：括號雙信道開關預設開啟。
- **已知問題**：無。該環節在組件庫內處於可用狀態。

### 2.3.2 節點0：記憶召回（P1 職能①，與分詞並行）

- **設計原則**：召回是首要任務，P1 的作用是召回加發散。系統借回溯機制，結合上下文、注意力集中與多軸視角，查看此前的內容（data 層、熱層、冷層），匹配後取出並告知主模型，此過程不需要很智慧的判斷。設計者明確區分召回與發散的邊界：召回讀取記憶資料層，而發散本身只看最近數句上下文、不讀召回的資料。
- **處理機制**：以最近數條上下文加聯想加演算法，查看壓縮記憶的 data/熱/冷三層，作關鍵詞與資訊匹配，進行**大量擦邊召回**，其結果作為發散錨點。召回與分詞並行；發散只看最近上下文、不讀召回資料。
- **目前實現**（須區分兩條獨立線）：
  - 模組 `p1_node0_recall.mjs` 提供發散管線內的**上下文錨點**：取最近若干句上下文，逐句作聯想交集與詞向量餘弦打分，排序後取靠前者作為錨點，高頻詞作軟降權處理。
  - 模組 `p1_node0_data_recall.mjs` 提供 data 三層擦邊召回，預設關閉、處於灰度狀態。
  - **真正的記憶召回是另一條線**：由記憶召回模組 `memoryRecall.mjs` 在發散管線之前獨立呼叫，召回片段以系統訊息形式並入對話歷史，而非以召回記憶 XML 形式注入。發散管線內的上下文錨點與真正的記憶召回互不引用（二者的隔離為設計約束）。
- **關鍵參數**：上下文句數為初始預設值；錨點強度採用與命中數相關的遞增公式；data 三層召回預設關閉；data 層三層權重按熱、溫、冷遞減；data 召回強度設上限以保證召回不主導。
- **已知問題**：真正的記憶召回目前尚未讀取熱/冷壓縮層（而是遍歷整個記憶目錄樹），「讀壓縮層」一項設計者判定為暫緩；data 三層召回預設關閉，待驗證後轉正。設計者標注該環節「需要進一步討論和定位」，為未定項。

### 2.3.3 節點1：收攏₁（分詞 + 排除無資訊詞）

- **設計原則**：收攏之後由分詞器分詞，排除無資訊內容；先聚攏再發散，為發散提供錨點。
- **處理機制**：分詞後排除無資訊詞（虛詞、超高頻詞），得到有意義的詞作為錨點。**例外**：程度副詞與極性強化詞（如「這麼」「太」「很」）不作為雜訊刪除，而保留為相鄰內容詞的強度、極性加權信號。
- **目前實現**：模組 `p1_node1_tokenize.mjs` 承擔分詞與無資訊詞排除職能，採用分詞器配合高頻詞表排除無資訊詞，程度副詞與極性詞另行保留。該節點在發散主流程內被串行呼叫。
- **關鍵參數**：高頻詞頻率閾值為經實驗校準的定檔值；所用資源包括分詞組件、詞性詞典（作詞性交叉驗證）、約十餘萬條的詞頻表、多份停用詞表及程度副詞表。
- **已知問題**：無。組件庫內處於可用狀態。

### 2.3.4 節點2：發散₁（聯想發散，P1 職能②，發散引擎核心）

- **設計原則**：以原內容加上下文作聯想發散；聯想發散為核心發散機制，轉接器為其配套的轉換機制。
- **處理機制**：有意義的詞加上下文經聯想發散產生散詞池。**發散距離須保持中遠程**，禁用同義近距擴散（該項為紅線）。
- **目前實現**：模組 `p1_node2_swow.mjs` 承擔聯想發散職能，主路徑走一種「查詢—鍵—值」式的池交汇發散：以輸入詞的詞向量質心為查詢，以聯想線索詞對質心的餘弦相似度為鍵，從交汇線索鏈式再發散得到值。設有雙重門控：線索詞須與輸入有直接聯想關聯，且餘弦相似度須達閾值；僅當輸入詞數達到下限時才啟用該路徑（以防止單詞噴發）。返回散詞池與輸入質心。設計記錄中同時留存了一條注釋，說明早先的「逐詞獨立聯想發散兜底」分支因違反「禁止逐詞發散」紅線而被純刪除。
- **關鍵參數**：聯想發散距離保持中遠程（紅線）；池交汇尺寸為經實驗校準的定檔值（更大尺寸雖降幅溫和但易漂詞且算力成本顯著上升）；線索餘弦閾值與聯想候選數上限為配套參數。
- **已知問題**：無。歷史上同義近距擴散曾導致召回品質大幅下降（約七成），此為血換的教訓，現鎖定為紅線。

### 2.3.5 節點3：六軸獨立並行發散（每軸多維，6+n）

- **設計原則**：六軸中每軸多維（六個學科、每學科含多個子方向定位），每個軸配有對應資源；六軸是一個「面」，不應做成「線」；六者並行、走完後合並到一處觀察關聯性。設計者曾手寫一個示例說明「面」的形態：對「你為什麼這麼笨」一句，可拆出資訊詞「笨」「笨蛋」，各軸分別產出——資訊學給出否定、反面、錯誤、失望，邏輯學給出錯誤、長期問題、失落，心理學給出負面、失望、預期不達標、最佳化渴求、同情，社會學給出吐槽、不滿、無語疑惑，認知學給出預期偏差，語言學給出負面，其中「這麼」起到加重「笨」這一資訊的作用。
- **處理機制**：散詞池經六個學科軸各自獨立並行發散（每軸多維判斷加專屬資源），各吐一個「面」（一組豐富資訊，而非單一分數），合並到一個池觀察關聯性，並帶主方向軸與衰減。
- **目前實現**：模組 `p1_node3_axis6.mjs` 承擔六軸發散職能，散詞池經六軸各吐面，含軸衰減，返回各軸面、軸衰減、主軸及詞屬性畫像。其**軸衰減機制**為：計算各軸的關聯度（該軸上候選值之和），按關聯度降序排名，衰減按排名指數遞減——主軸（排名首位）為最高值，遠軸指數衰減但恆大於零、永不歸零（軟隔離）；另設一軟停閾值，關聯度低於該閾值的軸不再發散（不注入新錨點），但其已有的「面」不刪除。
- **關鍵參數**：軸衰減係數為經實驗校準的定檔值（係數越大遠軸衰減越劇烈）；軟停閾值為一固定比例。各軸專屬資源包括心理學的情緒與情感詞庫、資訊學的領域詞庫等。
- **已知問題**：其中兩處子機制曾被判為框架偏離，目前接線正常。

### 2.3.6 節點4：子方向空間細化 + 詞向量300維

- **設計原則**：子方向空間用於細化定位，六軸確定發散點、子方向空間作大致定位再擴充產出；六軸與子方向空間不是同一事物；子方向「原本是激活的、非全部」。系統裁定：打分是打分框架與詞向量的職責，不是子方向空間的職責（子方向只定位不打分）。
- **處理機制**：六軸發散結果在細分子方向空間中作詳細**定位**（子方向空間是定位坐標，不是屬性打分），配合詞向量維度輔助，確定激活哪些子方向（而非全部）。子方向空間是產出端的空間定位，不是六個學科軸的下級子分類。
- **目前實現**：模組 `p1_node4_axis47.mjs` 承擔子方向定位職能，散詞命中術語後記入命中集，經重寫後**只定位不打分**，返回激活集與命中證據集。
- **關鍵參數**：所用資源包括子方向坐標術語表、少維兜底摘要及詞向量表。
- **已知問題**：歷史審查曾記錄一處子方向鍵命名分裂導致靜默丟分的疑似缺陷，需按目前程式碼核實是否已修（本章僅記錄，不作裁定）。設計者亦自承子方向空間的設計尚不完善，而六軸劃分是成立的。

### 2.3.7 節點5：資源庫多資源定位細化（算子，可多處複用）

- **設計原則**：以資源庫的多種資源作定位與細化；系統資源庫資源豐富，應充分利用；定位即細化，資源庫的定位細化可在多個位置複用，而非僅在單個位置——系統在「做流程」而非「打補丁」。該環節應置於空間投票**之前**。
- **處理機制**：用 P1 資源庫的多種資源對候選作定位與細化。它**不是一次性的單點步驟，而是可在流程多處（如節點4、6、7）複用的算子**，只產出「確認信號」（有多少資源確認了這一位置及語義關係），不改動坐標、不投票、不排序。
- **目前實現**：模組 `p1_node5_resource.mjs` 承擔資源交叉確認職能，用概念網、詞林、同義、反義、常識庫等多種資源作交叉確認，只產出確認計數與語義關係，不改坐標、不投票。該職能掛接於資訊詞清洗環節。
- **關鍵參數**：所用資源包括大規模概念網、常識庫、詞林、同義詞庫、框架語義庫等（另有若干可擴展但未接入的資源）。
- **已知問題**：歷史審查曾有「該節點空跑」的結論，經核實已證偽（該節點確有下游消費者，產出確認信號被使用）。

### 2.3.8 節點6：匯總到一個池 → 空間 → 內容分佈投票（主排名）

- **設計原則**：匯總到一個池，不是相乘，而是空間，進行內容分佈投票；系統採用空間相加，而非線性相乘、非硬匹配；加溫度畫一個圓，太近不行、太遠也不行，需要篩選；空間匹配更優，在空間中匹配、排除空間外的、找空間內的。
- **處理機制**：定位細化後的候選匯總到一個空間（**相加，非相乘，非硬匹配**），作內容分佈投票，以多維坐標確定多個錨點，再加溫度畫圓作為邊界。太近者排除（廢詞、冗餘），太遠者自然衰減（不硬刪），中間甜蜜區保留。
- **目前實現**：模組 `p1_node6_spaceVote.mjs` 承擔空間投票職能，是資訊詞打分的主排名環節。採用**多對一累加投票**：每個候選獨立地對每個目標投票，總得票為各票之逐項累加（無連乘、無除以路徑數）。其核心邏輯為：以詞向量距離為基礎，低於投票下限（太遠）者不投票；圓外者不硬刪（僅用於排序與錨點篩選）；以逆距離權重乘以候選權重得到單票，累加為總票。溫度畫圓的邏輯為：依據輸入詞數分檔確定溫度（短句取高溫、大圓，長句取低溫、小圓），圓半徑等於基準半徑乘以溫度。
- **關鍵參數**（均為目前實測值）：逆距離陡度、基準半徑、溫度分檔值（短句高溫、長句低溫）、內邊界比例（預設關閉）、領域加分因子——其中經三檔實驗裁定的陡度值為經實驗校準的定檔值，基準半徑為鈍調參數，內邊界比例預設關閉。
- **已知問題**：**「太近」內邊界環節曾因其閾值缺乏依據而被移除**，目前內邊界比例預設關閉（以保證零迴歸），其實驗檔位待大規模 A/B 測試確定；「太近」的部分職能現由節點10 的甜蜜區衰減承接。此處有一條重要工程約束：**切勿以「乘以品質係數」的方式給投票打補丁**——連乘等同於硬匹配，違反「空間相加、非相乘」的設計原則（該做法曾被引入又被刪除，程式碼注釋明確記錄此紅線）。歷史審查中「該節點為死程式碼」的結論已證偽。

### 2.3.9 節點7：發散資訊詞（第二次發散）

- **設計原則**：在空間投票後再發散資訊詞；系統設計了兩次發散——第一次是上下文加聯想，第二次再發散為資訊詞；發散詞包含跨領域關聯、上下流程關聯、歸因關聯；六度分隔可簡化為二到三跳，聯繫過小時自動停止。
- **處理機制**：空間投票結果經第二次發散產出資訊詞，為方向詞提供更多有用的可能性。所有路徑的產物都並入資訊詞清單，作為額外資訊詞加性參與節點9 的投票，而非替換節點9 的投票機制。
- **目前實現**：該環節內聯於轉接器模組，含**多條發散路徑**，各路徑由獨立開關門控（預設全開）。各路徑共享去重圖、歸一化尺度與推入助手（原始分經歸一後並入，形態與「面」一致）。各路徑及其資料源如下：

  | 路徑 | 資料源 | 觸發方式 | 衰減機制 |
  |---|---|---|---|
  | 個性化隨機遊走 | 知識圖譜（詞/概念/術語節點） | 以輸入詞為種子 | 冪迭代，含阻尼係數與自然衰減 |
  | 二跳關聯 | 錨點概念經常識庫到術語 | 一跳聯想結果取靠前者 | 二跳，含衰減係數，異軸與同軸分別加權，每詞設上限 |
  | 因果關聯 | 錨點經常識庫因果邊到術語 | 以錨點聯想結果為種子 | 依常識庫因果類型，路徑接力降權 |
  | 類比關聯 | 主軸錨點向其他軸作詞向量餘弦匹配 | 正向主軸到其他軸，反向次軸到主軸 | 跨域結構同構，倒 U 型甜蜜區門控，設錨點數與每錨點上限 |
  | 六度關聯 | 錨點經常識庫全關係一到二跳到術語 | 以錨點靠前者為種子 | 獨立遊走去重，含衰減係數；跨域時給予遞增獎勵 |

  以六度跨域發散為例，其核心邏輯為：對每個遊走到的術語，依據是否跨軸給予不同的判別權重，乘以路徑衰減（按跳數遞減，不含種子分），當路徑衰減低於停止閾值時終止；跨域涉及的領域越多，跨域獎勵越高（鼓勵跨學科聯想），已收錄的術語不重複推入。這一設計對應「跨框架類比本質上就是六度分發」的思路。
- **關鍵參數**：各路徑的阻尼係數、迭代上限、衰減係數、獎勵上限、跨域獎勵係數、節點整體縮放等，為經實驗校準的定檔值與初始預設值的混合。
- **已知問題**：該環節以異常捕獲包裹，拋錯不影響主鏈（合理設計）。頭注釋中提及的一處打分框架呼叫在目前程式碼中並不存在（詳見節點8 已知問題）。

### 2.3.10 節點8：打分框架 + 篩選①（篩資訊詞）

- **設計原則**：打分框架用於評分與篩選（可用於多個位置）；打分框架是演算法框架，轉接器是各類機制的總和、包含打分框架；聯想發散為核心發散、打分框架為轉接器；乘積應取均值；需要多維標注而非單一內容標注（即空間）。打分框架是轉接器內部的「打分裝置」，**既非發散引擎也非選擇器**——方向由投票環節「選」，打分框架在選後只作降權、篩廢詞與紅線處理。
- **處理機制**：資訊詞經打分框架評分後篩選（保留高品質，降權萬金油、雜訊、極性不匹配、冗餘）。收攏階段包含側抑制（近義去重）、多樣性重排與配額（保證各軸有代表）。
- **目前實現**（打分框架位於 `p1_node8_10_blq.mjs`）：核心為**六個加分維加權線性求和，再減去若干抑制維的加性扣分**（採用線性組合而非連乘）。六個加分維分別為：空間距離項、詞頻飽和項、跨學科路徑和諧項（僅此一處計入，絕不在外層重複相乘）、詞向量相關性項、特異性項、資源確認項。四個抑制維為加性扣分：萬金油、極性不匹配、無關、孤立雜訊。最終得分取「加性匯總」與「加性匯總減去扣分總和」中的較大者（設軟地板，防止多門疊扣硬歸零）。側抑制階段執行完整打分加側抑制（近義壓制）、多樣性重排與配額限制。
- **關鍵參數**：各加分維權重與各扣分係數均為經實驗校準的定檔值；側抑制近義閾值、多樣性係數、單軸與單維配額、輸出條數為定檔值。
- **已知問題（重要）**：
  1. **打分框架目前是「死引用」（孤兒）**：轉接器模組中雖有對打分框架的引用聲明，但全文並無實際呼叫，也無對應門控開關。頭注釋所稱「被轉接器呼叫、門控開啟」與磁碟實際不符。**目前活躍管線中，打分框架並不參與打分**——資訊詞的打分實際由節點6 的空間投票與節點3 的軸衰減承擔。打分框架的六維框架是完整落地的設計（程式碼可逐行閱讀），但尚未接入主迴圈。
  2. 該節點的完整精排外殼同樣是孤兒（無生產呼叫）。
  3. 演算法史：舊版本曾採用四個抑制維連乘的公式（全部觸發時呈指數級壓制），違背設計方向。實驗表明乘積公式導致召回大幅下降（約六成），幾何均值方案亦顯著惡化，加性優於乘積為血換的定檔結論。

### 2.3.11 節點9：資訊詞作為池 → 空間 → 選出方向詞（唯一出詞路徑）

- **設計原則**：資訊詞再作為池與空間選出方向詞；多個資訊詞對應一個方向（多對一），而非一個資訊詞對應多個方向詞；不是一個詞發散一堆，而是資訊池發散；方向詞是給主模型的建議，而非對使用者的判斷。
- **處理機制**：資訊詞整體作為池，在空間中觀察池指向什麼方向，作**多對一投票**，選出方向詞。
- **目前實現**：模組 `p1_node9_dirword.mjs` 承擔方向詞選擇職能，是**唯一的出詞路徑**。採用霍夫式多對一投票：每個資訊詞對每個合格目標投票（加性），累加為總票（空間相加，非相乘）；收口時以總票乘以軸衰減得到最終得分。
- **關鍵參數**：預設衰減值、多投票器開啟（每個資訊詞獨立投票以實現多對一）、霍夫投票取頂數、方向詞輸出條數（約二十條）。
- **已知問題**：某類詞的產出存在結構性偏斜（近義合并無法解決），歸入產詞線待定問題。

### 2.3.12 節點10：打分 + 篩選② → 輸出（線上真實執行環節）

- **設計原則**：打分加篩選；輸出廢詞也無妨，量大擦邊，但方向必須與對話一致；給方向，不要給路線、誘導或代替使用者表達；主模型裸讀原文也能推出的詞即廢詞；刪除會讓主模型誤認為是使用者主觀體驗的詞彙。
- **處理機制**：方向詞經第二次篩選後最終輸出，排除廢詞、路線詞、診斷詞、主觀體驗詞及極性不匹配詞。
- **目前實現**（節點10 為線上真實執行環節）：
  - 方向詞精排環節由 `p1_pipeline.mjs` 真實呼叫（門控預設開啟）。它**不跑六維線性求和**，只作「節點9 得分乘以高斯漸變衰減」（該衰減用於計算位置而非壓分）加斷崖棄權（打破「填滿固定條數」的天花板）加紅線標注。該環節不複用打分框架的六維打分，只保留「衰減加紅線」兩件事。
  - 紅線判定環節由 `p1_pipeline.mjs` 呼叫（門控預設開啟），作**硬剔除**（命中即移出、不進方向詞輸出）：類別一為路線詞（建議、應該、方法、步驟等），類別二為誘導詞（「你需要」「你必須」等），類別三為主觀體驗詞，類別四為診斷詞（障礙、患者及各類疾病名等，其中對單字「症」作了排除「症狀」的處理）。
- **關鍵參數**：輸出條數（契約固定長度）、斷崖比例與斷崖下限、四類紅線的正規表示式種子（為結構常量而非數值魔法數字）。
- **已知問題**：節點10 內部對紅線僅作軟降權與標注，硬剔除在管線層的紅線判定環節執行；節點10 **不奪權**——以節點9 的多對一投票次序為主，節點10 只作降權、衰減與紅線處理。該節點已刪除舊版中的品質門連乘（其為死操作且會造成白盒觀測失真）。

### 2.3.13 貫穿機制之一：熱插拔自學習

- **設計原則**：熱插拔機制中，一個大型詞庫等同於一個額外的發散軸；迭代修正即熱插拔，既非溫度也非衰減；像打字一樣，經常出現或相近的內容可被記錄；由系統依據對話自行構建詞庫才是最優。
- **處理機制**：系統採用三層詞庫——內置固定層、可插拔適配層、使用者自學習層。一個大型詞庫等於節點3 的一個額外發散軸（六軸擴展為七軸或更多）。「打字機制」即自學習：如同輸入法詞庫，高頻或相似詞被記錄後提權。離線批次處理產出新詞庫後熱載入（週期性輪詢監控檔案修改時間，一旦變更即清快取、不重啟即生效），而非實時改參數。
- **目前實現**：管線模組中設有熱重載檢查（週期性節流檢查詞庫檔案修改時間）。以非同步方式寫入自學習盤：累積各軸統計與詞頻統計至使用者詞庫；轉接器側寫入詞頻統計。
- **關鍵參數**：熱重載輪詢週期為一固定值。
- **已知問題**：讀寫端已實裝（詞頻統計與升權可執行）；但離線批次處理觸發、自學習詞自動升庫、共現統計尚未實裝，目前只能手動編輯設定檔觸發熱插拔。此外，詞庫改動須在激活術語表與轉接索引兩處同步，否則新詞無法命中（鐵律）。需注意一處同名混淆：前端的「打字機串流渲染」與 P1 的「打字機制」（自學習）同名但無關。

### 2.3.14 貫穿機制之二：白盒可觀測

- **設計原則**：以單點斷點查看真實線路、不跑全量，此為最高原則；禁止使用評分工具，由系統自身查看實際輸出。
- **處理機制**：每個節點經過後可觀測到——輸入是什麼、做了什麼、輸出是什麼、為何輸出此而非彼。可在任一節點設斷點查看完整中間狀態。
- **目前實現**：模組 `p1_whitebox.mjs` 提供追蹤職能，在各節點入口與出口埋設上述四問，預設常駐全開。以節點6 為例，其追蹤段將輸入、處理、原因三段全部埋點。
- **關鍵參數**：白盒開關預設全開。
- **已知問題**：無。這是設計者最高原則的落地，不可關閉。

> 本節所述為系統的**歷史架構版本**，其結構、節點與資料流對理解目前設計的由來有價值，但**行號錨點與檔案已隨架構遷移而失效**，不代表現行實現。讀者應關注其結構與設計意圖，而非具體細節。

### 2.4.1 仿生三層架構（早期版本）

系統早期以仿生學作比，將整體分為三層：P1 為「眼睛」（掃描輸入輪廓、給出方向詞），主模型為「大腦」（看方向、決策、寫回覆），協作分身為「手」（探索、搜尋、驗證）。設計者將 P1 定位為視覺系統：給主模型一張已標好路線的地圖，而不是讓它從白紙開始。

```
P1 = 眼睛（掃描輪廓，給方向詞）
  輸入：使用者對話 + 對話歷史 + 記憶
  處理：三段式流程（收攏 → 發散 → 收攏）
  輸出：方向詞 XML（認知術語/方向詞/召回記憶/語篇/情緒/情境/提示）
        │ 方向詞注入（給已標好路線的地圖）
        ▼
主模型 = 大腦（看方向，決策，寫回覆）
  接收方向詞 → 據方向決策與組織回覆 → 跨學科類比擴展
        │ 派任務
        ▼
分身 = 手（探索/搜尋/驗證）
  程式碼調研 · 聯網與歷史召回 · 實驗驗證
```

### 2.4.2 三段式流程（早期版本）

早期架構採用三段式流程：收攏一（整合與坐標累積）、發散（聯想加向量發散，含多機制並行：情節、具身、隱喻、敘事、對立、類比）、收攏二（轉接器投票）。該版本的收攏二採用多因子投票（逐詞查表主導），是後來萬金油現象的根源。目前架構已將收攏二重寫為加性打分，範式由「逐詞查表主導」切換為「空間搜尋主導」（見 2.4.5）。三段式結構本身有效，具體行號已失效。

### 2.4.3 五固定軸加衰減（早期版本）

早期採用五個固定軸（不含認知學）：心理學、資訊學、社會學、邏輯學、語言學。目前六軸定型已加入認知學。在早期的部分模式中，認知學是「激活軸」而非「固定軸」，這構成一處歷史表述張力——目前六軸定型含認知學，而歷史五固定軸版不含。衰減公式為按軸距離指數衰減，配合分檔係數，遵循「不硬刪、不影響主力」的軟隔離原則。

### 2.4.4 點線面體架構（早期版本）

早期以「點線面體」刻畫空間結構：點為單一激活術語或原子概念，線為軸向連接與關係鏈，面為多軸交叉平面，體為全架構立體與跨學科同構體。資料由點連成線、線織成面、面構成體。圖中標注的轉接索引詞條數為早期快照值，目前實測值另計。

### 2.4.5 三紀元演進（結構有效，細節已失效）

系統程式碼體經歷了三個紀元的演進，是理解「為何目前是節點流水線」的歷史底座：

| 紀元 | 名稱 | 狀態 | 時間 |
|---|---|---|---|
| 第一紀元 | 單體架構 | 已退役 | 2026年4月下旬至5月下旬 |
| 第二紀元 | 三檔案架構 | 已退役 | 2026年5月下旬定型 |
| 第三紀元 | 節點流水線（目前） | 目前生產 | 2026年5月下旬起 |

- **第一紀元為何被放棄**：其一，體積失控（單檔案一度達四十餘萬位元組、近八千行）；其二，難以維護（連續多版診斷出同批頑疾卻改不動，單體耦合改一處易崩全域）；其三，**範式被推翻**——由逐詞查表主導（萬金油率約七成）切換為空間搜尋主導（萬金油率約百分之四）。
- **第二紀元為何被放棄**：其仍為檔案級線性呼叫，無法實現節點級的熱插拔、白盒埋點與線路切換。第三紀元以流水線編排取代線性呼叫，方才支援可切換的三線路。第二紀元到第三紀元並非推翻，而是重組加改名（轉接器模組由舊的發散模組直接改名延續）。
- **第三紀元仍在演化**：一處代表性演化是子方向空間的「去坍縮」改造——子方向空間退回為範圍門，打分交由打分框架與詞向量承擔。設計者的裁定為：「打分是打分框架與詞向量的職責，不是子方向空間的職責。」

**範式切換的量化證據**：

| 範式 | 主導機制 | 萬金油率 |
|---|---|---|
| 舊範式 | 逐詞查表倒排 | 約 74% |
| 新範式 | 空間搜尋（詞向量質心/範圍）主導 | 約 4% |

打分框架的因子數在演進過程中反覆增刪（早期由六因子逐步擴至十餘因子，一度達十七因子，後經一次重寫以約二百九十行的加性框架取代舊的約三千行連乘框架，此後又有若干因子加重排序融合方案）。因子數在不同歷史片段間高度不一致，此處不作鎖定，僅記錄其演化趨勢。

### 2.4.6 評分軌跡（歷史里程碑）

系統在開發過程中以綜合評分作為迭代目標，其里程碑如下（供理解演算法演進之用）：

| 版本階段 | 綜合評分 | 改動核心 |
|---|---|---|
| 早期 | 約 2.01 | 雙信道融合 |
| 詞庫化後 | 約 2.96 | 五份詞庫約六千七百詞 |
| 雙輪擴詞後 | 約 3.69 | 擴詞 |
| 融合後 | 約 3.62 | 模式融合 |
| 軸均值演算法 | 約 4.05 | 軸均值演算法（首次突破 4.0） |
| 路由加萬金油治理 | 約 4.04 | 大中小路由加收攏二萬金油治理 |

綜合評分自早期到後期約翻倍。萬金油次數在此過程中大幅下降（約減少八成）。一條關鍵教訓是：設計者指出「改公式都是治標」——多輪改公式實驗證明，僅調整打分公式只能把一類萬金油轉變為另一類，根本解法是**依輸入規模的大中小三級路由**（由輸入觸發局部精排，而非全域打分）。

## 2.5 小結

本章給出了 P1 系統的完整架構與處理流程。系統的處理骨架是一條五步標準鏈：六軸與機制並行獨立執行、匯入一個池、在池內作內容分佈投票打分、找出接近的軸與點位、沿溫度擴散出邊界，最終由資訊詞作為池選出方向詞。這條鏈的若干設計判斷是全系統的基石：機制並行而非軸並行；池是空間相加而非線性相乘；打分是加性投票而非多因子連乘；溫度畫圓以「太近太遠皆需篩除」確定發散邊界；軸衰減只降權不刪除以實現軟隔離。

在實現層面，系統由一條節點流水線編排十餘個處理節點，配以橫切全程的熱插拔自學習與白盒可觀測兩個機制，並預留了 LLM 最佳化器可插入不同位置的三條線路方案。本章對各節點作了逐一的規格化描述，並如實標注了目前實現與設計意圖之間的差距——最值得注意的是，打分框架目前為未接入主鏈的孤兒實現，資訊詞的實際打分由空間投票與軸衰減承擔；「太近」內邊界因閾值缺乏依據而被移除，其職能部分由後段甜蜜區衰減承接；三條線路中的 LLM 環節尚未合入主鏈。

需再次強調本章開篇的系統狀態：本章所述完整自驅動發散鏈為組件庫內已實現、待接回的演算法，目前線上出詞由 AI 預設集檢索承擔。系統的歷史演進（附節 2.4）顯示，目前的節點流水線架構是在單體架構體積失控、範式由逐詞查表切換為空間搜尋之後形成的，這一範式切換將萬金油率由約七成降至約百分之四，是理解現行架構的關鍵歷史脈絡。
