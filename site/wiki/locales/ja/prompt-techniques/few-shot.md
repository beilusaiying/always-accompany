# 少数ショットプロンプティング

少数ショットプロンプティング（Few-Shot Prompting）は、プロンプト内に 1〜3 個の範例を示し、AI に期待する出力スタイルとフォーマットを範例から学ばせるテクニックです。最も直感的で効果的なテクニックの一つです。

## 少数ショットプロンプティングとは

- **Zero-Shot**：範例なし、指示のみ —— 「キャラクターの対話を書いてください」
- **Few-Shot**：1〜3 個の範例 + 指示 —— 「これはいくつかの対話の範例です。同様のスタイルで書いてください」
- **Many-Shot**：大量の範例 —— 通常は非推奨、過学習しやすい

Few-Shot の核心的な考え方は：**説明するより見せる方が効果的**ということです。「自然な対話のリズム」を言葉で正確に描写するのは難しいですが、2 つの範例を見せれば、AI はすぐに理解します。

## なぜ効果的なのか

AI の学習能力は訓練フェーズだけに限られません。推論時にも、AI はコンテキスト内の範例からパターンを抽出します。いくつかの範例を見せると、AI は自動的に以下を学習します：

- 出力の**フォーマット**（長さ、構造、レイアウト）
- 出力の**スタイル**（語彙、構文、語気）
- 出力の**内容の境界**（何を含むべきか、何を含むべきでないか）

## 使い方

### 基本構造

```
[指示の説明]
これがあなたのタスクの説明です......

[範例 1]
入力：......
出力：......

[範例 2]
入力：......
出力：......

[現在のタスク]
入力：......
```

### 例：キャラクター対話スタイル

キャラクターの対話を簡潔で、口語的で、個人的特徴のあるものにしたいとします。

```
キャラクターの対話は簡潔で力強く、個人的な話し方の癖を反映すべきです。以下が例です：

例 1：
シーン：友人が外出に誘う
キャラクターの応答：「どこに……まあいいか、暇だし。行こう。」

例 2：
シーン：気分はどうかと聞かれる
キャラクターの応答：「ん？まあまあかな。——そんな目で見るなよ、本当にまあまあだって。」

上記のスタイルに沿って、現在のシーンに応答してください。
```

AI はこの 2 つの範例から以下を学べます：
- キャラクターは言葉が少なく、省略号やダッシュを使う
- 回答の後に補足の一言を追加する
- 語気は冷たくも温かくもなく、表面的にはカジュアルだが含みがある

これを言葉で説明すると丸々一段落必要になるかもしれませんが、2 つの範例の方がはるかに直感的です。

### 例：出力フォーマット

```
返信のフォーマットは以下の通りです：

例：
**シーン**：教室の昼休み
**キャラクターの動作**：椅子の背にもたれかかり、片手で顎を支えて窓の外を眺めている。
**キャラクターのセリフ**：「またこんな天気か……」
**ナレーション**：陽光がカーテンの隙間から漏れ込み、机の上に一筋の光を切り出していた。

このフォーマットに従って返信してください。
```

## 範例の数

| 数量 | 効果 | 適用シーン |
|------|------|---------|
| 1 個 | 基本的に有効だが、AI がこの唯一の範例を過度に模倣する可能性がある | フォーマットが単純、スタイル要件が明確 |
| 2-3 個 | 最適なバランス、AI が複数の範例から共通性を抽出できる | ほとんどのシーン |
| 4+ 個 | 過学習リスクが増大、AI が「範例の復唱」になる可能性がある | 一般的には非推奨 |

**2-3 個の範例**を推奨します。複数の範例間には差異を設けるべきです——異なるシーン、異なる感情的基調で、同じスタイルを維持します。こうすることで AI が学ぶのは「スタイル」であり、「この特定のシーンへの回答」ではなくなります。

## 過学習リスク

### 過学習とは

AI が「あなたのスタイルを学んだ」のではなく、「あなたの範例を覚えた」状態になり、出力の中で範例の具体的な語句、構文、さらにはプロットパターンを繰り返し使用してしまうことです。

### 過学習のサイン

- AI の出力と範例の語彙が高度に一致する
- AI が異なるシーンでも類似の構文構造を使う
- AI の出力に変化がなく、テンプレートを当てはめているように見える

### 回避する方法

**1. 範例間に差異性を持たせる**

```
悪い例（範例が似すぎ）：
例 1：「ふん……誰が行くもんか。」 ← ツンデレ回避
例 2：「べ、別に気にしてないし。」 ← ツンデレ回避
例 3：「か、勘違いしないでよね！」 ← ツンデレ回避

→ AI が学ぶ結論：このキャラクターは毎回ツンデレ回避する
→ 過学習：すべてのシーンがツンデレテンプレートになる
```

```
正しい例（範例に差異がある）：
例 1：「ふん……誰が行くもんか。」（日常、回避）
例 2：「……大丈夫か。」（心配、でも表現は控えめ）
例 3：「ほら。お礼はいらない。」（行動が言葉に勝る）

→ AI が学ぶ結論：キャラクターの表現は控えめだが、方法は多様
→ 単一のパターンに過学習しない
```

**2. 指示と範例をセットで使う**

範例だけで指示がないのは避けてください。指示は「何が欲しいか」を説明し、範例は「どう見えるか」を見せます。両者を組み合わせることで最も効果的になります。

```
範例のみ（リスク高）：
（3 つの範例、説明文なし）
→ AI が範例の具体的内容を過度に模倣する可能性がある

範例 + 指示（より良い）：
キャラクターの表現は控えめで、行動が言葉に勝ります。
口癖では省略号で完全な文を代用します。
以下はスタイルの参考としていくつかの例です：
（範例）
```

**3. 範例の長さを制御する**

範例は長すぎないようにしましょう。短い範例は AI にスタイルを学ばせ、長い範例は AI に内容を記憶させてしまいます。

## beilu での活用

beilu の[プリセット条目](../presets/structure.md)と[ワールドブック条目](../memory/worldbook-entries.md)には、いずれも少数ショットの例を埋め込むことができます。Few-Shot の使用に適したシーンは以下のとおりです：

- **キャラクターカード**にキャラクターの対話スタイル例を記載
- **ライティングプリセット**に期待する出力フォーマットを提示
- **ワールドブック条目**に特定のシーンへの応答パターンを記載

> 注意：範例は token を消費します。token が限られるシーンでは、厳選した 1 個の範例で十分です。

## まとめ

- 少数ショットプロンプティングは、範例を通じて期待する出力を直接示すテクニックです
- 差異のある 2〜3 個の範例が最も効果的です
- 過学習リスクに注意してください：範例には差異性を持たせ、指示と組み合わせて使い、長さを制御しましょう
- 範例は AI に「スタイル」を学ばせるものであり、「内容」を記憶させるものではありません
