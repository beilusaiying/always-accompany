# フォーマットと記号の活用

プロンプトのフォーマット——見出しの階層、記号マーク、視覚的な区切り——は、AI のコンテンツに対する解読ウェイトに影響します。適切なフォーマットはポイントを際立たせ、階層を明確にします。過剰なフォーマットは逆効果になります。

## 核心原則：適度さ

フォーマット記号は多いほど良いわけではありません。過多な太字、見出し、区切り線は「飽和攻撃」を形成します——すべてが強調されているとき、何も強調されていないのと同じです。

```
悪い例（飽和攻撃）：
────────────────
# **重要なルール**
## *ライティングスタイル*
### ⚠️ 注意事項
- **必ず** **白描** を使うこと
- **必ず** **テンポ** を維持すること
- **絶対に** ~~比喩~~ を使わないこと
---
## **キャラクター設定**
### ⚡ コア特徴
> ⚠️ **重要**：キャラクターは**必ず** **一貫性** を維持すること

→ 至る所に太字、見出し、記号、区切り線があり、
  AI は何が本当に重要か判別できません。
```

```
正しい例（適度な使用）：
────────────────
# ライティングスタイル
白描を主とし、テンポを明快に保ちます。

# キャラクター設定
キャラクターは異なるシーンでも**コアの性格**の一貫性を保ちますが、
感情や表現方法はシーンに応じて変化を許容します。

→ 「コアの性格」だけが太字にされています。
  この段落で最も重要なコンセプトだからです。
```

## 見出しの階層

### 一級見出しのみを使う

プロンプトでは、`#` 一級見出しのみを使ってモジュールを区切ることをお勧めします。多すぎる階層（`##` `###`）は構造を複雑にし、AI が階層関係を解析するために余分な労力が必要になり、かえって内容そのものへの注意が分散されます。

```
悪い例（階層が多すぎ）：
# ライティングガイド
## スタイル
### ナラティブ
#### テンポ
##### 対話のテンポ
段落は3行以内。

正しい例（フラットな構造）：
# ナラティブのテンポ
段落は3行以内、対話は口語的な短文で。
```

内容を細分する必要がある場合、段落で自然に区切れば十分で、すべての層に見出しを付ける必要はありません。

## 強調マークの使い方

### 引用符と太字

`""` や `**` で**本当に重要な**内容を囲みます。何が本当に重要なのかというと、AI がその語/その文を無視した場合、出力全体の方向が逸れてしまう——そういうものが強調に値します。

```
効果的な強調：
キャラクターの行動は**現在の感情状態**に基づくものでなければならず、
キャラクター設定のデフォルトの性格に基づくものではありません。

→ 「現在の感情状態」がこの文のキーとなる区別点です。
   強調しないと、AI はデフォルトでキャラクター設定の性格で
   行動を駆動する可能性があります。
```

```
効果のない強調：
**キャラクター**の**行動**は**必ず**現在の**感情状態**に**基づく**こと。

→ すべてが太字 = 何も太字でないのと同じ。
```

### 使用ガイドライン

| 記号 | 用途 | 頻度 |
|------|------|------|
| `#` | モジュールの区切り | 各テーマモジュールに1つ |
| `**太字**` | 重要コンセプトの強調 | 1段落で最大1〜2箇所 |
| `""引用符` | 専門用語や特定の表現 | 正確に引用する必要がある場合 |
| `---` 区切り線 | 大モジュール間の視覚的区切り | 時折使用 |
| `> 引用ブロック` | 補足説明や注意事項 | 時折使用 |

## よくあるフォーマットの問題

### リストの乱用

すべてのコンテンツをリスト化する必要はありません。コンテンツ間に論理的な関係（順序、因果）がある場合、自然言語の段落の方が適切です。

```
不適切なリスト：
- まずキャラクターの現在の感情を分析する
- 次にキャラクターがどう反応するか考える
- 最後にキャラクターの動作と対話を書く

より良い書き方：
キャラクターの現在の感情から出発し、キャラクターの反応を推測し、
動作と対話で表現します。
```

リストは並列的で独立した項目に適しています。例えば：
- 複数のキャラクターの特徴をそれぞれ列挙する
- 互いに関連のない複数の注意事項
- チェックリスト式のフォーマット要件

### 過度なネスト

```
悪い例：
- キャラクターの特徴
  - 性格
    - コアの性格
      - 沈着
    - サブの性格
      - 時折ユーモラス
  - 話し方
    - 口癖
      - 「まあ」
    - 構文
      - 短文が主

正しい例：
キャラクターの性格は沈着で、時折ユーモアを見せます。
話す際に「まあ」を口癖として使い、短文が主です。
```

深いネストのリストはプロンプトにおいてほとんど正の効果がありません。AI は構造がより「完全」だからといってパフォーマンスが上がるわけではありません——AI が必要とするのは明確な情報であり、精緻なアウトラインではありません。

## まとめ

- **少ないことは多いこと**：記号とフォーマットは本当に強調が必要な場合にのみ使用します
- **フラットは階層に勝る**：一級見出しでモジュールを分け、段落でディテールを分け、層層のネストは不要です
- **強調は正確に**：一段落で強調するのは最も重要な 1〜2 個のコンセプトだけです
- **自然言語優先**：論理的な関係のあるコンテンツは段落で表現し、並列的で独立した項目にのみリストを使います
