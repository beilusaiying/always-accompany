# ファイル操作 (beilu-files)

beilu-files は AI がコンピュータ上でファイルの読み書きやコマンド実行を行えるようにします。[IDE モード](beilu:mode/files)と[ワークモード](beilu:mode/work)のコアツールプラグインであり、AI はこれを通じてディレクトリの閲覧、コードの読み取り、ファイルの書き込み、ターミナルコマンドの実行を行います。

すべてのファイル操作はサンドボックス内で実行され、多層セキュリティメカニズムで保護されています。

## サポートされる操作

| 操作タイプ | 説明 | AI タグ |
|---------|------|--------|
| read | ファイル内容の読み取り | `<file_op>` / `<tool_call>` |
| write | ファイルの書き込み/上書き | `<file_op>` / `<tool_call>` |
| create | 新規ファイルの作成 | `<file_op>` / `<tool_call>` |
| delete | ファイルの削除 | `<file_op>` / `<tool_call>` |
| list | ディレクトリ内容の一覧表示 | `<file_op>` / `<tool_call>` |
| move | ファイルの移動/名前変更 | `<file_op>` / `<tool_call>` |
| exec | ターミナルコマンドの実行 | `<file_op>` / `<tool_call>` |

## セキュリティアーキテクチャ

beilu-files は 4 層の多層防御を採用しており、すべてのファイル操作（ソースを問わず）は以下を通過する必要があります：

### 第 1 層：パス正規化（resolveCanonicalOpPath）

相対パスをワークスペースのルートディレクトリに固定し、`..`（親ディレクトリ参照）を処理して、パス結合によるサンドボックス脱出を防止します。

### 第 2 層：システムパスブロック（checkSystemDriveBlock）

システムの機密パス、機密ファイル拡張子、キーワードへのアクセスをブロックします。

### 第 3 層：ワークスペースサンドボックス

すべての操作はワークスペースルートディレクトリ（workspaceRoot）内で実行する必要があります。ワークスペース境界を超えるパスは一律拒否されます。

### 第 4 層：ホワイトリスト/ブラックリスト

精密なパス許可/禁止リストです。プレフィックス + 境界セパレータ比較を使用します（`/a/b` が誤って `/a/bc` をブロックすることを防止）。

### 3 つのパスが共用

どの入口からの操作であっても、同一のセキュリティゲートを通過する必要があります：

- **AI パス**：AI 返信中の `<file_op>` / `<tool_call>` タグ
- **フロントエンドパス**：ユーザーが UI から直接ファイルを操作
- **承認パス**：ユーザーが保留中の操作を承認

## 操作フロー

### AI が発起する操作

```
AI の返信にファイル操作タグが含まれる
    ↓
ReplyHandler が操作を解析
    ↓
Bot 権限ゲート（N42、Bot ソースのアクセスレベルをチェック）
    ↓
always ルールチェック（N46）
    ↓
権限スイッチチェック
    ↓
validateOpSecurity（4 層多層防御セキュリティ検証）
    ↓
自動承認 / 承認待ちキューに入る
    ↓
executeFileOperation（ディスク操作）
    ↓
結果が pendingOpResults キューに入る
    ↓
次のターンの GetPrompt で結果をインジェクション、AI が実行結果を見て作業を継続
```

### 承認メカニズム

一部の操作（書き込み、削除、コマンド実行など）はデフォルトでユーザー承認が必要です：

- **自動承認**：読み取り操作は通常自動的に通過
- **承認待ちキュー**：書き込み/削除/実行はキューに入り、ユーザーがフロントエンドで確認するのを待つ
- **一括承認**：保留中のすべての操作をワンクリックで承認可能

## コマンド実行（exec）

exec タイプの操作は AI がターミナルコマンドを実行できるようにします。セキュリティリスクが高いため、追加のゲート制御で保護されています：

- **deployGatedAllow ゲート**：ローカルデプロイ（local モード）ではデフォルトで許可。サーバーデプロイ（server モード）ではデフォルトでオフ、インスタンス owner がセキュリティセンターで明示的に有効化する必要があります
- 設定パネルで `allowExec` スイッチを制御可能
- 環境変数 `BEILU_FILE_EXEC=on` で強制有効化可能

## ファイル履歴

beilu-files はファイル操作履歴を記録し、以前のバージョンへのロールバックをサポートします。書き込み操作前に古いバージョンを自動保存するため、問題が発生した場合に復元できます。

## GitHub 統合

beilu-files には GitHub 統合モジュールが含まれており、GitHub API を通じたリポジトリ操作をサポートしています。

## ワークスペース設定

### workspaceRoot

ワークスペースのルートディレクトリは beilu-files のサンドボックス境界です。すべてのファイル操作はこのディレクトリ内で行う必要があります。プラグイン設定で指定できます。

### workspaceRoots

マルチワークスペースのサポートです。複数のワークスペースルートディレクトリを設定でき、AI はこれらのディレクトリ間を切り替えできます。

## マルチユーザー分離

マルチユーザー環境では、beilu-files は AsyncLocalStorage を使用してユーザーごとの分離を実現します。ワークスペース設定などのフィールドはユーザーごとに独立して保存され、異なるユーザー間で干渉しません。
