# 注入系統 (INJ)

## 查看和編輯 INJ 規則

INJ 規則決定什麼資訊、以什麼身分、在什麼位置注入 AI 的上下文。系統內建多條 INJ 規則，涵蓋表格說明、檔案層提示詞、Bot 平台提示詞、聯網教學、歷史標籤等。核心的幾條：

| INJ | 名稱 | 功能 |
|-----|------|------|
| **INJ-1-chat** | chat 模式表格規則 | 告訴 AI chat 模式下 #0-#9 各表的用途和寫入格式 |
| **INJ-1-write-code** | code 模式表格規則 | 告訴 AI code 模式下 C0-C5 各表的用途和寫入格式 |
| **INJ-1-work** | work 模式表格規則 | 告訴 AI work 模式下 W0-W4 各表的用途和寫入格式 |
| **INJ-2** | 檔案層 AI 提示詞 | 告訴 AI 如何操作專案檔案（連接 IDE 時切換為 INJ-2-code 變體） |
| **INJ-3** | Bot 平台提示詞 | 來自 Bot 平台（如 Telegram/Discord）的提示詞 |

除上述外還有 INJ-4（全智能能力調度）、INJ-5（聯網搜尋教學）、聊天歷史標籤等內建條目。INJ-1 的三個變體根據目前工作模式互斥生效——只有對應的那一條門控比對。

每條 INJ 規則有三個關鍵設定：

### autoMode（門控模式）

決定 INJ 在什麼條件下生效：

| autoMode | 含義 |
|----------|------|
| **chat** | 僅 chat 模式下生效（chat 模式同時接受 airp 別名域） |
| **code** | 僅 code 模式下生效 |
| **work** | 僅 work 模式下生效 |
| **bot** | 僅 Bot 平台模式下生效 |
| **always** / **all** | 始終生效（全模式） |
| **manual** | 手動控制，開啟即生效 |
| **file** | 由檔案層設定決定（進入 IDE/檔案模式時生效） |

目前工作模式接受的注入域 = 無條件域（always / all / manual）+ 檔案門控域（file，僅檔案模式）+ 目前模式自己的域及其別名。一條 INJ 的 autoMode 落在這個集合裡才生效。

### depth（注入深度）

控制 INJ 注入到上下文的位置：

| depth 值 | 含義 |
|----------|------|
| **999** | 系統提示級——位於上下文最前端，優先級最高 |
| **0** | 最近訊息之後——位於上下文最末端 |
| **N** | 第 N 輪對話之前——插入到聊天歷史的指定位置 |

depth 越大，越靠近系統提示（上下文開頭），AI 在處理時越早看到。

### role（角色身分）

每條 INJ 注入的訊息以什麼身分出現：

| role | 含義 |
|------|------|
| **system** | 系統訊息，AI 視為系統級指令 |
| **user** | 使用者訊息，AI 視為使用者說的話 |
| **assistant** | 助手訊息，AI 視為自己說過的話 |

role 影響 AI 對該資訊的處理方式。system 級指令通常被 AI 賦予最高優先級。

## INJ 做什麼

AI 的上下文不是一個簡單的「對話記錄」。一個完整的上下文包含系統提示詞、記憶表格、世界書條目、模式說明、檔案層提示詞、Bot 平台提示詞和對話歷史——這些內容需要按特定順序和位置組裝。INJ 系統就是這個組裝的規則集。

### 運行鏈

```
使用者發送訊息
    ↓
系統開始建構上下文
    ↓
遍歷所有 INJ 規則：
  1. 檢查 autoMode → 目前模式/平台是否比對
  2. 檢查互斥規則 → 有衝突的 INJ 只保留一條
  3. 取得 INJ 的 content（可能包含巨集替換）
    ↓
對 content 執行巨集替換（~30 種 {{macro}}）
    ↓
按 depth 排序，將各 INJ 內容放入上下文的對應位置
    ↓
與角色設定、對話歷史、世界書條目合併
    ↓
最終上下文發送給 AI
```

### 巨集替換

INJ 的 content 中可以使用 `{{macro}}` 語法，在注入時被替換為實際值。系統提供約 30 種巨集，常見的包括：

- `{{user}}`：目前使用者名稱
- `{{char}}`：目前角色名稱
- `{{time}}`：目前時間
- `{{date}}`：目前日期

巨集替換發生在注入時（非編輯時），確保值始終是最新的。

### 互斥規則

某些 INJ 之間存在互斥關係：

- **INJ-1 系列**：INJ-1-chat / INJ-1-write-code / INJ-1-work 三者互斥，只有目前模式對應的那條生效
- **INJ-2 系列**：INJ-2 與 INJ-2-code 是互斥的變體對——當 IDE 連接時使用 INJ-2-code 變體，否則使用 INJ-2

互斥保證同一類資訊不會重複注入。
