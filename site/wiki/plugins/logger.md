# 日志插件：保留最近的错误和警告，方便判断“哪里真的失败了”

beilu-logger 面向排错，而不是长期审计。它在服务器进程内收集最近的 `console.error` 和 `console.warn`，让设置页或诊断工具可以查看真实错误，而不是只看到“功能没反应”。

## 当前行为

- 插件加载时开始监听 error/warn；
- 原始终端输出仍然保留；
- 内存环形缓冲区最多保存最近 500 条；
- 查询默认最多返回 200 条，可按时间和级别过滤；
- 可以从面板或接口清空；
- 插件卸载后停止写入自己的缓冲区，不拆掉其他日志模块的监听链。

## 完整链路

```text
插件 / 服务产生 warning 或 error
  → logger 在不阻断原输出的情况下复制一份
  → 内存环形缓冲区
  → 设置页或日志 API 按时间 / 等级读取
  → 用户定位具体模块与错误文本
```

## 它不是什么

- 不是持久化日志数据库；进程重启后内存缓冲会消失；
- 不收集所有普通 `console.log`；
- 不证明某项功能已经通过测试；它只提供运行时发生过的错误和警告；
- 清空缓冲不会修复错误，也不会清理终端或其他诊断系统的记录。

## 隐私与分享

错误堆栈可能包含本地路径、请求信息、插件配置片段或外部服务错误。把日志贴到 Issue 前先检查并删除：

- 用户名和本地绝对路径；
- API key、Cookie、token；
- 私有对话、文件名和服务地址；
- 可以识别直播间或工作区的信息。

## 推荐排错顺序

1. 复现一次问题；
2. 记下发生时间；
3. 先筛 `error`，再看相邻 `warn`；
4. 将第一条根因错误与后续连锁错误分开；
5. 保存必要片段后再清空缓冲，验证问题是否重复出现。
