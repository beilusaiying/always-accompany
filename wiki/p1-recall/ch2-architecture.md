第2章 系统架构与处理流程

## 2. 引言

本章描述 P1 自驱动发散召回系统的整体架构与处理流程。P1 是一个联想发散引擎，其当前生产线路（线路1）不依赖大语言模型（LLM）在线推理；设计中另含 LLM 优化器可插入不同位置的三线路方案与规划中的小模型前置定位层（见 2.2.2）。其设计目标是在对话进行时，为主对话模型提供一组"方向词"——即主模型仅凭裸读原文难以自发想到的关联方向。设计者将 P1 的定位概括为"外置的发散思维链"：它并不替主模型作判断，也不生成回复内容，而是先行扫描输入、标注关联方向，把一组预先整理的方向线索提供给主模型，降低其从零开始搜索方向的负担。

需要在开篇明确一项系统状态。本章所描述的完整"召回—发散"处理链，是系统组件库内部已经实现、可逐行阅读的算法，但在当前线上（live）运行路径中并未接入主链——它是储备能力，当前默认休眠（各运行模式声明 `selfDriven: false`）。根据设计记录（2026年7月），系统的在线检索职能由"AI P1"承担（下称 AI 预设检索）：每条消息由一个检索 AI（P1 预设）主观判定要调哪些记忆。本章所述的自驱动发散管线处于"组件态"，即算法已落地、待接回主链。为避免读者混淆，本章在描述各处理环节时，会区分"设计意图与算法实现"和"当前线上是否启用"两个层面，凡未接入线上主链者均如实标注。

本章的组织如下：2.1 给出系统的标准处理链五步总纲，作为理解全流程的骨架；2.2 给出整体架构，包括十二节点处理图、三条线路方案与 U 型注入机制，并配以正文解说；2.3 对各处理节点逐一作规格化描述，说明其输入、处理、输出与关键参数；2.4 作为附节介绍架构的历史演进版本（标明为历史版本，非现行实现）；2.5 为本章小结。

在术语上，本章首次出现的自造术语均先给出定义。为便于外部读者建立整体图景，此处先约定几个贯穿全章的核心概念：

- **轴（axis）**：一个学科视角。系统以六个学科轴作为发散的输入端，每个轴从其学科角度对输入词各自独立地产生一组关联信息。
- **面与线**：设计者用"面"与"线"区分一个轴的产出形态。一个轴对一个词若只给出单一分数（如一个标量性质），称为吐"线"；若给出一组丰富的关联信息词，称为吐"面"。系统要求各轴吐"面"而非吐"线"。
- **池（pool）与空间（space）**：各轴产出的候选词汇合并进入一个共享集合，称为"池"；系统在词向量空间中对池内内容作分布式聚合与定位，故亦称"空间"。设计者强调池的语义是"空间相加"而非"线性相乘"。
- **温度（temperature）**：控制发散范围的参数。设计者以"画圆"作比喻——从锚点向周围扩散出一个圆，圆过小则只得同义冗余词，圆过大则纳入无关噪声，需在两者之间筛选出合适区间。
- **信息词与方向词**：系统的中间产物是"信息词"（描述输入相关内容的词），最终产物是"方向词"（供主模型参考的关联方向）。二者经由一次"信息词作为池再选出方向词"的转换。

## 2.1 标准处理链五步总纲

系统的核心处理流程可归纳为一条连续的认知链，由五个步骤构成：六轴与各机制并行、各自独立运行，结果汇入同一候选池，在池内打分，定位每个候选所接近的轴与点位，最后沿温度扩散。这五步并非五个孤立算法，而是"各机制各自并行运行 → 汇入一个池 → 在池内打分定位 → 沿温度向边界扩散"的一条连贯链路。以下逐步展开。

### 2.1.1 第一步：六轴与机制并行、独立运行

第一步的核心原则是**机制并行，而非轴并行**。系统区分两类并行对象：一是六个学科轴各自独立发散（轴并行），二是若干发散机制（如情节、隐喻、类比等）各自独立运行（机制并行）。设计者反复强调 P1 采用的是机制并行，且发散应"沿主轴延伸，而非独立平铺"，唯有沿主轴延伸方能形成真正的发散与联系，而非彼此无关的词汇堆叠。

六个学科轴构成系统的**输入端**，各自并行发散，分别是：心理学、信息学、社会学、逻辑学、语言学、认知学。其中"六轴含认知学"为当前定型形态；系统早期曾采用不含认知学的五个固定轴，认知学系后期加入，这一演化过程在 2.4 历史版本中说明。设计者将六轴定性为"输入端"，与产出端的定位坐标（见第三步与第四步）明确区分。

各轴发散遵循"先学科后分布"的次序，即先由各学科视角产出候选，再在后续步骤中作空间分布。并行的目的在于**防遗漏**：各轴走完各自路径后再合并观察关联性，而非在过程中相互裁剪，从而避免过早丢弃潜在有价值的关联。

一条贯穿本步的铁律是"吐面不吐线"：每个学科轴对每个词应输出一组关联信息（一个"面"），而非一个模糊的性质分数（一条"线"）。即设计上要求每个学科轴对每个词提供一组信息，而非单一数值。相应地，每个学科轴配有其专属的知识资源。

综上，第一步可归纳为如下流水线：六轴各自独立运行，心理、信息、社会、逻辑、语言、认知各产出其候选词面；随后合并入一个池；池内数据对各轴的靠拢程度确定主方向（主轴）；再从主方向向其他轴发散（受跳数约束，沿主轴延伸而非平铺）；最后施加轴衰减（主轴权重最高、次轴与远轴依次降权，只降权不删除）。

### 2.1.2 第二步：放入池（合并到一个池）

第二步是将各轴产出汇入一个共享池。此处的关键设计判断是：**池的本质是空间叠加，不是相乘**。设计者的完整表述为："汇总到一个池，不是相乘，而是空间，进行内容分布投票……信息词再作为池与空间选出方向词。"系统在词向量空间中作"空间相加"，通过内容的分布式投票确定方向，而非对各路径分数作线性相乘，也非硬匹配。

进池的语义是**信息叠加**。当多个词同时进入池（例如"喜欢"与"笨蛋"的组合），系统将其内容相加、在空间中定位其合成位置，而非分别处理后取乘积。

进池遵循一条铁律：**禁止逐词发散后相加**。设计者明确反对"一个词就发散出一堆、再把多个词各自发散的结果相加"的做法，认为这样既不准确，又是"万金油"现象（即产出大量对任何输入都通用、缺乏针对性的词）的根源。正确的做法是"信息池发散"而非逐词发散——先形成池，再从池整体发散。

为刻画池的空间语义，设计者引入"点、线、面、体"四层结构：点为词汇，线为方向（词汇的种类），面为类型（用户对话的实际需求），体为多维空间。对应到系统结构，体是全部轴构成的总空间，面是六个学科轴（每轴吐一组信息词），线是更细的子方向坐标，点是具体术语。

### 2.1.3 第三步：打分（内容分布投票）

第三步在池内对候选打分。基础原则是**空间内容分布投票**：候选在空间中的分布决定其得分，而非逐词查表得分。投票方向为**多对一**——多个信息词共同指向一个方向，而非一个信息词指向多个方向词。

关于"取均值"存在一处需要辨析的设计张力。系统一方面有"不取均值以保留分布张力"的原则，另一方面又有"某些轴分数过高时应取均值"的表述。这两条并不冲突，因其作用对象不同（该辨析已于设计记录中裁定）：

- **不取均值**，作用于**词间票聚合**：当多条路径命中同一个词时，票数求和而非求均值，以保留分布张力。这是词级机制层的红线。
- **应取均值**，作用于**轴间尺度校准**：不同学科轴的分数量纲天然不同，某些"大轴"分数偏高会垄断排名，故对轴间分数作均值归一。这是轴级尺度校准。

二者对象不同、互不矛盾，已共存于系统设计中。在打分聚合方式上，系统采用**加性投票**而非乘法。早期版本曾采用多因子连乘的评分公式，被认定为万金油现象的根源，后重写为加性聚合。当前打分环节的核心形式为"加性投票，得票等于权重乘以逆距离权重，不作连乘、不除以路径数"，其算法细节见 2.3 相应节点。

### 2.1.4 第四步：找接近的轴与点位（近轴归属与点位定位）

第四步在池内完成方向定位，包含两个动作：确定接近的轴，以及在细粒度空间中定位点位。

**近轴归属**指：将池内信息投射到细分子方向空间后，找出与之最接近的若干个（约三到五个）轴，再对这些轴施加衰减、发散，并将信息词转换为方向词后输出。设计者强调细分子方向空间"原本是激活的、并非全部启用"，即只激活与当前输入相关的子方向，而非遍历全部。

确定主方向的依据是**靠拢度**——池内数据对各轴的靠拢程度即主方向。例如输入"外婆去世"时，池内心理学相关候选多且强，主方向即为心理学；输入涉及技术编程内容时，池内信息学候选占优，主方向即为信息学。设计者并未给出靠拢度的具体数学公式，系统实现上以"投票后统计各轴累计票数确定主轴"近似之。

系统区分两组轴：六个学科轴负责**确定发散点**（输入端），细分子方向空间负责**大致定位、扩充与产出**（产出端）。二者不是同一事物，细分子方向也不是六个学科轴的下级子分类。设计者指出细分子方向空间的设计尚不完善，而六个学科轴的划分是成立的。

**点位定位**采用多维坐标加锚点密度的方式：以多维坐标定位，再加温度向左右扩散。其类比为：先通过多词组合的空间投票确定锚点位置（类似症候群的组合模式识别），再从锚点用温度向周围作圆形扩散。

### 2.1.5 第五步：沿温度扩散

第五步从锚点沿温度向外扩散，得到最终的发散边界。其核心设计为：温度定义了一个以锚点为圆心的圆，候选向周围扩散，过近与过远均不可取，须经筛选。具体拆解为：

- **"太近"** 是圆的内边界，用于筛除废词与同义冗余（离锚点过近的词往往是主模型自己也能想到的，缺乏发散价值）。
- **"太远"** 是圆的外边界，用于排除无关噪声。
- **中间区间** 为需要保留的**最优语义距离区间**（下文简称最优距离区间）。

"太近"的判据由"废词"概念支撑：主模型裸读原文也能推出的词即为废词，而 P1 的价值恰在于提供主模型自己想不到的方向。

设计者明确区分了三个易混概念：**衰减**指定向发散、不遍历全库（靶向而非全做）；**温度**指子方向空间收缩后的定向扩散范围；**热插拔机制**指迭代修正的自学习，既非温度也非衰减。三者不可混为一谈。

关于**衰减**，设计原则是"涉及其他轴时再加，但需衰减，不影响主力"。系统实现上采用分档衰减：主轴权重最高，次轴与远轴依次降低，但远轴权重不归零（只降权不删除），以实现"软隔离"。

关于**扩散的停止条件**，系统采用跳数约束（约束在数跳之内）配合轴衰减。此外有一条实验得出的距离红线：联想发散的距离必须保持在中远程区间，最近距离（同义扩散）为禁用项——实验表明，将发散退化为同义扩散会导致召回质量大幅下降（在一项基准测试中下降约七成），故该项被锁定为禁用。

需要指出，"太近"内边界的一个具体实现环节曾因其阈值缺乏依据而被移除（详见 2.3 相应节点的已知问题），当前"太近"的部分职能由后段节点的最优距离区间衰减逻辑承接，并非完全断链。

### 2.1.6 五步与节点的对应关系

标准处理链的五步与 2.3 所述的具体处理节点存在如下对应关系：

| 标准链步骤 | 对应节点 | 核心设计原则 |
|---|---|---|
| ① 六轴与机制并行独立运行 | 节点3（六轴吐面） | 先学科后分布；六轴为输入端各自并行发散 |
| ② 放入池 | 节点6 第一次调用（信息池） | 汇总到一个池，不是相乘，而是空间 |
| ③ 打分 | 节点6 空间投票 + 节点8 打分框架 | 内容分布投票；轴间尺度校准取均值 |
| ④ 找接近的轴与点位 | 节点4（子方向激活）+ 节点9 | 找最接近的若干轴；靠拢度定主方向 |
| ⑤ 沿温度扩散 | 节点6 温度圆 + 节点7 二次发散 | 加温度画圆，太近太远皆筛除 |
| 输出方向词 | 节点9 → 节点10 | 信息词作为池，在空间中选出方向词 |

### 2.2.2 三条线路方案（LLM 优化器的位置）

系统在设计上预留了三条线路，其差异仅在于**LLM 优化器插入的位置**。此处 LLM 的角色被严格限定为"方向、头部、转换词的优化器"，而非发散的来源，且受四条红线约束（见下文）。三条线路的基础发散引擎相同，区别在于是否引入 LLM 以及引入的时机：

- **线路1（基础，无 LLM）**：根据对话作记忆召回与大量擦边召回，再根据上下文作第一次联想发散，然后由转接器转换再发散。全程不引入 LLM。
- **线路2（LLM 在联想发散之前）**：在记忆召回、擦边召回之后，先由 LLM 从整体上判断方向、头部、次要发散方、多头、可能的错别字或隐藏内容、上下文逻辑，再作联想发散，然后转接器转换。
- **线路3（LLM 在联想发散之后）**：先作记忆召回、擦边召回与第一次联想发散，再由 LLM 依据上下文与发散输出优化头部、方向、重要转换词、次要方向以及辅助识别错别字或隐藏内容，然后转接器转换。
- **线路C（双位置）**：LLM 在上述两个位置均介入，为规划中的测试方向。

以 ASCII 图示三条线路（其中"实装"表示对应环节已实现，"实验态"表示已在实验分支实现但未合入主链）：

```
                  用户对话输入
                       │
                       ▼
             记忆召回（大量擦边）
                       │
                       ▼
                  上下文整合
        ┌──────────────┼──────────────┐
        ▼              ▼              ▼
   [线路1 基础]    [线路2 A路径]   [线路3 B路径]
   无 LLM          LLM 在发散前     LLM 在发散后
        │              │              │
   联想发散(实装)   LLM 看整体(实验) 联想发散(实装)
        │              │              │
   转接器再发散     注入配置后        LLM 逐词标注(实验)
   (实装)          联想发散(实装)     │
        │              │           权重修改(实验)
        │          LLM 后处理提降权   │
        │          (实验)          二次发散(实验)
        │              │              │
        │          二次发散(实验)    转接器(实装)
        │              │              │
        ▼          转接器(实装)       ▼
    XML 输出          │           XML 输出
                      ▼
                  XML 输出
```

此外，设计中另有一项规划中的**小模型前置定位层**：在发散之前由本地部署的小模型（Qwen3.5:2B）承担方向定位——只做方向理解与标注，不产出创造性内容（与上述 LLM 红线一致）。该层尚未实装，当前纯词典与向量的定位路径是其落地前的过渡形态。

关于三条线路的**实装状态**：线路1 已基本实装（无 LLM，仅走生产路径）；线路2 与线路3 的 LLM 环节已在实验分支实现完毕，但尚未合入主链，处于条件启用状态；线路C 为双位置方案，实装度最低。其中一处关键断链在于：LLM 输出回送至转接器的通路尚未接通——实验分支内已写就 LLM 结果到二次发散的映射，但主链尚未消费 LLM 结果。需强调，这套三线路是系统早期单体架构时期的设计与代码快照，当前流水线架构的线上出词走线路1（无 LLM 分支）；LLM 接入另有后续版本演进，属组件态。

**LLM 的四条红线**：LLM 在系统中被定位为"标签生成器"而非"标注专家"（后者会引入不受控的创造性），其绝对不可逾越的四条约束为：不创造（产出以原文与召回内容为主，仅极小比例来自封闭枚举）；不评分（不产生任何数字字段）；不投影（不推测用户未言明的内容）；不影响系统（其输出为标注，不改动主链）。

### 2.2.3 P1 在对话流程中的位置

在整体设计上，P1 为双引擎结构：自驱动 P1（本章所述纯算法管线）为主力，另有 AIP1 作为可选的保底引擎——由用户自选的 LLM 在自驱动产出的基础上接续深化，而非替换。本章以下只描述自驱动一线。

P1 在整个对话处理流程中的位置如下。在获取提示词阶段，系统依次加载记忆数据、确定当前模式、注入表格数据、注入热层记忆、注入提示词链，随后进入 P1 自驱动认知发散环节（异步执行，不阻塞主流程），最后作模式专属注入与联网搜索。P1 环节之后，主模型生成回复，再由后续的归档与记忆迁移管线处理。

```
用户输入
  │
  ▼
获取提示词阶段
  ├─① 加载记忆数据
  ├─② 确定当前模式（对话/编码/工作）
  ├─③ 表格数据注入
  ├─④ 热层记忆注入
  ├─⑤ 注入提示词链
  ├─⑥ P1 自驱动认知发散（异步，不阻塞主流程）   ← P1 在此
  │    → 设计：置信度达阈值时输出方向词 XML
  │    → 设计：置信度不足时回退至 AI 预设检索
  │    → 当前线上：自驱动充分性判定恒为假，恒走 AI 预设检索
  ├─⑦ 模式专属热层注入
  └─⑧ 联网搜索（当 P1 输出含搜索提示时触发）
  ▼
主模型生成回复
  ▼
回复处理 → 归档 → 日终整理 → 层级迁移 → 定期整理
```

图中标注"当前线上：自驱动充分性判定恒为假"对应本章开篇的系统状态声明——线上主链恒走 AI 预设检索，本章所述自驱动发散链为待接回的组件态实现。

### 2.2.4 U 型注入机制

P1 的输出在注入主模型时采用 **U 型注入**，即依据注意力的首因效应与近因效应，将最重要的内容放在序列的首端与尾端，最弱的内容放在中间。注入按深度分层：

```
深度2 → API 缓存区（跨轮稳定）
深度1 → 系统提示区（缓存友好）
深度0 → 对话尾部（注意力最强）  ← P1 方向词 XML 在此注入
          ├─ 认知激活块（按模式：对话/编码/工作/特定场景）
          │    含认知术语 / 方向词 / 技术信号 / 扩展 / 锚点
          └─ 内存动态数据
```

P1 方向词 XML 注入于深度0（对话尾部，注意力最强处）。在方向词 XML 内部同样采用 U 型排列：排名第一的方向词置于首位（首因效应），排名第二置于末位（近因效应），排名第三这一相对最弱者置于中间（最弱位置）。整个 XML 块的各组成部分亦按此原则排列，召回记忆居首、方向词居尾。

## 2.3 各处理节点规格化描述

本节对各处理节点逐一作规格化描述。每个节点按"设计原则 → 处理机制 → 当前实现 → 关键参数 → 已知问题"五层展开。各节点的代码实现位于系统记忆模块的 P1 子目录下，节点模块以 `p1_node*.mjs` 命名，模块名在描述中保留作为职能标识。凡未接入线上主链者，均在"已知问题"中如实标注。参数标注中，"经实验校准的定档值"指由实验落定的数值，"初始默认值（未经系统性调优）"指尚无实验依据的取值。

### 2.3.1 Step-1：括号双信道（分词前置层）

- **设计原则**：括号是一种元语言符号，P1 必须在分词之前先识别括号，将主信道（正文）与副信道（括号内容）分别处理，否则会丢失真实情绪。副信道常承载正文未明说的真实情绪。
- **处理机制**：在所有算法之前、早于分词，识别括号并拆分为主信道与副信道，二者分别处理且**不取均值、保留张力**（当正文与括号内情绪反向时，取均值会相互抵消）。序号、旁注等格式性括号予以豁免。无括号时走单信道，零额外开销。
- **当前实现**：模块 `p1_step1_bracket.mjs` 提供括号信道拆分职能，返回主信道、副信道及是否含括号的标志。副信道另行运行一次发散，两个池以集合并集方式合并（不取均值），主副散词共同进入空间投票，反向情绪不相抵消。无括号时整段跳过。
- **关键参数**：括号双信道开关默认开启。
- **已知问题**：无。该环节在组件库内处于可用状态。

### 2.3.2 节点0：记忆召回（P1 职能①，与分词并行）

- **设计原则**：召回是首要任务，P1 的作用是召回加发散。系统借回溯机制，结合上下文、注意力集中与多轴视角，查看此前的内容（data 层、热层、冷层），匹配后取出并告知主模型，此过程不需要很智能的判断。设计者明确区分召回与发散的边界：召回读取记忆数据层，而发散本身只看最近数句上下文、不读召回的数据。
- **处理机制**：以最近数条上下文加联想加算法，查看压缩记忆的 data/热/冷三层，作关键词与信息匹配，进行**大量擦边召回**，其结果作为发散锚点。召回与分词并行；发散只看最近上下文、不读召回数据。
- **当前实现**（须区分两条独立线）：
  - 模块 `p1_node0_recall.mjs` 提供发散管线内的**上下文锚点**：取最近若干句上下文，逐句作联想交集与词向量余弦打分，排序后取靠前者作为锚点，高频词作软降权处理。
  - 模块 `p1_node0_data_recall.mjs` 提供 data 三层擦边召回，默认关闭、处于灰度状态。
  - **真正的记忆召回是另一条线**：由记忆召回模块 `memoryRecall.mjs` 在发散管线之前独立调用，召回片段以系统消息形式并入对话历史，而非以召回记忆 XML 形式注入。发散管线内的上下文锚点与真正的记忆召回互不引用（二者的隔离为设计约束）。
- **关键参数**：上下文句数为初始默认值；锚点强度采用与命中数相关的递增公式；data 三层召回默认关闭；data 层三层权重按热、温、冷递减；data 召回强度设上限以保证召回不主导。
- **已知问题**：真正的记忆召回目前尚未读取热/冷压缩层（而是遍历整个记忆目录树），"读压缩层"一项设计者判定为暂缓；data 三层召回默认关闭，待验证后转正。设计者标注该环节"需要进一步讨论和定位"，为未定项。

### 2.3.3 节点1：收拢₁（分词 + 排除无信息词）

- **设计原则**：收拢之后由分词器分词，排除无信息内容；先聚拢再发散，为发散提供锚点。
- **处理机制**：分词后排除无信息词（虚词、超高频词），得到有意义的词作为锚点。**例外**：程度副词与极性强化词（如"这么""太""很"）不作为噪声删除，而保留为相邻内容词的强度、极性加权信号。
- **当前实现**：模块 `p1_node1_tokenize.mjs` 承担分词与无信息词排除职能，采用分词器配合高频词表排除无信息词，程度副词与极性词另行保留。该节点在发散主流程内被串行调用。
- **关键参数**：高频词频率阈值为经实验校准的定档值；所用资源包括分词组件、词性词典（作词性交叉验证）、约十余万条的词频表、多份停用词表及程度副词表。
- **已知问题**：无。组件库内处于可用状态。

### 2.3.4 节点2：发散₁（联想发散，P1 职能②，发散引擎核心）

- **设计原则**：以原内容加上下文作联想发散；联想发散为核心发散机制，转接器为其配套的转换机制。
- **处理机制**：有意义的词加上下文经联想发散产生散词池。**发散距离须保持中远程**，禁用同义近距扩散（该项为红线）。
- **当前实现**：模块 `p1_node2_swow.mjs` 承担联想发散职能，主路径走一种"查询—键—值"式的池交汇发散：以输入词的词向量质心为查询，以联想线索词对质心的余弦相似度为键，从交汇线索链式再发散得到值。设有双重门控：线索词须与输入有直接联想关联，且余弦相似度须达阈值；仅当输入词数达到下限时才启用该路径（以防止单词喷发）。返回散词池与输入质心。设计记录中同时留存了一条注释，说明早先的"逐词独立联想发散兜底"分支因违反"禁止逐词发散"红线而被纯删除。
- **关键参数**：联想发散距离保持中远程（红线）；池交汇尺寸为经实验校准的定档值（更大尺寸虽降幅温和但易漂词且算力成本显著上升）；线索余弦阈值与联想候选数上限为配套参数。
- **已知问题**：无。历史上同义近距扩散曾导致召回质量大幅下降（约七成），该教训经实验确证，现锁定为红线。

### 2.3.5 节点3：六轴独立并行发散（每轴多维，6+n）

- **设计原则**：六轴中每轴多维（六个学科、每学科含多个子方向定位），每个轴配有对应资源；六轴是一个"面"，不应做成"线"；六者并行、走完后合并到一处观察关联性。设计者曾手写一个示例说明"面"的形态：对"你为什么这么笨"一句，可拆出信息词"笨""笨蛋"，各轴分别产出——信息学给出否定、反面、错误、失望，逻辑学给出错误、长期问题、失落，心理学给出负面、失望、预期不达标、优化渴求、同情，社会学给出吐槽、不满、无语疑惑，认知学给出预期偏差，语言学给出负面，其中"这么"起到加重"笨"这一信息的作用。
- **处理机制**：散词池经六个学科轴各自独立并行发散（每轴多维判断加专属资源），各吐一个"面"（一组丰富信息，而非单一分数），合并到一个池观察关联性，并带主方向轴与衰减。
- **当前实现**：模块 `p1_node3_axis6.mjs` 承担六轴发散职能，散词池经六轴各吐面，含轴衰减，返回各轴面、轴衰减、主轴及词属性画像。其**轴衰减机制**为：计算各轴的关联度（该轴上候选值之和），按关联度降序排名，衰减按排名指数递减——主轴（排名首位）为最高值，远轴指数衰减但恒大于零、永不归零（软隔离）；另设一软停阈值，关联度低于该阈值的轴不再发散（不注入新锚点），但其已有的"面"不删除。
- **关键参数**：轴衰减系数为经实验校准的定档值（系数越大远轴衰减越剧烈）；软停阈值为一固定比例。各轴专属资源包括心理学的情绪与情感词库、信息学的领域词库等。
- **已知问题**：其中两处子机制曾被判为框架偏离，当前接线正常。另需标注一处设计与实现的已知偏差：设计意图是每个学科轴为每个词提供**多个信息点**（信息与信息范围，即 6+n 多维定位），信息点转移到候选池后一个词应携带多维信息；当前实现在面词与轴关联度计算中把每轴对每词的贡献压缩为单一数值参与求和，属设计的降维执行，多信息点的完整保留为待改进方向。

### 2.3.6 节点4：子方向空间细化 + 词向量300维

- **设计原则**：子方向空间用于细化定位，六轴确定发散点、子方向空间作大致定位再扩充产出；六轴与子方向空间不是同一事物；子方向"原本是激活的、非全部"。系统裁定：打分是打分框架与词向量的职责，不是子方向空间的职责（子方向只定位不打分）。
- **处理机制**：六轴发散结果在细分子方向空间中作详细**定位**（子方向空间是定位坐标，不是属性打分），配合词向量维度辅助，确定激活哪些子方向（而非全部）。子方向空间是产出端的空间定位，不是六个学科轴的下级子分类。
- **当前实现**：模块 `p1_node4_axis47.mjs` 承担子方向定位职能，散词命中术语后记入命中集，经重写后**只定位不打分**，返回激活集与命中证据集。需标注设计与实现的一处已知差距：设计上子方向空间是六主轴粗定位之后的**方向细化层**——刻画定位点处向各子方向细化与发散的方向，驱动后续定向发散与扩充产出；当前以术语命中集合近似该定位，属设计的简化执行。
- **关键参数**：所用资源包括子方向坐标术语表、少维兜底摘要及词向量表。
- **已知问题**：历史审查曾记录一处子方向键命名分裂导致静默丢分的疑似缺陷，需按当前代码核实是否已修（本章仅记录，不作裁定）。设计者亦自承子方向空间的设计尚不完善，而六轴划分是成立的。

### 2.3.7 节点5：资源库多资源定位细化（算子，可多处复用）

- **设计原则**：以资源库的多种资源作定位与细化；系统资源库资源丰富，应充分利用；定位即细化，资源库的定位细化可在多个位置复用，而非仅在单个位置——系统在"做流程"而非"打补丁"。该环节应置于空间投票**之前**。
- **处理机制**：用 P1 资源库的多种资源对候选作定位与细化。它**不是一次性的单点步骤，而是可在流程多处（如节点4、6、7）复用的算子**，只产出"确认信号"（有多少资源确认了这一位置及语义关系），不改动坐标、不投票、不排序。
- **当前实现**：模块 `p1_node5_resource.mjs` 承担资源交叉确认职能，用概念网、词林、同义、反义、常识库等多种资源作交叉确认，只产出确认计数与语义关系，不改坐标、不投票。该职能挂接于信息词清洗环节。
- **关键参数**：所用资源包括大规模概念网、常识库、词林、同义词库、框架语义库等（另有若干可扩展但未接入的资源）。
- **已知问题**：历史审查曾有"该节点空跑"的结论，经核实已证伪（该节点确有下游消费者，产出确认信号被使用）。

### 2.3.8 节点6：汇总到一个池 → 空间 → 内容分布投票（主排名）

- **设计原则**：汇总到一个池，不是相乘，而是空间，进行内容分布投票；系统采用空间相加，而非线性相乘、非硬匹配；加温度画一个圆，太近不行、太远也不行，需要筛选；空间匹配更优，在空间中匹配、排除空间外的、找空间内的。
- **处理机制**：定位细化后的候选汇总到一个空间（**相加，非相乘，非硬匹配**），作内容分布投票，以多维坐标确定多个锚点，再加温度画圆作为边界。太近者排除（废词、冗余），太远者自然衰减（不硬删），中间的最优距离区间保留。
- **当前实现**：模块 `p1_node6_spaceVote.mjs` 承担空间投票职能，是信息词打分的主排名环节。采用**多对一累加投票**：每个候选独立地对每个目标投票，总得票为各票之逐项累加（无连乘、无除以路径数）。其核心逻辑为：以词向量距离为基础，低于投票下限（太远）者不投票；圆外者不硬删（仅用于排序与锚点筛选）；以逆距离权重乘以候选权重得到单票，累加为总票。温度画圆的逻辑为：依据输入词数分档确定温度（短句取高温、大圆，长句取低温、小圆），圆半径等于基准半径乘以温度。
- **关键参数**（均为当前实测值）：逆距离陡度、基准半径、温度分档值（短句高温、长句低温）、内边界比例（默认关闭）、领域加分因子——其中经三档实验裁定的陡度值为经实验校准的定档值，基准半径为钝调参数，内边界比例默认关闭。
- **已知问题**：**"太近"内边界环节曾因其阈值缺乏依据而被移除**，当前内边界比例默认关闭（以保证零回归），其实验档位待大规模 A/B 测试确定；"太近"的部分职能现由节点10 的最优距离区间衰减承接。此处有一条重要工程约束：**切勿以"乘以质量系数"的方式给投票打补丁**——连乘等同于硬匹配，违反"空间相加、非相乘"的设计原则（该做法曾被引入又被删除，代码注释明确记录此红线）。历史审查中"该节点为死代码"的结论已证伪。

### 2.3.9 节点7：发散信息词（第二次发散）

- **设计原则**：在空间投票后再发散信息词；系统设计了两次发散——第一次是上下文加联想，第二次再发散为信息词；发散词包含跨领域关联、上下流程关联、归因关联；六度分隔可简化为二到三跳，联系过小时自动停止。
- **处理机制**：空间投票结果经第二次发散产出信息词，为方向词提供更多有用的可能性。所有路径的产物都并入信息词清单，作为额外信息词加性参与节点9 的投票，而非替换节点9 的投票机制。
- **当前实现**：该环节内联于转接器模块，含**多条发散路径**，各路径由独立开关门控（默认全开）。各路径共享去重图、归一化尺度与推入助手（原始分经归一后并入，形态与"面"一致）。各路径及其数据源如下：

  | 路径 | 数据源 | 触发方式 | 衰减机制 |
  |---|---|---|---|
  | 个性化随机游走 | 知识图谱（词/概念/术语节点） | 以输入词为种子 | 幂迭代，含阻尼系数与自然衰减 |
  | 二跳关联 | 锚点概念经常识库到术语 | 一跳联想结果取靠前者 | 二跳，含衰减系数，异轴与同轴分别加权，每词设上限 |
  | 因果关联 | 锚点经常识库因果边到术语 | 以锚点联想结果为种子 | 依常识库因果类型，路径接力降权 |
  | 类比关联 | 主轴锚点向其他轴作词向量余弦匹配 | 正向主轴到其他轴，反向次轴到主轴 | 跨域结构同构，倒 U 型最优距离区间门控，设锚点数与每锚点上限 |
  | 六度关联 | 锚点经常识库全关系一到二跳到术语 | 以锚点靠前者为种子 | 独立游走去重，含衰减系数；跨域时给予递增奖励 |

  以六度跨域发散为例，其核心逻辑为：对每个游走到的术语，依据是否跨轴给予不同的判别权重，乘以路径衰减（按跳数递减，不含种子分），当路径衰减低于停止阈值时终止；跨域涉及的领域越多，跨域奖励越高（鼓励跨学科联想），已收录的术语不重复推入。这一设计对应"跨框架类比本质上就是六度分发"的思路。
- **关键参数**：各路径的阻尼系数、迭代上限、衰减系数、奖励上限、跨域奖励系数、节点整体缩放等，为经实验校准的定档值与初始默认值的混合。
- **已知问题**：该环节以异常捕获包裹，抛错不影响主链（合理设计）。头注释中提及的一处打分框架调用在当前代码中并不存在（详见节点8 已知问题）。

### 2.3.10 节点8：打分框架 + 筛选①（筛信息词）

- **设计原则**：打分框架用于评分与筛选（可用于多个位置）；打分框架是算法框架，转接器是各类机制的总和、包含打分框架；联想发散为核心发散、打分框架为转接器；乘积应取均值；需要多维标注而非单一内容标注（即空间）。打分框架是转接器内部的"打分装置"，**既非发散引擎也非选择器**——方向由投票环节"选"，打分框架在选后只作降权、筛废词与红线处理。
- **处理机制**：信息词经打分框架评分后筛选（保留高质量，降权万金油、噪声、极性不匹配、冗余）。收拢阶段包含侧抑制（近义去重）、多样性重排与配额（保证各轴有代表）。
- **当前实现**（打分框架位于 `p1_node8_10_blq.mjs`）：核心为**六个加分维加权线性求和，再减去若干抑制维的加性扣分**（采用线性组合而非连乘）。六个加分维分别为：空间距离项、词频饱和项、跨学科路径和谐项（仅此一处计入，绝不在外层重复相乘）、词向量相关性项、特异性项、资源确认项。四个抑制维为加性扣分：万金油、极性不匹配、无关、孤立噪声。最终得分取"加性汇总"与"加性汇总减去扣分总和"中的较大者（设软地板，防止多门叠扣硬归零）。侧抑制阶段执行完整打分加侧抑制（近义压制）、多样性重排与配额限制。
- **关键参数**：各加分维权重与各扣分系数均为经实验校准的定档值；侧抑制近义阈值、多样性系数、单轴与单维配额、输出条数为定档值。
- **已知问题（重要）**：
  1. **打分框架当前是"死引用"（孤儿）**：转接器模块中虽有对打分框架的引用声明，但全文并无实际调用，也无对应门控开关。头注释所称"被转接器调用、门控开启"与磁盘实际不符。**当前活跃管线中，打分框架并不参与打分**——信息词的打分实际由节点6 的空间投票与节点3 的轴衰减承担。打分框架的六维框架是完整落地的设计（代码可逐行阅读），但尚未接入主循环。
  2. 该节点的完整精排外壳同样是孤儿（无生产调用）。
  3. 算法史：旧版本曾采用四个抑制维连乘的公式（全部触发时呈指数级压制），违背设计方向。实验表明乘积公式导致召回大幅下降（约六成），几何均值方案亦显著恶化，加性优于乘积为经实验确证的定档结论。

### 2.3.11 节点9：信息词作为池 → 空间 → 选出方向词（唯一出词路径）

- **设计原则**：信息词再作为池与空间选出方向词；多个信息词对应一个方向（多对一），而非一个信息词对应多个方向词；不是一个词发散一堆，而是信息池发散；方向词是给主模型的建议，而非对用户的判断。
- **处理机制**：信息词整体作为池，在空间中观察池指向什么方向，作**多对一投票**，选出方向词。
- **当前实现**：模块 `p1_node9_dirword.mjs` 承担方向词选择职能，是**唯一的出词路径**。采用霍夫式多对一投票：每个信息词对每个合格目标投票（加性），累加为总票（空间相加，非相乘）；收口时以总票乘以轴衰减得到最终得分。
- **关键参数**：默认衰减值、多投票器开启（每个信息词独立投票以实现多对一）、霍夫投票取顶数、方向词输出条数（约二十条）。
- **已知问题**：某类词的产出存在结构性偏斜（近义合并无法解决），归入产词线待定问题。

### 2.3.12 节点10：打分 + 筛选② → 输出（线上真实运行环节）

- **设计原则**：打分加筛选；输出废词也无妨，量大擦边，但方向必须与对话一致；给方向，不要给路线、诱导或代替用户表达；主模型裸读原文也能推出的词即废词；删除会让主模型误认为是用户主观体验的词汇。
- **处理机制**：方向词经第二次筛选后最终输出，排除废词、路线词、诊断词、主观体验词及极性不匹配词。
- **当前实现**（节点10 为线上真实运行环节）：
  - 方向词精排环节由 `p1_pipeline.mjs` 真实调用（门控默认开启）。它**不跑六维线性求和**，只作"节点9 得分乘以高斯渐变衰减"（该衰减用于计算位置而非压分）加断崖弃权（打破"填满固定条数"的天花板）加红线标注。该环节不复用打分框架的六维打分，只保留"衰减加红线"两件事。
  - 红线判定环节由 `p1_pipeline.mjs` 调用（门控默认开启），作**硬剔除**（命中即移出、不进方向词输出）：类别一为路线词（建议、应该、方法、步骤等），类别二为诱导词（"你需要""你必须"等），类别三为主观体验词，类别四为诊断词（障碍、患者及各类疾病名等，其中对单字"症"作了排除"症状"的处理）。
- **关键参数**：输出条数（契约固定长度）、断崖比例与断崖下限、四类红线的正则种子（为结构常量而非数值魔法数字）。
- **已知问题**：节点10 内部对红线仅作软降权与标注，硬剔除在管线层的红线判定环节执行；节点10 **不夺权**——以节点9 的多对一投票次序为主，节点10 只作降权、衰减与红线处理。该节点已删除旧版中的质量门连乘（其为死操作且会造成白盒观测失真）。

### 2.3.13 贯穿机制之一：热插拔自学习

- **设计原则**：热插拔机制中，一个大型词库等同于一个额外的发散轴；迭代修正即热插拔，既非温度也非衰减；像打字一样，经常出现或相近的内容可被记录；由系统依据对话自行构建词库才是最优。
- **处理机制**：系统采用三层词库——内置固定层、可插拔适配层、用户自学习层。一个大型词库等于节点3 的一个额外发散轴（六轴扩展为七轴或更多）。"打字机制"即自学习：如同输入法词库，高频或相似词被记录后提权。离线批处理产出新词库后热加载（周期性轮询监控文件修改时间，一旦变更即清缓存、不重启即生效），而非实时改参数。
- **当前实现**：管线模块中设有热重载检查（周期性节流检查词库文件修改时间）。以异步方式写入自学习盘：累积各轴统计与词频统计至用户词库；转接器侧写入词频统计。
- **关键参数**：热重载轮询周期为一固定值。
- **已知问题**：读写端已实装（词频统计与升权可运行）；但离线批处理触发、自学习词自动升库、共现统计尚未实装，当前只能手动编辑配置文件触发热插拔。此外，词库改动须在激活术语表与转接索引两处同步，否则新词无法命中（铁律）。需注意一处同名混淆：前端的"打字机流式渲染"与 P1 的"打字机制"（自学习）同名但无关。

### 2.3.14 贯穿机制之二：白盒可观测

- **设计原则**：以单点断点查看真实线路、不跑全量，此为最高原则；禁止使用评分工具，由系统自身查看实际输出。
- **处理机制**：每个节点经过后可观测到——输入是什么、做了什么、输出是什么、为何输出此而非彼。可在任一节点设断点查看完整中间状态。
- **当前实现**：模块 `p1_whitebox.mjs` 提供追踪职能，在各节点入口与出口埋设上述四问，默认常驻全开。以节点6 为例，其追踪段将输入、处理、原因三段全部埋点。
- **关键参数**：白盒开关默认全开。
- **已知问题**：无。这是设计者最高原则的落地，不可关闭。

## 2.4 附节：架构的历史演进版本

> 本节所述为系统的**历史架构版本**，其结构、节点与数据流对理解当前设计的由来有价值，但**行号锚点与文件已随架构迁移而失效**，不代表现行实现。读者应关注其结构与设计意图，而非具体细节。

### 2.4.1 仿生三层架构（早期版本）

系统早期以仿生学作比，将整体分为三层：P1 为"眼睛"（扫描输入轮廓、给出方向词），主模型为"大脑"（看方向、决策、写回复），协作分身为"手"（探索、搜索、验证）。设计者将 P1 定位为视觉系统：预先向主模型提供已标注方向的关联框架，而非让其从零开始处理输入。

```
P1 = 眼睛（扫描轮廓，给方向词）
  输入：用户对话 + 对话历史 + 记忆
  处理：三段式流程（收拢 → 发散 → 收拢）
  输出：方向词 XML（认知术语/方向词/召回记忆/语篇/情绪/场景/提示）
        │ 方向词注入（提供已标注方向的框架）
        ▼
主模型 = 大脑（看方向，决策，写回复）
  接收方向词 → 据方向决策与组织回复 → 跨学科类比扩展
        │ 派任务
        ▼
分身 = 手（探索/搜索/验证）
  代码调研 · 联网与历史召回 · 实验验证
```

### 2.4.2 三段式流程（早期版本）

早期架构采用三段式流程：收拢一（整合与坐标累积）、发散（联想加向量发散，含多机制并行：情节、具身、隐喻、叙事、对立、类比）、收拢二（转接器投票）。该版本的收拢二采用多因子投票（逐词查表主导），是后来万金油现象的根源。当前架构已将收拢二重写为加性打分，范式由"逐词查表主导"切换为"空间搜索主导"（见 2.4.5）。三段式结构本身有效，具体行号已失效。

### 2.4.3 五固定轴加衰减（早期版本）

早期采用五个固定轴（不含认知学）：心理学、信息学、社会学、逻辑学、语言学。当前六轴定型已加入认知学。在早期的部分模式中，认知学是"激活轴"而非"固定轴"，这构成一处历史表述张力——当前六轴定型含认知学，而历史五固定轴版不含。衰减公式为按轴距离指数衰减，配合分档系数，遵循"不硬删、不影响主力"的软隔离原则。

### 2.4.4 点线面体架构（早期版本）

早期以"点线面体"刻画空间结构：点为单一激活术语或原子概念，线为轴向连接与关系链，面为多轴交叉平面，体为全架构立体与跨学科同构体。数据由点连成线、线织成面、面构成体。图中标注的转接索引词条数为早期快照值，当前实测值另计。

### 2.4.5 三纪元演进（结构有效，细节已失效）

系统代码体经历了三个纪元的演进，是理解"为何当前是节点流水线"的历史底座：

| 纪元 | 名称 | 状态 | 时间 |
|---|---|---|---|
| 第一纪元 | 单体架构 | 已退役 | 2026年4月下旬至5月下旬 |
| 第二纪元 | 三文件架构 | 已退役 | 2026年5月下旬定型 |
| 第三纪元 | 节点流水线（当前） | 当前生产 | 2026年5月下旬起 |

- **第一纪元为何被放弃**：其一，体积失控（单文件一度达四十余万字节、近八千行）；其二，难以维护（连续多版诊断出同批顽疾却改不动，单体耦合改一处易崩全局）；其三，**范式被推翻**——由逐词查表主导（万金油率约七成）切换为空间搜索主导（万金油率约百分之四）。
- **第二纪元为何被放弃**：其仍为文件级线性调用，无法实现节点级的热插拔、白盒埋点与线路切换。第三纪元以流水线编排取代线性调用，方才支持可切换的三线路。第二纪元到第三纪元并非推翻，而是重组加改名（转接器模块由旧的发散模块直接改名延续）。
- **第三纪元仍在演化**：一处代表性演化是子方向空间的"去坍缩"改造——子方向空间退回为范围门，打分交由打分框架与词向量承担。设计者的裁定为："打分是打分框架与词向量的职责，不是子方向空间的职责。"

**范式切换的量化证据**：

| 范式 | 主导机制 | 万金油率 |
|---|---|---|
| 旧范式 | 逐词查表倒排 | 约 74% |
| 新范式 | 空间搜索（词向量质心/范围）主导 | 约 4% |

打分框架的因子数在演进过程中反复增删（早期由六因子逐步扩至十余因子，一度达十七因子，后经一次重写以约二百九十行的加性框架取代旧的约三千行连乘框架，此后又有若干因子加重排序融合方案）。因子数在不同历史片段间高度不一致，此处不作锁定，仅记录其演化趋势。

### 2.4.6 评分轨迹（历史里程碑）

系统在开发过程中以综合评分作为迭代目标，其里程碑如下（供理解算法演进之用）：

| 版本阶段 | 综合评分 | 改动核心 |
|---|---|---|
| 早期 | 约 2.01 | 双信道融合 |
| 词库化后 | 约 2.96 | 五份词库约六千七百词 |
| 双轮扩词后 | 约 3.69 | 扩词 |
| 融合后 | 约 3.62 | 模式融合 |
| 轴均值算法 | 约 4.05 | 轴均值算法（首次突破 4.0） |
| 路由加万金油治理 | 约 4.04 | 大中小路由加收拢二万金油治理 |

综合评分自早期到后期约翻倍。万金油次数在此过程中大幅下降（约减少八成）。一条关键教训是：设计者指出"改公式都是治标"——多轮改公式实验证明，仅调整打分公式只能把一类万金油转变为另一类，根本解法是**依输入规模的大中小三级路由**（由输入触发局部精排，而非全局打分）。

## 2.5 小结

本章给出了 P1 系统的完整架构与处理流程。系统的处理骨架是一条五步标准链：六轴与机制并行独立运行、汇入一个池、在池内作内容分布投票打分、找出接近的轴与点位、沿温度扩散出边界，最终由信息词作为池选出方向词。这条链的若干设计判断是全系统的基石：机制并行而非轴并行；池是空间相加而非线性相乘；打分是加性投票而非多因子连乘；温度画圆以"太近太远皆需筛除"确定发散边界；轴衰减只降权不删除以实现软隔离。

在实现层面，系统由一条节点流水线编排十余个处理节点，配以横切全程的热插拔自学习与白盒可观测两个机制，并预留了 LLM 优化器可插入不同位置的三条线路方案。本章对各节点作了逐一的规格化描述，并如实标注了当前实现与设计意图之间的差距——最值得注意的是，打分框架当前为未接入主链的孤儿实现，信息词的实际打分由空间投票与轴衰减承担；"太近"内边界因阈值缺乏依据而被移除，其职能部分由后段最优距离区间衰减承接；三条线路中的 LLM 环节尚未合入主链。

需再次强调本章开篇的系统状态：本章所述完整自驱动发散链为组件库内已实现、待接回的算法，当前线上出词由 AI 预设检索承担。系统的历史演进（附节 2.4）显示，当前的节点流水线架构是在单体架构体积失控、范式由逐词查表切换为空间搜索之后形成的，这一范式切换将万金油率由约七成降至约百分之四，是理解现行架构的关键历史脉络。
