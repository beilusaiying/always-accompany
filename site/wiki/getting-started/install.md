# 配置 AI 服务源

AI 服务源决定由哪家服务、哪个模型生成回复。always-accompany 负责组织界面、上下文、记忆、工具与权限；模型服务负责生成内容。

## 当前界面里的“API 类型”是什么

当前设置面板从后端的 provider 元数据生成“API 类型”列表，前端不再维护另一份固定渠道表。你会看到两类入口：

- **原生入口**：Google Gemini（原生）和 Ollama（本地原生）；
- **OpenAI 兼容入口**：Claude、DeepSeek、OpenRouter、通义千问、OpenAI 兼容等 provider 变体，运行时统一走兼容生成器，再按 provider 映射参数。

因此，下拉框里的名称不是“模型强弱排名”，而是请求格式与参数映射。使用官方 Gemini Key 时选原生 Gemini；使用 OpenAI 兼容中转时选对应 provider，找不到时再试“OpenAI 兼容”。

## 跟着做：添加一个服务源

1. **打开面板**：右上角齿轮（或 `Ctrl + ,`）→ 左侧闪电图标「AI服务源」（[设置 → AI服务源](beilu:settings/api)）→ 点「添加」。
2. **填名称**：自己起，比如"我的中转站"或"官方Gemini"，纯粹用来区分。
3. **选 API 类型**：官方 Gemini / 本地 Ollama 选对应原生项；中转或聚合服务优先选其声明兼容的 provider，拿不准再试“OpenAI 兼容”。
4. **看服务地址**：选完类型会自动填入该渠道的默认地址。用中转站的话，把它换成中转站给你的完整地址。
5. **填 API Key**：服务商或中转站给你的密钥，原样粘贴。
6. **选模型**：点「获取模型列表」，下拉里挑一个。列表拉不出来通常说明地址或 Key 有问题。
7. **保存**。界面会重新读取刚写入的配置核对 generator 与 config；读取失败或内容不一致时不会显示假成功。然后在左栏（或底栏）的模型选择器里确认已选中这个源。

## 常见场景速查

| 你手上有的 | API 类型选什么 |
|------|---------|
| 中转站 / 一键 API / 聚合服务 | 对应服务商的渠道；找不到就选「OpenAI 兼容（自动检测）」 |
| Claude 官方或 Claude 系中转 | Claude 渠道 |
| Gemini 官方 API Key | Google Gemini（原生） |
| DeepSeek 官方或中转 | DeepSeek 渠道 |
| 本地跑的 Ollama | Ollama（本地原生），地址填你本机的 Ollama 服务地址 |
| OpenRouter | OpenRouter 渠道 |

## 可以配好几个源

服务源不止能配一个，而且很值得多配：

- **不同角色绑不同 AI**：角色卡编辑里可以给每个角色单独指定源；
- **不同模式用不同模型**：写代码用强模型、闲聊用便宜模型，子模式可独立绑定；
- **主源挂了切备用**：中转站抽风时一秒换路。

详见 [支持的 AI 服务商](beilu:wiki/ai-service/providers.md)。

## 验证与排错

配好后发条消息试试，能回复就成了。不通的话按这个顺序查：

1. [后台监控](beilu:settings/monitor) 看错误日志——401 是 Key 错，404 多半是地址错，模型不存在就是模型名不对；
2. 中转站用户确认地址填的是**完整端点**（一般以 `/v1/chat/completions` 结尾，中转站文档里都写了）；
3. 核对渠道声明——能确定服务商类型时优先选对应渠道；只有服务商明确提供 OpenAI Chat Completions 兼容端点、但列表里没有对应项时，再试「OpenAI 兼容（自动检测）」。

## 常见坑 FAQ

**问：渠道列表里为什么没有我用的服务商？**
答：先确认服务商文档是否明确提供 OpenAI Chat Completions 兼容端点。确认兼容后，可以选「OpenAI 兼容（自动检测）」；它会依据 URL 和模型名做兜底判断，但代码也把这条路线标为“不推荐”，无法保证识别每一种中转或自部署命名。

**问：两个 Gemini 到底选哪个？**
答：官方 API Key → 原生；中转站买的 → OpenAI 兼容那个。

**问：思维链（Thinking / CoT）下拉怎么选？**
答：当前有“渠道默认 / 关闭 / 标准 / 最大”四个选项。它们会按 provider 映射成对应参数；不是所有模型都支持全部档位，不确定时保留“渠道默认（不发参数）”。

**问：模型列表拉不出来，但我确定 Key 是对的？**
答：多半是地址少了或多了路径段。对照中转站文档把完整地址粘一遍，注意首尾不要带空格。
