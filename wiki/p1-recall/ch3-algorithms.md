# 第3章 算法设计与形式化描述

## 3.1 引言

本章给出自驱动发散召回系统在算法层的完整规格。该系统是一条为"发散思维"服务的外挂式处理管线：在大语言模型（LLM）之外，以规则计算、词向量运算与轻量标注取代对大模型的额外调用，从而在不产生额外推理成本的前提下，为主模型提供发散方向。设计者将其定位概括为"外置的发散思维链"。

本章的组织遵循如下逻辑。3.2 节先建立术语基础，对后文反复使用的自造术语给出定义。3.3 节逐项形式化描述系统的原创算法，每项按"设计动机—形式化定义/公式—设计依据—相关工作对照"四层展开。3.4 节给出核心评分框架 BLQ（Bilu Quality，转接器内部的候选质量打分装置）的完整规格。3.5 节以"消融与失败方案"的体裁记录算法演进史中被实测证伪的方案，这在技术报告中是有价值的负面证据。3.6 节汇总相关工作，并给出分档定位表。3.7 节小结。

需要预先声明的实现现状是：系统的发散主循环（runPipeline）与记忆召回组件（recallMemories）当前处于组件态，即算法已实现但尚未接回线上主链路，线上检索暂由模型预设承担；本章描述的是这套已实现、待接回的组件库算法。本章所有具体数值均按来源级别标注：凡经受控实验校准并锁定者标注为"经实验校准的定档值"，凡为初始取值而未经系统性调优者标注为"初始默认值"。所有公式均逐字保留其原始形状，未作改写；每个公式配以变量定义表。

## 3.2 术语定义

为使不具备本系统背景的读者能够零上下文理解后文，先定义本章反复使用的自造术语。

- **信息词（information word）**：发散过程产生的中间语义单元。它不直接输出给主模型，而是作为下游收拢的原材料。例如"习得性无助""职业倦怠"这类中间概念。
- **方向词（direction word）**：由多个信息词经"多对一收拢"后输出的最终语义单元，作为提供给主模型的"知识入口种子"，指示思考方向而非给出具体路线。例如"认知重构""价值澄清"。
- **废词（null word）**：主模型仅凭裸读上下文即可自行推出的词。此类词对主模型无信息增益，其价值被定义为零并予以剔除。
- **BLQ（Bilu Quality）**：转接器内部的候选质量打分装置。它在多个标注维度上对候选词一次性加性出分，用于降权、筛除废词与红线剔除，本身不承担"选择方向"的职能。
- **万金油问题（over-general hub problem）**：指少数高连接度的枢纽词（hub word）在发散过程中把大量不相关候选吸附到自身周围，导致输出泛化、失去方向性的现象。"万金油词"即这类过度通用、对任何输入都会被高频召回的词。
- **红线词（redline word）**：违反输出准则、命中即被硬性移出候选（而非降权）的词，包括给出具体路线、替用户下判断、代替用户表达、把用户判定为病症四类。
- **轴（axis）**：一条独立并行的学科发散维度。系统采用心理、信息、社会、逻辑、语言、认知六条学科轴。
- **点位（子轴）**：产出端的子方向坐标。系统在产出端设置子方向坐标空间，输入激活其中的子集以完成"定位"，此步只定位不打分。
- **0-token 原则**：发散步骤不调用大语言模型、全程可白盒观测的设计立场。发散由规则计算、向量运算与小模型标注完成。该原则的适用范围为当前生产线路（线路1），见 3.3.14。

后文涉及具体代码实现处，仅以模块名（如 node8、node10、axisDecay 等）作为实现标识，不展开实现细节。

## 3.3 原创算法逐项形式化描述

本节逐项描述系统的原创算法设计。每项给出：设计动机、形式化定义或公式（配变量表）、设计依据、以及与相关工作的对照。相关工作的分档口径统一在 3.6.1 节定义，此处仅引用分档结论。

### 3.3.1 三段机制：收缩—发散—收缩

**设计动机。** 大语言模型在生成时倾向于收拢到单一路径，难以自发进行广域发散。本系统认为发散能力必须由模型之外的机制承担：先以记忆召回锚定上下文（收缩），再进行两次联想发散（发散），最后收拢为方向词注入提示词（收缩）。

**结构（形状级）。**

```
输入 → [收缩] 记忆召回 + 上下文锚定
     → [发散] 联想网络第一次发散 → 空间投票 → 第二次发散产信息词
     → [收缩] 多对一投票收拢为方向词 → 注入提示词
```

**设计依据。** 收拢阶段以擦边、大量的方式召回记忆以锚定语境；发散阶段的目的是让主模型在后续思考中不被困死于单一点位；系统本身只提供框架、记忆与发散路径，收拢、聚合与思考仍交由主模型完成。就设计定位而言，本系统面向的是回溯与发散，而非续写或复现大语言模型的生成能力。

**实现摘录（节选，摘自 p1_pipeline.mjs 主入口 runPipeline，节选）。** 上述"收缩—发散—收缩"三段在主循环 `runPipeline` 中以串联的节点调用落地，与上文的形状级结构逐段对应：括号双信道前置层（Step -1）先于分词，随后依次经召回、六轴、资源确认、空间投票、多对一收拢与红线剔除。为便于阅读，此处仅保留调用骨架，省略降级回退、白盒 trace 与热插拔轮询等实现杂项。

```javascript

  const recallResult = callNode("recall", [_mainText, chatHistory, seenNodes, { ... }], { ... });
  const swowPool = recallResult.swowPool || new Set(inputWords);
  // …（略：副信道另跑一次 recallV2，Set union 并入 swowPool）
```

**相关工作对照。** 分档 B（观念层）。"LLM 需外挂脚手架以分离发散与收敛"这一核心主张在 CreativeDC（arXiv 2512.23601，2025-12）与 Scaffolding Creativity（arXiv 2510.26490，2025-10）中已先行公开并有理论支撑。但这两项工作均在单模型内部以两阶段 prompt/温度或 persona 切换实现，不含记忆召回锚定、空间投票与多对一收拢；观念在先，实现路径不同。

### 3.3.2 空间相加投票（反距离加权与温度画圆）

**设计动机。** 候选词的收拢不应采用线性相乘或硬匹配，而应在词向量空间中按内容分布做加性投票，以避免任一维度的低分对整体的乘法式否定。

**公式（形状级）。**

```
idw = 1 / (1 + d² · k)          # 反距离加权，d = 语义距离，k = 缩放系数
边界圆半径 = 温度系数 T 缩放     # T 大→半径大→更多候选；T 小→半径小→精确
投票 = Σ 加性累加（禁乘法链）
```

**变量定义。**

| 符号 | 含义 | 来源级别 |
|------|------|----------|
| `idw` | 单候选的反距离加权投票贡献 | — |
| `d` | 候选与查询在词向量空间的语义距离 | — |
| `k` | 距离缩放系数 | 经实验校准的定档值 |
| `T` | 温度系数，控制边界圆半径 | — |

**实现摘录（节选，摘自 p1_node6_spaceVote.mjs，节选）。** 上文形状级公式 `idw = 1/(1+d²·k)` 与"投票为加性累加、禁乘法链"在节点6 的投票内循环中逐字落地，`k` 即代码中的陡度系数 `_P1_NODE6_IDW_STEEPNESS`（属经实验校准的定档值，此处以符号代之）。省略温度圆半径缩放、内圈排除等分支：

```javascript
const d = 1 - cos;                              // 空间距离，d = 1 − cosine
// …（略：太远不投的下限门、温度圆内/外判定）
const idw = 1 / (1 + d * d * _P1_NODE6_IDW_STEEPNESS);   // 反距离加权，k = 陡度系数
let vote = w * idw;                             // 加性票 vote = w·idw，非乘法链
// …（略：域信号 domainBonus 加成，累加器取键）
rec.totalVote += vote;                          // 累加，全程无 /N（空间相加不相乘）
```

其中 `rec.totalVote += vote` 直接对应形状级公式的"投票 = Σ 加性累加（禁乘法链）"，累加过程不除以票数 N、不连乘，体现"多维标注是空间而非相乘"这一设计原则。

**设计依据。** 系统采用空间加性投票而非线性相乘：候选在向量空间中按内容分布投票，结果汇总到同一候选池；发散方向应表现为"沿空间走"而非落在孤立的点。

**相关工作对照。** 分档介于 C 与 B 之间。反距离加权本体为 Shepard（1968）经典空间插值公式，属通用零件；"语义空间按距离选候选"亦为通用专利套路（如 US 11086920 等，2018–2021）。但"反距离加权投票 + 温度系数缩放半径圆做边界 + 全程加性禁乘法链"这一具体组合未找到公开对应，在组合层可判为 D。

### 3.3.3 多对一方向词投票（Hough 式）

**设计动机。** 若由单个中间词直接产出方向词，易受该词偶然性影响。本系统令多个中间信息词对同一目标术语独立投票，以票数收拢选出最终方向词，从结构上抑制"单词直喷"。

**公式（形状级）。**

```
每个信息词 wᵢ → 对候选方向词 t 投票 vote(wᵢ, t)
方向词得分 = Σᵢ vote(wᵢ, t)      # 多对一累积投票（Hough voting 范式）
→ 票数峰值 = 最终方向词
```

**变量定义。**

| 符号 | 含义 |
|------|------|
| `wᵢ` | 第 i 个中间信息词 |
| `t` | 候选方向词 |
| `vote(wᵢ, t)` | 信息词 wᵢ 对方向词 t 的投票贡献 |
| 方向词得分 | 对某方向词的累积票数，取峰值者为最终方向词 |

**理论支撑。** 该设计与 Condorcet 陪审团定理同构：设 N 个独立投票者、每个正确率大于 50%，则多数投票的正确率约为 1 − (1/2)^N，随 N 指数增长——3 票时约大于 87.5%，5 票时约大于 96.9%，而单票仅约 50%（故单票应降权）。这为"多票高置信、单票低置信"提供了数学依据。

**实现摘录（节选，摘自 p1_node9_dirword.mjs，节选）。** 上文形状级公式"方向词得分 = Σᵢ vote(wᵢ, t)"在节点9 以一个共享累加器 `_voteAcc` 落地：每个信息词对同一候选方向词独立投票，票值加进 `totalVote`，投票者计数进 `voterCount`（即峰值判定所依据的"被多少信息词共同指向"），最终得分为累积票乘以该轴衰减。省略范围门、通道合并与金字塔分层等分支：

```javascript
// 每个信息词 wᵢ 对同一 eligible 方向词 t 独立投票（真正的多对一）
const vote = iwWeight * (relW + _domainW + ...);   // vote(wᵢ, t)，加性
_entryTotalVote += vote;                           // 单靶累积：Σᵢ vote(wᵢ, t)
_entryVoterCount++;                                // 投票者计数（多对一的"多"）
// …（略：过 47D 范围门、极性/温度校准）
const rec = _voteAcc.get(key);                     // 统一累加器（Hough/CN/bridge_to 共汇于此）
rec.totalVote  += _entryTotalVote;                 // 空间相加，非相乘
rec.voterCount += _entryVoterCount;
// …（略：排序、取 topN）→ 每个方向词最终得分：
score: cand.totalVote * Math.max(nd, _houghDecayFloor) * _resW,   // 累积票 × 轴衰减 nd
```

其中 `rec.totalVote += _entryTotalVote` 是"多对一累积投票（Hough voting 范式）"的直接实现；末行 `cand.totalVote × 轴衰减` 说明多对一得分在产出端还乘上了 3.3.5 节的轴衰减系数——这一点在形状级公式中未显式给出，属实现在设计稿基础上的接线细节（轴衰减经 node3 导出、node9 消费）。

**设计依据。** 关联数据中的词本质是"点"，系统需将点转换为"线"，发散即线的延展；产出方向词应基于多个相近词的多维加法收拢，而非依赖单个词。

**相关工作对照。** 分档 C（迁移层为 D）。Hough 投票范式极为成熟（Hough 1962；VoteNet，ICCV 2019），但既有工作全部集中于计算机视觉与点云领域。经多轮检索，未找到将 Hough 式投票迁移到自然语言处理中关键词/方向词生成的公开工作；将该范式迁移至词选择任务并赋予"防直喷"的结构性动机，是本系统较为独特的一处。

### 3.3.4 两次发散架构

**设计动机。** 单次发散难以兼顾广度与相关性。本系统采用异质两跳结构：第一次发散后先以空间投票收窄，再进行第二次发散产出信息词，最后收拢为方向词。

**结构（形状级）。**

```
发散₁（联想网络）→ 空间投票（收窄）→ 发散₂（产信息词）→ 多对一收拢（方向词）
```

**设计依据。** 系统的发散以"合并"为锚点展开：先检索既往关联与记忆，再基于联想网络（结合注意力式的查询—键—值机制）发散，然后转接进入下一跳。

**相关工作对照。** 分档 D。"两次发散、中间夹一层空间投票收窄、再发散产信息词"的特定两跳架构未找到公开对应。Tree-of-Thoughts（ToT）是概念邻居（C），但其为同质分支搜索加评估回溯，本系统为异质两跳（发散—投票—发散—收拢），结构不同。

### 3.3.5 六轴面发散

**设计动机。** 面向人物扮演式反馈的应用需要多学科支撑，单一维度的发散不足以覆盖心理、社会、语言等不同侧面。本系统令六条学科轴（心理、信息、社会、逻辑、语言、认知）并行独立发散，每轴输出多维的"面"而非单一分数，轴间以软衰减实现隔离而非硬切断。

**公式（形状级，轴衰减 axisDecay）。**

```
各轴关联度 axisRelevance[axis] = Σ(该轴 face 词贡献值)
按关联度降序排名 → axisRank，rank0 = 主方向轴
轴衰减 axisDecay[axis] = exp(-rank · β)
  rank0 → exp(0) = 1.0（主轴）
  rank1 → exp(-0.5) ≈ 0.607
  rank2 → exp(-1.0) ≈ 0.368
```

**变量定义。**

| 符号 | 含义 | 来源级别 |
|------|------|----------|
| `axisRelevance[axis]` | 某轴的关联度，等于该轴各面词贡献值之和 | — |
| `axisRank` | 各轴按关联度降序的排名，rank0 为主方向轴 | — |
| `β` | 轴衰减率 | 经实验校准的定档值（取 0.5） |
| `axisDecay[axis]` | 该轴的衰减系数，随排名指数衰减但恒大于 0 | — |

**实现摘录（节选，摘自 p1_node3_axis6.mjs，节选）。** 上文形状级公式的三行——关联度求和、按关联度降序取排名、`axisDecay = exp(-rank·β)`——在 `_computeAxisDecay` 中逐字对应，`β` 即代码常量 `AXIS_DECAY_BETA`（经实验校准的定档值，取 0.5）。省略 AXIS_CUTOFF 软停与白盒 trace：

```javascript
for (const axis of AXES) {                        // 各轴关联度 = 该轴 face 词贡献值之和
  axisRelevance[axis] = fw.reduce((s, x) => s + (x.v || 0), 0);
}
const ranked = AXES.slice().sort((a, b) => axisRelevance[b] - axisRelevance[a]);   // 按关联度降序
ranked.forEach((axis, rank) => {                  // rank0 = 主方向轴
  axisRank[axis] = rank;
  // 衰减如 exp(-rank·β)：rank0（主轴）= 1.0，远轴指数衰减但 >0 永不删
  axisDecay[axis] = axisRelevance[axis] > 0 ? +Math.exp(-rank * AXIS_DECAY_BETA).toFixed(4) : 0;
  // …（略：AXIS_CUTOFF 软停判定、cutoffRatio 记录）
});
```

`Math.exp(-rank * AXIS_DECAY_BETA)` 与形状级公式 `exp(-rank·β)` 完全一致，其中一处实现约定值得注明：关联度为 0 的轴其衰减取 0（而非 `exp(0)=1`），以避免未激活轴被误当主轴，此为公式在实现中的边界处理。

远轴的衰减系数指数下降但永不归零，实现"软隔离"：远离主方向的轴仍保留微弱贡献，允许适度擦边而不输出完全不相关的内容。

需标注设计与实现的一处已知偏差：设计意图是每个学科轴为每个词提供**多个信息点**（信息与信息范围，即 6+n 多维定位），信息点转移到候选池后一个词应携带多维信息；当前实现在面词贡献与轴关联度计算中把每轴对每词的多维定位压缩为单一数值 `v` 参与求和，属设计的降维执行，多信息点的完整保留为待改进方向。

**设计依据。** 人物扮演反馈需要写作、心理学、语言学、逻辑学等多学科并行支撑；发散允许擦边，但不应输出完全不相关的内容。学科轴数经由四轴、五轴到六轴的演进确定，设计者否决了进一步降维压缩的方案。

**相关工作对照。** 分档 C（数字/概念撞名）。Biber 的多维分析（MDA，1988）、LIWC（2001）及认知科学的"六支撑学科"均使用了"多维""六"这类词，但没有一项是"六条学科轴并行独立发散、每轴产多维面而非分数、轴间软衰减"的机制（机制层可判 D）；且学科清单亦不同，本系统含信息、逻辑、认知轴，而无哲学、人类学、神经等轴。

### 3.3.6 子轴激活定位（只定位不打分）

**设计动机。** 在产出端需要一个高分辨率的方向坐标空间，用于把输入映射到具体的子方向；此步的职能是"定位"而非"评分"，二者应明确分离。

**结构（形状级）。**

```
产出端 = 子方向坐标空间（子轴集合）
激活子集 = 输入命中的子方向（仅被输入指向的子方向被激活，其余保持沉默）
→ 定位（不打分）
```

**设计依据。** 产出端子方向坐标数量较大，其行为可参照统计物理中的系综——大量粒子叠加涌现出宏观态。产出端子轴与六条学科轴是相互分离的两层，子轴并非六轴的下级切片。就职能而言，设计上子轴层是六主轴粗定位之后的**方向细化层**——刻画定位点处向各子方向细化与发散的方向，驱动后续定向发散与扩充产出；当前实现以术语命中集合近似该定位，属设计的简化执行。

**相关工作对照。** 分档 D（概念邻居 C）。"激活子集定位、只定位不打分"这一明确区分"定位"与"打分"的产出端子轴坐标机制未找到公开对应。Axis-Aligned Subspace 贝叶斯优化（arXiv 2504.06111，2025-04，打分驱动）与神经元多义性研究（arXiv 2505.07831）是远概念邻居，用途与机制均不相符。

### 3.3.7 括号双信道

**设计动机。** 在对话文本中，括号内容常承载与正文不同层次的元语言信息（如动作、旁白、语气标注）。若将其与正文混合并取均值，会消解二者之间的张力。本系统将括号内容作为元语言副信道，与正文主信道分离处理。

**结构（形状级）。**

```
正文 → 主信道处理
括号内容 → 元语言副信道（独立处理）
两信道不混合、不取均值 → 保留张力
```

**设计依据。** 两信道不取均值，以保留对立信号之间的张力，避免降维式的均值化把相互冲突的信号抹平。

**相关工作对照。** 分档 C。"多信道分离不混合""保留张力"等概念词在全双工语音的用户流路由（User-Stream Routing，arXiv 2605.10199，2026-05）与叙事张力研究（arXiv 2604.09854，2026-04）中出现，但"把对话括号内容当作元语言副信道、与正文主信道分离、不取均值"这一具体做法未找到公开对应（机制层 D）；相关工作亦多在 2026 年 4、5 月，晚于或平行于本系统设计期。这是本系统较为独特的一处。

### 3.3.8 大量擦边召回

**设计动机。** 与追求精确的检索增强生成（RAG）不同，本系统的召回是为下游发散服务的：它采用低门槛、大量、模糊的召回策略，召回结果仅作锚点，不主导发散方向。

**公式（形状级，加权线性召回打分）。**

```
composite = 0.45×relevance + 0.20×recency + 0.20×attention + 0.15×weight
scoreRecord = max-pool（对所有查询节点取最强同向节点）
```

**变量定义。**

| 符号 | 含义 | 来源级别 |
|------|------|----------|
| `relevance` | 语义相关度 | — |
| `recency` | 时间新近度 | — |
| `attention` | 注意力集中度 | — |
| `weight` | 记忆重要度权重 | — |
| 权重系数 0.45/0.20/0.20/0.15 | 各分量的线性组合权重 | 经实验校准的定档值 |
| `scoreRecord` | 一条记忆的最终得分，对该记忆所有查询节点取最大值 | — |

**设计依据。** 召回以擦边、大量的方式进行；其机制为"上下文加注意力集中加多轴"去匹配既往内容（如数据层、热层、冷层）并取出，不要求很智能的判断——本质是关键词匹配，这也是"召回不消耗大模型 token"这一原则的来源。

**相关工作对照。** 分档 B（手段层）。"低门槛、高召回、关联式模糊召回"作为技术手段，在 HippoRAG（arXiv 2405.14831，2024-05）、SYNAPSE（arXiv 2601.02744，2026-01）、Predictive Associative Memory（2026-02）中均已实现且早于或接近本系统。但这些系统的目的是提升检索准确率或多跳问答表现，追求"准"；本系统的召回目的与角色相反——召回只做发散锚点、不主导、故意保持模糊以撑开候选，为下游发散提供候选素材，追求覆盖广而容忍模糊。手段层撞车（B），目的与角色层不同。

需要特别指出，SYNAPSE（2026-01-06，早于本系统）与本系统共享扩散激活、侧抑制、扇出效应三个术语，但用途正交（前者用于检索问答准确率，后者用于发散生成）。仅凭公开摘要无法排除实现级更深层的相似，此项列为需人工复核的重点之一。

### 3.3.9 查询—键—值池交汇发散

**设计动机。** 孤立、无联系的候选词会导致发散漂移过大。本系统借鉴注意力机制的查询—键—值（QKV）结构，将其改造为一条外挂发散管线，用注意力过滤控制漂移。

**公式（形状级）。**

```
Q = 输入词向量质心
K = 联想网络 cue（收拢锚点 = 输入关键词 + recallAnchors）
V = 交汇 cue → 链式再联想 → 注入 XML 的发散词
attention(Q, K) = softmax(Q · Kᵀ / √d)     # 低 attention 候选过滤（漂移控制）
```

**变量定义。**

| 符号 | 含义 |
|------|------|
| `Q` | 查询，取输入词向量的质心 |
| `K` | 键，取联想网络线索（输入关键词与召回锚点的收拢） |
| `V` | 值，取交汇线索并链式再联想产出发散词 |
| `d` | 词向量维度，`√d` 为缩放因子 |
| `attention(Q, K)` | 注意力权重，用于过滤低注意力候选以控制漂移 |

**设计依据。** 发散基于收拢后的内容进行；孤立无联系的词汇会导致漂移过大，故引入注意力机制，同时参考语义相近的词与召回锚点，以锚定发散范围。

**相关工作对照。** 分档 C（概念类比撞名）。"注意力即检索/关联记忆"是自 2017 年起的通用解读（现代 Hopfield 网络等价于注意力，Ramsauer 2020）；"查询质心"在键值加速工作（CSAttention，2026-04）中撞名。但"Q 取词向量质心、K 取联想网络线索、V 取交汇线索做链式再联想"这一把 QKV 三元组改造成外挂发散管线的具体用法未找到公开对应（管线化用法层 D）。

### 3.3.10 大中小三级路由

**设计动机。** 全局打分容易被万金油词与高连接度枢纽词主导。本系统以倒排索引的三级路由（大类方向、中类局部、小类术语）替代全局打分，从结构上治理万金油/枢纽词问题。

**结构（形状级）。**

```
触发词 → 倒排激活子类别（中类）→ 局部精排（小类术语池）
= 书本类比：目录（大）→ 章节（中，可叠加）→ 文字（小，术语）
```

**设计依据。** 大类为大致方向，中类为方向的局部（可叠加），小类为术语池并落到具体术语；其类比是书本的目录、章节与文字，其中目录（中类）内容可相互结合。此三级划分的目的是避免枢纽词把一切吸附过去。

**相关工作对照。** 分档 B（结构层）。"粗到细、大中小分级路由加倒排索引"是成熟的信息检索范式（HRR，arXiv 2503.02401，2025-03；CITADEL，2022-11；倒排索引，1970 年代），均早于本系统。但"触发词经倒排激活子类别再局部精排、且明确以治理万金油/枢纽词为设计目标"的动机未找到直接对应——通用分级检索面向效率与精度，本系统面向"避免枢纽词把一切吸过去"这一发散质量动机。

### 3.3.11 热插拔词库作为额外发散轴

**设计动机。** 系统希望通过增加词库文件来直接扩展发散能力：新增一个词库文件即等价于系统多出一条发散轴，且支持运行时热加载。

**结构（形状级）。**

```
三层词库（优先级 learned > packs > core，类比输入法）：
  core/    内置随部署不可删（swow / cooccur / cilin / cogmech）
  packs/   可插拔运行时生效（如 acg-chinese 27878 词 / medical / airp-techniques 等）
  learned/ 逐用户从对话自学
mtime 30s 检查 → 改文件 30s 内自动 reload
打字式升权 userBoost(word) = log(1+freq[word]) × 0.1   （上限 +0.3）
```

**变量定义。**

| 符号 | 含义 | 来源级别 |
|------|------|----------|
| `freq[word]` | 某词在用户对话中的出现频次 | — |
| `userBoost(word)` | 打字式升权量，随频次对数增长 | — |
| 系数 0.1、上限 +0.3 | 升权缩放系数与封顶值 | 初始默认值 |
| mtime 检查周期 30s | 文件修改时间轮询周期 | 初始默认值 |

**设计依据。** 系统追求词库热插拔与使用适应性，使其行为如打字般随用户习惯调整；由模型依据对话自行构建与调整词库，被视为更优的路径。

**相关工作对照。** 分档 C（基建撞名）。"热加载词库/插件"是极常见的基建（如 Elasticsearch 词典热加载，2020-11；Obsidian Hot-Reload；各类监听重载机制），文件修改时间轮询撞名。但"每加一个词库文件即等价于系统自动多出一条发散计算轴"这一把词库文件等同于发散维度的语义未找到公开对应（D）。SillyTavern 的 World Info 是最近的生态邻居（可热加载关键词词库），但其机制为"触发即注入固定文本"，而非"新增发散轴"，机制不同。

### 3.3.12 二级词汇体系与废词判据

**设计动机。** 系统需要区分两类语义单元并施加信息增益约束：中间产出的信息词不外泄，经多对一收拢为方向词后才输出；同时以"主模型是否已能自行推出"作为词价值的判据，剔除无信息增益的废词。

**结构（形状级）。**

```
信息词（中间、不输出）→ 多对一收拢 → 方向词（输出、知识入口种子）
废词判据：主模型裸读能推出的词 = 废词 = 价值 0
方向词准入 6 条全满足：可搜索 + 有共识 + 是方向词 + 非诊断词 + 非路线词 + 非口语
```

系统以"点—线—面—体"的几何模型刻画信息层级：

- 体 = 用户一次对话的完整信息（输入加记忆数据）；
- 面 = 召回、联想发散与信息词（如"习得性无助""职业倦怠"），不输出；
- 线 = 输出的方向词（如"认知重构""价值澄清"），输出；
- 点 = 主模型据方向词组织的最终回复。

**设计依据。** 联想数据中的词是"点"，需将点转为"线"，发散即线的延展；系统应给主模型的是"方向"而非"线路"。方向词的组织遵循四项优先原则：体验词优先于术语、口语锚点优先于抽象、经历词优先于需要词、合并时保留锚点。

**相关工作对照。** 分档介于 C 与 D 之间。"种子词/启动（priming）"松散撞概念（Seeding priming，2023–24）。但"信息词（中间、不输出）与方向词（输出、多对一收拢）的二级词汇体系，加上'主模型裸读能推出的词即废词、价值为零'这一信息增益判据"未找到任何公开对应。以"基础模型是否已能推出"定义词价值为零的废词判据，是相当独特的判据设计（D），为本系统明显原创的一处。

### 3.3.13 BLQ 多维加性打分框架

**设计动机。** 候选词的综合评分若采用乘法链，等价于一个"与门"（AND 门）：任一维度低分即对整体形成否定，导致候选被单维度扼杀。本系统在多个标注维度上统一采用一次性加性出分（CombSUM），辅以侧抑制与最大边际相关性（MMR）配额，使评分呈"或门"（OR 门）语义。

**公式（形状级，详见 3.4 节）。**

```
additive = W_SPATIAL·dSpatial + W_TF·dTf + W_PATH·dPath
         + W_NB·dNb + W_SPEC·dSpec + W_CONFIRM·dConfirm   （加权 CombSUM，不连乘不取均值）
blqScore = max(additive · FLOOR, additive − Σpenalty)      （抑制维加性扣分 + 软地板）
```

**设计依据。** 多维标注构成的是一个"空间"而非相乘关系；早期曾表述为"多轴打分后取均值，不达标则删除"，但取均值的方案后被否决，改为加性——因为取均值会归零维度间的张力。

**相关工作对照。** 分档 B（组件层）。三大组件——CombSUM（Fox & Shaw 1994）、MMR（Carbonell & Goldstein 1998）、侧抑制——均为数十年历史的经典信息检索/神经科学零件，远早于本系统；SYNAPSE（2026-01）亦将侧抑制用于记忆。但未找到"CombSUM + 侧抑制 + MMR 配额三件套统一组装、并明确以'加性即或门、对抗乘法链即被单维否定的与门'为设计论据"的公开完整框架。本系统的原创性主张在于"为何必须加性而非乘法"的论据与三件套的特定编排，而非单个零件。该框架的完整规格见 3.4 节。

### 3.3.14 0-token 白盒立场（横切原则）

**设计动机。** 这是一条横切整个发散步骤的设计原则而非单一算法：整个发散过程不调用大语言模型、全程可白盒观测，以规则计算、向量运算与小模型标注完成，避免为单次发散耗费大模型 API 成本。

**设计依据。** 系统一贯以零成本为目标，不将高成本大模型用于发散这类步骤；观测上采用白盒立场，直接检视实际输出而非依赖代理评分工具。

需界定该原则的适用范围：0-token 描述的是**当前生产线路（线路1）**的发散步不调用 LLM。设计中另含 LLM 优化器可插入不同位置的三条线路（见第2章 2.2.2）与规划中的小模型（Qwen3.5:2B）前置定位层——小模型只承担方向理解与标注、不产出创造性内容，且为本地部署，不改变零 API 成本的立场。0-token 不应被理解为"设计中不存在任何 LLM 环节"。

**相关工作对照。** 分档 D（竞争格局层）。在最接近的若干方案对比中，本系统是唯一实现"0-token、发散步不需大模型"的方案（SA-RAG、FS-RAG、LWOW、MAD 均需大模型参与发散或检索）。相关研究（MAD 与 LiveIdeaBench）还表明"大模型的发散能力与其通用智能分数不相关"，即投入更多大模型算力并不能解决发散问题，这从侧面支持了本系统外挂式 0-token 路线的合理性。就该原则统领下的具体机制而言，多学科坐标定位（第二步）与沿坐标再发散（第三步）是较为新颖的组合。

**小结（3.3 节）。** 逐项核查表明：在"机制高度相似且早于本系统设计期（2026-04）"的严格意义上，上述原创项均未与公开工作撞车。撞到的多为通用零件（B 档）或概念/术语撞名（C 档）。本系统的原创性主张普遍落在"把成熟零件组装成一条为发散服务的外挂管线、在生成任务上的迁移用法、以及若干具体判据"这一层，而非单个零件本身。分档定义与汇总见 3.6 节。

## 3.4 BLQ 评分框架完整规格

本节给出 BLQ 评分框架的完整规格。BLQ 的职能定位为转接器内部的候选质量打分装置，而非发散引擎或选择器：方向的"选择"由空间投票与多对一投票承担，BLQ 在选择之后只做降权、筛除废词与红线剔除。

### 3.4.1 接线现状

在完整规格之前需诚实声明各组件的接线状态。BLQ 打分核心（calcBLQ）实现了完整的多维加性框架，代码存在且可逐行审读，但当前尚未接入发散主循环——线上信息词打分实际由空间投票与轴衰减承担；方向词精排组件（node10）使用的是打分核心的简化版本，仅执行高斯衰减与红线剔除，不运行完整的六维 CombSUM；红线硬剔组件与方向词精排组件当前为线上活跃状态。本节描述的完整六维框架属"已实现、待接回"的组件库算法。据此，具体权重与系数均按来源级别标注。

### 3.4.2 六个加分维（CombSUM）

BLQ 打分核心的结构为：六个加分维加权线性相加（CombSUM），再减去若干抑制维的加性扣分。设计铁律为不作全乘积、不取均值。六个加分维如下。

| 维 | 名称 | 公式（逐字保留） | 权重 | 权重来源级别 |
|----|------|-----------------|------|------|
| N1 | 空间距离 dSpatial | `const dSpatial = Math.tanh(rawScore);` | `W_SPATIAL: 1.0`（主信号） | 经实验校准的定档值 |
| N2 | BM25-TF 饱和 dTf | `const dTf = _bm25Tf(tf);`，其中 `_bm25Tf(f) = f/(f+k1·(1-b+b))`（本场景平均文档长度为 1，退化为 `f/(f+k1)`） | `W_TF: 0.6`；`BM25_K1: 1.5`；`BM25_B: 0.75` | 经实验校准的定档值 |
| N3 | 跨学科路径和谐 dPath | `const dPath = Math.log(1+disc)/Math.log(1+6);`（对数归一，六轴为上限） | `W_PATH: 0.4` | 经实验校准的定档值 |
| N4 | 邻域相关性 dNb | `const dNb = nbCos != null ? Math.max(0, nbCos) : 0.3;`（无邻域信息时取中性值 0.3） | `W_NB: 0.5` | 经实验校准的定档值 |
| N5 | 特异性 dSpec | `const dSpec = spec;`（越具体越加分，抑制泛化的万金油词） | `W_SPEC: 0.4` | 经实验校准的定档值 |
| N6 | 资源确认 dConfirm | `const dConfirm = _confirmCount>0 ? Math.log(1+_confirmCount)/Math.log(1+6) : 0;`（六通道上限归一） | `W_CONFIRM: 0.3` | 经实验校准的定档值 |

**变量定义。**

| 符号 | 含义 |
|------|------|
| `rawScore` | 空间投票的原始得分，经 tanh 压缩至 [0,1) 以防单一空间票垄断 |
| `tf` | 候选词频，经 BM25 饱和函数处理 |
| `k1`, `b` | BM25 的词频饱和与长度归一参数 |
| `disc` | 候选覆盖的不同学科数 |
| `nbCos` | 候选与邻域中心的余弦相似度 |
| `spec` | 候选的特异性度量 |
| `_confirmCount` | 候选在各资源通道被确认的次数 |
| `W_*` | 各维的加权系数 |

一项结构性约束是：跨学科路径和谐（N3）仅在此处计入一次，不得在外层再次相乘。历史上曾存在"内层排名与外层各乘一次"的做法，会导致全乘积式坍缩，已被否决。

### 3.4.3 加性汇总（CombSUM）

六维加权汇总的实现逐字如下：

```javascript
const additive =
  CFG.W_SPATIAL * dSpatial +
  CFG.W_TF * dTf +
  CFG.W_PATH * dPath +
  CFG.W_NB * dNb +
  CFG.W_SPEC * dSpec +
  CFG.W_CONFIRM * dConfirm;
```

即加权线性和（Fox & Shaw 1994 提出的 CombSUM），不连乘、不取均值。这是"多维标注是空间而非相乘"这一设计原则的直接落地。

### 3.4.4 四个抑制维（加性扣分）

每个抑制门先计算一个乘子 `m ∈ (0,1]`，再转换为加性扣分 `penalty_d = additive · (1 − m_d)`。各门只此一处，不构成旧式全乘积链。

| 抑制门 | 触发条件 | 乘子常量 | 来源级别 |
|--------|----------|----------|----------|
| mOverused（万金油） | 命中万金油惩罚词表（130 条手工标注）或候选自带过用标记 | `OVERUSED_PENALTY: 0.35` | 经实验校准的定档值 |
| mPolarity（极性不匹配） | 输入为正向而候选为负向（或反之） | `POLARITY_MISMATCH: 0.3` | 经实验校准的定档值 |
| mNbIrrelevant（无关） | `nbCos < NB_IRRELEVANT_COS`（阈值 0.05） | `NB_IRRELEVANT_PEN: 0.15` | 经实验校准的定档值 |
| mIsolatedNoise（孤立噪声） | 需消费资源确认但确认计数为 0 | `ISOLATED_NOISE_PEN: 0.5` | 经实验校准的定档值 |

最终得分的实现逐字如下：

```javascript
const penaltySum = penOverused + penPolarity + penNbIrrelevant + penIsolatedNoise;  // 各 = additive·(1−m)
const blqScore = Math.max(additive * CFG.BLQ_SUPPRESS_FLOOR, additive - penaltySum);
```

**变量定义。**

| 符号 | 含义 | 来源级别 |
|------|------|----------|
| `m_d` | 第 d 个抑制门的乘子，取值于 (0,1] |
| `penalty_d` | 第 d 个抑制门的加性扣分，等于 `additive·(1−m_d)` |
| `penaltySum` | 四个抑制门扣分之和 |
| `BLQ_SUPPRESS_FLOOR` | 软地板系数，取 0.1，多门叠扣时不硬归零 | 经实验校准的定档值 |
| `blqScore` | BLQ 最终得分 |

该设计的两个性质值得说明。其一，单门触发时 `additive − additive·(1−m) = additive·m`，与旧式单门连乘等价；多门触发时为线性叠扣，不发生指数坍缩。其二，软地板保证多门叠扣不硬归零，体现"大量擦边"下的软隔离原则。系统另设抑制维聚合模式开关，默认采用加性模式，乘法连乘模式仅保留用于对照实验。

### 3.4.5 红线硬剔（isRedlineWord）

红线剔除为硬性移除：命中即移出候选池，不进入产出，而非降权。四类红线的正则种子属结构常量，非可调数值。

- **R1 路线词**：给出"应该怎么做"的动作、方法、步骤（如"建议""应该""方法""步骤""策略"及英文 technique/strategy/step 等）。设计准则是只给方向不给路线。
- **R2 诱导词**：替用户下判断的引导语（如"你需要""你必须""一定要""快去"及英文 you must/you need to 等）。
- **R3 主观体验/代替用户表达**：形如"你（很/好/真/太/是/觉得/感到……）""我觉得""感觉很……"的表达。设计准则是不代替用户表达。
- **R4 诊断词**：把用户判定为障碍或病症的词（如"障碍""患者""抑郁症""焦虑症""确诊"及英文 disorder/syndrome 等）。其中裸"症"字以"症(?!状)"排除"症状"，因为"症状"是描述而非诊断——此细化系由白盒观测实际输出时发现。

万金油、配额、极性、高斯衰减等均为降权（不删除），只有 R1–R4 为硬剔除。

### 3.4.6 两级精排的差异（node8 筛信息词 vs node10 筛方向词）

系统在两个层级各设一套精排逻辑，二者职能不同。

| 维度 | node8 筛信息词 | node10 筛方向词 |
|------|----------------|-----------------|
| BLQ 打分 | 运行完整六维 CombSUM | 不跑六维；仅 `node9 得分 × 高斯衰减` |
| 侧抑制 | 有（邻域余弦超阈值判近义并压制） | 无 |
| MMR 多样性 | 有（`λ·rel − (1−λ)·maxSim`，λ=0.7） | 无 |
| 配额 | 有（单轴配额 8、单维配额 3，超配额降权） | 无 |
| 相关性衰减 | 无（衰减在 BLQ 抑制维内） | 高斯渐变 `_gaussDecay(cos, PEAK=0.45, SIGMA=0.25, FLOOR=0.15)`（算位置而非压分） |
| 断崖弃权 | 无 | 有（前词大于后词乘以断崖比 3 且序位不小于 5 时断崖，突破"填满 15 词"的天花板） |
| 输出上限 | 30（信息词） | 15（方向词，契约为长度 15 的字符串数组） |
| 输出红线 | 不做（信息词不外泄给主模型） | 标注红线，由红线硬剔组件执行 |
| 接线状态 | 组件态（无生产调用） | 线上活跃 |

一句话概括：node8 是"完整 BLQ 精排引擎（六维加侧抑制加 MMR 加配额）"，当前为组件态；node10 是"轻量选后处理（高斯衰减加红线标注加断崖）"，当前线上活跃。node10 不复用完整六维打分，仅保留"衰减"与"红线"两件事，且不夺多对一投票（node9）的权——多对一投票的次序为主导，node10 只做降权、衰减与红线。

### 3.4.7 可公开的原创口径

BLQ 框架的三大组件（CombSUM、MMR、侧抑制）均为经典标准件，本系统不主张发明它们。可对外主张的原创限于三点：其一，"加性即或门、对抗乘法链即被单维否定的与门"这一设计论据；其二，三件套加六加分维加四抑制维的特定编排；其三，软地板软隔离机制。所有权重系数、惩罚系数、衰减率与截断参数均为经实验校准或初始默认的具体取值，属参数细节，发布时以结构为主而不锁定具体值。

### 3.4.8 打分核心实现摘录（节选）

前几节以逐维公式与变量表描述了 BLQ 的结构，此处补充打分核心 `calcBLQ` 的连续骨架，以呈现"六加分维一次性 CombSUM、再减若干加性扣分、末以软地板托底"这一形状在实现中的整体样貌。摘自 p1_node8_10_blq.mjs，节选，六个加分维的归一表达式已在 3.4.2 表内逐行给出，此处仅保留聚合与抑制主干，省略白盒 trace、极性推断分支与边界回退：

```javascript
// ── 六加分维加权 CombSUM（加法聚合，不连乘、不取均值）──
const additive =
  CFG.W_SPATIAL * dSpatial + CFG.W_TF * dTf + CFG.W_PATH * dPath +
  CFG.W_NB * dNb + CFG.W_SPEC * dSpec + CFG.W_CONFIRM * dConfirm;
// ── 四抑制维：各门先算乘子 m∈(0,1]，再转加性扣分 penalty = additive·(1−m)（各门只此一处）──
const penOverused      = additive * (1 - mOverused);
const penPolarity      = additive * (1 - mPolarity);
const penNbIrrelevant  = additive * (1 - mNbIrrelevant);
const penIsolatedNoise = additive * (1 - mIsolatedNoise);
const penaltySum = penOverused + penPolarity + penNbIrrelevant + penIsolatedNoise;
// ── 软地板托底：多门叠扣不硬归零（软隔离）──
const blqScore = Math.max(additive * CFG.BLQ_SUPPRESS_FLOOR, additive - penaltySum);
```

其中权重 `W_*`、四个惩罚乘子常量与软地板系数 `BLQ_SUPPRESS_FLOOR` 均为经实验校准的定档值，此处以符号保留而不锁定具体取值。该骨架逐字印证 3.4.3/3.4.4 节的两条主公式：加分维走加法（`additive` 为纯加权和），抑制维走"乘子转加性扣分"（`penalty = additive·(1−m)`），单门触发时等价于旧式单门连乘 `additive·m`，多门触发时为线性叠扣而非指数坍缩。

节点10 的方向词轻量精排不复用上述六维打分，仅以高斯衰减替代（对应 3.4.6 节"算位置而非压分"）。其核心函数摘录如下（摘自 p1_node8_10_blq.mjs，节选）：

```javascript
function _gaussDecay(cos, peak, sigma, floor) {   // 落最优带→~1.0，偏离→渐降到 floor（不归零）
  if (cos == null) return 1.0;
  const g = Math.exp(-((cos - peak) ** 2) / (2 * sigma * sigma));
  return floor + (1 - floor) * g;
}
```

`peak/sigma/floor` 为该函数的最优带中心、带宽与下限（经实验校准的定档值，以符号代之）。`floor + (1-floor)·g` 的结构保证再远也不归零，与 BLQ 主框架的软地板同为"软隔离"原则在不同层级的两次落地。

## 3.5 消融与失败方案

本节以"消融与失败方案"的体裁记录算法演进史中被实测证伪的方案。在技术报告中，负面证据具有独立价值：它标明了设计空间中哪些"看似更合理"的方向已被实证排除，可避免后续重复踩坑。本节所列公式多为历史方案，不是当前实装，读者不应将其当作现行系统行为。

### 3.5.1 打分公式的三代演进

**第一代：十三因子乘积（已废弃，作为反面教材列出）。**

早期（2026-05-05 版）的收缩打分采用十三因子全乘积：

```
finalScore = vote^1.2
           × dynamicPE          × ibApprox         × crossFaceBonus
           × valCoh             × nbBoost          × dimOverlapPenalty
           × stageBoost         × routeBoost       × crossoverBoost
           × memAnchorBoost     × registerBoost    × modeDirBoost
```

其被判为反面教材的原因有三：其一，十三因子全乘积等价于一个与门，任一因子偏低即导致全局崩溃；其二，各因子并非相互独立（如投票项与交叉项高度相关），违背了朴素贝叶斯乘积所要求的独立性假设；其三，若干因子各自的定义另有缺陷，如动态惊喜度存在跨用户污染、某加权项虚增投票、维度重叠惩罚项 `0.55^(dims-2)` 会消灭枢纽词，与"小词激活大模块"的设计取向相反。

**第二代：轴均值（已重写）。**

其后改为十四维坐标点积后取均值，首次突破 4.0 分（4.050）：

```
score = Σ[(coordAccum[i] × termCoords[i]) / max(|coordAccum[i]|, 0.5)] / 14
```

该方案对应"万金油主要是因为部分轴分数过高、故应取均值"的早期设想，但取均值后被否决：取均值归零了维度间的张力，导致万金油词增加约 25%。由此演进到第三代加性投票。

**第三代：加权线性/加性投票（当前方向）。**

召回侧当前采用加权线性组合：

```
composite = 0.45×relevance + 0.20×recency + 0.20×attention + 0.15×weight
```

其中权重系数为经实验校准的定档值。该方案是"不要简化"这一红线之下唯一被批准的算法简化，因为它是增强而非退化。实测表明该方向在多个数据集上带来显著收益。相应的红线包括：不回退乘积（乘积方案实测导致召回率大幅下降）、不删去 softmax 归一化、以及权重的具体数值可调而"加权线性方向"本身锁定。

系统另保留一套旧的乘积式单节点打分供调试使用：

```javascript
ebbinghaus = record.freq × (1 / (1 + days × 0.1));            // Ebbinghaus 遗忘曲线
importance = record.weight × Math.max(0, 1 - days / 60);      // 60 天外完全消失
axisOverlap = Σ cosineSim(qVec, kVec) / |axes|;               // 多轴投影同向（归一化）
spreadDecay = Math.pow(0.6, spreadDistance);                  // 0/1/2/3 → 1.0/0.6/0.36/0.216
scorePerNode = ebbinghaus × importance × axisOverlap × spreadDecay;
scoreRecord = max(scorePerNode)  // max-pool：一条记忆一个维度极强即召回
```

并有一套三因子置信度用于闸门判断（不参与排序）：

```
confidence = 0.5×max(score) + 0.3×(命中数/2 clamp[0,1]) + 0.2×轴一致性
闸门阈值：chat/airp 0.5 / game 0.6 / work/bot 0.7 / code·memory 不跑发散
```

上述三因子权重与闸门阈值均为经实验校准的定档值。

### 3.5.3 置信度路由（历史，手调阈值无统计基础）

早期的置信度路由如下：

```
confidence = F1×0.45 + F2×0.35 + F3×0.20    （F1 丰富度 / F2 分差 / F3 历史）
≥0.55       → normal (6 词)
0.30-0.55   → multi_candidate (10 词)
<0.30       → meta_signal (0 词静默)
```

其中 0.55/0.30 为手调阈值，缺乏统计基础，属初始默认值，规划以保形预测（Conformal Prediction）类方法替代。

### 3.5.4 远距联想的距离带（现行参照）

系统采用一个最优语义距离区间控制发散的远近，作为现行参照：

```
semDist < 0.15 → blq × 0.4   (太近，同义词冗余)
semDist < 0.25 → blq × 0.7
semDist > 0.80 → blq × 0.5   (太远，随机噪声)
semDist > 0.70 → blq × 0.8
```

最优距离区间为 `0.15 < semDist < 0.80`，其中各衰减系数为经实验校准的定档值。一条相关红线是：距离为 1 的同义扩散实测导致召回率与排序指标显著下降，故"类比是跨域同构，不做同义扩散"被列为红线。

### 3.5.5 完整认知激活方程（未实装）

系统曾规划完整的 ACT-R 激活方程，但当前仅接入了其中的扇出惩罚项，基础激活与扩散激活部分未实装：

```
基础激活: B_i = ln(Σ_j t_j^{-d})            d = 0.5（衰减率）        ← 未实装
扩散激活: S_ji = S - ln(fan_j)              S = 2.0（最大联想强度）  ← 未实装
         W_j = 1.0 / len(context_chunks)                            ← 未实装
完整方程: A_i = B_i + Σ_j(W_j × S_ji) + ε_i  ε = 0.5（噪声）        ← 未实装
检索阈值: τ = -2.0    延迟: T = 0.35 × e^{-A_i}
```

当前实装的仅为扇出惩罚 `fanPenalty = 0.015 × log(fan(term))`（对应 ACT-R 的扇出效应，Anderson 1974），完整激活方程约五十行未接。其中衰减率、最大联想强度、噪声、检索阈值等均为规划中的初始默认值。

### 3.5.7 历史统一公式设计稿（乘法版，非现行实装）

演进中曾出现一份七因子的统一公式设计稿，采用乘法形式：

```
F(w) = Activation(w) × IB-tradeoff(w) × (1+λ·Sys(w))
     × LogicScore(w) × PathHarmony(w) × NoveltyBonus(w) × Σαₐ·scoreₐ(w)
```

其中各分项定义为：激活 `A(w) = A₀·∏[γ·wₖ·I_disc(k)]`（γ 取 0.7–0.85，链长 K 不超过 3，学科切换指示 I_disc 在跨学科时为 1、同学科时为 0.5，激活低于 0.15 时停止）；信息瓶颈权衡 `Score(w) = d(w)/(1+α·d(w)²)`，最优距离 `d* = 1/√α`（倒 U 型，中间值最优）；结构映射 `Sys = 0.5·H(高阶关系) + 0.3·R(一阶) + 0·A(属性不计分)`；路径和谐 `log(1+不同学科数) × 连贯性`，连贯性等于 `1 − (切换次数−学科数)/总步数`；新颖度 `1/√(historical_count+1)`（置信上界的简化版）。

需强调：此设计稿为七因子乘法版本，与 3.4 节当前实装的加性 CombSUM 版本不同。它是演进过程中被"加性优于乘法"论据取代的中间态，非现行实装。

### 3.6.3 需人工复核的重点

有三处相似度较高，列为需人工复核的重点。

其一，SYNAPSE（arXiv 2601.02744，2026-01，早于本系统）与"大量擦边召回"共享扩散激活、侧抑制、扇出效应三个术语，但用途正交（检索问答准确率 vs 发散生成）；摘要层无法排除实现级更深撞车，需核对全文确认。

其二，一套热/温/冷三层记忆结构（arXiv 2603.00037，2026-03-18）不仅同名，且同样以物理文件目录分层、同样有日期命名日志；本系统的三层设计起始时间据项目记录早约数日，但差距仅数日、机制高度相似——这是相似度最高的一项，需核对项目记录以确认独立平行发明。

其三，系统中的部分变量更新与模板引擎能力来自 SillyTavern 生态的移植（如变量更新机制及提示词模板引擎），发布时须致谢相应上游项目；本系统在此之上的原创扩展限于执行依赖链的编排与服务端整合。

### 3.6.4 借鉴来源清单

系统在设计中借鉴了多领域的经典工作。认知科学与仿生学方面，已实装的借鉴包括：激活扩散（Collins & Loftus 1975）对应多路扩散激活；扇出效应（ACT-R，Anderson 1974）对应扇出惩罚；模式分离/补全（海马体）对应三层记忆库；互补学习系统理论（McClelland 1995）对应召回与扩散激活的二元结构；信息瓶颈的倒 U 型（Tishby 1999）对应信息瓶颈近似；惊奇调制（Pearce-Hall 1980）对应频次衰减；弱连接理论（Granovetter 1973）对应桥接路径；结构映射引擎（Gentner 1983）对应结构类比；脚本/框架理论（Schank 1977）对应框架模式；系统功能语言学（Halliday 1994）对应虚词处理；依恋理论（Mikulincer-Shaver）对应角色心理通道。

信息检索与机器学习方面，已实装的借鉴包括：CSLS 几何修正（Lample 2018）、MMR 多样性（Carbonell 1998）、逆文档频率（Spärck Jones 1972）、Numberbatch 词向量（Speer & Lowry-Duda 2017）、缩放点积注意力（Vaswani 2017）、SWOW 联想数据（De Deyne 2019）、BM25（Robertson 1994）、CombSUM（Fox & Shaw 1994）等。

规划中尚未实装但拟借鉴的工作包括：HippoRAG（Gutiérrez，NeurIPS 2024，arXiv 2405.14831）及其后续（ICML 2025，arXiv 2502.14802）的个性化 PageRank 检索；倒数排名融合（Cormack 2009）用于跨尺度融合；LambdaMART（Burges 2010）用于替代手调因子；保形预测路由（Su 2025）用于替代手调阈值；离线版 HyDE（Gao 2023，在线版因违反 0-token 原则被拒）；以及评估校准相关的 PPI（Angelopoulos 2023）与多评审（Verga 2024）方法。此外，跨学科类比参照方面，系统各环节可与主成分分析、统计物理系综平均、玻尔兹曼分布、聚光灯注意、Condorcet 定理、PageRank 随机游走、信息瓶颈、信道编码等建立同构关系。

### 3.6.5 全局事实层小结

综合来看，可得如下事实层结论。第一，算法线无一项在"机制高度相似且早于 2026-04"的意义上撞车（A=0）；框架/系统线仅三层记忆一项相似度极高（差数日、同名加物理文件）。第二，本系统的原创性主张普遍落在"组装/迁移/设计论据"层，而非单个零件——所涉零件（反距离加权、Hough 投票、CombSUM、MMR、侧抑制、激活扩散、粗到细路由、热加载词库等）多为 1990 年代至 2020 年代的成熟技术，本系统不主张发明它们；未找到公开对应的是"把它们编排成一条为发散服务的外挂管线"以及若干具体判据与迁移（Hough 迁移至方向词生成、括号双信道、废词判据、词库文件即发散轴、加性对抗乘法的与门论据）。第三，上述三处高相似项需人工复核。

## 3.7 小结

本章形式化描述了自驱动发散召回系统的算法设计。核心可归纳为三层。在机制层，系统以"收缩—发散—收缩"的三段结构外挂于大语言模型之外，通过两次异质发散、六轴面并行、空间加性投票与多对一收拢，把孤立的关联点转换为可供主模型使用的方向词。在评分层，BLQ 框架以加权 CombSUM 的加性打分对抗乘法链的单维否定，辅以侧抑制、MMR 配额、软地板与红线硬剔，形成一套完整而可白盒审读的候选质量装置；其中信息词精排引擎当前为组件态，方向词轻量精排为线上活跃态。在原则层，全流程遵循 0-token 白盒立场，不为单次发散调用大语言模型。

从相关工作对照看，系统所用的单个算法零件多为成熟技术，其原创性主张落在编排、迁移与设计论据三个层面；逐项核查未发现在"机制高度相似且早于设计期"意义上的撞车，仅有若干高相似项需进一步人工复核。演进史中被证伪的方案——以十三因子乘积、轴均值、乘法版统一公式为代表——共同支撑了当前"加性优于乘法、软隔离优于硬归零"的设计取向，构成本系统算法设计的负面证据基础。
